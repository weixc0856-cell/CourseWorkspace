# S2/S3 数据契约设计（T1-01 视角，先设计不生产）

- **状态**：提案，待 owner 审。**不生成任何空文件，不改 deck，不签任何闸门。**
- **目标**：让 `brief → outline → narrative-plan → shot-sheet` 四个阶段引用同一份 Claim/Evidence，不在多个文件里重复维护同一句话。

## 1. 唯一权威

| 事实 | 唯一来源 | 其他文件怎么引用 |
| --- | --- | --- |
| Claim 文本、章节、页码、图号、证据类型 | `book/curation.yaml` → `book/index.json`（`K-*`） | 只写 Claim ID |
| 本集选哪些 Claim、是否 must_teach | `lessons/<slug>/authoring/episode.spec.yaml` 的 `claims` | 只写 ID + status + visual |
| 本集教学目标、受众、范围 | `authoring/brief.json` 的 `objectives` / `claim_ids` / `scope_out` | 不复制 Claim 文本 |
| 页面序列、每页讲哪条 Claim | `authoring/outline.json` 的 `pages[].claim_ids` | 不复制 Claim 文本 |
| 六幕叙事结构 | `authoring/narrative-plan.json` 的 `beats[].claim_ids` | 不复制 Claim 文本 |
| 运动镜头的证据/素材引用 | `storyboard.yaml` v2 的 `evidence_refs` / `asset_refs` | 只写 K-/F- ID 与资产路径 |
| 声线/词典 | `audio/voice-bibles/<id>.yaml`、`audio/lexicons/<id>.yaml`；课程默认 `audio/courses/<course_id>/voice.yaml` | lesson 只写 ID |

**禁止**：把 Claim 原文同时写进 spec、brief、outline、narrative；四处各写一份，必然再次漂移。

## 3. 需要补的字段

### 3.1 `episode.spec.yaml` 的 claim 从“复制文本”改为“引用”

现状：`claims: [{id, text, source, status, visual}]`，文本和 source 在 spec 里又写了一遍。

提案：

```yaml
claims:
  - {id: K-T1-01-S1, status: must_teach, visual: 2}
  - {id: K-T1-01-S2, status: must_teach, visual: 4}
  - {id: K-T1-01-S3, status: support,    visual: 6}
```

- 加载时从 `book/index.json` 解析 `text`/`source`；spec 不再保存这两项。
- 兼容旧 `C##` claim（仍可带 `text`/`source`），迁移完成后再删兼容分支。
- 好处：改一次 Claim 文本，brief/outline/narrative/spec 同步变化。

### 3.2 `brief.json` 增加 `claim_ids`

现有字段保留：`audience`、`objectives`、`prerequisites`、`duration`、`scope_in`、`scope_out`、`assumptions`、`source_map`、`generator`。

新增：

```json
{
  "claim_ids": ["K-T1-01-S1", "K-T1-01-S2", "K-T1-01-S3", "K-T1-01-S4", "K-T1-01-S5"],
  "scope_out": [
    "Ch. 3 energy/consumption claims (T3)",
    "section 1.10 design conflict, Fig. 1.66/1.67 (T1-10)"
  ]
}
```

- `objectives` 是教学语言（三条）；`claim_ids` 是证据选择；两者不互相复制。
- `source_map` 引用 digest 的 section ref（`S1-...`），不写页码/图号。

### 3.3 `outline.json` 的页面增加 `claim_ids`

现有 `OutlinePage` 有 `claim: str`（自由文本）和 `source_refs`。提案：

```json
{
  "slide": 2,
  "title": "The car changes the air around it",
  "claim_ids": ["K-T1-01-S1"],
  "target_seconds": 50,
  "visual": "Fig. 1.4a smoke; streamline spacing",
  "visual_kind": "book_figure",
  "source_refs": ["S1-1.1.2"]
}
```

- `claim_ids` 是权威；`claim` 改为可选展示标签（≤80 字），不承载证据。
- `source_refs` 指向 digest section，不重复页码。
- 纯视觉/预览页允许 `claim_ids: []` + `no_source` 理由（模型已有 `no_source`）。

### 3.4 `narrative-plan.json` 的六幕增加 `claim_ids`

```json
{
  "form": "long",
  "audience": "...",
  "promise": "...",
  "beats": [
    {"id": "cold_open", "start_s": 0,  "end_s": 25,  "summary": "...", "evidence": "real_data", "claim_ids": ["K-T1-01-S3"]},
    {"id": "question",  "start_s": 25, "end_s": 70,  "summary": "...", "evidence": "schematic", "claim_ids": ["K-T1-01-S3"]},
    {"id": "intuition", "start_s": 70, "end_s": 180, "summary": "...", "evidence": "schematic", "claim_ids": ["K-T1-01-S1"]},
    {"id": "mechanism", "start_s": 180,"end_s": 360, "summary": "...", "evidence": "real_data", "claim_ids": ["K-T1-01-S2"]},
    {"id": "test",      "start_s": 360,"end_s": 600, "summary": "...", "evidence": "real_data", "claim_ids": ["K-T1-01-S4"]},
    {"id": "connect",   "start_s": 600,"end_s": 720, "summary": "...", "evidence": "schematic", "claim_ids": ["K-T1-01-S5"]}
  ],
  "payoff": "..."
}
```

- 六幕是叙事功能，不是第二套 beat 表；它只引用 Claim，不定义镜头。
- `validate_plan` 新增规则（见 §4），保证 spec 的 must_teach claims 全部出现在某一幕。

### 3.5 `storyboard.yaml` v2 的镜头引用 Claim/Figure

- `ShotSpec.evidence_refs` 允许 `K-*`（Claim）或 `F-*`（Figure）ID。
- `asset_refs` 仍解析到 lesson 资产；`evidence_refs` 在校验时用 `book/index.json` 解析。
- **deck-only 课允许 0 个 shot**：页面的 Claim/证据映射在 `outline.json`，不要为了通过校验造一个空 shot。当前 storyboard 的 1 个 manim shot 只有在保留动效时才需要 `visual-design`。

### 3.6 Voice Bible / Lexicon 的课程级继承

现状：`resolve_assets` 只读 lesson 的 `narration.voice_bible`/`lexicon`，没有课程默认。

提案：

```text
audio/
├── voice-bibles/<id>.yaml
├── lexicons/<id>.yaml
└── courses/<course_id>/voice.yaml
```

`audio/courses/automotive-aerodynamics/voice.yaml`：

```yaml
schema_version: 1
course: automotive-aerodynamics
voice_bible: owner-en
lexicon: automotive-en
```

解析顺序：

1. lesson `narration.voice_bible` / `narration.lexicon`（显式覆盖）
2. course profile（`course_id` 从 lesson 读）
3. none（`narration-assets` 明确打印 none，不静默通过）

- lesson 不复制 YAML，不复制参考音；只写 ID。
- `narration.meta.json` 记录解析到的 bible/lexicon 哈希（现有字段可复用）。

## 4. narrative-validate 规则

保留现有 N-00…N-25（配置、唯一性、时间、六幕顺序、时长）。新增：

| 规则 | 检查 | 失败后果 |
| --- | --- | --- |
| N-30 | 每个 spec `must_teach` Claim 至少出现在一个 narrative beat 的 `claim_ids` | error |
| N-31 | 每个 `claim_ids` 存在于 `book/index.json` | error |
| N-32 | narrative beat 的 `claim_ids` ⊆ spec 选中的 claims | error |
| N-33 | 六幕覆盖 0→duration，无空洞/重叠（现有 N-02/03 已覆盖重叠，补“覆盖到结尾”） | warning |
| N-34 | `evidence: real_data` 的 beat 至少引用一个 figure/table 证据 | warning |

注意：validator 只证明结构，不证明教学有效；Q2 仍标 BLOCKED/WARN。

## 5. lesson.yaml 的 authoring 配置

字段已存在，只补声明：

```yaml
authoring:
  sources: authoring/sources.yaml
  digest: authoring/source-digest.json
  brief: authoring/brief.json
  outline: authoring/outline.json
  narrative: authoring/narrative-plan.json
```

- `brief`/`outline`/`narrative` 必须由真实内容生成；不能用空对象占位。
