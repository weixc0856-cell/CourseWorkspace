# 生产流水线：阶段、命令与中间交付物

- **版本**：v1.0（2026-11-16）
- **状态**：现行。**一条生产线的命令顺序、每个阶段的中间交付物、闸门与签字人，以本文件为准。**
- **上位**：`PRD.md`（产品边界）、`ARCHITECTURE.md`（结构与数据契约）、`课程生产统一契约V1.md`（字段）。
- **分工**：`生产合同.md` 定义 G0–G7 的门与四份合同；`v2/生产方向-*.md` 定义三条产品线的内容标准；`ACCEPTANCE.md` 定义验收命令与状态词。本文件只回答一件事：**什么时候跑哪条命令，跑完留下什么，谁来签字。**

> 冲突处理：同一问题出现两种说法时，按 **本文件（命令与产物）→ 生产合同（门）→ 生产方向（内容标准）→ 指南** 的顺序取值；仍冲突时以 `DECISIONS.md` 中日期更新的决策为准，并把旧说法标为 `record`。

## 1. 三个位置

| 位置 | 放什么 | 能不能删 |
| --- | --- | --- |
| 程序仓库（本仓库） | 代码、Schema、夹具、规范、检查脚本 | 按 git 规则 |
| 内容根 `<内容根>` | `lessons/`、`projects/`、`engines/`、`audio/`、`knowledge/`、`references/` | 不能 |
| 过程区 `build/` | 某个 slug 的阶段产物、缓存、日志 | **能**，重建即可 |
| 交付区 `deliver/` | 最终交付包，`package` 写的唯一位置 | 交付完成后归档 |
| 历史区 `archive/` | 已结束的项目、构建与记录 | 不参与检查 |

内容根其余目录的规则见 `<内容根>/README.md`。

**开发回归与生产检查分开**：`check.ps1` 只使用 `%TEMP%/CourseWorkspace/run-*` 的隔离内容根（`COURSEWORKSPACE_MODE=dev`），运行代码、夹具与合成课程全链测试，不读取也不写入生产内容根；`release-check`、`release-approve`、`package`、`package-verify` 是生产命令，必须显式指定生产内容根，dev 模式直接拒绝。生产内容根本身由 `course-control content-audit` 只读审计（build 布局、课程链、审批新鲜度、交付包 schema、残留临时目录），不写任何文件。

## 2. 阶段表

每一阶段只有三件事：**输入 → 命令 → 中间交付物**。闸门分两类：`auto`（程序判定，`pass/fail/incomplete`）与 `human`（具名签字）。

| # | 阶段 | 命令 | 中间交付物（内容根内） | 闸门 |
| --- | --- | --- | --- | --- |
| S0 | 立项 | `project-validate`、`validate --scope spec`、`preflight` | `projects/<系列>/project.yaml`、`lessons/<slug>/lesson.yaml`、`authoring/episode.spec.yaml`、`authoring/quality.rubric.yaml` | auto：`project-validate` + `preflight` + `validate --scope spec` 无 error；human：专题精华/cut 与 rubric 阈值签一次（G0） |
| S1 | 研究 | `ingest`、`digest` | `authoring/sources/`、`authoring/source-digest.json` / `.md`；新闻另有 `authoring/fact-check.md` | auto：摘要可复现、引用 ref 稳定；human：`author-accept --kind digest --by <name>`；新闻：事实矩阵不得为空 |
| S2 | 叙事 | `brief`、`outline`、`script`、`narrative-validate` | `build/<slug>/authoring/candidates/` 下的候选；签字后进 `authoring/brief.json`、`outline.json`、`narration.script.json` | human：`author-accept --kind brief|outline|script --by <name>`，`approval.json` 记 sha256；auto：`narrative-validate`（长视频/Shorts 必过） |
| S3 | 分镜 | `content-draft`、`author-accept --kind content --by <name>`、`shot-sheet`、`visual-design`、`sound-design` | `slides.md`、`lecture_notes.md`、`storyboard.yaml`；`build/<slug>/shot-sheet/plan.json`、`design/visual_design.json`、`sound/` | auto：`shot-sheet` 的引用与指纹；human：内容签字 |
| S4 | **静态分镜闸门** | `storyboard-page`、`storyboard-review --by <name>`、`author-accept --kind storyboard-page --by <name>` | `build/<slug>/storyboard/index.html`、`manifest.json`；签字后 `authoring/storyboard-review.json` | **human：逐页放行/否决；未签字不得注入动效、配音或渲染** |
| S5 | 声音 | `narration-build`、`subtitles-build`、`subtitles-accept --by <name>` | `build/<slug>/narration/narration.wav`、`narration.meta.json`、`subtitles/`；签字后 `lessons/<slug>/subtitles.srt` | auto：实测时长与字幕 QC；human：字幕签字 |
| S6 | 预览 | `animatic`、`preview-pilot`、`render shot|segment|project --mode preview` | `build/<slug>/animatic/`、`build/<slug>/preview/`、`preview/pilot.json` | auto：480p 时间线与缓存报告；human：抽看 |
| S7 | 正式渲染 | `render … --mode release` 或 `build` | `build/<slug>/animation/`、`contracts/shots.json`、`contracts/timeline.spec.json`、`final/` | auto：每段 QC、`frame-audit`；human：hero 帧（G4）与终审（G7） |
| S8 | 验收 | `media-qc`、`subtitles-qc`、`quality-report`、`quality-gate`、`release-check`（含分镜签字步骤） | `build/<slug>/quality/{media-qc,subtitles-qc,gate,certificate,defects}.json` | auto：`release-check` 输出 `PASS / FAIL / INCOMPLETE`；`INCOMPLETE` 不是通过 |
| S9 | 交付 | `release-approve --lesson` 或 `--project`（先跑完整 `release-check`，具名签核）、`package`（全部自动检查与两位具名审批成立才 pass；非 pass 不替换旧交付）、`package-verify`（重算证据，schema 2） | `deliver/<slug>/`（`final/master.mp4`、字幕、报告、`manifest.json`、`delivery-checklist.md`） | auto：`package-verify`；human：发布签核（具名） |

### 2.0 课程项目层

S0 的 `projects/<系列>/project.yaml` 是**课程项目层**，不是仓库配置。它用 `ProjectSpec` 的 `production.course` 声明课程规模、计划、卡片目录、Claim 索引、声线和禁用词；课程链先读它，仓库的 `config/course-chain.yaml` 只作 legacy/测试回退。分层与新课接入见 `课程开发管线-分层架构.md`。

### 2.0.1 教材来源的 S1 入口（Docling Bridge）

CourseWorkspace 自己不解析 PDF。教材先由独立的 Docling Bridge 产出 `output/<source_id>/`（`document.md`、`document.json`、`assets/`、`bookmarks.json`、`manifest.json`），再进 lesson：

- **长书 / 教材**：`docling-bridge to-knowledge output/<source_id>` → 在 CourseWorkspace 里 `knowledge-studio retrieve --root knowledge/<source_id> --query ... --pages <PDF 页范围> --full-pages --into-lesson lessons/<slug> --register` → `course-control digest --lesson <slug>`。
- **短资料**：`docling-bridge to-lesson output/<source_id> --lesson <slug> --register --digest`。

`ingest` 是接收端命令（复制源并登记 `sources.yaml`），不是 PDF 转换器。S1 的产物是 `authoring/sources/`、`authoring/sources.yaml`、`authoring/source-digest.json`；没有这些，`brief`/`outline`/`script` 不应开始。

| 线 | 与通用链的差异 |

### 2.4 实际执行顺序（含依赖）

阶段编号 S0–S9 是身份，不是严格的执行顺序。实际顺序是：

```text
S0 立项
  → S1 研究（Docling → retrieve --register → digest）
  → S2 叙事（brief → outline → narrative-plan → script）
  → S3 分镜（content-draft → shot-sheet）
  → S4 静态分镜页 + 人工逐页签（硬闸门）
  → build --through collect（产出 timeline.spec.json；这一步必须先于 animatic）
  → S6 animatic（依赖 collect 的 timeline + 实测旁白）
  → S7 render（依赖 S4 签字与 animatic 抽查）
  → S8 QC（media-qc / subtitles-qc / quality-gate / release-check）
  → S9 package（依赖 S8 的 PASS 与具名 release-approve）
```

- **S6 的 `animatic` 依赖 S7 的 `build --through collect` 产物**（`build/<slug>/contracts/timeline.spec.json` 或 page-plan）。不要按编号先跑 animatic 再跑 build；`build` 会被 S4 未签挡住，`animatic` 会报 no timeline。
- `build` / `preview-pilot` / `narration-build` 都在 S4 签字后放行；`narration-build --dry-run` 也不能绕过 S4。
- **`--capture-only` 只推迟下游证据，不推迟审批**：它仍要求 brief/outline/script 的审批哈希有效（V-33）且脚本与讲授稿一致（V-29），只推迟实测旁白、动画场景与最终时长门。报告会打印 `scope: capture` 与推迟项，不能当成整课通过。
- **截图与 slides.md 绑定**：`capture-manifest.json` 记录被截图的 `slides_sha256`；`storyboard-page` 遇到不匹配的截图直接拒绝，`storyboard-review` + 签字也要求该绑定存在。改了 slides 必须重跑 `build --capture-only`，否则签的页面与 slides 不是同一版。
- **候选不能静默覆盖当前文件**：`author-accept` 默认只提升"生成时目标未变"的候选；旧候选被拒绝。只批准当前文件用 `--source current --expect-sha256 <hash>`，需要预览先加 `--dry-run`。
- **开发回归只审夹具，不审真实 composition**：`check.ps1` 用仓库内 `src/audit/chapter-fixture.tsx`（固定素材 + procedural 车模），`public/staging` 为空也能绿；真实 Chapter 审计是 `node RemotionStudio/scripts/frame-audit.mjs`，需要该集 staging 素材，缺文件会按 404 报出路径，不进入开发回归。
- `visual-design` / `sound-design` 只在保留运动镜头（storyboard.yaml 有 shot）时需要；deck-only 课不把它们当 S3 硬闸。
- `package-verify` 的接口是 `--package <path>`，不是 `--lesson`。

## 4. 闸门怎么算数

1. **`pass` 只表示检查执行且通过。** `skip`、`not_run`、`incomplete`、采样不足一律不是通过，必须打印并进入异常队列（`quality/exceptions.json` 或 `release-check` 的步骤表）。
2. **每个自动检查必须有一个能红的负例。** 新检查没有负例就不算接入；`scripts/check.ps1` 里同类检查用 `Expect-Failure` 或 `--selftest`。
3. **人只签机器判不了的。** 事实、出处、数字由程序查；讲没讲透、画面好不好看由人签。
4. **签字绑定内容。** `author-accept --by <name>` 记录 sha256；内容一改，旧签字失效，必须重签；`human`/`owner` 等角色名不是具名审批。
5. **例外必须显式。** 没有旁白、跳过某阶段、使用外部素材，都要写进对应规范或 `project.yaml`，不得静默降级。

## 5. `build/` 布局契约

### 5.1 顶层只允许四类

```text
build/
├── _engine-cache/    引擎缓存（Manim media、code-video、motion-output、remotion-staging）
├── _shared/          跨课程的工具产物，一个工具一个目录
│   ├── authoring/    本地 authoring 服务的日志（llama-server.log）
│   ├── evidence-audit/ 证据路径审计报告
│   ├── golden/       golden 帧与报告
│   ├── frame-audit/  帧审计输出与自测夹具
│   ├── reviews/      ReviewRunner 的独立审查证据
│   ├── static-hold/  死画面检测输出
│   ├── fixtures/     测试媒体
│   ├── audit-bundle/ 帧审计打包缓存
│   └── ...
├── _logs/            回归日志与一次性运行日志
├── <slug>/           一门课一个目录
└── <project-id>/     主题项目（project.yaml 声明）一个目录
```

- **不允许散落文件**（`*.log`、`*.md`、单张 png 都不行）。日志进 `_logs/`，临时图进 `_shared/<tool>/` 或 `build/<slug>/tmp/`。
- **不允许临时目录**（`run-1/`、`stills-old/`、`probe2/` 之类）。一次性的东西进 `<slug>/tmp/`，结束后清掉。
- 测试夹具的 slug（`lesson-*`，由 `CourseControl/tests/fixtures/` 声明）是唯一例外，由 `prepare-fixtures.ps1` 重建。

### 5.2 `<slug>/` 内的标准目录

| 目录 | 内容 | 可否删 |
| --- | --- | --- |
| `authoring/` | 候选稿、签字前后的中间稿 | 交付后可删 |
| `slides/` | 幻灯片截图、录屏 | 可删，重建 |
| `scenes/`、`animation/`、`blender/` | 引擎渲染片段 | 可删，重建 |

| `design/`、`director/`、`sound/` | 视觉、导演、声音设计与 cue sheet | 交付后可删 |
| `animatic/`、`preview/` | 预览与成本记录 | 可删 |
| `quality/`、`review/` | 质量报告、异常队列、审查 | **不要删**（发布证据） |

### 5.3 清理与保留

- `build/` 整体可删；删除前先确认 `deliver/<slug>/` 已有交付包。
- `quality/`、`narration/narration.meta.json`、`final/` 是发布证据，交付完成前不删。
- `_engine-cache/` 可删，但会拖慢下一次构建。
- `_logs/` 保留最近 20 次回归；更早的进 `archive/`。
