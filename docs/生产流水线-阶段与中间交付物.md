# 生产流水线：阶段、命令与中间交付物

- **版本**：v1.0（2026-11-16）
- **状态**：现行。**一条生产线的命令顺序、每个阶段的中间交付物、闸门与签字人，以本文件为准。**
- **上位**：`PRD.md`（产品边界）、`ARCHITECTURE.md`（结构与数据契约）、`课程生产统一契约V1.md`（字段）。
- **分工**：`生产合同.md` 定义 G0–G7 的门与四份合同；`v2/生产方向-*.md` 定义三条产品线的内容标准；`ACCEPTANCE.md` 定义验收命令与状态词。本文件只回答一件事：**什么时候跑哪条命令，跑完留下什么，谁来签字。**

> 冲突处理：同一问题出现两种说法时，按 **本文件（命令与产物）→ 生产合同（门）→ 生产方向（内容标准）→ 指南** 的顺序取值；仍冲突时以 `DECISIONS.md` 中日期更新的决策为准，并把旧说法标为 `record`。

## 1. 三个位置

| 位置 | 放什么 | 能不能删 |
| --- | --- | --- |
| 程序仓库（本仓库） | 代码、Schema、夹具、规范、检查脚本 | 按 git 规则 |
| 内容根 `<内容根>` | `lessons/`、`projects/`、`engines/`、`audio/`、`knowledge/`、`references/` | 不能 |
| 过程区 `build/` | 某个 slug 的阶段产物、缓存、日志 | **能**，重建即可 |
| 交付区 `deliver/` | 最终交付包，`package` 写的唯一位置 | 交付完成后归档 |
| 历史区 `archive/` | 已结束的项目、构建与记录 | 不参与检查 |

内容根其余目录的规则见 `<内容根>/README.md`。

## 2. 阶段表

每一阶段只有三件事：**输入 → 命令 → 中间交付物**。闸门分两类：`auto`（程序判定，`pass/fail/incomplete`）与 `human`（具名签字）。

| # | 阶段 | 命令 | 中间交付物（内容根内） | 闸门 |
| --- | --- | --- | --- | --- |
| S0 | 立项 | `project-validate`、`validate`、`preflight` | `projects/<系列>/project.yaml`、`lessons/<slug>/lesson.yaml`、`authoring/episode.spec.yaml`、`authoring/quality.rubric.yaml` | auto：preflight 无 error；human：专题精华/cut 与 rubric 阈值签一次（G0） |
| S1 | 研究 | `ingest`、`digest` | `authoring/sources/`、`authoring/source-digest.json` / `.md`；新闻另有 `authoring/fact-check.md` | auto：摘要可复现、引用 ref 稳定；human：`author-accept --kind digest`；新闻：事实矩阵不得为空 |
| S2 | 叙事 | `brief`、`outline`、`script`、`narrative-validate` | `build/<slug>/authoring/candidates/` 下的候选；签字后进 `authoring/brief.json`、`outline.json`、`narration.script.json` | human：`author-accept --kind brief|outline|script`，`approval.json` 记 sha256；auto：`narrative-validate`（长视频/Shorts 必过） |
| S3 | 分镜 | `content-draft`、`author-accept --kind content`、`shot-sheet`、`visual-design`、`sound-design` | `slides.md`、`lecture_notes.md`、`storyboard.yaml`；`build/<slug>/shot-sheet/plan.json`、`design/visual_design.json`、`sound/` | auto：`shot-sheet` 的引用与指纹；human：内容签字 |
| S4 | **静态分镜闸门** | `storyboard-page`、`author-accept --kind storyboard-page` | `build/<slug>/storyboard/index.html`、`manifest.json`；签字后 `authoring/storyboard-review.json` | **human：逐页放行/否决；未签字不得注入动效、配音或渲染** |
| S5 | 声音 | `narration-build`、`subtitles-build`、`subtitles-accept` | `build/<slug>/narration/narration.wav`、`narration.meta.json`、`subtitles/`；签字后 `lessons/<slug>/subtitles.srt` | auto：实测时长与字幕 QC；human：字幕签字 |
| S6 | 预览 | `animatic`、`preview-pilot`、`render shot|segment|project --mode preview` | `build/<slug>/animatic/`、`build/<slug>/preview/`、`preview/pilot.json` | auto：480p 时间线与缓存报告；human：抽看 |
| S7 | 正式渲染 | `render … --mode release` 或 `build` | `build/<slug>/animation/`、`contracts/shots.json`、`contracts/timeline.spec.json`、`final/` | auto：每段 QC、`frame-audit`；human：hero 帧（G4）与终审（G7） |
| S8 | 验收 | `media-qc`、`subtitles-qc`、`quality-report`、`quality-gate`、`release-check`（含分镜签字步骤） | `build/<slug>/quality/{media-qc,subtitles-qc,gate,certificate,defects}.json` | auto：`release-check` 输出 `PASS / FAIL / INCOMPLETE`；`INCOMPLETE` 不是通过 |
| S9 | 交付 | `package`（非 pass 不替换旧交付）、`package-verify`（校验证据链）、`release-approve --lesson` 或 `--project`（未签/未过检查拒批） | `deliver/<slug>/`（`final/master.mp4`、字幕、报告、`manifest.json`、`delivery-checklist.md`） | auto：`package-verify`；human：发布签核（具名） |

### 2.1 与 G0–G7 的对应

`生产合同.md` 的 G0–G7 是课程线的闸门名；本文件的 S0–S9 是命令与产物的顺序。两者不是两套流程：

| 生产合同 | 本文件 |
| --- | --- |
| G0 规格 | S0 立项 + S2 叙事（episode spec / rubric） |
| G1 镜头表 | S3 分镜 |
| G2 骨架 | S3 组件装配 + S4 静态分镜页 |
| G3 旁白 / animatic | S5 声音 + S6 预览 |
| G4 代表镜头 | S7 正式渲染（hero 帧） |
| G5 批量 | S7 正式渲染 |
| G6 字幕 | S5 字幕 + S8 验收 |
| G7 交付 | S8 验收 + S9 交付 |

### 2.2 三条线的差异

| 线 | 与通用链的差异 |
| --- | --- |
| 01 完整课程 | 全链；S0 的四份合同必填；S4 逐页签字；S8 走 `release-check` 的课程分支 |
| 02 新闻调查 | S1 增加 `authoring/fact-check.md`（证据矩阵 + 本片明确不主张）；S2 六幕；S8 另按 100 分制，研究准确性 <16/20 不发布 |
| 03 三分钟 Vibe | S2 五幕、一个点；S4 可只签字关键页；S8 五问 + `release-check`；S9 主题片先渲染到 `build/<project>/release/`，`release-approve --project` 绑定候选后才安装 |

## 4. 闸门怎么算数

1. **`pass` 只表示检查执行且通过。** `skip`、`not_run`、`incomplete`、采样不足一律不是通过，必须打印并进入异常队列（`quality/exceptions.json` 或 `release-check` 的步骤表）。
2. **每个自动检查必须有一个能红的负例。** 新检查没有负例就不算接入；`scripts/check.ps1` 里同类检查用 `Expect-Failure` 或 `--selftest`。
3. **人只签机器判不了的。** 事实、出处、数字由程序查；讲没讲透、画面好不好看由人签。
4. **签字绑定内容。** `author-accept` 记录 sha256；内容一改，旧签字失效，必须重签。
5. **例外必须显式。** 没有旁白、跳过某阶段、使用外部素材，都要写进对应规范或 `project.yaml`，不得静默降级。

## 5. `build/` 布局契约

### 5.1 顶层只允许四类

```text
build/
├── _engine-cache/    引擎缓存（Manim media、code-video、motion-output、remotion-staging）
├── _shared/          跨课程的工具产物，一个工具一个目录
│   ├── authoring/    本地 authoring 服务的日志（llama-server.log）
│   ├── evidence-audit/ 证据路径审计报告
│   ├── golden/       golden 帧与报告
│   ├── frame-audit/  帧审计输出与自测夹具
│   ├── reviews/      ReviewRunner 的独立审查证据
│   ├── static-hold/  死画面检测输出
│   ├── fixtures/     测试媒体
│   ├── audit-bundle/ 帧审计打包缓存
│   └── ...
├── _logs/            回归日志与一次性运行日志
├── <slug>/           一门课一个目录
└── <project-id>/     主题项目（project.yaml 声明）一个目录
```

- **不允许散落文件**（`*.log`、`*.md`、单张 png 都不行）。日志进 `_logs/`，临时图进 `_shared/<tool>/` 或 `build/<slug>/tmp/`。
- **不允许临时目录**（`run-1/`、`stills-old/`、`probe2/` 之类）。一次性的东西进 `<slug>/tmp/`，结束后清掉。
- 测试夹具的 slug（`lesson-*`，由 `CourseControl/tests/fixtures/` 声明）是唯一例外，由 `prepare-fixtures.ps1` 重建。

### 5.2 `<slug>/` 内的标准目录

| 目录 | 内容 | 可否删 |
| --- | --- | --- |
| `authoring/` | 候选稿、签字前后的中间稿 | 交付后可删 |
| `slides/` | 幻灯片截图、录屏 | 可删，重建 |
| `scenes/`、`animation/`、`blender/` | 引擎渲染片段 | 可删，重建 |
| `narration/`、`tts/` | 分段旁白、实测 meta | `narration/` 不要删（实测证据） |
| `subtitles/`、`contracts/`、`timeline/` | 字幕草稿、shots/timeline、页计划 | 交付后可删 |
| `design/`、`director/`、`sound/` | 视觉、导演、声音设计与 cue sheet | 交付后可删 |
| `animatic/`、`preview/` | 预览与成本记录 | 可删 |
| `quality/`、`review/` | 质量报告、异常队列、审查 | **不要删**（发布证据） |
| `final/` | 渲染输出，不是最终交付 | 打包后可删 |
| `producer/` | 制片清单 | 可删 |
| `storyboard/` | 静态分镜页与 manifest | 签字后可删 |
| `logs/` | 本课日志 | 可删 |
| `tmp/` | 实验、试渲染、一次性脚本 | 可删 |

规则：**每个阶段只写自己的目录**；需要跨课共享的产物进 `_shared/`，不得写进别人课的目录。

### 5.3 清理与保留

- `build/` 整体可删；删除前先确认 `deliver/<slug>/` 已有交付包。
- `quality/`、`narration/narration.meta.json`、`final/` 是发布证据，交付完成前不删。
- `_engine-cache/` 可删，但会拖慢下一次构建。
- `_logs/` 保留最近 20 次回归；更早的进 `archive/`。
