# 本地模型与配音工作流

本工作区不迁移、不重装本地模型。所有大模型与配音运行时都在 `<AI_ROOT>`，通过本地 HTTP 调用。
> **2026-11-08 起**：课程文本生产、字幕翻译、ContentQA、ModelingStudio 文本规划默认使用 Claude Code；本地模型与远程 API 是显式回退/视觉阶段后端。详见 `docs/DECISIONS.md` D-042 与 `config/claude-code.example.yaml`。


本机绝对路径不写入仓库：`<AI_ROOT>`、`<BLENDER_EXE>` 等占位符的实际值见 `config/local-paths.yaml`（已忽略）。

## 零、接入原则：三层结构

| 层级 | 负责什么 | 是否允许模型参与 |
| --- | --- | --- |
| 内容生产层 | 逐字稿、翻译、润色、动画参数、素材初稿 | 允许 |
| 控制执行层 | YAML 解析、路径检查、任务调度、时间线、构建 | 不允许 LLM 决策 |
| 验收层 | 文件完整性、音视频参数、时长、字幕、报告 | 不允许 LLM 判定 |

本地模型与 VoxCPM2 是 CourseWorkspace 外部的算力节点，不是构建流水线里的智能决策节点。

“确定性”指**调用边界、输入输出、执行流程和验收标准**确定；模型输出本身不保证确定性。构建只消费已经审核并落盘的文件，因此模型升级、输出变化或服务不可用，都不影响已生产课程的重建。

## 二、本地大模型

### 2.1 启动

```powershell
<AI_ROOT>\start_server.bat
# 后端回车默认 SYCL
# 模型选择 Qwen3-30B-A3B-Instruct-2507-Q4_K_M
# 档位选择 16K / 32K / 64K
```

服务是 OpenAI 兼容接口，**不设 API Key**；部分客户端要求非空 key，可填 `sk-local`。

`ModelingStudio` 也使用同一 8080 服务：按阶段启动 Qwen3-VL / Qwen3 / Qwen3-Coder，阶段结束即停止；与 `start_server.bat` 不能同时运行。

**统一调度（2026-11-03 起）**：所有本地模型调用必须经过 `shared/ai_runtime` 的跨进程锁（`runtime/locks/llama-8080.lock`），同一时刻只允许一个任务；任务状态写入 `runtime/tasks/`。手工启动的 `start_server.bat` 实例会被复用，不会被杀死。见 [本地自动建模工作流](AI-Blender本地建模工作流.md) 与 [架构](ARCHITECTURE.md) §5。

**在线模型**：内容审查由独立工程 `ContentQA` 承担（OpenAI 兼容接口，凭据只从环境变量读取）。未配置时返回 `blocked`，不会降级到本地模型。见 [ContentQA](../ContentQA/README.md)。

### 2.3 调用

```powershell
curl http://127.0.0.1:8080/v1/chat/completions `
  -H "Content-Type: application/json" `
  -d '{"model":"Qwen3-30B-A3B-Instruct-2507-Q4_K_M","messages":[{"role":"user","content":"你好"}],"max_tokens":64}'
```

模型名可通过 `/v1/models` 查询；别名中带 `default` 的即默认模型。

### 2.4 能做什么，不能做什么

**可以**：单页措辞润色、中英语气调整、动画时长与坐标参数、`.zh-sub` 闭合检查、单页口播改写、短片段翻译。

**不要**：整份 `slides.md` 重构（16K 上下文会丢分页符）、从零写 Motion/Manim/Blender 脚本（会编 API）、数学推导与论文细节（会一本正经地错）。

### 2.5 远程回退（8080 被占用时）

- 本地 8080 仍是首选；`shared/ai_runtime` 先尝试本地锁与服务。
- 复制 `config/model-routing.example.yaml` 为 `config/model-routing.yaml`（已忽略），按需填写 `provider`、`base_url`、`model`、`api_key_env`。它可以是 DeepSeek，也可以是任意 OpenAI 兼容端点。
- API key 只从系统环境变量读取（本机已有 `DeepSeek-API`），**不要写入 `.env`、YAML、日志或任何文件**。
- **`.env` 是本地实际配置（git 忽略）；`.env.example` 进远程，只含占位符和配置说明。** 通用变量：`REMOTE_PROVIDER` / `REMOTE_BASE_URL` / `REMOTE_MODEL` / `REMOTE_VISION_MODEL` / `REMOTE_API_KEY_ENV`；DeepSeek 也兼容 `DEEPSEEK_*`。任何文件都不得出现明文 key。
- 本地 `busy` / `start_error` / `lock_timeout` / `missing_executable` 时按配置回退；任务记录写 `provider=remote` 和实际模型，不会写成 `local`。
- 视觉阶段（图片分析/修正）只有在配置了 `vision_model` 且 `supports_vision=true` 时才回退；否则保持本地失败，不把图片交给文本模型。
- 2026-11-07 实测：`deepseek-flash` 支持图片理解（256×256 PNG → 返回“红色”）。
- **DeepSeek 调用固定 `deepseek-flash`；`deepseek-v4-pro` 已禁用。** `RemoteConfig`、ModelingStudio 配置与 ContentQA 配置都会拒绝 pro。
- 远程不可达或无 key 时仍按失败/`blocked` 处理，不静默换模型。
- `deepseek-flash` 默认把输出预算花在 reasoning 上；长输出必须关闭 thinking（`RemoteConfig.thinking="disabled"`，authoring 默认已关闭），否则可能返回空内容。

```yaml
# config/model-routing.example.yaml（节选，任意 OpenAI 兼容端点）
remote:
  enabled: true
  provider: "openai-compatible"   # 或 "deepseek"
  base_url: "<OPENAI_COMPATIBLE_BASE_URL>"
  model: "<MODEL_ID>"
  api_key_env: "<API_KEY_ENV_VAR_NAME>"
  supports_vision: false
  vision_model: null
fallback:
  on: ["busy", "start_error", "lock_timeout", "missing_executable"]

# 当前本机 DeepSeek 实际值（写在本地 .env / 忽略配置，不写 key）：
# provider: deepseek
# base_url: https://api.deepseek.com/v1
# model: deepseek-flash
# vision_model: deepseek-flash
# api_key_env: DeepSeek-API
```

## 三、VoxCPM2 配音

> 2026-11-06 起，`50000` 由 `<AI_ROOT>/VoxCPM-Runtime`（VoxCPM2）接管；CosyVoice 已停用。接口路径与响应头沿用，但 VoxCPM2 **没有预置音色**。

### 3.1 运行时

| 项 | 值 |
| --- | --- |
| 服务 | `<AI_ROOT>/VoxCPM-Runtime`，`api_server.py`（FastAPI） |
| 端口 | `127.0.0.1:50000`，本机唯一 TTS 实例 |
| 权重 | `<AI_ROOT>/models/voxcpm2`（`model.safetensors` 4.58 GB + `audiovae.pth` 0.38 GB） |
| 设备 | CPU-only，约 6 GB 内存，不占 A750 |
| 输出 | 48 kHz / 16-bit PCM / 单声道 WAV |
| 启动 | `start_voxcpm.bat`；23–29 秒到 `ready` |
| 速度 | RTF ≈ 12–16（本机实测约 16）；2 分钟旁白约 24–32 分钟 CPU 时间 |
| 许可 | Apache-2.0；允许商用；禁止冒充；AI 内容需标注 |

同一时刻只允许一个实例；谁启动谁停止；空闲时 50000 应为空。

> 单段 `course-control narrate`、`tts-status` 与整课 `narration-build` 已实现：自动起停、50000 锁、逐页缓存、拼接、meta 与样片。旁白 meta/哈希/页跨度由 V-30 检查。详见 [代码/终端镜头与执行验证](评估-代码镜头与执行验证.md) §10.3。
>
> 2026-11-08 实测：`narration-build --lesson 01-transformer-demo --sample-pages 1` 生成第 1 页样片 43.92 s（计划 45 s，drift -1.08 s），`style_applied=true`（`(clear, measured pace)`），RTF 16.45；服务自动停止。

### 3.2 接口

```powershell
# 健康检查（loading / ready）
curl http://127.0.0.1:50000/health

# 合成（参考音必须是本机路径）
curl -X POST http://127.0.0.1:50000/tts `
  -H "Content-Type: application/json" `
  -d '{"text":"很多人以为算力瓶颈在显卡。","prompt_wav":"<VOICE_REF_WAV>","prompt_text":"参考音频的逐字文本","speed":1.0,"text_frontend":true}' `
  -o segment.wav
```

- `/speakers` 恒为空；没有预置音色，传 `speaker` 会 400。
- 缺 `prompt_wav`（且没有配置默认参考音）会 400。
- 响应头记录 `X-Audio-Seconds`、`X-Synth-Seconds`、`X-Sample-Rate`、`X-Prompt-Mode`、`X-Text-Normalize`、`X-Speed-Stretch`。
- 超时不要低于 600 秒；本机调用要忽略系统代理（`trust_env=False` 或 `ProxyHandler({})`）。

### 3.3 音色参考

VoxCPM2 是零样本克隆，必须提供 3–5 秒干净人声与逐字文本：

- 参考音与逐字文本放在调用方项目或本机忽略配置中；运行时默认不内置任何个人录音。
- 参考音必须是本人或已获授权的声音；不要把参考音提交到仓库。
- 同一份参考音多次合成音色一致，但**时长有随机波动**（实测同一句 3.2–3.5 s），不能按单次时长做结论。

### 3.4 许可与合规

VoxCPM 代码与模型为 Apache-2.0，允许商用；禁止冒充他人、欺诈与虚假信息。AI 生成的旁白应在成片或说明中标注。

## 四、把旁白接进构建

### 4.1 生成

1. 从 `lessons/<slug>/lecture_notes.md` 按页提取“逐字口播”，按页或按段合成。
2. 确保 `50000` 已 `ready`（`start_voxcpm.bat`）。
3. 逐页/逐段调用 `/tts`，带参考音与逐字文本，保存片段。
4. 记录每段实测时长、合成耗时与响应头；不要按字数估算。
5. 统一转成 48 kHz 单声道 16-bit，便于后续混音：

```powershell
ffmpeg -y -i raw.wav -ac 1 -ar 48000 -c:a pcm_s16le narration.wav
```

### 4.2 放入构建输入

```text
build/<slug>/narration/narration.wav
```

`lesson.yaml`：

```yaml
narration:
  enabled: true
  source: narration.wav
```

构建时：

1. `collect` 用 ffprobe 读取音频时长，写入 `shots.json` 的 `narration`。
2. `stage-assets` 把音频复制到 `RemotionStudio/public/staging/<slug>/narration/`。
3. `RemotionStudio` 的 `<Audio>` 播放旁白。
4. `verify` 的 V-15 检查成片含音频流，且音频与视频时长差 ≤ 0.5 秒。

### 4.3 片段与缓存（单段已实现）

- 输出：`build/<slug>/narration/segments/slide-001.wav`，再拼接为 `narration.wav`。
- 缓存键：`sha256(text + voice_ref_sha + prompt_text_sha + model/version + timesteps + cfg + text_frontend + speed)`。
- 改一页只重合成一页；命中缓存要写入 `cache_hit: true`。
- 页面预算仍是上限；片段超页返回 `NARRATION_OVERFLOW`，由作者改文本或改预算，程序不改正文。

### 4.4 母带备份

`build/` 不入库。旁白母带建议另存到 `assets/audio/<slug>/` 或外部存储，构建时再复制到 `build/<slug>/narration/`。

### 4.5 旁白元数据（单段已实现）

建议每次合成在 `build/<slug>/narration/narration.meta.json`（或按页/按段分文件）记录：

| 字段 | 说明 |
| --- | --- |
| `source_notes_sha256` | 对应 `lecture_notes.md` 或逐页文本的 SHA-256 |
| `tts_model` / `tts_version` | VoxCPM2 与运行时版本 |
| `voice_ref_sha256` / `prompt_text_sha256` | 参考音与逐字文本的哈希 |
| `sample_rate` / `channels` / `duration_s` | 音频参数 |
| `generated_at` | 生成时间 |
| `audio_sha256` | 最终 WAV 的 SHA-256 |

用途：改一页讲稿时，可以定位哪些旁白需要重新生成，而不是整门课重做。单段 `narrate` 写 `segments/<id>.meta.json`；整课 `narration-build` 负责缓存、拼接与 `narration.meta.json`；V-30 检查 meta/哈希/页跨度。

## 五、字幕

字幕不做自动语音识别：

1. 把 SRT 放到 `lessons/<slug>/subtitles.srt`。
2. `lesson.yaml` 设置 `subtitles.enabled: true`、`content.subtitles: subtitles.srt`。
3. `collect` 复制到 `build/<slug>/subtitles.srt` 并统计 cue 数。
4. Remotion 渲染字幕，V-16 校验。

## 六、画图与 ComfyUI

`flux-2-klein-4b-Q4_K_M.gguf` 是扩散模型权重，llama-server 不能加载。需要 ComfyUI + 文本编码器 + FLUX.2 VAE（**不是 FLUX.1 VAE**）与 `city96/ComfyUI-GGUF` 节点。当前机器尚未搭建 ComfyUI，`8188` 仅作预留。

## 七、故障排查

| 现象 | 处理 |
| --- | --- |
| 8080 返回 Access denied | 另一个带 `--api-key` 的实例先绑定了端口；`netstat -ano \| findstr :8080` 查 PID |
| 两个进程都监听 8080 | Windows 允许，请求会被先绑定的实例接走；以 netstat 为准 |
| VoxCPM2 一直 `loading` | 模型加载 23–29 秒；超过 120 秒检查 `logs\server.log` 与内存 |
| VoxCPM2 返回 400 | 缺参考音或 `prompt_text` 与 `prompt_wav` 不匹配；`/speakers` 为空，不能传 `speaker` |
| 合成很慢 | RTF ≈ 12–16 属正常；2 分钟旁白约 24–32 分钟；不要设短超时 |
| 50000 被占用 | 同一时刻只允许一个 TTS 实例；不要 kill 别人的进程 |
| 旁白与视频不同步 | V-15 会报 `delta`；检查音频是否为 6 秒等与页面预算匹配的时长 |
| Remotion 读不到音频 | 确认 `shots.json` 的 `narration.path` 相对 `build/<slug>/`，并已 staging |
| 本地模型输出截断 | 提高档位或在请求里限制 `max_tokens`；不要用它重构整份课件 |

## 八、边界

- 不在 `CourseWorkspace` 内安装 VoxCPM2、llama.cpp 或模型依赖。
- 不把模型权重、缓存、运行时迁入工作区。
- 不修改 `<AI_ROOT>` 的启动脚本与模型目录，除非另有明确任务。
- 不把本地模型输出当作事实核验或最终文案。
- 不自动 TTS 整门课并直接发布；旁白仍需人工审听。


## 九、接入现状与评估（2026-11-01）

### 9.1 现状

| 能力 | 当前接入方式 | 是否进入构建代码路径 | 说明 |
| --- | --- | --- | --- |
| 本地大模型 | 人工 / 助手侧调用 `8080` | 否 | CourseControl、scripts、Remotion 中没有 8080 调用 |
| VoxCPM2 配音 | `course-control narrate` 单段合成；`tts-status` 查询 | 是（显式命令） | 构建默认不调用 50000；产物仍是 WAV |
| 字幕 | 人工编写 SRT | 是（校验与渲染） | 不做语音识别 |
| FLUX / ComfyUI | 未部署 | 否 | 只有权重，没有运行时 |
| 服务健康检查 | 未自动化 | 否 | 检查时 8080 / 50000 / 8188 均未监听 |

检查时的结论：**构建流水线对本地 AI 运行时没有硬依赖**。本地模型与 VoxCPM2 都是按需启动的外部工具；关掉它们，`build`、`verify`、`check.ps1` 仍能运行。

### 9.2 评价

优点：

- 构建可重复：不依赖模型服务的可用性和随机输出。
- 责任清晰：模型负责辅助生成，人工负责审稿，控制层只校验文件。
- 失败可定位：没有网络调用，构建失败集中在文件、路径、渲染和编码。

不足：

- 旁白合成是手工步骤，容易忘记更新音频或版本。
- 没有记录旁白来源（模型、音色、采样率、文本哈希），无法追溯某段音频由哪版逐字稿生成。
- `check.ps1` 不检查 8080 / 50000 是否可用，启动前的环境问题要等到人工调用时才发现。
- 已有单段 `narrate`、`tts-status` 与整课 `narration-build`（缓存、拼接、meta、样片）；V-30 覆盖旁白一致性。

### 9.3 建议（2026-11-03：健康检查与在线审查已部分落地）

1. 增加只读健康检查：`check.ps1` 探测 `8080/v1/models`、`50000/health`、`8188`；只告警，不阻止构建。
2. `course-control narrate` 单段适配器已实现（VoxCPM2、超时、日志、50000 锁、meta）；整课逐页编排与手工导入回退仍待完成。
3. 在构建报告中记录旁白元数据：模型、音色、采样率、文本哈希、生成时间。
4. 继续禁止把 LLM 放进 `validate` / `verify` 的判定路径；事实核验仍由人工负责。
5. 母带与 `local-paths.yaml` 一样，放在仓库外或加密存储。


### 9.4 生成与验收分离

模型可以辅助找问题，但不能成为最终事实判定者。数学推导、论文结论、CFD 技术结论必须由人工和来源证据确认；V-14 / V-15 / V-16 只检查文件与媒体参数，不判断内容正确性。

### 9.5 R4/R5 边界

以上改动不在 R4/R5 范围内，当前先保持“外部服务 + 文件契约”的边界。2026-11-06：VoxCPM2 已接管 50000；单段 `narrate` / `tts-status` 已实现，整课编排见 [代码/终端镜头与执行验证](评估-代码镜头与执行验证.md) §10。

## 十、R1 整课旁白与双语字幕（2026-11-07）

### 10.1 整课旁白

```powershell
# 整课（实测时间轴）
uv run --project CourseControl course-control narration-build --lesson <slug> --mode reference_only --timing measured

# 先出 3 页样片试听
uv run --project CourseControl course-control narration-build --lesson <slug> --mode reference_only --sample-pages 3
```

- 一个 `TtsService` 持 50000 锁跑完整课；逐段缓存键 v2 包含 mode/style/speed/timesteps/cfg/text_frontend/参考音 sha。
- 输出：`build/<slug>/narration/segments/*.wav`、`narration.wav`、`narration.meta.json`；样片在 `narration/sample/`。
- 48 kHz mono；拼接时插入 `pause_after_ms` 与页间停顿；实测页跨度写回 `narration.meta.json`，`collect` 在 `timing=measured` 时使用。
- `reference_only` 支持 VoxCPM2 句首括号情绪提示；`prompt_reference` 会忽略提示，仅作回退。
- 英文旁白建议配置 `tts.voice_ref_en` + `tts.prompt_text_en`（3–5 秒、纯净、已授权）；为空时回退 `tts.voice_ref`，但跨语种克隆可能有口音与平调。

### 10.2 双语字幕

```powershell
# 计划版草稿（未跑 TTS 时）
uv run --project CourseControl course-control subtitles-build --lesson <slug> --planned --remote

# 实测版（跑完旁白后）
uv run --project CourseControl course-control subtitles-build --lesson <slug> --remote
uv run --project CourseControl course-control subtitles-accept --lesson <slug>
```

- 英文在上、简体中文在下；SRT/ASS/VTT。
- 中文 ≤15 字/行、英文 ≤42 字/行、最多 2 行、1–6 秒/条、相邻 ≥2 帧、中文 CPS ≤9。
- 翻译逐 cue 编号；条数/顺序不符即 blocked。计划版允许策略警告，实测版必须严格通过。

### 10.3 双版本成片

- `final/course-video.mp4`：干净母版（Rollup/Remotion 不渲染字幕）。
- `final/course-video-captioned.mp4`：ffmpeg `ass=` 烧录；QSV 优先，失败回退 libx264。
- Windows 路径必须转义为 `ass='D\:/...'`。

### 10.4 共享 50000 的排队

50000 是本机唯一 TTS 实例；其他项目（如 <LOCAL_DRAMA_STUDIO>）也可能直接调用。`TtsService` 会持 `runtime/locks/tts-50000.lock`，但**不阻止**未使用该锁的外部调用；请求会在服务内部排队。整课 TTS 前先确认 50000 没有长任务，或接受排队；不要 kill 他人进程。

### 10.5 生成英文参考音（voice design）

VoxCPM2 支持无参考音的 voice design：在文本开头放英文括号描述即可。工作区脚本 `scripts/generate_voice_ref.py` 直接用 VoxCPM 运行时 venv 调库，生成 3–6 秒英文参考音：

```powershell
<VOXCPM_RUNTIME>/venv/Scripts/python.exe scripts/generate_voice_ref.py `
  --model-dir <AI_ROOT>/models/voxcpm2 `
  --out lessons/<slug>/assets/voice/en_narrator_v1.wav
```

产出的 `.meta.json` 记录 style、文本、模型、RTF。可用 `ffmpeg loudnorm` 生成响度归一版，再把 `config/local-paths.yaml` 的 `tts.voice_ref_en` 指向它。该参考音是后续整课旁白的音色蓝本；生成时只调用本地模型，不碰 8080。

### 10.6 当前音色选择（2026-11-07）

- 用户音色参考：`<VOICE_REF_WAV>`（本机忽略配置，不入库）
- 选定蓝本：`lessons/01-transformer-demo/assets/voice/en_user_voice_refonly_v1_norm.wav`（reference-only；基频中位数 114.6 Hz，原参考 122.8 Hz）
- 对照：`en_user_voice_v1_norm.wav`（组合模式，基频 175.7 Hz，更像英文母语但音色偏移）；`en_narrator_v1_norm.wav`（纯 voice design，不是用户音色）
