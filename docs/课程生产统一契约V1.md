## 1. 总体分层

```text
作者内容（不变）
  lesson.yaml / storyboard.yaml / slides.md / lecture_notes.md
        │  规范化（只读，不改变作者语义）
        ▼
LessonSpec ── ShotSpec[] ── NarrationSpec
        │
        ▼
TimelineSpec（整数帧，唯一时间事实）
        │
        ├── Manim / Session / Simulation / Graphics / Blender / Slide 适配器
        │         └── 每个镜头产出 RenderManifest 条目 + 可选 EvidenceManifest
        ▼
RenderManifest（最终视频/音频/字幕 + 哈希 + 自动检查）
```

**边界**：

- 作者文件仍是 `lesson.yaml` / `storyboard.yaml`，V1 不替换它们。
- V1 是**规范化运行时契约**，由控制层生成，落在 `build/<lesson_id>/contracts/`。
- `ShotsFile` / `shots.json` 保留，作为 `TimelineSpec → Remotion` 的兼容产物。
- E6 现有 `manifest.json` 保留，作为 V0 输入，由适配器转成 `RenderManifest`。

- 不允许用 `lesson_id` 代替 `shot_id` 做证据主键。

## 3. 时间单位（关键决策）

### 3.1 决策

**时间线主单位 = 整数帧（frame），帧率由 `fps` 唯一声明。**

- `TimelineSpec`、`ShotSpec.timing`、`RenderManifest.output` 全部用 `start_frame` / `duration_frames` / `total_frames`。
- **毫秒只用于外部边界**：WAV 实测时长、SRT 导出、FFmpeg 探测结果、TTS 返回时长。
- **秒只保留在旧契约**：`LessonConfig` / `Storyboard` / `ShotsFile` / E6 V0 manifest 的 `*_s` 字段，由适配器一次性换算，不进入 V1 内部计算。
- 不使用浮点秒做累加；不把 `0.1 + 0.2` 一类值写入时间线。

### 3.2 帧率的有理数表示

帧率不再写成整数 30，而是：

```json
{"fps_num": 30000, "fps_den": 1001}
```

- `24/1`、`25/1`、`30/1`、`30000/1001`、`60000/1001` 都是一等输入。
- 禁止把 30 fps 写死为全系统帧率；每个 `LessonSpec`、`TimelineSpec`、`NarrationSpec`、`RenderManifest.output` 各自声明 `fps`。
- `fps_num`、`fps_den` 必须为正整数；0、负数、浮点都直接失败。

### 3.3 换算规则（唯一实现）

```python
# round-half-up，只用整数；n/d >= 0
def _round_half_up(n: int, d: int) -> int:
    return (2 * n + d) // (2 * d)

def ms_to_frame(ms, fps_num, fps_den=1):
    return _round_half_up(ms * fps_num, 1000 * fps_den)

def frame_to_ms(frame, fps_num, fps_den=1):
    return _round_half_up(frame * 1000 * fps_den, fps_num)
```

- 舍入规则统一为**四舍五入、.5 向上**；不静默截断。
- 帧边界从**累计毫秒**一次换算，再取差值，禁止逐段 `round` 后累加：

```python
start_frame_i = ms_to_frame(cumulative_ms_i, fps_num, fps_den)
duration_frames_i = start_frame_{i+1} - start_frame_i
```

- 30 fps 下 1 帧 = 33.333 ms；`frame_to_ms` 的结果允许与真实时间相差 ≤ 半帧。
- 已知边界结果：

| fps | 1 帧 → ms | 1 秒 → 帧 | 1 秒 → ms |
| --- | --- | --- | --- |
| 24/1 | 42 | 24 | 1000 |
| 25/1 | 40 | 25 | 1000 |
| 30/1 | 33 | 30 | 1000 |
| 30000/1001 | 33 | 30 | 1000 |
| 60000/1001 | 17 | 60 | 1000 |

- `30` 帧在 `30000/1001` 下是 `1001 ms`，不是 `1000 ms`；测试必须覆盖这种差异。

### 3.4 音频采样与视频帧对齐

音频是连续采样，视频是离散帧；对齐只允许在边界量化一次：

```python
def frame_to_sample(frame, sample_rate, fps_num, fps_den=1):
    return _round_half_up(frame * sample_rate * fps_den, fps_num)

def sample_to_frame(sample, sample_rate, fps_num, fps_den=1):
    return _round_half_up(sample * fps_num, sample_rate * fps_den)
```

- 每个旁白段先由采样区间求出 `start_frame` / `end_frame`，再把这两个帧边界映射回采样索引。
- 映射回采样的差值记录为 `start_drift_samples` / `end_drift_samples`，**不得静默修正**。
- 容差为 1 帧对应的采样数：`ceil(sample_rate * fps_den / fps_num)`。
- 48 kHz / 30 fps：1 帧 = 1600 采样，漂移 0。
- 48 kHz / 30000/1001 fps：1 帧 = 1601.6 采样；`1600..48000` 对齐到 1..30 帧后，回映射为 `1602..48048`，漂移 `+2 / +48` 采样，仍在 1 帧容差内。

### 3.5 SRT 毫秒时间戳生成

```python
def frame_to_srt(frame, fps_num, fps_den=1):
    return format_srt_timestamp(frame_to_ms(frame, fps_num, fps_den))
```

- SRT 一律 `HH:MM:SS,mmm`；毫秒由 `frame_to_ms` 一次生成。
- 读入 SRT 时用 `ms_to_frame` 回到帧；`end <= start` 或不足 1 帧的字幕直接失败。
- 导出后回读，帧边界必须与 `TimelineSpec.subtitles` 一致；容差 40 ms。

### 3.6 为什么不是毫秒主单位

- Manim、Remotion、FFmpeg 最终都按帧取画面；毫秒主单位会在每帧边界产生累计误差。
- 帧是整数，可精确比较、可做哈希、可复现。
- 毫秒只在音频与字幕交换格式出现，换算点集中在 `timecode.py`，便于测试。

## 4. 素材引用 `AssetRef`

所有输入/输出文件统一用 `AssetRef`，禁止裸路径：

```json
{
  "path": "build/manim-transformer/e6/media/videos/.../TokensScene.mp4",
  "sha256": "64位小写十六进制",
  "bytes": 1234567,
  "kind": "video",
  "origin": "rendered",
  "version": "manim-0.22.0"
}
```

| 字段 | 类型 | 必填 | 约束 |
| --- | --- | --- | --- |
| `path` | string | 是 | 默认相对工作区根，POSIX `/`，不得 `..`；仅 `origin=external` 允许绝对路径 |
| `sha256` | string | 是 | `^[0-9a-f]{64}$`；落盘后计算 |
| `bytes` | integer | 是 | ≥ 0 |
| `kind` | enum | 是 | `video` / `audio` / `image` / `subtitle` / `font` / `data` / `log` / `json` |
| `origin` | enum | 是 | `author` / `rendered` / `captured` / `generated` / `external` |
| `version` | string \| null | 否 | 工具/模型版本，如 `manim-0.22.0`、`voxcpm2` |

哈希在文件写完并关闭后计算；读取时校验；不匹配即 `CONTRACT_HASH_MISMATCH`。

`origin=external` 只用于只读外部素材（例如本机参考音）。它允许绝对路径，但不得复制进仓库、不得写入远程；哈希仍必须记录，便于发现参考音被替换。

## 8. `TimelineSpec`

唯一时间事实，供 Remotion / FFmpeg / 校验器使用。

```json
{
  "schema_version": 1,
  "kind": "timeline_spec",
  "lesson_id": "e6-transformer-attention",
  "fps": {
    "fps_num": 30,
    "fps_den": 1
  },
  "width": 1920,
  "height": 1080,
  "total_frames": 993,
  "video": [
    {
      "shot_id": "s1",
      "start_frame": 0,
      "duration_frames": 240,
      "role": "base",
      "z": 0,
      "asset": {"path": "...", "sha256": "...", "bytes": 0, "kind": "video", "origin": "rendered"}
    }
  ],
  "audio": [
    {
      "narration_id": "e6-s1",
      "start_frame": 0,
      "duration_frames": 206,
      "asset": {"path": "...", "sha256": "...", "bytes": 0, "kind": "audio", "origin": "generated"},
      "gain_db": 0.0
    }
  ],
  "subtitles": [
    {"index": 1, "start_frame": 0, "end_frame": 206, "text": "..."}
  ],
  "sync": {
    "audio_tolerance_frames": 1,
    "subtitle_tolerance_ms": 40,
    "allow_gap_frames": 1
  }
}
```

规则：

- `total_frames == max(video.start_frame + duration_frames)`；音频不得超出。
- `video` 的 base 镜头连续覆盖 `[0, total_frames)`；允许 ≤ `allow_gap_frames` 的空隙，超出即 fail。
- `audio` 按 `narration_id` 唯一；可短于所在镜头（尾部静音），不得超出。
- `subtitles` 以帧存储；导出 SRT 时用 `frame_to_ms`，并回读校验。
- `TimelineSpec` 不包含“是否通过”；检查结果写 `RenderManifest.checks`。

示例：`docs/contracts/examples/timeline.spec.json`

## 10. `RenderManifest`

一次渲染的最终记录；课程报告、E6 成片、Remotion 输出共用。

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `schema_version` | `1` | 是 | |
| `kind` | `"render_manifest"` | 是 | |
| `lesson_id` | string | 是 | |
| `render_id` | string | 是 | §2 |
| `run_id` | string | 是 | §2 |
| `created_at` | string | 是 | ISO 8601 UTC |
| `source` | object \| null | 否 | 规范化渲染为 `{lesson_spec, timeline, narration}` 三个 `AssetRef`；仅 legacy 迁移可为 `null`，但必须提供 `legacy.v0_manifest` |
| `output` | object | 是 | `{fps: {fps_num, fps_den}, width, height, total_frames, duration_ms}`；`duration_ms` 必须由帧数换算 |
| `shots` | array | 是 | 每镜头：`shot_id`、`track`、`start_frame`、`duration_frames`、`asset`、`evidence`（可选 `AssetRef`） |
| `narration` | object \| null | 否 | `{asset, duration_ms, segments}` |
| `subtitles` | object \| null | 否 | `{asset, format, cues}` |
| `video` | `AssetRef` | 是 | 最终成片 |
| `checks` | array | 是 | `{id, status, detail, evidence?}`；status 用五状态 |
| `tool_versions` | object | 是 | `manim`、`ffmpeg`、`node`、`voxcpm2` 等 |
| `legacy` | object | 否 | 仅迁移时保留旧字段与原始 manifest 哈希 |

约束：

- `checks` 必须由程序生成；手工字符串不得直接写 `pass`。
- 任一 `checks.status=fail` 时 `video` 仍可存在，但整体结论必须为 fail；`skip ≠ pass`。
- `video.sha256` 必须是最终文件的哈希；mux 后重新计算。

示例：`docs/contracts/examples/render.manifest.json`

## 11. 失败状态与错误码

沿用现有 `FailureCode`，V1 增加契约层错误码；不删除旧码。

| 错误码 | 触发 | 归属 |
| --- | --- | --- |
| `CONTRACT_INVALID` | Schema/Pydantic 校验失败 | 契约 |
| `CONTRACT_MISSING_ASSET` | `AssetRef` 文件不存在 | 契约 |
| `CONTRACT_HASH_MISMATCH` | sha256 不匹配 | 契约 |
| `CONTRACT_TIME_DRIFT` | 帧/毫秒换算超容差 | 契约 |
| `TIMELINE_OVERLAP` | base 镜头重叠 | 时间线 |
| `TIMELINE_GAP` | base 镜头空隙超限 | 时间线 |
| `NARRATION_OVERFLOW` | 旁白超出镜头 | 旁白 |
| `NARRATION_MISMATCH` | 文本哈希/音频缓存不一致 | 旁白 |
| `TTS_UNAVAILABLE` / `TTS_BUSY` / `TTS_TIMEOUT` | 已有 | 旁白 |
| `EXECUTION_FAILED` / `ASSERTION_FAILED` / `RECORDING_FAILED` | 已有 | 执行 |
| `EVIDENCE_INCOMPLETE` | 证据字段缺失 | 执行 |
| `RENDER_FAILED` | 渲染进程失败 | 渲染 |
| `RENDER_MISSING_STREAM` | 成片缺音频/字幕/视频流 | 渲染 |
| `RENDER_SYNC_DRIFT` | 音视频/字幕超容差 | 渲染 |
| `NETWORK_REQUIRED` / `OFFLINE_VERIFY_FAILED` / `WAIT_TRIM_INVALID` | 已有 | 执行 |

状态语义：

- `pass`：程序检查通过且有证据。
- `fail`：检查失败，或必需证据缺失。
- `skipped`：显式跳过（如无 Docker），不是通过。
- `not_run`：未执行。
- `not_applicable`：该镜头不适用此检查。

## 12. 与现有 E6 `manifest.json` 的兼容

现有 V0 结构（`build/manim-transformer/e6/manifest.json`）：

- `lesson`、`resolution`、`fps`、`shots[]`、`narration`、`subtitles`、`video`、`checks`。

只读适配规则（已实现于 `legacy_e6.py`）：

1. `lesson` → `lesson_id`。
2. `shots[].duration_s` → 整数毫秒（Decimal 半入），`start_frame` 由累计 ms 一次换算。
3. `shots[].file` + `sha256` → `AssetRef`（`kind=video`，`origin=rendered`）；实际哈希重新计算。
4. `narration.file` → `RenderNarration.asset`；E6 只有混合 WAV，**不生成 `NarrationSpec`**；`segments[].start_frame` 由镜头起点推断，并在 `legacy.narration_segments_start_inferred=true` 标明。
5. `subtitles.file` → `AssetRef`；SRT 逐条解析，检查非空、不重叠、落在某个镜头内。
6. `video.file` + `sha256` → `RenderManifest.video`；ffprobe 检查分辨率、帧率、音频格式与三条流。
7. `checks` 的原字符串不进入 V1 `checks`；标记为 `legacy.manual_checks`，`manual_checks_trusted=false`，并生成一条 `not_applicable` 记录。
8. 原始 manifest 作为 `legacy.v0_manifest` 的 `AssetRef` 记录；因缺少 `lesson.yaml` / `storyboard` 与逐段音频，`source=null`。

**迁移结论**：E6 现有产片可以被 V1 描述；自动检查在本地 E6 产物上得到 35 条 pass + 1 条 not_applicable（共 36 条）。V0 的人工 `checks` 仍是人工声明，不计为 V1 pass。

## 13. 各轨道如何接入

| 轨道 | `ShotSpec.source` | 产出 | 证据 |
| --- | --- | --- | --- |
| Slide | `{kind:"slide", slide:3}` | 截图/录屏 `AssetRef` | 可选 |
| Manim | `{kind:"manim", file, class}` | MP4 `AssetRef` | 渲染日志 |
| Session | `{kind:"session", session_spec, session_id}` | 录屏 MP4 | `EvidenceManifest` |
| Simulation | `{kind:"simulation", project, entry, params}` | 帧序列/MP4 | 运行日志、参数哈希 |

| Blender | `{kind:"blender", task}` | MP4/PNG 序列 | IR v2 校验报告 |

公共出口：每个适配器只负责

```text
ShotSpec -> (asset, optional EvidenceManifest, checks)
```

时间线、合成、字幕、最终哈希由 `TimelineSpec` / `RenderManifest` 统一处理。适配器不得各自定义时间单位。
