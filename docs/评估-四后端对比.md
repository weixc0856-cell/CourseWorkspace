# 评估：本地模型 / DeepSeek API / Claude Code / DeepSeek Harness 四后端对比（2026-11-07）

- **目的**：在既有本地模型接入环境（8080 + `shared/ai_runtime` 锁与远程回退）下，判断 Claude Code 是否值得作为课程镜头/内容的生产代理，并量化它与本地模型、DeepSeek 纯 API、DeepSeek Harness 的差距。
- **结论先行**：**Claude Code 交付质量最好，dsh 接近但更慢更贵；纯 API 合规但单薄；本地 Qwen3-Coder 本轮不合格。**
- **边界**：只测一个 8 秒 Code2Video 镜头，不代表整课、TTS、字幕或长视频；四者都使用同一份 `SPEC.md` 与同一渲染/QC。

## 1. 环境

| 后端 | 实际执行 | 模型 |
| --- | --- | --- |
| 本地 | `shared/ai_runtime.model_service` + 跨进程锁，8080 | `Qwen3-Coder-30B-A3B-Instruct-Q4_K_M`，CPU-only，64K |
| DeepSeek API | `ai_runtime.remote.chat_completion` 单轮 | `deepseek-flash`，`thinking=disabled` |
| Claude Code | `claude -p`（2.1.319），工具代理 | 经 cc-switch（`127.0.0.1:15721`）路由到 DeepSeek-V4-flash |
| DeepSeek Harness | `dsh headless`（0.2.2-rc.1），工具代理 | `deepseek-official / deepseek-flash` |

- 本地服务由 `model_service` 启动并在任务结束后自动停止；实测结束后 8080 已释放（`000`）。
- Claude Code 与 dsh 都是 **agent harness**，可读文件、编辑、跑命令；本地与纯 API 是 **单轮生成**。这个差异本身是结论的一部分，不能只当作模型差距。

## 2. 任务

同一份 `SPEC.md`：8.0 s、1920×1080、30 fps、Canvas 2D、单个自包含 `index.html`、固定文案、`window.READY` / `window.seek(t)` / `window.DUR=8`、确定性、无外部资源、8 条 must-have。

统一提示词要求只返回完整 HTML；agent 侧要求写入当前目录的 `index.html`，不改 SPEC、不渲染。

## 4. 逐项判断

### 4.1 本地 Qwen3-Coder：不合格

- 输出仅 5.9 KB / 1,647 token，SPEC 的固定文案 `query`、`key`、`value` 完全缺失；Q/K/V 方框没有对应单词。
- `scores` / `softmax` / `weights` 被画在同一坐标，画面文字重叠；`softmax` 步骤不可读。
- 内容只占画面中间一小块（方框 120 px、柱宽 40 px），在 1080p 下显得空旷。
- 0–1.5 s、1.5–4 s、4–6 s 三段近乎静止；虽然机器 QC 只报 freeze warning，但视觉上缺少连续动效。
- 生成速度 12.4 token/s，196.8 s 才完成 1,647 token；本地 30B 在 CPU 上不适合作为镜头代码的主生成器。
- **定位**：只适合离线、低风险、可人工大改的草稿；不能直接进入交付。

### 4.2 DeepSeek 纯 API：合规但单薄

- 10.5 s、3,042 输出 token，费用约 **¥0.012**；固定文案齐全，`READY/seek/DUR` 正确，无外部资源。
- 画面干净、边距合规，但元素偏小、构图只占上半屏，缺少“数据流”关系（scores → softmax → weights → output 只是纵向罗列）。
- `weights` 用绿色区分，`output` 在 6 s 出现；must-have 全过。
- **关键前提**：必须 `thinking=disabled`。本轮实测未关闭时，8K/16K 输出预算全部被 reasoning 吃掉，`content` 为空。该能力已补入 `ai_runtime.remote`（`RemoteConfig.thinking` / `chat_completion(thinking=...)`），authoring 默认对远程调用关闭。
- **定位**：结构化、短输出、成本敏感场景的主力；不适合要求画面完成度的镜头。

### 4.3 Claude Code：本轮最佳交付

- 245 s、45,440 输出 token，费用约 **¥0.222**；15.0 KB，固定文案齐全。
- 画面完整：左侧 Q/K/V 卡片、中间 scores 五柱、softmax 胶囊、右侧 weights 五柱带百分比（34/26/20/12/8，和为 1）、6 s 出现 output 卡片；层级、对比度、留白都明显更好。
- must-have 8/8；机器 QC 只有一段 4.43–5.93 s 的定格 warning（weights 停留），不是失败。
- 渲染更贵（161 ms/帧，42 s），因为阴影/发光/渐变更多；但仍在可接受范围。
- **定位**：镜头代码、复杂版式、需要自检与返工的任务首选。

### 4.4 DeepSeek Harness：接近 Claude，但更慢更贵

- 372 s、20 步、63,209 输出 token，费用约 **¥0.297**；15.3 KB。
- 画面同样完整：Q/K/V、scores、softmax、weights、output 横向流水线；机器 QC **0 warning**，是三路 agent 中最干净的。
- 但文字层级略弱（无百分比）、weights 柱形差异小、output 在 6 s 偏暗；整体观感略逊于 Claude。
- 20 步中 11 次 edit，说明它在反复微调；缓存读 1.15M token，成本约为 Claude 的 1.34 倍。
- **定位**：可选的独立第二代理/复核；不作为默认生产执行器。

## 5. 结论与建议

1. **默认生产代理：Claude Code。** 在当前 cc-switch 路由下，它的交付完成度、视觉质量、返工能力最好；单镜头成本约 ¥0.22，远低于人工审片时间。
2. **纯 API 保留为远程回退与结构化任务主力。** 必须显式关闭 thinking；适合 brief/outline/JSON/短文本，不适合需要画面设计的镜头。
3. **本地模型只做离线草稿。** 本轮 Qwen3-Coder 在固定文案、布局、动效上都不达标；即使免费，也不能省掉人工重做。
4. **dsh 作为第二意见。** 质量接近 Claude，但慢 52%、贵 34%；只在关键镜头需要交叉验证时使用。
5. **机器 QC 不够。** 本轮本地产物 QC 通过但文字重叠/缺文案，说明必须保留 Contact Sheet + 人工逐条 must-have 检查；后续可引入 HyperFrames 的 `text_below_floor` / 重叠类 lint。

## 6. Claude Code 接入方式（可行性结论）

**可行，但应作为“受控外部代理”，不要嵌入 CourseControl 进程内。**

### 6.1 前置条件

- cc-switch 代理运行在 `127.0.0.1:15721`，`ANTHROPIC_BASE_URL` 指向它，`ANTHROPIC_AUTH_TOKEN` 已注入（只读环境变量，不落盘）。
- Claude Code CLI 已安装（本轮 2.1.319）。
- 代理不可用时必须显式 `blocked`，不得冒充本地或纯 API。

### 6.1.1 两条接入路径（均已实测）

| 路径 | 配置 | 结果 |
| --- | --- | --- |
| cc-switch（默认） | `ANTHROPIC_BASE_URL=http://127.0.0.1:15721`，代理上游 `https://api.deepseek.com/anthropic` | 四后端对比即走此路径；有缓存读，245 s 完成镜头 |
| 直连 DeepSeek Anthropic 端点（回退） | `ANTHROPIC_BASE_URL=https://api.deepseek.com/anthropic`，`ANTHROPIC_AUTH_TOKEN` 取系统变量 `DeepSeek-API`，`--model deepseek-flash` | 实测 2.5 s 返回 `DIRECT_OK`；CLI 报 `unrecognized_model` 警告但可用；无 cc-switch 依赖 |

- 直连路径下 Claude Code 仍按 Anthropic 价目显示 `total_cost_usd`，实际账单按 DeepSeek 价目；不能用它做成本核算。
- 直连实测一次简单请求输入约 22K token（系统提示），未观察到缓存命中；生产默认仍用 cc-switch，代理不可用时才直连。
- 两条路径的 key 都只从进程环境变量注入，不写 `.env`、配置或日志。

### 6.2 推荐调用

```powershell
claude -p `
  --permission-mode acceptEdits `
  --allowedTools "Read Write Edit Glob Grep" `
  --output-format stream-json --verbose `
  "<task>" > run.jsonl
```

- cwd 固定为 `build/<slug>/agent/` 或镜头目录，禁止指向 `lessons/`。
- 从最终 `result` 事件读取 `usage`、`num_turns`、`duration_ms`；`total_cost_usd` 只作参考，不写实际账单。
- 任务结束后必须跑 `capture.mjs` + `code_video_qc` + Contact Sheet，再进入人工批准门。
- 失败/超时：记录 `provider=claude-code`、`reason`，回退到纯 API 或人工，不静默重试。

### 6.3 禁止项

- 不使用 `--dangerously-skip-permissions`；不开放无限制 Bash。
- 不让它直接改写 `slides.md` / `lecture_notes.md` / `approval.json`。
- 不把代理 token、完整环境变量或课程正文写进日志。
