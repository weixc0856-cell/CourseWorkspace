# 内容根迁移方案：把课程内容移出程序目录

- **日期**：2026-11-12
- **状态**：已执行（2026-11-12）。§12 记录实际结果与遗留项；本文其余部分保留为方案说明。
- **目标**：程序归程序，课程归课程。仓库只放管线代码；课程正文、中间产物、交付包、运行时状态放在工作区外的内容根。
- **已定决策**：内容根放在工作区外的独立目录，具体取值由 `config/local-paths.yaml` 的 `content_root` 决定；引擎场景目录本轮不动（见 §10）。

---

## 0. 结论

现状不是“乱放”，是**代码里没有内容根这一层**。`LessonPaths` 只有一个 `workspace` 参数，`build/`、`deliver/`、`runtime/` 都写成 `workspace / "<name>"`，而所有入口脚本都把 `workspace` 传成仓库根。于是内容只能长在程序旁边。

改造分两层：

1. **加一层配置**：新增 `content_root` 解析，默认等于工作区（零破坏）。
2. **搬目录**：把六个内容目录移到 `<内容根>`，配置指过去。

代码改动点已经数清楚：`paths.py` 3 个入口、44 处 `--lesson-dir` 默认值、13 处裸 `workspace / "build"`、6 处 `runtime`、1 处 `deliver`。全部是机械替换，风险集中在脚本与验证，不在业务逻辑。

## 3. 配置契约

新增解析顺序（后者覆盖前者）：

1. 默认：`workspace`
2. `config/local-paths.yaml` 的 `content_root:`（相对路径按 workspace 解析，绝对路径直接用）
3. 环境变量 `COURSEWORKSPACE_CONTENT_ROOT`
4. CLI `--content-root`（仅 `build` / `package` / `validate` 等主命令需要时再加）

选 `config/local-paths.yaml` 作为主入口的理由：它已经被 gitignore，全机配置集中在一处，且 `docling_root` 等键本来就在这里。

示例（本机配置，不入库）：

```yaml
content_root: <内容根绝对路径>
```

**关键约束**：内容根只影响路径解析，不改变任何文件名、目录名与契约。`build/<slug>/`、`deliver/<slug>/`、`lessons/<slug>/` 的相对结构保持不变，所以文档里的路径写法仍然有效，只是根变了。

## 4. 代码改动清单

### 4.1 新增 `workspace_layout.py`

`CourseControl/src/course_control/workspace_layout.py`：

```python
def content_root(workspace: Path) -> Path          # 按 §3 解析并缓存
def lessons_root(workspace: Path) -> Path          # content_root / "lessons"
def build_root_for(workspace: Path, slug: str) -> Path
def delivery_root_for(workspace: Path, slug: str) -> Path
def runtime_root(workspace: Path) -> Path
```

缓存键用 `(workspace, config_mtime)`，避免在长构建里反复读 YAML 或缓存过期。

### 4.2 `paths.py`

- `LessonPaths.load(workspace, lesson_dir=None, ...)`：`lesson_dir` 为空时取 `lessons_root(workspace)`；非空时保持“相对 workspace 解析”的现有语义（测试夹具依赖这一点）。
- 实例上保存 `content_root` 与 `lesson_dir`，避免属性访问时重复解析。
- `build_root` → `content_root / "build" / slug`（`build_root_override` 优先级不变）。
- `delivery_root` → `content_root / "deliver" / slug`。
- `engine_root` 本轮不变。

### 4.3 CLI

44 处 `lesson_dir: Path = typer.Option(Path("lessons"), "--lesson-dir")` 改为：

```python
lesson_dir: Path | None = typer.Option(None, "--lesson-dir", help="lesson directory (default: <content_root>/lessons)")
```

`cli/_common.py::_paths` 统一解析：

```python
def _paths(workspace, lesson, lesson_dir):
    root = content_root(workspace)
    base = (lesson_dir or (root / "lessons"))
    if not base.is_absolute():
        base = workspace / base
    return LessonPaths.load(workspace.resolve(), (base / lesson).resolve())
```

`--lesson-dir` 显式传入时仍按“相对 workspace”解析，夹具与测试不受影响。

### 4.4 13 处裸 `workspace / "build"`

全部替换为 `build_root_for(workspace, slug)`：

| 文件 | 位置 |
| --- | --- |
| `authoring/llm.py` | llama-server 日志 |
| `blender_runner.py` | manifests / logs |
| `blender_task.py` | 期望输出根 |
| `cli/render.py` | 单段语料、TTS 日志 |
| `pipeline.py` | 默认 build root |
| `producer/orchestrator.py` | rebuild 根 |
| `session_evidence_v1.py` / `session_runner.py` / `vscode_runner.py` | 会话证据 |

### 4.5 6 处 `runtime`

替换为 `runtime_root(workspace)`：`alignment.py`、`build_lock.py`、`cli/render.py`、`narrate.py`。

注意 `runtime/locks` 是跨进程锁，迁移必须在没有构建与 TTS 运行时进行（见 §7 前置条件）。

### 4.6 `knowledge/` 与 `assets/`

代码无引用。迁移后更新 `config/local-paths.yaml` 的 `docling_root`（若它指向工作区内）即可；`assets/` 只需移动目录，并在 `docs/课程生产交付物规范.md` 更新说明。

## 7. 执行步骤

### 前置条件

1. 没有正在运行的构建、渲染、TTS；8080 / 50000 空闲。
2. `git status` 干净或已知（当前工作区有未提交改动，迁移前先确认提交或 stash）。
3. 目标盘剩余空间 ≥ 内容体积；先算一次 `du`。

### 阶段 0：只加代码，不搬（可独立提交）

1. 新增 `workspace_layout.py`，`content_root` 默认返回 workspace。
2. 改写 `paths.py`、13 处 build、6 处 runtime、44 处 CLI 默认值。
3. 不改任何脚本、不配置 `content_root`。
4. 跑 `.\scripts\check.ps1` 与 `course-control validate --lesson <fixture>`。

**验收**：行为与改造前完全一致，`check ok`。

### 阶段 1：配置内容根（不搬）

1. 在 `config/local-paths.yaml` 写入 `content_root: <内容根绝对路径>`。
2. 手动验证解析：`course-control config-resolve` 或新增的调试输出应显示内容根。
3. 此时内容目录还不存在，命令会报“lesson not found”，属预期。

### 阶段 2：搬目录

```powershell
$content = (Get-ContentRoot)   # scripts/_layout.ps1，见 §5
New-Item -ItemType Directory $content -Force
robocopy .\lessons   (Join-Path $content 'lessons')   /E /MOVE
robocopy .\build     (Join-Path $content 'build')     /E /MOVE
robocopy .\deliver   (Join-Path $content 'deliver')   /E /MOVE
robocopy .\runtime   (Join-Path $content 'runtime')   /E /MOVE
robocopy .\knowledge (Join-Path $content 'knowledge') /E /MOVE
robocopy .\assets    (Join-Path $content 'assets')    /E /MOVE
```

`/MOVE` 会删源目录；执行前先确认没有进程占用。`deliver/` 若被占用会报 `WinError 5`，先关掉资源管理器里打开的目录。

### 阶段 3：脚本与文档

按 §5、§6 修改；`check.ps1` 的课程 validate 应从内容根找到课程，不再 skip。

### 阶段 4：验证与清理

1. `course-control validate --lesson a01-why-cars-need-aerodynamics`
2. `course-control build --lesson lesson-smoke --lesson-dir CourseControl/tests/fixtures`（夹具路径仍走 workspace）
3. `course-control package-verify --lesson <已有交付>`（验证 deliver 解析）
4. `.\scripts\check.ps1` → `check ok`
5. 删除工作区中残留的空目录与 `.tmp` 交付目录。

## 9. 风险与回滚

| 风险 | 处置 |
| --- | --- |
| Windows 文件占用导致 `/MOVE` 失败 | 先停构建与 TTS；`deliver/` 关闭资源管理器窗口 |
| 锁文件迁移打断并发 | 迁移前后各跑一次 `build_lock` 自检；确认无 `runtime/locks/*.lock` 活跃 |
| 脚本仍有写死路径 | 阶段 4 用 `grep -rn "lessons/\|build/" scripts/*.ps1` 复查 |
| 文档路径失效 | 相对结构不变，只有根变了；更新三份定义位置的文档即可 |
| 需要回退 | 删除 `content_root` 键即回到工作区；目录用 `robocopy /MOVE` 搬回。代码层无需回滚 |

**回滚成本**：一次配置删除 + 一次目录搬回，不涉及重新构建。

## 10. 第二阶段：引擎课程目录（本轮不做）

ManimSandbox、BlenderStudio/scenes、BlenderStudio/tasks、CodeVideoStudio/shots 里的课程专属目录本轮保留原位，原因是要先解决三件事：

1. **`common` 共用模块**：Manim 场景靠 `sys.path.insert(0, parents[1])` 导入 `common.design_system`。场景搬出 `ManimSandbox/` 后这个相对路径失效。可选方案：把 `common` 做成 uv 路径依赖包（推荐）、或由构建注入 `PYTHONPATH`。
2. **测试夹具必须留在仓库**：`BlenderStudio/tasks/scene-system/`（9 个契约用例）与 `tasks/lesson-*` 被 `check.ps1` 使用，不能跟着课程搬走。迁移时要按“课程目录 vs 夹具”逐目录判定。
3. **storyboard 的 `scene:` 是引擎根相对路径**：`engine_root()` 需要支持“有内容根时按课程解析、无内容根时回退引擎目录”，否则所有 `storyboard.yaml` 都要改。

建议的第二阶段目标是：

```text
<内容根>\<slug>\
├── scenes\manim\...
├── scenes\blender\...
└── shots\code_video\...
```

配套改动：`engine_root(engine)` 增加按 slug 解析；`common` 打包；迁移 `01-transformer-demo`、`02-car-aerodynamics`、`a01-*`、`ai-economics-e01`、`ai-era-01-shell`、`b01-b02-bluff-body` 六组课程场景；保留 `scene-system`、`lesson-*`、`primer-*`、`gpu-trace` 等模板与夹具。
