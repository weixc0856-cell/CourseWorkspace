# 技术雷达：课程视频生产开源项目评估（2026-11-07）

- **目的**：把“发现一个仓库就接入”改成可重复的评估机制；先解决交付质量，再决定集成。
- **评估对象**：Code2Video、video-production-skill、HyperFrames、VideoZero；附带 givemotion、dolly、Blender MCP、Awesome 索引。
- **与本项目关系**：CourseControl 仍是唯一编排与契约层；外部项目只作为镜头能力、制作方法或检查工具接入。

## 1. 评估维度与硬门槛

| 维度 | 权重 | 判断 |
| --- | --- | --- |
| 课程适用性 | 30% | 能否解决真实课程生产问题 |
| 技术成熟度 | 20% | 可运行代码、真实案例、维护状态 |
| Agent 适配度 | 20% | Skills / API / MCP / CLI |
| 集成成本 | 15% | 能否融入现有契约与流水线 |
| 商业许可 | 15% | 是否允许后续商业化 |

硬性淘汰：

1. 许可证不明确 → 不进入生产。
2. 只有宣传视频、无复现案例 → 不作为成熟方案。
3. 依赖特殊硬件且现有环境无法运行 → 不作为近期方案。
4. 与现有能力高度重复且无明确收益 → 不重复建设。

## 4. 逐项判断

### 4.1 Code2Video（已接入 P2）

- **接入方式**：Skill + `SPEC.md` + `frame(t)` + Contact Sheet + `VERIFY.md`；`adapters/code_video.py` 产出镜头 MP4；不接管整课。
- **优化方向**：
  - 已生产化为 `CodeVideoStudio/`，保留 Apache 2.0 NOTICE。
  - 统一 `SPEC.md` 与我们的 `ShotSpec` 字段（时长、尺寸、fps、must-have、来源）。
  - `VERIFY.md` 的 must-have 检查进入 `build-report.json`。
  - 继续用 Claude Code + DeepSeek；不部署 27B。
- **效果**：镜头级动效可确定性重放，返工有证据；不增加最终合成层。
- **风险**：长轨迹上下文、Windows `drawtext`/`python3` 兼容性；已在本机修出 shim/Pillow fallback。

### 4.2 video-production-skill（吸收，不安装）

- **接入方式**：只读研究 `SKILL.md`、`production-standards.md`、`source-playbooks.md`、`scripts/`；不把它的 10 步流程变成第二条流水线。
- **可直接吸收**：
  - 持久 job workspace + `manifest.json` + `exports/` + `logs/` 的归档约定（映射到 `build/<slug>/`）。
  - 分段 narration（`segments.json`）、逐段 TTS、`timings.json`、响度归一。
  - QC：抽帧、文字裁切、LaTeX 破损、音画同步、ffprobe 时长/音轨。
  - “未验证不得报成功”“不要把唯一成片留在 /tmp”。
- **不吸收**：Kokoro TTS（我们用 VoxCPM2）、它的 Manim/PIL 视觉流水线（我们已有 Manim/Remotion/Blender）、它的 orchestrator。
- **效果**：补齐交付归档与 QC 纪律，成本低；不增加运行依赖。

### 4.3 HyperFrames（做 POC）

- **接入方式**：只做 **HTML 镜头渲染后端** POC；不替换 Remotion 最终合成。
- **POC 内容**：
  1. 用 HyperFrames 重做 `CodeVideoStudio/shots/attention-flow` 或一个现有 HTML/SVG 课程页。
  2. 对比 `capture.mjs`、HyperFrames、Remotion：成片质量、渲染时间、确定性、lint/QC、集成代码量。
  3. 只测 15–30 秒 1080p30；不测长课。
- **可能收益**：更成熟的 HTML 时间轴/lint/inspect/音频混合；无构建步骤；Apache 2.0。
- **风险**：与 Remotion 都是 headless Chrome + ffmpeg，重复建设；GSAP 商业许可需单独核查；Node 22+；项目较年轻。
- **决策**：如果 POC 在质量/时间/维护成本上明显优于 `capture.mjs`，再考虑作为 `code_video` 的渲染后端；否则只吸收其 lint/QC 思路。

### 4.4 VideoZero（做 POC）

- **接入方式**：只用于**现有 Motion Canvas 资产**的自动导出；不作为新引擎。
- **POC 内容**：
  1. 在 `MotionStudio` 的临时副本加 `agent-plugin.ts` / `agent-client.ts`。
  2. `npm start` + 浏览器/Playwright 保持编辑器连接。
  3. 调用 `/__agent/seek`、`/screenshot`、`/render`，测试一个现有场景（如 `attention-flow`）。
  4. 判断能否在无人点击的情况下产出 MP4；记录失败点（编辑器依赖、HMR、浏览器）。
- **可能收益**：解决 Motion Canvas 人工导出节点；现有 9 个场景可批量导出。
- **风险**：官方 API 依赖运行中的编辑器与浏览器，**不是纯 headless**； Motion Canvas 3.17.2 兼容性需实测；会修改 MotionStudio 工程。
- **决策**：如果能在无人点击下稳定出片，增加 `motion_canvas` 自动导出路径；否则保持人工导出，继续用 Manim/Remotion。

### 4.5 其余

- **givemotion**：与 HyperFrames/Code2Video 高度重叠；等 HyperFrames POC 结果后再决定是否对比。
- **dolly**：只借鉴组件库、镜头语言、模板组织；不引入。
- **Blender MCP**：三维能力已有 BlenderStudio/IR v2；MCP 的任意脚本执行权限风险高，后置并单独评审。
- **Awesome 索引**：作为技术雷达的输入，不进入生产依赖。

## 8. POC 执行结果（2026-11-07）

### 8.1 HyperFrames

- 位置：`CodeVideoStudio/backends/hyperframes/hf-poc/`
- 版本：`hyperframes@0.9.20`，Apache 2.0，安装 24 MB。
- 内容：10s / 1920×1080 / 30 fps HTML + CSS + GSAP，300 帧。
- `npm run check`：修复首帧空白与 22px 小字后，**0 error / 0 warning**；Contrast 34/34 WCAG AA。
- `npm run render`：**27.1 s**（6 workers，hardware GPU；capture 11.4 s，encode 0.1 s），H.264 / yuv420p / 300 帧 / 10.0 s。
- 发现：
  - `first_frame_empty`、`text_below_floor` 这类 lint 是 Code2Video 的 `check_video.sh` 没有的，对交付质量有价值。
  - 依赖 GSAP CDN（网络）；可改用本地/WAAPI，但需重新验证。
  - 与 Remotion 同为 headless Chrome + ffmpeg，重复建设风险高。
- **结论**：作为 **HTML/GSAP 镜头的可选渲染与 lint 后端**保留；不替换 Remotion 最终合成，也不替换 Code2Video 默认 `capture.mjs`。P2 只决定“是否值得作为 code_video 的第二后端”，不是全量迁移。

### 8.2 VideoZero

- 位置：`build/videozero-poc/`（临时 POC，未改主 MotionStudio）。
- 安装：`agent-plugin.ts` + `agent-client.ts`，Vite `agentPlugin`，`project.ts` 加 `agentClient()`。
- 实测：
  - `GET /__agent/status` → `connected:true`，场景 `attention-flow`，3006 帧 / 30 fps。
  - `GET /__agent/scenes` → 9 个场景全部列出。
  - `POST /__agent/seek` → `{ok:true, frame:30}`。
  - `POST /__agent/screenshot` → `screenshots/probe-30.png`。
  - `POST /__agent/render`（默认 image-sequence exporter）→ 自动写出 **3007 张 PNG**，无需点击编辑器。
  - 外部 ffmpeg 编码 → `output/attention-flow.mp4`：1920×1080 / 30 fps / 3007 帧 / 100.233 s / 1.49 MB。
- 阻塞/适配：
  - **FFmpeg exporter 直接导出会挂起/不产帧**（Motion Canvas 3.17.2 + `@motion-canvas/ffmpeg` 3.17.2）；image sequence + 外部 ffmpeg 是可靠路径。
  - Vite 需要 `server.fs.strict:false` 或把 `node_modules` 纳入 allow list（POC 用了 junction，触发 allow-list 问题）。
  - 需要浏览器页面保持打开（Playwright 可隐藏运行）；不是纯 headless 进程。
- **结论**：**可以自动化 Motion Canvas 的“帧序列导出 + 外部 ffmpeg 编码”**，但需要一个小 wrapper 和 MotionStudio 工程改动；不建议直接依赖它的 FFmpeg 导出。作为现有 Motion Canvas 资产的自动导出路径保留，等 R1 内容稳定后再接入主工程。

### 8.3 video-production-skill

- 未安装；已核对 `SKILL.md`、`production-standards.md`、`source-playbooks.md`、`scripts/`。
- 采用建议：把 job workspace、manifest、分段旁白/timings、抽帧 QC、归档/备份纪律写入我们的交付规范；不引入 Kokoro、不接管 CourseControl 编排。

### 8.4 Code2Video 镜头 QC 门（2026-11-07）

- 新增 `CourseControl/src/course_control/code_video_qc.py`：`check_video` 校验可解码视频流、分辨率、fps、时长窗口、H.264、yuv420p 与音轨策略；`blackdetect` / `freezedetect` 只产生 warning（有意定格不等于失败）；`contact_sheet` 用 Pillow 生成抽帧图。
- `adapters/code_video.py` 在 PASS 与 FAIL 两条路径都写 `<project>.qc.json` 和 `<project>.contact.jpg`，并把 QC warning 透传到构建记录。
- 真实运行：`build/code-video-qc2/animation/attention-flow.mp4`，QC pass，5 段 freeze warning（对应设计中的定格），contact sheet 已生成。
- 测试：`test_code_video_qc.py` 4 项 + `test_code_video_adapter.py` 4 项；CourseControl 合计 212（210 通过 + 2 跳过）。
- **效果**：镜头从“文件存在”升级为“可解码、参数匹配、有抽帧证据”；warnings 不伪装成 pass。

### 8.5 DeepSeek Harness CLI（Agent 运行时对比，2026-11-07）

- `@deepseek-ai/dsh@0.2.2-rc.1` 可通过 `dsh headless` 非交互运行，默认 `deepseek-official/deepseek-flash`；支持 profiles/plugins、session 持久化、JSON 事件与权限预设。
- 在同一 8 秒 Code2Video SPEC 上：dsh 294 s / 15 步 / 输出 49.9K token；Claude Code 2.1.319 184 s / 5 次工具调用 / 输出 35.0K token。两者产物都通过 capture + QC；dsh 多 1 段 freeze warning，逐帧渲染约 200 ms vs Claude 49 ms。
- Windows 上 dsh 的 shell 沙箱被禁用，`workspace-write` 只是审批边界；凭据需在启动进程时注入 `DEEPSEEK_API_KEY`（本机系统变量名为 `DeepSeek-API`）。
- **结论**：不替换 Claude Code、不进入 CourseControl 运行时；仅作为人工按需的独立第二代理/复核。详见 `docs/评估-DeepSeek Harness.md`。

### 8.6 四后端镜头生成对比（2026-11-08）

- 同一 8 秒单文件 Code2Video SPEC：本地 Qwen3-Coder / DeepSeek 纯 API / Claude Code / DeepSeek Harness。
- 结果：Claude Code 与 dsh 均 8/8 must-have，Claude 观感最佳；纯 API 8/8 但构图单薄；本地 4/8（缺 query/key/value、文字重叠、构图过小、长定格）。
- 成本：本地 ¥0；纯 API ¥0.012；Claude ¥0.222；dsh ¥0.297（空闲价，Claude/dsh 输出含推理 token）。
- 关键前提：DeepSeek flash 默认把输出预算用于 reasoning，纯 API 长输出必须 `thinking=disabled`；已补入 `ai_runtime`。
- 决策：Claude Code 作为受控外部代理，不进入 CourseControl 运行时；dsh 仅作第二意见。详见 `docs/评估-四后端对比.md`、D-041、D-042。

### 8.7 Claude Code 全量默认后端落地（2026-11-08）

- 新增 `shared/ai_runtime/claude_code.py`：文本模式 `--tools=`，Agent 模式显式 tools；解析 `--output-format json` 的 result/usage，凭据只从环境变量注入。
- CourseControl authoring（brief/outline/script/content）、字幕翻译、ContentQA、ModelingStudio 文本规划默认 `backend=claude_code`；ModelingStudio vision 阶段仍走本地/远程视觉模型。
- 任务记录 `provider` 枚举扩展为 `local` / `remote` / `claude_code`；`shared/schemas/model-task.schema.json` 同步。
- 真实 smoke：文本 JSON（1.1 s）、Agent 写文件、authoring `chat_json`、真实 `course-control brief`（`build/01-transformer-demo/authoring/candidates/brief.json`，`provider=claude_code`）、ContentQA `chat_json`、ModelingStudio route 均通过。
- 回归：五套 **328 个用例（326 通过 + 2 跳过）**，`check.ps1 = check ok`。
