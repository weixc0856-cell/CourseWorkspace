# 样片：Attention（2 分钟）与 3B1B 的差距分析

日期：2026-11-08
参考：3Blue1Brown《Attention in transformers, visually explained》<https://www.youtube.com/watch?v=wjZofJX0v4M&t=707s>
成片：`build/attention-3b1b/attention.mp4`（1920×1080 / 60 fps / 2 分 03 秒）
源码：`ManimSandbox/06-attention-3b1b/`
说明：本片只借“视觉语言”，不复制原片脚本、旁白与音轨。

## 1. 本片做了什么

一个机制，十一个镜头：

1. 句子出现，`it` 被圈出：它指谁？
2. 一个词不是数字，是一个方向（12,288 维，降到二维画）。
3. 每个词发出 query / key / value 三支向量。
4. 三者各自的含义。
5. 点积的几何：一支向量在另一支上的投影（长度实时变化）。
6. 同向、无关、反向三种情形。
7. 所有词两两打分，得到 attention pattern（10×10）。
8. 因果遮罩：不能看未来。
9. softmax：一行分数变成和为 1 的权重。
10. 用权重把 value 向量首尾相接，得到 context。
11. 回到句子：`it` 的权重 0.53 落在 `animal` 上。

技术栈：Manim CE 0.22 + LaTeX（Computer Modern）+ VoxCPM2 本地旁白；镜头边界与旁白共用 `timing.json` 一条时间轴。

## 2. 结论

**没有达到 3B1B 的成片效果。** 它是一支合格的数学可视化讲解片，但不是 3B1B 级的“连续图解”。

| 维度 | 3B1B | 本片 | 判定 |
| --- | --- | --- | --- |
| 视觉变化是否推进理解 | 每次变形都对应一个讲解点 | 部分镜头只是静态等待旁白 | 差距明显 |
| 转场语法 | 同一场景图持续变形，几乎不切 | 镜头之间整体淡出再重建 | 差距明显 |
| 镜头运动 | 连续的推、拉、平移，穿过嵌套坐标空间 | 2 次推近，其余固定机位 | 差距明显 |
| 图形资产 | 自研 OpenGL 库：光晕、景深、手绘抖动、向量云 | Manim 基础图元 + 直线箭头 | 差距明显 |
| 音频 | 真人配音 + 原创配乐 + 音效 + 词级对齐 | 本地 TTS，无音乐/音效，镜头级对齐 | 差距明显 |
| 帧率 | 60 fps | 60 fps（本轮已对齐） | 无 |
| 内容深度 | 高维空间、真实 GPT-3 数值、多头 | 二维投影、玩具句、单头 | 有意简化 |
| 单分钟工时 | 约 1–2 人周（含分镜、录音、混音、返工） | 约 2–3 小时（本机，含 TTS 与渲染） | 量级差距 |

自评（10 分制，3B1B 基线按 9.5 计）：视觉语言 6.5；运动连续性 5；信息密度 5；音频 5.5；完成度 7。

## 3. 为什么达不到

**不是引擎问题，也不是算力问题。** 瓶颈按影响排序：

1. **导演层缺失。** 每个镜头只有“学习意图 + 一句旁白”，没有逐秒的视觉节拍表。3B1B 的每一秒都绑定一个具体的图形变化；本片很多秒只有静态构图在等旁白。
2. **运动语法不同。** 3B1B 的对象是长寿命的：一个箭头可以从 embeddings 镜头一路变形到 attention 镜头。本片每个镜头重建一套对象，镜头之间用淡入淡出收尾，观众感到“换页”而不是“推进”。
3. **资产层缺失。** 光晕、景深、手绘线条、数百支小箭头的向量场、矩阵悬停读数，都是自研渲染资产。Manim CE 能画，但默认没有这些质感；临时补齐的成本高于写脚本本身。
4. **音频层缺失。** 3B1B 的节奏一半来自音乐和音效；本片只有人声，静音段落显得空。词级对齐也没有做，旁白与图形只能镜头级同步。
5. **内容密度取舍。** 为了两分钟内讲完整条链路，点积、softmax、加权和各占一个镜头；3B1B 会用一个镜头讲 30–60 秒并插入多个反例。

## 4. 达到的路线

### 阶段 1：把手上的工具用到位（1–2 天）

- 60 fps；镜头关键帧推拉（`MovingCameraScene` + Updater），不写相机系统。
- 转场改成变形：query 箭头直接变形成 pattern 的一行，而不是整体淡出。
- 用 FFmpeg 做轻微光晕；Remotion 负责片头/字幕/音乐层。
- WhisperX 对现有旁白做词级对齐，动画跟到词。
- VoxCPM2 切可控克隆 + 段落级风格指令，先盲听五组再定默认值。

### 阶段 2：只沉淀教学组件（按需，不预建框架）

`ProjectionGuide`、`AttentionMatrix`、`TokenFlow`、`VectorFan`、`CameraPreset` 放进 `ManimSandbox/common/`，下一支片子直接复用。Manim 已有的变换、相机、Updater 不再重写。

### 阶段 3：ManimGL 对照 POC（迁移前必做）

挑 QKV 分发、attention matrix、加权求和三个镜头，CE 与 ManimGL 各做一版，统一 1080p60、同一旁白、同一时长；记录开发/渲染工时和返工次数，看完整片再决定是否迁移。详见 `docs/评估-动画音频口播-整合.md`。

### 阶段 4：音频与音乐（等授权与盲听结论）

没有明确商用授权前不加 BGM；音乐按教学功能分类，先做 A/B/C/D 盲听；响度按 -16 LUFS、TP ≤ -1 dBTP 的可配置目标验收。

## 5. 验收方式

直接看完成片，按时间点记问题；不设抽帧/关键帧评审关卡（见 `docs/DECISIONS.md` D-047）。

## 6. 2026-11-09 本轮落地：去掉补偿性运镜，补导演节拍

本轮针对成片反馈做了三件事，并把 05 校准课作为第一个试验场。

### 6.1 研究结论

- 3B1B 的核心不是“镜头一直在动”，而是**每个变化都在论证**：SIGGRAPH 2021 的说法是 “animation is argument, not illustration”，Manim 里最常用的原语是 `Transform`；访谈里反复提到统一视觉系统与“先具体后抽象”。
- Manim 社区的相机实践一致强调：运动要有动机（全景 → 推近 → 拉远），不要让观众眩晕；`TransformMatchingShapes` 一类工具的价值在于**保持对象身份**，让同一对象跨镜头存活。
- 因此“每个 play 附带 1.4 %/s 缩放”虽然能把 `freezedetect` 压到 0，但它是补偿性运镜，不是导演设计；本轮删除。

### 6.2 已实施

1. **删除补偿性运镜**：移除 `Scene.play` 的相机缩放覆写与 `zoom_fill`；全片相机固定在 14.22 画幅，不再有无动机推拉。
2. **删除底部灰色说明行**：21 条 `caption()` 与字幕重复，全部移除；原位置改为“指认式”视觉动作（逐行扫亮、逐层高亮、轮流压暗/恢复、分开再合并等），见 `ManimSandbox/05-transformer-5min/beats.md`。
3. **字幕下移**：`Subtitles.bottom_margin` 可配置（默认 190 px，本课 60 px），ASS 锚点从 `height-190` 改为 `height-bottom_margin`，双语字幕块整体下沉，图形主体回到字幕带之上。
4. **补导演节拍**：按镜头逐条补动作，镜头内静止时间从最长 8.4 s 压到 2 s 以内；每个动作都对应旁白里的一个论证点。
5. **评审修复**：`Create(card)` 会逐字揭示文本，看起来像末尾字母被截断（`source sequenc`），改为整卡淡入；公式改为整体淡入，避免 `Write` 的局部字形；字幕改为加粗、`#111111`、去掉白色描边；补 `scaled: q·k/√d_k` 与 `h·d_v → d_model` 注记；转场清屏从 0.8 s 缩到 0.5 s，减少空白帧。

### 6.3 仍存在的差距

- **对象寿命**：多数镜头之间仍是整页淡出再重建；3B1B 是同一场景图持续变形。下一步是把句子行、focus token、分数矩阵做成跨镜头长寿命对象，用 `TransformMatchingShapes` / `ReplacementTransform` 交接。
- **资产层**：光晕、景深、手绘线条、向量场仍是 Manim 基础图元。
- **音频层**：只有人声 + BGM，没有音效与词级对齐。
- **工时**：本轮仍是“脚本 + 迭代预览”，不是逐秒分镜 + 返工的 1–2 人周/分钟。
