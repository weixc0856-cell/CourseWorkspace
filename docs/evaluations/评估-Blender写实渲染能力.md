# 评估：Blender 写实渲染能力（2026-11-09）

## 1. 目的

用三个可量化的小样回答一个问题：**本机（Arc A750 8 GB + Blender 5.2.3）能把三维内容做到什么程度**，以及“1:1 复刻参考片”是否在能力范围内。

测试对象：

- 参考片 A（B 站，22 秒，作者自述渲染 75 小时）：写实森林 + 列车 + 湖面，多镜头；
- 参考片 B：陆家嘴夜景（外滩经典机位），用户提出的生成目标。

## 2. 环境

| 项 | 值 |
| --- | --- |
| Blender | 5.2.3 LTS（`--factory-startup`） |
| 渲染器 | Cycles GPU（oneAPI）+ OpenImageDenoise；EEVEE 对照 |
| 设备 | Intel Arc A750，8 GB 显存（oneAPI 可用，CUDA/HIP 不可用） |
| 分辨率 | 1280×720 |

## 3. 测试一：森林 + 列车（对照参考片 A）

- 场景：程序化地形、轨道、四节简化列车、**20,000 棵实例树**（4 种原型）、体积雾、Cycles 32 采样。
- 结果：**4.53 秒/帧**（90 帧连续渲染，均值；首帧 5.47 s）；场景构建约 60 s。
- EEVEE 对照：4,000 棵树时 **2.71 秒/帧**；20,000 棵树的 EEVEE 序列中途停止，未取得完整数据。
- 观感：构图可对齐（俯拍林间轨道 + 列车），但树冠是低模团块、颜色单一、列车为几何体，与参考片的叶片级植被差距明显。

## 4. 测试二：程序化精细树

- 做法：递归分枝（7 级）+ **叶片卡片**（程序化叶脉贴图，UV 正确映射）+ 树皮噪声材质。
- 结果：近景叶片有形状与透空，中景可信；**720p / 32 采样 约 3 秒/帧**；520 棵树共享网格实例化后航拍呈连续冠层。
- 局限：树形是“伞状”，缺树种与树形多样性；写实森林仍需资产或更强的生成算法。

## 5. 测试三：陆家嘴夜景体块

- 场景：90 栋程序化塔楼 + 4 个地标（东方明珠、金茂、环球、上海中心，脚本造型）、江面反射、体积雾、合成器 Glare 辉光。
- 机位：外滩岸线、35 mm、目标点抬高以容纳 632 m 塔身。
- 结果：**720p / 48 采样 约 6 秒/帧**；一眼可认出“陆家嘴夜景”，但地标造型、立面灯光语言、江面前景均粗糙。
- 结论：**“能认出”是当前上限**，不是写实。

## 6. 过程中暴露的工程坑

| 坑 | 现象 | 处理 |
| --- | --- | --- |
| 相机裁剪 | 1.4 km 外的天际线整片消失 | `clip_end` 默认 1000 m，显式设为 8000 m |
| 窗格贴图 | 窗格被压扁/拉长 | 用 Object 坐标做 box projection 时，必须先应用物体缩放 |
| 合成器 API | `scene.node_tree` 不存在 | Blender 5.x 改为 `scene.compositing_node_group`，Glare 参数变成输入端口 |
| 图像缓冲 | `pixels` 长度不匹配 | 生成贴图必须写 RGBA 四通道 |
| 布尔开口 | 环球顶部开口 | 旋转立方体 + Boolean DIFFERENCE，需应用修改器后删除 cutter |

## 7. 结论

1. **算力不是瓶颈**：720p 下写实风场景 4–6 秒/帧；按像素外推 1080p 约 10–14 秒/帧，22 秒全片约 2 小时。
2. **瓶颈是资产与美术**：参考片的价值在叶片级植被、真实列车、灯光与调色，这些不是程序化几何能补的。
3. **1:1 复刻不在能力范围内**；“可辨识的体块 + 程序化立面”是当前上限。
4. **本流水线的甜区是 3D 讲解**：机制、结构、数据驱动的解释镜头，风格化是加分项，且可确定性重建。
