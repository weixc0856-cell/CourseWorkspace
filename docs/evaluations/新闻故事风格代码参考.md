# 新闻故事风格代码参考

- **日期**：2026-11-14
- **状态**：**评估中，未生效**。本文是提案与实现参考，不是标准、不是门禁，也不进入 CLAUDE.md 的硬约束。
- **转正条件**：15 秒 style probe 通过；2 分钟短剧再通过一次成片评审。两次都过，才考虑写入标准。
- **范围**：只讨论“用 2D 动画段落讲新闻、讲故事”的方法与代码实现；不涉及访谈、实拍与整条纪录片。
- **参考对象**：一条时政调查视频中约 2 分钟的动画短段（不记录作者、平台与片名）。分析仅取方法，不复用形象、画法与桥段。
- **材料处置**：分析用的视频与截帧只在本机临时目录使用，已删除；仓库与交付包中不保留任何原片素材。

---

## 0. 归档摘要

这份文档记录三件事：

1. 对参考动画段的逐段拆解：它怎么讲新闻、怎么讲故事。
2. 用现有代码管线复刻这套**方法**的可行性、工程量与边界。
3. 由此提出的、对我们现有新闻片的改进提案（第六节），以及验证顺序。

它**不是**：

- 不是新的视觉语法或新引擎；
- 不是“以后都改成卡通”的决定；
- 不是对参考片形象、画风或桥段的授权。

---

## 1. 结论

这段动画的说服力不来自画风，而来自**调度**：一句台词配一个动作，一个动作配一个反应，抽象机制被演成一次具体的任务流转。

- **叙事方法可以完全代码化**：分层角色 + 姿态/表情切换 + 插画背景 + 真实材料插入 + 快切。
- **不需要生成式视频，也不需要逐帧手绘**。
- 真正的成本是角色资产与表演设计，不是渲染。
- 但它是否值得产品化，取决于样片的最终观感——技术可行不等于好看。

---

## 2. 它是怎么讲故事的（逐段观察）

| 手法 | 观察 | 作用 |
| --- | --- | --- |
| 角色即职位 | 决策者（坐主位）、执行者（站着汇报）、外包者（缩在工位） | 观众不用记名字，直接看懂权力关系 |
| 一场戏 = 一次任务 | 布置 → 转手 → 执行 → 出事 → 追责 | 把抽象机制演成可看见的流程 |
| 空间即结构 | 主位/客位、独立办公室/开放工位、白天/夜晚 | 不说“层级”，画面自己说明层级 |
| 信息靠嘴，关系靠画面 | 对白与旁白交代事实；画面给表情、站位、反应 | 避免用画面编造事实 |
| 反应镜头 | 听完话后的 0.5–1 秒表情特写 | 态度与讽刺由反应承担，不由旁白下结论 |
| 真实材料插入 | 软件界面、代码屏、文件截图硬切进卡通画面 | 把虚构段落拉回证据 |
| 快切 | 平均 1.5–3 秒一个镜头 | 维持信息密度，掩盖有限动画的不足 |
| 夸张有边界 | 表情与姿态夸张，事实与数字不夸张 | 讽刺针对结构，不针对事实 |

一句话概括：**用卡通演流程，用材料定事实，用反应给态度。**

---

## 3. 六种可复用的节拍

| 节拍 | 画面 | 台词功能 |
| --- | --- | --- |
| `briefing` 布置 | 上级坐主位，下属站立；桌上文件/屏幕 | 给出任务与指标 |
| `handoff` 转手 | 两个角色交接文件/账号/电话；镜头切到下一层 | 说明“谁转给谁” |
| `insert` 材料 | 真实界面、合同、聊天记录、代码 | 提供证据，标注来源 |
| `reaction` 反应 | 面部特写：愣住、扶额、假笑、沉默 | 表达态度，不写结论 |
| `blame` 追责 | 多人同框，视线指向某人；或电话两端 | 展示责任如何被推走 |
| `timecard` 时间跳 | 日期卡、夜晚/白天、重复工位 | 省略过程，推进节奏 |

一段 2 分钟的短剧，通常是 4–6 个 `briefing/handoff` 循环，中间插入 2–3 次 `insert`，结尾一个 `blame`。

---

## 4. 代码实现映射

| 叙事组件 | 实现 | 现状 |
| --- | --- | --- |
| 分层角色 | 头/身/眼/眉/嘴/手臂分层，Canvas 合成 | 需新增 |
| 姿态 | 每角色 8–12 个离散姿势，切换 2–3 帧过渡 | 需新增 |
| 表情 | 6–8 套眼/眉/嘴组合，按台词切换 | 需新增 |
| 口型 | 从旁白 wav 取 20 ms 能量包络，切 3 个嘴型 | 低成本 |
| 背景 | 一张插画 + 慢推/视差；同场景复用 | 需资产 |
| 材料插入 | 截图/文件卡直接合成，保留来源标签 | 已有 |
| 快切与时间线 | `content.json` 的 beat 模型 | 已有 |
| 旁白、音效、混音 | VoxCPM2 + 四层声音 | 已有 |
| 逐帧确定性 | Canvas `seek(t)` + Playwright + ffmpeg | 已有 |

**不需要**：生成式视频、3D 角色、逐帧手绘。

---

## 5. 叙事边界（硬规则）

1. **演流程，不演指控。** 已被文件证实的行为可以演；“可能发生了什么”不能演成画面。
2. **演出来的段落必须标 `DRAMATISED`**，与 `DOCUMENTED / REPORTED / INFERENCE / CLAIM` 并列；插入的真实材料标来源。
3. **数字与结论不夸张。** 夸张只用于表情、动作与构图。
4. **一段一个反讽点。** 与 [编辑口吻与反讽指南](../creative/编辑口吻与反讽指南.md) 一致，不靠角色堆段子。
5. **不影射真实个人。** 角色是职位类型（决策者、执行者、外包者），不是某个人；外形、口音、身份不作笑点。
6. **不替代证据。** 动画段之后必须回到文件、数据或时间线；卡通不能成为唯一论据。

## 6. 对我们的改进提案（待样片验证，未生效）

即使暂时不做角色动画，参考片的叙事调度也有四条现在就能用。

### 6.1 我们缺的四件事

| 缺什么 | 现在的样子 | 后果 |
| --- | --- | --- |
| 人 | 全是字、图、时间线 | 观众没有可跟随的对象 |
| 场景 | 六幕是标签，不是戏 | 每一幕都在“陈述”，没有“发生” |
| 反应 | 数字出现后直接进下一句 | 观众来不及产生态度 |
| 声音表情 | 旁白全程同一语速与情绪 | 再好的句子也像在读稿 |

### 6.2 六条改进

1. **每集至少一场 60–90 秒的戏**，放在 Mechanism 幕：两个角色、一次任务流转、一个追责结尾。画面标 `DRAMATISED`，前后各接一次真实材料。
2. **冷开场先给人，再给数**：第一句先给一个具体的人与处境，再上数字。
3. **关键数字后加 0.5–1 秒反应**：一张脸、一个空镜、或一行停住的大字，不立刻接下一句。
4. **每 30 秒出现一次“真东西”**：文件、界面、财报、时间戳；卡通和排版都不能连续超过 30 秒没有材料。
5. **每一幕结尾留一个问题**，下一幕开头回答；六幕从并列改成问题链。
6. **每幕一句冷话，且必须落在证据之后**：先给文件，再给反差；不提前下结论，不拿受害者开玩笑。

### 6.3 声音

- 旁白按幕变速：证据幕慢、冲突幕快、反讽句后停 0.6–1 秒。
- 关键判断句单独合成、单独试听，不用整段同一参数。
- 角色段可做轻微音色区分（同一声线，音高/语速微调），不引入第二套 TTS 音色。

### 6.4 不改的底线

- 事实层级不降：演出来的段落只能是流程，不能是指控。
- 一段一个反讽点，不变成段子合集。
- 材料永远比卡通先出现或后收尾；卡通不能成为唯一论据。
- 100 分制里“研究与事实准确性 < 16/20 不发布”不动。

## 7. 落地顺序与 go / no-go

| 阶段 | 产出 | 通过条件 | 不通过怎么办 |
| --- | --- | --- | --- |
| 1. 15 秒 probe | `briefing → reaction → insert`，一个角色两姿态三表情 | 角色在“演”；跨镜头同一人；插入物不打架；静音可读 | 停在单张插画，不扩工程 |
| 2. 2 分钟短剧 | 完整一次任务流转，含 2 次材料插入 | 100 分制 ≥ 75；研究与事实准确性 ≥ 16 | 只保留“改进六条”中的非角色项 |
| 3. 整集试用 | 调查片内插入 1–3 分钟短剧 | 成片评审通过；观众能复述判断 | 退回纯排版形态 |

工程量（2 分钟短剧）：约 3 周。渲染不是瓶颈：现有 262 秒片子约 18 分钟，分层合成预计 1.3–1.6 倍。
