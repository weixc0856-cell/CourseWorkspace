# 课程质量保障体系：仓库实现差距审查与实施方案

- **审查日期**：2026-11-09
- **审查基线**：`feat/v1-pipeline-remote-fallback` / `ed53c2b`
- **依据**：《CourseWorkspace 课程质量保障体系与实施规范 v1.0-draft》
- **审查方式**：代码路径核对 + 现有产物核对 + 测试/构建证据核对；**本轮没有创建任何课程质量模块，也没有修改生产主链**。
- **状态词**：`IMPLEMENTED`（有代码）/ `TESTED`（有自动化测试）/ `VERIFIED`（有真实运行证据）/ `PARTIAL`（部分实现）/ `DESIGNED`（只有设计）/ `NOT_STARTED` / `BLOCKED`。
- **硬规则**：`TESTED` 不等于 `VERIFIED`；模型意见一致不等于事实正确；构建通过不等于课程质量合格。

## D. P0 / P1 / P2 实施路线

### P0-1 真实课程闭环（最高优先级）

1. 完成整课旁白：`narration-build` 产出 `narration.meta.json`（50 段已有 wav，可续跑/校验缓存）。
2. 用实测 meta 重建字幕：`subtitles-build`（不带 `--planned`），消除 cue 273/317 告警，人工 `subtitles-accept`。
3. 完整构建：`build --storyboard build/01-transformer-demo/director/storyboard.director.yaml`，产出 `final/course-video.mp4` 与 `build-report.json`。
4. 全片检查：ffprobe 解码、音视频时长、响度、峰值、异常静音、黑帧、冻结帧。
5. `producer-run` 由 `blocked` 变为 `awaiting_approval`；人工批准后再谈交付。
6. 如实记录每一步：未执行 = `NOT_RUN`，缺证据 = `INCOMPLETE`。

### P0-2 五条质量防线框架

1. 定义 `quality-report` 契约：五维独立状态、证据路径、检查时间、工具版本。
2. 统一状态：`PASS / WARN / BLOCKED / INCOMPLETE`；三层状态：`BUILD_PASS / QUALITY_PASS / RELEASE_APPROVED`。
3. 聚合器只读现有产物，不推断：缺证据就是 `INCOMPLETE`，不允许“其他维度通过所以算过”。
4. 输出给用户的最小视图：`quality-report.html`（可交付）+ `release-manifest.json`（可审计）。

### P1-1 内容可信度

1. Claim Registry：`claim_id / text / type / source_refs / slide_id / risk_level / applicability / review_status`。
2. 独立审查 A/B：同一原始材料、互不可见；ReviewRunner 负责隔离执行与归档。
3. 证据核验：来源是否支持主张、是否过期、是否适用。
4. 冲突报告：一致但无来源 → 仍需复核；冲突 → 人工裁决。
5. 禁止把模型 `supported` 写成课程事实通过。

### P1-2 教学有效性

1. 目标覆盖检查：`learning_objective` 与页面/旁白覆盖关系。
2. 概念递进、前置知识、示例/反例、认知负荷。
3. AI 学习者模拟（候选问题发现，不作为效果证明）。
4. 真实学习者小样本测试流程（人工组织）。

### P1-3 双语生产

1. 统一知识资产层（claim/concept/example）先行。
2. 中英文旁白独立生成；允许不同时长和语序。
3. 术语表 + 双语字幕 + 跨语言一致性报告（事实/逻辑/术语/数字/时间轴）。
4. 当前只有 `language: en` 旁白 + 双语字幕草稿，不能声称双语成片。

### P1-4 参考作品与规范

1. 结构化 Reference Library（开场/口播/镜头/动画/字幕/音频/结构）。
2. 形成 Narration / Subtitle / Editing / Animation / Visual / Audio 规范资产。
3. 不直接复制参考作品内容或视觉资产。

### P2

- 音频 BGM/ducking 接入 Remotion 混音。
- 章节卡自动插入时间线。
- 长序列模拟（当前 180 s 失败，未修复前不声称可用）。
- 生图/ComfyUI（不在当前范围）。

## E. 每项任务的验收标准

| 任务 | 验收标准（必须可核对） |
| --- | --- |
| 整课旁白 | `build/<slug>/narration/narration.meta.json` 存在，段数与 script 一致，每段有真实 `duration_s`；总时长由 `probe_audio` 核对 |
| 实测字幕 | 字幕构建不带 `--planned`；cue 时间来自实测 meta；`validate_cues` 0 problem；人工 `subtitles-accept` 后才进入课程目录 |
| 完整构建 | `final/course-video.mp4` 可 `ffprobe` 解码；分辨率/fps/帧数/时长符合 `lesson.yaml`；`build-report.json` 记录检查项 |
| 全片音频 QC | 报告包含响度、峰值、削波、异常静音区间；未执行则 `INCOMPLETE` |
| 全片视频 QC | 报告包含黑帧、冻结帧、异常空白、帧数；不能只抽查 |
| 音画一致 | 有 ASR/对齐时间戳，字幕与音频对齐误差在阈值内；无 ASR 时状态必须是 `INCOMPLETE`，不能写 PASS |
| 质量报告 | 五维独立状态；任何一维 `BLOCKED/INCOMPLETE` 时不得输出 `QUALITY_PASS` |
| 发布 | `release-manifest.json` 含文件哈希、版本、构建记录、授权状态、人工批准；缺一项即 `RELEASE_APPROVED` 不成立 |
| Claim Registry | 每条高风险主张有来源与证据；无来源主张进入风险清单 |
| 多模型审查 | A/B 输入独立；没有模型互相引用；冲突报告存在；人工裁决记录 |
| 教学 QA | 问题能定位到具体页面/知识点；分数只作参考，不作为通过依据 |
| 双语一致性 | 事实、数字、术语、步骤、时间轴差异报告；关键差异未处理不得发布 |

## F. 一门真实课程的端到端验证计划

以 `01-transformer-demo` 为对象（已有 12 页、12 镜头、50 段 wav、357 cue 草稿）：

1. **基线冻结**：记录当前 `ed53c2b`、构建产物哈希、缺失清单。
2. **旁白**：重跑/续跑 `narration-build`，产出聚合 meta；核对 50 段与 script 一一对应。
3. **字幕**：`subtitles-build`（实测）→ `validate_cues` → 人工 `subtitles-accept`。
4. **合成**：`build --storyboard ...` 产出完整成片与 `build-report.json`。
5. **全片 QC**：音频（响度/峰值/静音）、视频（黑帧/冻结/帧数）、字幕同步、音画一致。
6. **内容 QA**：用 `sources.yaml` 对真实页面做一次完整审查；保留原始报告。
7. **教学 QA**：对 1–2 个知识模块做人工 + AI 双轨检查，记录问题定位。
8. **交付**：生成 `quality-report.html`、`release-manifest.json`；人工填写发布决定。
9. **回归**：`check.ps1` 必须仍为 `check ok`；新增质量检查有独立测试。

**成功标准**：不是“新增了多少模块”，而是用户只看成片 + 质量报告就能决定是否发布；系统能指出“第 06 页英文旁白漏掉中文稿的适用条件”这类具体问题。

### H.3 隔离与隐私

- 默认 `--ignore-user-config`：本机 MCP 服务器、插件不加载；项目路由配置只提供 `base_url/model/api_key_env`，**不读取、不复制 key**。
- key 由 Codex 子进程从环境变量读取（项目约定 `DeepSeek-API`），不进入 argv、日志或 manifest。
- Course 审核默认拒绝外发，必须逐次 `-AllowExternalContent`；Docs 必须显式 `-Files`；`lessons/`、`config/`、`.env`、媒体/模型权重一律排除。
- 审核前后对临时输入目录做 SHA256 校验；快照被修改即 `EXECUTION_FAILED`。

### H.4 状态与退出码

- 执行轴：`NOT_RUN / EXECUTION_SUCCESS / EXECUTION_FAILED`。
- 审核轴：`NOT_RUN / REVIEW_COMPLETED / REVIEW_INCOMPLETE`。
- 退出码：`0` 审核完成（可有 findings）、`1` 契约/范围错误、`2` 隐私或预算拒绝（未调用 Codex）、`3` 执行失败或输出不完整。
- `production_effect: none`；没有 verdict；findings 一律 `unverified`，必须人工复核。
- 预算判定：输入超过 64K 才是 `BUDGET_VIOLATION`（审核不完整）；输出超过 8K 预留只记
  `OUTPUT_OVER_RESERVE` 告警，不否定审核。实际 `turn.completed.usage` 为累计值，已记录。

### H.6 已知限制
