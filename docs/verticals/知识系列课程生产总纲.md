# 知识系列课程生产总纲

- **版本**：v1.0（Draft）
- **日期**：2026-11-10
- **状态**：指导性规范。**不新增 `FR-*` / `NFR-*`，不新增运行时契约，不新增模块、引擎或评分器。**
- **适用**：在 CourseWorkspace 上接入一个新学科 / 知识领域的系列课程（Season → Chapter → Episode）
- **首个实例**：本机 `docs/verticals/economics/经济学系列-第一季生产方案.md`（课程开发内容，不入库）
- **上游**：[PRD.md](../PRD.md)、[ARCHITECTURE.md](../ARCHITECTURE.md)、[课程生产统一契约V1.md](../课程生产统一契约V1.md)、[叙事设计与观众留存规范](../creative/叙事设计与观众留存规范.md)、[多视觉语法生产系统-设计](../architecture/多视觉语法生产系统-设计.md)、[跨学科生产能力矩阵与能力边界规范](../product/跨学科生产能力矩阵与能力边界规范.md)
- **质量基准**：[知识视频质量基准](../知识视频质量基准.md)（本文只定义“怎么接入”，不定义“什么算好”）
- **硬约束**：系列是**编目与叙事**的单位，不是数据模型。集仍是 `lessons/<slug>/`，镜头仍是 `production.yaml` / `storyboard.yaml`，时间仍是帧，证据仍是 `real_data / simulation / schematic`。

> 本文件回答“怎样把一个领域接进现有系统”。具体领域讲什么、先讲什么，写在各自的领域方案里（§13 给出必填清单与模板）。

## 0. 结论先行

1. 知识系列 = 领域内**有先后依赖、可长期连载**的成组课程。它决定先讲什么、后讲什么，**不决定系统怎么跑**。
2. 接入一个领域，只写**一份领域方案**；不改引擎、不加语法、不加评分器、不 fork 品牌。
3. 一集 = 一个 lesson 目录，走现有链路：`validate → director-plan → narration-build → build → quality-gate → producer-run`。
4. 知识来源分**框架层 / 事实层 / 叙事层**，三者不能互相顶替；每个叙事 beat 必须标证据等级。
5. 视觉语法按**镜头的认识对象**选，一集混用多种；既不允许“一集一套模板”，也不允许“一季一套模板”。
6. **版权决定选题能否成立**，在选题阶段核验，不放到发布前补救。

## 1. 层次与术语

| 层级 | 含义 | 落点 | 是否进入运行时契约 |
| --- | --- | --- | --- |
| **Season（季）** | 一条完整的认知路径，10 集量级 | `docs/verticals/<domain>/` 下的季文档、术语表、选题表 | **否**（纯文档） |
| **Chapter（章）** | 季内的知识分组，2–3 集一组 | 季文档的小节 | 否 |
| **Episode（集）** | 最小交付单元，一集一个 lesson | `lessons/<slug>/` | **是** |
| **Shot（镜头）** | 生产、渲染、验收、重渲的第一等公民 | `authoring/production.yaml` 或 `storyboard.yaml` | 是 |
| **Model Asset（知识资产）** | 可参数化、可复用的模型组件 | `CodeVideoStudio/shots/<shot>/`、`ManimSandbox/` | 是（作为镜头源） |

规则：

- 不引入 `series_id` / `season_id` 之类的新主键。集的身份仍是 `lesson_id`，跨集关系靠**文档索引 + 命名**表达。
- 季文档不是大纲的替代品：每集仍有自己的 `outline.md` / `narrative-plan.json`，季文档只负责集与集之间的依赖。
- 领域方案里出现的任何“新增字段”，先问一句：**它能不能落在 `lesson.yaml` / `production.yaml` / `narrative-plan.json` 的现有字段里？** 不能，就先记录到待决问题，不在领域文档里发明契约。

## 2. 内容模型：三层来源与证据等级

### 2.1 三层来源

| 层 | 作用 | 典型材料 | 不能用来做什么 |
| --- | --- | --- | --- |
| **框架层** | 知识骨架、术语一致性、依赖顺序 | 教材、综述、课程大纲、权威百科 | 不能作为事实终点（教材会滞后、会简化、有立场） |
| **事实层** | 数字、事件、参数、法条、测量值 | 统计机构、一手数据集、论文、年报、监管文件 | 不能替代解释框架；单项数字不等于机制 |
| **叙事层** | 入口问题、冲突、案例、生活现象 | 新闻报道、企业公告、个人经历、历史事件 | 不能当作规律证据；单例不能证明一般性 |

规则：

1. 每集至少有一条框架层来源；事实层的每个数字都能回溯到来源、口径、时间点。
2. 叙事层的案例必须**用事实层数据交叉校核**，并标注“这是例子，不是证据”；只有叙述、查不到数据的例子不进正片。
3. 三层混用时，观众要能分辨哪句是模型结论、哪句是观测、哪句是推测。

### 2.2 证据等级

沿用 `narrative-plan.json` 的 `evidence` 枚举，不新增：

| 值 | 含义 | 强制要求 |
| --- | --- | --- |
| `real_data` | 真实测量、统计、一手记录 | 来源 + 口径 + 时间点 + 单位；图表不截取他人成品 |
| `simulation` | 数值模拟 | 规则、初始条件、参数、可复现；不得写成“实验证明” |
| `schematic` | 概念示意 | 旁白/字幕不得暗示它是求解结果 |

硬规则：

- 旁白里出现的任何数字，必须是 `real_data` 且有来源；没有来源的数字不上屏、不上口播。
- 示意动画不得用真实数据的外观（网格、误差棒、置信带）伪装成结果。
- 同一集内混用等级时，画面标注要能区分（数据页有来源条，示意页没有）。

### 2.3 数据资产

数据不是截图，是**带版本的资产**：

- 记录数据集 ID / 表名、取数日期、单位、季节调整与否、地区口径；
- 能落地成本地文件就落地（`lessons/<slug>/assets/data/`），并在 `sources.yaml` 登记；
- 图表一律**自己重绘**，不复用他人图表图像；
- 数据更新导致结论变化时，重渲该集并记录版本。
- **数据必须有解释价值**：每组数据要能回答"它支持哪句主张、不能证明什么"。与机制无关的数字、只为显得严谨而加的图表，一律删；讲机制时，一个有出处的具体案例可能比宏观统计更清楚。
- **数据与主张冲突时改主张**，不改口径、不换样本、不延长区间去凑方向。

## 3. 选题准入

每个选题进制作前必须能回答五问；答不上就不做：

1. 观众熟悉的**现实问题**是什么？（不是术语）
2. 要讲清楚的**一个原理**叫什么？能否一句话命名？
3. 哪个**机制**可以动画/数据/模拟呈现？（画面承担解释，不是装饰）
4. 有**真实案例**能验证或反驳它吗？
5. 它的**边界**是什么——在什么条件下不成立？常见误解是什么？

三类直接拒收：

- **纯术语科普**：没有现实入口，观众不知道为什么要看。
- **不可视化的抽象主张**：画面只能配 PPT，机制无法呈现。
- **事实无法核验的爆点**：为了点击量放弃可追溯性。

选题通过后，`audience` / `promise` / `payoff` 三者写进 `authoring/narrative-plan.json`；写不清就不进入制作（见叙事规范 §7）。

## 4. 集内结构

**六 beat 骨架由 [叙事设计与观众留存规范](../creative/叙事设计与观众留存规范.md) §2 定义，本文件不重定义，只给时间预算。**

| Beat | 作用 | 8–12 min 参考 | 3–6 min 校准片 |
| --- | --- | --- | --- |
| `cold_open` | 现象/矛盾/反直觉，不寒暄 | 0–20 s | 0–12 s |
| `question` | 本集问题 + 为什么值得看 | 20–50 s | 12–35 s |
| `intuition` | 简单例子建立变量与关系 | 50 s–3 min | 35–90 s |
| `mechanism` | 动画/数据/模拟展示因果 | 3–7.5 min | 1.5–3.5 min |
| `test` | 案例、边界、反例、参数变化 | 7.5–10.5 min | 3.5–4.5 min |
| `connect` | 收束成模型 + 迁移 + 下一步 | 10.5–12 min | 4.5–5 min |

规则：

- 表中时间是**预算**，不是门禁。`narrative-validate` 对结构错误判 `fail`，对时间偏差判 `warn`；warning 只说明预算要重估。
- **不为凑时长拆镜头，也不为一个动作硬拖时间。** 长句给长镜头，一句话讲完就切走；没有"必须做满 N 秒动画"这类规则（见 §11 与 D-071）。
- 语速用**实测值**估算，不用稿子自带的估计。本机 VoxCPM2：英文 ≈ 133 词/分钟（0.45 s/词），中文 ≈ 4.4 字/秒；800 词英文稿 ≈ 6 分钟。
- `narrative-validate` 只证明结构，不证明讲得懂；Q2 教学有效性在没有学习者证据时只能是 `INCOMPLETE`。

## 5. 视觉语法：按认识对象选

注册表是唯一事实源：[shared/grammars/visual-grammars.yaml](../../shared/grammars/visual-grammars.yaml)（`course-control grammar-list` 可列出）。语法是**镜头的属性**，不是整片分档。

| 要讲清的认识对象 | 推荐语法 | 典型渲染器 |
| --- | --- | --- |
| 变量之间的连续关系、变换、几何 | `long_take`、`geometric` | Manim、CodeVideo |
| 分布、时间序列、对比、指数 | `data_viz` | CodeVideo（HTML/Canvas/SVG）、ScientificFigures |
| 规则演化、多主体、参数实验 | `simulation` | CodeVideo、Manim |
| 结构、空间、整体形态 | `geometric`（2.5D/3D） | Blender、Motion Canvas |
| 冲击、并列、历史片段 | `montage`、`kinetic_edit` | CodeVideo、Remotion |
| 定义、关键词、结论 | `kinetic_type` | CodeVideo、Remotion |

规则：

1. **主片通常混用两种以上语法**；如果一种就讲得最好，不必凑第二种。语法服务于解释，不服务于多样性指标。
2. 每镜必须声明 `purpose` / `grammar` / `renderer`；`production-validate` 校验渲染器能力。
3. 语法阈值（`long_take` 的 5–16 秒、动作密度、长寿命比例等）是**诊断指标**，不是放行条件。它们用来发现"这一段是不是太空/太碎"，不能用来要求"必须做满几秒动画"。
4. 不新增语法名。现有 7 个覆盖不了时，先写进待决问题，由 `shared/grammars/visual-grammars.yaml` 统一评审。

## 6. 可复用知识资产

**定义**：一个能被多集引用、靠参数改变输出的机制组件。不是一段好看的空镜。

准入六条，缺一不可：

1. **确定性**：`frame(t)` 或 `seek(t)` 是纯函数；同一输入逐帧同结果。
2. **无外部依赖**：不联网、不即时抓数据、不依赖本机路径；随机必须有固定种子。
3. **参数外置**：数据、初值、阈值从输入读取，不写死在画面里。
4. **规格与验收**：`SPEC.md`（讲什么、参数含义、边界）+ `VERIFY.md`（怎么判定它讲对了）。
5. **技术规格**：1920×1080、声明 fps、H.264、无音轨；底部为字幕留出安全区。
6. **许可自有**：资产本身是自制的；引用的数据按 §8 处理。

落点：

| 形态 | 位置 | 适用 |
| --- | --- | --- |
| CodeVideo shot | `CodeVideoStudio/shots/<shot>/` | 曲线、图表、模拟、动态文字（最通用） |
| Manim scene | `ManimSandbox/<project>/` | 几何变换、数学推导 |
| 科学图形 | `ScientificFigures/` | 静态图（先出 SVG/PNG，再由镜头承载） |
| Blender 场景 | `BlenderStudio/scenes/` | 真实空间感、实体演化 |

复用规则：

- **参数化，不复制粘贴**。同一曲线组件供 5 集使用，靠输入数据区分，而不是拷 5 份改常量。
- 资产变更触发受影响集的局部重渲（`producer-affected` / `producer-rebuild`），不整季重做。
- 资产的质量不等于集的质量：组件通过 QC，只能证明画面稳定，不能证明它在某一集里讲对了。

## 7. 角色、审查与语言

### 7.1 角色与独立审查

| 角色 | 负责 | 不许做 | 现有落点 |
| --- | --- | --- | --- |
| Researcher | 来源、事实、口径、证据链 | 替领域专家下结论 | `ingest` / `digest` / `fact-check.md` |
| **Domain Expert（可选）** | 模型、理论边界、反例、学科共识 | 不写稿、不导片（避免自证） | 人工；没有专家时由证据链替代（见硬规则 3） |
| Scriptwriter | 叙事、语言、术语一致性 | 决定事实真伪 | `authoring/script` + `approval.json` |
| Director | 章节、镜头、语法、节奏、版式 | 改内容主张 | `director-plan` / `production-validate` |
| Producer | 订单、预算、交付清单、增量 | 不渲染、不发布 | `producer-run` |
| QA | 内容、技术、审美三类检查 | 不代签发布 | `content-qa` / `media-qc` / `quality-gate` |
| Owner（人） | 投资决策与最终验收 | —— | `RELEASE_APPROVED` 必须人工 |

硬规则：

1. **同一角色不能既生产又签收。** 一个 AI 会话不得同时承担研究、写稿、导演、评价。
2. AI 输出一律是候选：结构化结果必须过程序校验，事实判断必须过人或来源证据（CLAUDE.md 硬约束 4）。
3. **专家不是前置条件，证据是。** 找不到领域专家时，用证据链替代：每条主张有具名来源、关键主张做交叉校核、模型表述标明假设、不确定处直接写不确定。Q1 按证据完整性判定，不按头衔判定。

### 7.2 语言：去 AI 味

本工作区的成片主语言固定为英文：画面文字与旁白用英文；中文是字幕与文章版本，默认不做中文配音。字幕英文在上、中文在下。

目标只有一个：**读起来像一个懂行的人在讲，而不是模型在总结。** 这一条适用于脚本、旁白、字幕、文章、封面文案，也适用于我们自己写的文档。

十条禁令（左边是典型 AI 句，右边是改法）：

| 不要 | 改成 |
| --- | --- |
| “在当今信息爆炸的时代……”、“让我们来看看……” | 直接给现象、数字或冲突，不铺垫 |
| “首先/其次/最后”式的三段骨架 | 按因果与时间推进，不用序号填空 |
| 一段里反复“不是 X，而是 Y” | 一段最多一次，其余直接说 Y |
| “总的来说”、“值得注意的是”、“毋庸置疑” | 删掉；结论只说一次，并带上条件 |
| 每段一个金句、句句对仗 | 允许平淡的过渡句；信息密度优先于漂亮 |
| 形容词堆叠（深刻、巨大、颠覆性、本质） | 换成数字、时间、对比（“成本降了 30%”） |
| 万能动词（赋能、助力、重塑、驱动） | 具体动作（“换了两班工人”、“产线停了 6 小时”） |
| 没有主语的判断句 | 写清谁在判断、依据是什么 |
| 标题与字幕过度对称（四字对四字） | 允许长短不齐 |
| 设问自答连发 | 一集最多两次，其余用陈述 |

六条正面要求：

1. **具体性**：每 30 秒至少一个具体数字、人名、时间、地点或来源。删掉这些之后还成立的句子，通常是空话。
2. **节奏不均**：短句和长句混用；该停就停，不追求每句一样长。
3. **有观点、有归属**：“我认为……因为……”或“某某的研究发现……”，不用无主的“研究表明”。
4. **术语先说白话**：第一次出现给一句人话解释，再给术语。
5. **删一遍**：定稿前删 10% 的形容词与连接词，读起来不会更差。
6. **朗读测试**：读不顺、换气来不及的句子，就是写坏了，回去改。

**主语言优先写，不从另一种语言翻译。** 成片是什么语言，就用那个语言直接写原始稿；辅助语言版本基于同一套知识结构重写，不是逐句翻译。中文逻辑正确，不代表英文叙事自然，反过来也一样。进旁白合成前过五问（出声读）：

1. 像真实母语知识频道的口语吗，还是像论文摘要或翻译稿？
2. 适合朗读吗——一口气读得完、重音落在要强调的词上吗？
3. 有没有源语言式的排比与过度对称（三连词、对仗句、"不是……而是……"连用）？
4. 有没有不必要的专业术语？首次出现能不能用一句白话替代？
5. **第一次听到能懂吗**——让一个只听不看的人复述这一段讲了什么。

字幕可以逐句翻译，但断行、译名与术语必须人工校对并与术语表一致。

边界：

- **不做自动“AI 检测”当门禁。** 检测器不可靠，会把正常句子判成 AI，也会放过真正的模板文；判定权在人。
- 可选做关键词提示（“总的来说”“值得注意的是”），只提示，不阻断。
- 去 AI 味 ≠ 故意口语化、装熟、加俚语；解释的准确性和证据不打折。
- 观察方法：从真实样本提取（用户指定的博主、目标语言的母语节目），逐条记“哪一期/哪个时间点/学到什么”，写进领域的 `references/`；不凭印象概括风格。

## 8. 版权与知识归属

### 8.1 三档许可

| 档 | 典型许可 | 允许 | 不允许 |
| --- | --- | --- | --- |
| **可改编** | 公有领域、CC BY、CC BY-SA（遵守相同方式共享） | 改写、翻译、商用；按许可署名 | 去掉署名、错误标注许可 |
| **受限** | CC BY-NC-*、CC BY-ND | 作为**研究依据**阅读、引用观点与事实 | 改编、翻译、混编进付费课程；复制图表/习题 |
| **保留版权** | 商业出版物 | 阅读、引用观点并注明出处、购买授权 | 复制章节/插图、制作实质性替代原书的改编课程 |

规则：

- 许可证**以官网为准**，在选题阶段核验并记录核验日期；不得凭印象写许可证号。
- 事实与数据可以引用（注明来源与口径）；**表达、结构、图表、习题**不可以复制。
- 引用谁的模型就写谁的名字；自己综合的框架要说明是综合。
- 每集留痕：`sources.yaml`（来源与许可）、`authoring/fact-check.md`（已核实/仅报道/不主张）、片尾或描述区署名。
- 商业化之前先过许可：受限材料不得进入付费产品，也不得成为付费产品的“影子版本”。

### 8.2 原创判定

一集算原创，需要同时满足：自己提的问题、自己组织的结构、自己写的脚本、自己做的图表与动画、观点有归属、案例有出处。缺一项就要在交付记录里说明，不得笼统写“原创课程”。

## 9. 品牌与产品形态

品牌层是单一色板 + 固定 lockup，见 [品牌与片头片尾](../品牌与片头片尾.md) 与 `shared/design-tokens/brand.json`。

规则：

1. **领域不得 fork 品牌。** 不新建第二套 hex、不在片头片尾塞系列名（现有品牌契约已禁止系列名/集号进片头）。
2. **品牌帧不承载内容分类标签。** 新领域不需要新增 `content_kind` 或类别名；品牌画面只有 lockup、单集英文标题、致谢与 CTA，内容归属由标题和封面承担（见 D-070）。
3. 频道归属（同频道 / 新频道 / 子品牌）是人的决策，影响封面体系、Shorts 签名、发布节奏；决定前不要先设计视觉。
4. 领域配色只从 [配色方案-学科适配](../evaluations/配色方案-学科适配.md) 的色族里选，一门课一个色族，不中途换纸面。

## 10. 产品族与内容漏斗

| 层 | 形态 | 作用 | 关键约束 |
| --- | --- | --- | --- |
| Discovery | Shorts 30–90 s 竖屏 | 获取新观众 | **独立脚本**，不从长片裁切（CLAUDE.md 硬约束 11） |
| Authority | 主片 8–22 min | 建立专业认知 | 六 beat + 质量门禁 |
| Retention | 文章 / 讲义 / 深读 | 建立长期关系 | 与主片同源，可展开不能矛盾 |
| Monetization | 系统课程 / 练习 / 交互模型 | 商业化 | 不是把视频打包收费 |

规则：

- 同一份研究可以支撑多种形态；但 **Shorts 必须有独立的问题与结论**。
- 长视频是知识资产的发布形式之一，不是资产本身；资产要能被重新组织成课程、讲义、练习。
- 付费产品必须有免费内容没有的东西：学习目标、前置关系、练习、测验、可交互模型、综合项目。

## 11. 生产节奏与阶段门

| 阶段 | 目标 | 退出条件 | 证据 |
| --- | --- | --- | --- |
| **P0 样片（pilot）** | 验证这条内容线能不能成立 | 一集完整成片通过 `quality-gate` + 人工看片 | `final/build-report.json`、质量报告、签字 |
| **P1 校准** | 修叙事、语速、字幕、视觉密度 | 第二集不再重复第一集的问题 | 对比记录、返工清单 |
| **P2 批量** | 稳定产出 | 每集独立验收通过 | 每集独立证据，不复用上一集结论 |
| **P3 复盘** | 决定继续/调整/停止 | 指标与成本复盘 | 留存、评论质量、单位成本 |

规则：

1. **先做一集，再批量。** 没通过样片就排 10 集，是把风险放大 10 倍。
2. **共享资产，不共享验收。** 模板、组件、术语表可以复用；每集的 `quality-gate`、看片、签字必须独立。
3. **两周一集的节奏优先于“周更”。** 质量不可压缩，产能只能靠资产库提升。
4. 时长、镜头数、语速都是计划值，以实测旁白与成片为准。

**真正要守住的只有三条**（其余指标都是它们的代理）：

1. **把问题讲明白。** 观众能复述本集的问题、机制和结论，且结论有适用条件。
2. **把画面做好。** 画面承担解释，不是装饰；静帧单看也成立；没有占位块、死帧、模板式转场。
3. **把交付做硬。** 文件能解码、音画对齐、字幕正确、证据齐全、来源可查。

与之冲突的就让路：镜头时长、动作密度、语法分档、评分卡都是**诊断工具**，不是发布条件。一个 3 秒切完讲得更清楚的镜头，不需要为了 5 秒下限拖长；一场 30 秒的连续演化如果每一秒都在讲，也不因为"平均镜头 8–12 秒"被拆掉。现有 `quality-gate` 的 grammar 层可用 `--waive` 逐条豁免并写明理由——这是机制，不是例外。

## 12. 与现有系统的映射

| 阶段 | 命令 | 产物 | 门禁 |
| --- | --- | --- | --- |
| 立项 | 建 `lessons/<slug>/` | 目录 | `validate` 必需文件 |
| 来源 | `ingest` / `digest` | `sources.yaml`、`source-digest.*` | 无来源不就绪 |
| 候选稿 | `brief` / `outline` / `script` / `content-draft` → `author-accept` | `authoring/*` | `approval.json` sha256 |
| 叙事 | `narrative-validate` | `quality/narrative.json` | 结构 `fail` 阻断 |
| 导演 | `director-plan` | `director_plan.json` | 时长/覆盖/引擎/来源 |
| 镜头契约 | `production-validate` | plan | 语法注册表 + 渲染器能力 |
| 节拍 | `beats-validate` | `authoring/beats.yaml` | 覆盖、时长、配色对比度 |
| 旁白 | `narration-build` | `narration.wav` + meta | 文本哈希锁定 |
| 字幕 | `subtitles-build` / `subtitles-accept` | `subtitles.srt` | 人工 accept |
| 构建 | `build` | `final/*.mp4` | `verdict=pass`，无 skipped |
| 混音/QC | `audio-mix` / `media-qc` / `quality-report` | 母版、`quality/` | 无 `FAIL` |
| 分层门禁 | `quality-gate` | hard / grammar / metrics / human | 人工签核才算可发布 |
| 内容审查 | `content-qa review` | `review/` | 候选意见，非事实裁定 |
| 交付 | `producer-run` | `build/<slug>/producer/` | `awaiting_approval` 是正常终态 |

补充：

- 全量回归：`.\scripts\check.ps1` 必须打印 `check ok`。
- 镜头驱动片型（短切、模拟、混合）用 `compose.mode: shots` + `authoring/production.yaml`；页面驱动片型用 `storyboard.yaml`。
- 当前已知边界：shots 模式端到端只验到 30 秒；分块捕获只测到 12 秒；示意/模拟的语义正确性没有自动判定。这些边界写进每集的风险记录，不写成通过。

## 13. 新垂直领域接入清单

### 13.1 必填十二项

一份领域方案（`docs/verticals/<domain>/…`）必须包含：

| # | 项目 | 必填内容 | 通过条件 |
| --- | --- | --- | --- |
| 1 | 定位与受众 | 面向谁、看完获得什么能力、不面向谁 | 能一句话说清，且不是“所有人” |
| 2 | 语言与产品形态 | 主语言/辅语言、`content_kind`、长/短形态配比 | 已核对 `brand.json` 的内容形态 |
| 3 | 知识骨架 | 学习阶段、术语表、集与集的依赖关系 | 前置关系无环；每集都有前置 |
| 4 | 来源与许可 | 框架/事实/叙事三层各 3–8 条，许可证结论 | 每条有链接与核验日期；受限材料只做研究依据 |
| 5 | 第一季选题表 | 集数、标题、核心问题、概念、主语法、资产、数据 | 每集能回答 §3 五问 |
| 6 | 时长与叙事预算 | 每集目标时长（预算）、beat 时间表、语速估算 | 与六 beat 骨架兼容；时间只作预算，不作验收 |
| 7 | 视觉语法映射 | 认识对象 → grammar → renderer | 只用注册表里的语法 |
| 8 | 资产库 | 名称、形态、参数、证据等级、验收 | 满足 §6 准入六条 |
| 9 | 配色与图表规范 | 色族、发散色、轴/单位/来源规则 | 对比度过门禁；不红绿发散 |
| 10 | 角色与证据责任 | 谁做事实核验、交叉校核与最终签发 | 有证据链要求；专家可选，证据必需 |
| 11 | 验收口径 | 五条质量防线在本领域的额外检查 | 不降低现有门禁 |
| 12 | 节奏、指标与商业化边界 | 发布频率、看的指标、免费/付费分界 | 指标只观察，不冒充质量 |

### 13.3 领域方案不得做的事

- 不得新增镜头语法、质量门禁、评分器或运行时字段；
- 不得在 `shared/design-tokens/` 之外另起视觉系统；
- 不得把领域术语写成系统概念（例如用“弹性”给某个模块命名）；
- 不得用“领域特殊”为理由跳过 `narrative-validate` / `quality-gate` / 人工签字；
- 不得把受限许可材料写成“参考”后实际改编。

## 14. 反模式

- 把一本书按章节改写成视频（教材摘要机）。
- 一季所有集用同一套模板，只换文案与数据。
- 为了视觉效果把模型讲错，或为了讲全把每集塞成一门课。
- 用模拟画面冒充真实数据；用单例案例冒充规律。
- 让一个 AI 角色同时做研究、写稿、导演、评价。
- 用结构校验通过代替教学质量结论；用构建 `pass` 宣布“课程合格”。
- 先设计封面与视觉，再决定受众与许可。
- 把“每 90 秒一个闭环”当硬指标机械执行。
- 用“必须做满几秒动画”“每 4 秒必须有一个动作”之类的秒数/帧数约束代替内容判断。
- 领域文档里发明新契约，再把实现补丁塞进系统。
