### 2.5 参考创作者

用户指定参考：小Lin说、硅谷101、老周横眉，以及同量级的头部知识博主。

用法与边界：

- 只提取**具体方法**，不收"风格标签"。写"他常用反直觉数字开场"没有用；要写清"第 3 分钟用哪一个数字、放在哪一句旁白之后、观众此刻知道什么、不知道什么"。
- 每条观察必须来自**实际看片**，记录"哪一期 / 哪个时间点 / 观察到了什么"，写进 `docs/verticals/economics/references/<creator>.md`；不凭印象总结。
- 参考语言与主产品语言不一致时（中文博主 vs 英文成片），只借结构，不借句式；英文表达另找英文样本校准。
- 参考不构成验收标准：不能因为"像某个博主"就判通过，也不能因为"不像"就判失败。

**方法提取问题单**（每个参考对象逐条回答；答不上就说明还没看够）：

1. 开头 15 秒怎么建立问题——先给现象、先给数字，还是先给一个错误常识？
2. 反直觉信息在第几分钟引入？引入前观众被安排在什么立场？
3. 抽象概念与真实案例怎么切换——先案例后概念，还是先概念再回填案例？
4. 图表出现在屏幕上时，旁白在做什么：读数、解释轴、还是讲图外的因果？
5. 什么时候切镜（信息切换/场景变化），什么时候保持连续（观众正在跟踪因果关系）？
6. 结尾怎么收——新增一层理解、给出边界，还是直接重复结论？

问题单的答案写进参考文件，并与自己的成片对照；能迁移的是这六条，不是"某某味儿"。

脚本语言遵守总纲 [§7.2 去 AI 味](../知识系列课程生产总纲.md)：先具体后概括、删形容词与连接词、朗读测试；英文稿以英文母语样本校准，不把中文博主的句式直译过去。

## 3. 来源与许可

### 3.1 教材类

| 材料 | 许可（记录于 2026-11-10，**使用前须在官网复核**） | 结论 |
| --- | --- | --- |
| CORE Econ《The Economy 2.0》 | 公开标注 CC BY-NC-ND 4.0（非商业、禁止演绎） | **只作研究依据**；不改编、不翻译、不进入付费课程 |
| OpenStax《Principles of Economics 3e》 | 公开标注 CC BY-NC-SA 4.0 | **只作研究依据**；商业使用需另行确认，不复制图表/习题 |
| Mankiw《Principles of Economics》 | 商业出版，保留版权 | 只读、只引用观点并注明；不复制章节 |
| Harford / Landsburg / Levitt & Dubner | 商业出版，保留版权 | 只学方法；案例须自行核验并改写 |
| Heilbroner / Piketty | 商业出版，保留版权 | 思想史与分配专题的研究依据 |

硬规则：

1. 许可证号以官网为准，逐条核验并记录核验日期；不得凭印象写。
2. 受限材料不得成为付费课程的"影子版本"（同结构、同顺序、同案例的改写也算）。
3. 图表、习题、章节结构一律自建。

### 3.2 数据源

| 来源 | 用途 | 引用要求 |
| --- | --- | --- |
| FRED | 美国宏观、利率、就业、通胀序列 | 记 series ID、取数日期、单位、频率 |
| World Bank Data | 跨国发展、收入、人口、贸易 | 记指标代码与年份口径 |
| IMF Data | 全球宏观与金融 | 记数据集与版本 |
| OECD Data | 生产率、工资、教育、产业 | 记指标与统计口径 |
| Our World in Data | 长期历史趋势 | 记原始来源（OWID 是二次汇编） |
| BLS | 美国就业、工资、CPI 分项 | 记表号、季节调整与否 |

规则：

- **数据优先，但数据要有解释价值**：能用数据说的，不用形容词说；能用具体案例说清的机制，不必硬塞宏观统计。判定标准是"这组数据是否直接支撑当前这句主张"，不是"这集有没有数据"。
- **数据不能为了满足规则而存在**：与机制无关的漂亮数字、为了显得严谨而加的图表，一律删。讲机会成本时，一个来源清楚的个人或企业选择案例，比一组宏观统计更能说明机制。
- **数据与主张冲突时改主张**，不改数据口径、不换样本、不延长区间去凑想要的方向。
- 每个数字带四件套：**来源、口径、时间点、单位**；缺一件不上屏。
- **案例必须交叉校核**：叙事层的例子（某公司、某年、某政策）至少用一个独立数据源验证它确实如此，并写清"这个例子证明了什么、没证明什么"；只有媒体叙述、没有数据的例子不进正片。
- 重绘图表，不截取官网图；来源条放在画面内（页面底部或角标）。
- 跨国对比先统一口径（购买力平价、季节调整、统计年份），口径不一致就不做同图对比。
- 数据快照落在 `lessons/<slug>/assets/data/`，并在 `sources.yaml` 登记 sha256。
- 交叉校核记录写进 `authoring/fact-check.md`：主张 / 来源 A / 来源 B / 是否一致 / 不一致时怎么表述 / **数据与核心主张的关联性**（这组数据直接证明了什么，不能证明什么）。
- 数据只解释它覆盖的范围：一国的数据不说成全球规律，一段时期的规律不说成永久规律，平均值不说成每个人都如此。

安排理由：

- E01–E04 从个人经验进入市场；E05–E07 从企业进入宏观；E08–E10 收束到技术与分配。

## 5. 每集结构与时间预算

默认 8–12 分钟，目标 10 分钟；英文稿按 133 词/分钟估算 ≈ 1300 词（允许 1050–1600）。

| Beat | 时间 | 内容 | 证据等级 |
| --- | --- | --- | --- |
| `cold_open` | 0:00–0:20 | 一个具体现象或数字反差，不寒暄 | `real_data` 或 `schematic` |
| `question` | 0:20–0:50 | 本集问题 + 看完能回答什么 | — |
| `intuition` | 0:50–3:00 | 日常例子建立变量与关系，先白话后术语 | `schematic` |
| `mechanism` | 3:00–7:00 | 曲线/数据/模拟展示因果链 | `real_data` + `simulation` |
| `test` | 7:00–9:30 | 真实案例、反例、边界、参数变化 | `real_data` |
| `connect` | 9:30–10:30 | 收束成模型 + 局限 + 下一集接口 | `schematic` |

内容标准（每集至少满足）：

1. 一个观众能感知的现实问题；
2. 一个能一句话命名的原理；
3. 一个可以用动画或数据展示的机制；
4. 一个真实案例，并说明它证明了什么、没证明什么；
5. 一条明确的边界或常见误解（"模型在什么条件下不成立"）。

时长纪律（**没有**"必须播满 N 秒"的规则）：

- 表里的时间是**预算**，用来估稿长和排期，不是验收条件；讲完了就结束，没讲完就加长。
- 不为凑 10 分钟重复表达；短于 8 分钟就按短课处理并在计划里说明。
- 不为满足某个镜头时长把一段解释切碎，也不为一个动作硬拖时间；镜头长度由"这一句话需要多少画面"决定。
- 每集镜头数量只是估算（按平均 10–12 秒，以实测旁白为准），不作为生产指标考核。
- `narrative-plan.json` 的 beat 时间与最终旁白偏差 >10% 时，改计划，不改结论。

### 5.1 英文 Master Script 与语言验收

**顺序**：英文稿是原始生产稿，中文版本基于同一套知识结构**重写**，不是逐句翻译。

理由很实际：中文逻辑正确，不代表英文叙事自然。逐句翻译会留下中文式排比、过长定语、并列堆叠和多余的抽象名词，读起来像翻译稿，不像一个人在讲。

每集英文稿进 `narration-build` 之前过五问（人工，出声读）：

1. 像真实英语知识频道的口语吗？还是像论文摘要或翻译稿？
2. 适合朗读吗——一口气读得完吗？重音落在要强调的词上吗？
3. 有没有中文式排比与过度对称（三连词、对仗句、"不是……而是……"连用）？
4. 有没有不必要的专业术语？首次出现能不能用一句白话替代？
5. **第一次听到能懂吗**——找一个人只听不看，让他复述这一段在讲什么；复述不出来就是没写清楚。

执行：

- 五问不过就不进旁白合成。改稿几分钟，重录加重剪是几十分钟。
- 英文定稿后才做中文版本；中文不逐字直译，保留信息与逻辑，按中文表达重写。
- 字幕（英→中）是辅助翻译，允许逐句，但断行、译名、术语必须人工校对并与术语表一致。
- 结论写进 `authoring/voice-check.md`：五问各自的判断 + 改了哪些句子。

## 6. 视觉体系

### 6.1 语法映射

按总纲 §5，语法是镜头属性。本季的固定用法：

| 认识对象 | 语法 | 渲染器 | 备注 |
| --- | --- | --- | --- |
| 曲线、均衡、存量流量 | `data_viz` | CodeVideo | 轴、单位、来源条必须有 |
| 选择、取舍、空间关系 | `geometric` | Manim / CodeVideo | 用面积与位移表达"代价" |
| 规则演化、多主体、份额变化 | `simulation` | CodeVideo | 标 `simulation`，写规则与参数 |
| 历史、价格标签、场景切换 | `montage` | CodeVideo / Remotion | 不用廉价素材堆砌 |
| 定义、结论、关键数字 | `kinetic_type` | Remotion / CodeVideo | 逐词强调只用于一个主张 |
| 连续因果链 | `long_take` | Manim | 只在该讲推导时用 |

禁止：全片一张白底 PPT 加浮动箭头；也禁止把每集做成同一种曲线动画。

### 6.2 配色

- 色族：`qiushan`（秋山设色，focus = 赭石）或 `editorial`（浅色编辑风）；**一门课只用一个色族**。
- 涨跌/正负用**蓝—橙发散**，不用红—绿（色盲高风险）。
- 纸面 70%、墨色 20%、重点 10%；一页最多两个语义色。
- 数据图：顺序数据用单色相色阶，不用彩虹色图；先转灰度检查层次。
- 对比度门禁沿用 `beats-validate`：正文 ≥7:1、图形 ≥3:1、次要文字 ≥4.5:1。

### 6.3 图表规范

1. 轴有标签与单位；无来源的数据不上屏。
2. 时间序列标出取数日期；不画"未来预测"除非明确标为情景假设。
3. 同一图内比较的序列必须同口径；口径不同就拆图。
4. 指数化要写基期（=100）。
5. 3D 柱状、透视饼图、面积夸张一律不用。

## 8. 首集详细方案：E01

**Why Is Everything So Expensive? / 为什么感觉什么都越来越贵？**

目标 10:30，英文约 1350 词。

| Beat | 时间 | 内容 | 画面 | 证据 |
| --- | --- | --- | --- | --- |
| `cold_open` | 0:00–0:18 | 同一张购物清单，十年前的 100 元和今天的 100 元 | 商品逐项扫码，总价溢出 | `real_data`（CPI 分项） |
| `question` | 0:18–0:50 | 价格为什么会变？谁在决定？为什么"统计通胀"和体感不一样？ | 三个问句逐个出现 | — |
| `intuition` | 0:50–3:00 | 稀缺 → 必须取舍 → 价格是取舍的信号 | 选择集收缩、机会成本面积 | `schematic` |
| `mechanism` | 3:00–6:40 | 需求移动、供给冲击、成本与生产率、货币与预期，四条通道依次演示 | 供需曲线移动 + 分项数据条 | `real_data` + `schematic` |
| `test` | 6:40–9:30 | 分项对比：电子产品更便宜、服务更贵、住房权重高；体感与统计差异的三个原因（消费结构、地区、替代） | 分项指数小倍数图 | `real_data` |
| `connect` | 9:30–10:30 | 价格是信息也是分配；模型有边界；引向 E02"免费并不免费" | 收束图 + 下集卡 | `schematic` |

数据需求（开工前落地）：

- 一个经济体的 CPI 总指数 + 4–6 个分项，近 10–20 年，月度，注明取数日期与是否季节调整；
- 至少一个"长期下降"的分项（如消费电子）与一个"长期上涨"的分项（如服务/住房），用于反差；
- 不承诺跨经济体同图对比；若做，先统一口径并单独说明。

边界与反模式（写进 `narrative-plan` 与 `fact-check.md`）：

1. 不把 CPI 当"生活成本"本身：它是加权平均，个体结构不同。
2. 不做"通胀=货币超发"的单一归因；四条通道都要出现，并说明各自适用条件。
3. 不预测下期数据。
4. 不用"以前 5 毛钱能买……"式的怀旧叙事替代机制解释。
5. 住房、医疗、教育的统计处理在不同经济体不同，跨国对比必须先说明。

验收：

- `validate` / `narrative-validate` 通过；`production-validate` 通过；
- `build` 的 `verdict=pass`，无 skipped；
- `quality-gate` hard/grammar 通过；
- 人工完整看一遍：字幕遮挡、语义错误、节奏；
- Q1 看证据链：每条主张有来源与交叉校核（§10.1），缺一项记 `INCOMPLETE`；
- 英文稿通过 §5.1 五问，结论记录在 `authoring/voice-check.md`。

## 10. 角色与证据责任

| 角色 | 谁 | 负责 | 边界 |
| --- | --- | --- | --- |
| Owner | 用户 | 定位、投资、最终验收 | 唯一能签 `RELEASE_APPROVED` |
| Researcher | Claude（候选）+ 人工复核 | 来源、数据、口径、交叉校核 | 输出是候选，不是事实裁定 |
| Scriptwriter | Claude（候选）+ 人工定稿 | 叙事、语言、术语一致 | 不决定事实真伪 |
| Director | `course-control director-plan` + 人工 | 镜头、语法、节奏、版式 | 不改内容主张 |
| QA | `content-qa` / `media-qc` / `quality-gate` | 技术、结构、证据链 | 不代签发布 |

### 10.1 没有专家也可以做，但不能没有证据

系统内没有经济学专家，这**不构成阻塞**：不是每个领域都能配到专业审校人，要求"先有专家"等于不做事。

替代方案是把责任落到证据上：

1. **每条事实主张有具名来源**：机构、数据集、报告、论文，能打开、能核对；口播里出现的判断必须能指回一条来源。
2. **关键主张交叉校核**：至少两个独立来源，或一个一手数据 + 一次独立复核；不一致时写清差异，不取"看起来对的那个"。
3. **模型表述标明假设**：说"在完全竞争假设下"，而不是说"市场就是这样"。
4. **不确定的就说不确定**：证据不足的争议点，说明"目前没有共识/数据不足"，不用四平八稳的句子蒙过去。
5. **数据有解释价值**：每组数据写清它支持哪句主张、不能证明什么；数据与主张冲突时改主张，不改口径。
6. **证据留痕**：`sources.yaml` + `authoring/fact-check.md`（主张 → 来源 → 校核结论 → 关联性），发布前由 Owner 抽查。

Q1 的判定随之改变：**看证据链是否完整，而不是看有没有专家头衔**。证据完整、可复核、口径一致 → 可以记 `PASS`；缺来源或缺交叉校核 → `INCOMPLETE`，补齐后再判。

## 11. 商业化路径与分界

| 阶段 | 内容 | 目的 |
| --- | --- | --- |
| 1 影响力 | YouTube 主片 + Shorts + 文章 | 建立"能把现实问题讲清楚"的认知 |
| 2 学习产品 | 知识地图、练习题、交互模型、专题讲义 | 验证是否有人愿意为系统学习付费 |
| 3 完整课程 | `Economics: Understanding How the World Works` | 系统课程 + 案例 + 测验 |
| 4 专题课 | 技术经济学、产业竞争、AI 与工作 | 与工程背景结合 |

分界（付费产品必须有、免费内容没有的）：

- 学习目标与前置关系；
- 章节讲义与阅读清单；
- 练习题与测验；
- 可交互模型（可调参数、可对比）；
- 综合项目。

不得：把免费视频打包卖；把 NC 许可材料做成课程主体；用"课程"名义售卖未经验证的观点。

## 12. 指标、风险与边界

### 12.1 只观察、不冒充质量的指标

| 指标 | 看什么 |
| --- | --- |
| 前 30 秒留存 | 开场是否建立兴趣 |
| 平均观看时长 / 百分比 | 解释是否撑得住 |
| 章节流失点 | 哪个机制讲崩了 |
| 评论质量 | 观众是否开始用概念解释现实，而不只是夸画面 |
| Shorts → 主片转化 | 短内容是否带来有效观众 |
| 单位成本 | 每集工时、渲染时长、返工率 |

### 12.2 风险

| 风险 | 影响 | 对策 |
| --- | --- | --- |
| 没有领域专家 | 判断可能偏，但不阻塞 | 证据链替代：具名来源 + 交叉校核 + 标注不确定（§10.1） |
| 教材许可（NC/ND） | 付费课程的法律风险 | 只作研究依据；结构、案例、图表全部自建 |
| 数据口径不一 | 结论错误 | 四件套 + 同口径才同图 |
| 模型过度简化 | 误导 | 每集写边界与反例；不做规范判断 |
| 政治/意识形态争议 | 品牌风险 | 陈述假设与证据，不站队；争议题不放进第一季 |
| 视觉同质化 | 观众疲劳 | 按认识对象选语法；不为多样性凑语法 |
| label 移除不彻底 | 旧配置或代码仍渲染类别名 | 按 §1 改动点一次改完；label 出现即报错 |

### 12.3 明确不做的

- 不做市场预测；讨论数据变化时只讲已发生的事实与机制，不猜下一步；
- 不讲"经济学终极真理"，不把模型当现实；
- 不把相关性写成因果；
- 不用单国数据代表"全世界"；
- 不做书籍解说搬运，不复制教材结构。
