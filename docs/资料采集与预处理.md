# 资料采集与预处理（PDF / YouTube）

- **版本**：v0.1
- **日期**：2026-11-11
- **状态**：流程已建立并做过单点验证；尚未批量采集。
- **适用**：课程研发所需的教材、论文、标准、技术报告与 YouTube 讲课。
- **边界**：原始 PDF、视频、音频、字幕与转录只在本机，不进仓库、不上传。

> 所有来源统一进入本机 Docling 资料区：原始件留在原处或 `input/`，处理后 Markdown 与 JSON 在 `output/`。CourseWorkspace 只消费处理结果。

---

## 1. 角色与位置

| 角色 | 位置 | 负责 |
| --- | --- | --- |
| 视频下载与转写 | `<YOUTUBE_B_ROOT>` | yt-dlp、人工/自动字幕、faster-whisper 兜底 |
| PDF 与资料区 | `<DOCLING_ROOT>` | PDF 版面识别、分页 Markdown、JSON、图片、质量报告、来源索引 |
| 课程生产 | 本仓库 | 读取 Markdown/JSON，做 claim、脚本、动画、成片 |

本机实际路径只放在环境变量或本机配置里，不写入本文档、脚本或提交文件。

## 2. 目录

```text
<DOCLING_ROOT>/
├── input/
│   └── youtube/
│       └── <video_id>/
│           ├── metadata.json            # yt-dlp 原始元数据
│           ├── transcript.original.vtt  # 原语种字幕原件（人工或自动）
│           └── <video_id>.<ext>          # 仅无字幕时下载的音频，供 Whisper 兜底
├── output/
│   ├── <source_id>/                     # PDF / 文档资料包
│   │   ├── document.md                  # 带页标记的整书 Markdown
│   │   ├── document.json                # 版面、页码、bbox、表格、图注
│   │   ├── pages/                       # 每页一个 Markdown
│   │   ├── pages.txt                    # 连续页标记，供 KnowledgeStudio
│   │   ├── manifest.json                # 输入哈希、页数、质量摘要、交接命令
│   │   └── source.json                  # 原始路径或来源 URL
│   ├── youtube/
│   │   └── <video_id>/
│   │       ├── metadata.json            # 元数据副本
│   │       ├── transcript.clean.md      # 带时间戳、段落化的 Markdown
│   │       ├── transcript.segments.json # 逐 cue 时间戳与文本
│   │       ├── chapters.json            # YouTube 章节；没有则空
│   │       └── source.json              # URL、语言、字幕来源、状态
│   └── catalog.json                     # 所有来源的索引
```

规则：

- 本地 PDF **不移动**。Docling 用原路径读取，`source.json` 记录原路径与 SHA-256。
- 视频不保存整片，除非没有字幕、需要 Whisper；只保留元数据、原语种字幕和处理结果。
- 原始字幕永远保留，AI 整理只写新的 Markdown/JSON，不覆盖原件。

## 3. PDF

```powershell
# 先看页数、文本层、是否需要 OCR
<DOCLING_ROOT>\.venv\Scripts\docling-bridge.exe inspect "<LOCAL_PDF>"

# 转换到 output/<source_id>/；PDF 留在原处
<DOCLING_ROOT>\scripts\convert.ps1 `
  -InputPath "<LOCAL_PDF>" `
  -SourceId <source_id> `
  -Title "<title>" `
  -Profile balanced
```

转换后先看 `report.md` 的 `review_pages`、空页、短页、表格与图注；`validate` 通过后再用：

```powershell
<DOCLING_ROOT>\scripts\import-to-course.ps1 -Bundle <DOCLING_ROOT>\output\<source_id> -Mode knowledge
```

PDF 的交付物是 `document.md`、`pages/`、`document.json` 与 `manifest.json`；课程引用页时以 `pages/` 和页码为准。

## 4. YouTube

```powershell
<YOUTUBE_B_ROOT>\.venv\Scripts\python.exe <YOUTUBE_B_ROOT>\scripts\collect_knowledge.py `
  "<YOUTUBE_URL>" `
  --docling-root "<DOCLING_ROOT>" `
  --lang auto
```

流程：

1. 读取元数据，确认视频 ID、标题、频道、日期、时长、章节与可用字幕。
2. 原语种字幕：人工字幕优先；没有人工字幕用自动字幕。
3. 两者都没有时，才下载音频并用本地 faster-whisper 转写；`--no-whisper` 可关闭兜底。
4. 保留原始 VTT/SRT 与逐 cue 时间戳；生成 `transcript.clean.md` 与 `transcript.segments.json`。
5. 写入 `output/youtube/<video_id>/source.json`，并更新 `output/catalog.json`。

规则：

- 只取原语种字幕；不下载 YouTube 的中文自动翻译。中文版本另做，不覆盖原文。
- 不做 AI 总结、改写或“润色”后冒充原讲话；清理只限去标签、去重复标记、按停顿分段。
- 没有字幕且不启用 Whisper 时，`source.json` 记为 `blocked_no_transcript`，不伪造文本。
- 频道、日期、URL、语言、字幕来源全部进 `source.json`，便于以后核对。

## 5. 索引

`output/catalog.json` 由 `build_catalog.py` 扫描生成：

```powershell
<DOCLING_ROOT>\.venv\Scripts\python.exe <DOCLING_ROOT>\scripts\build_catalog.py
```

每条记录至少包含：

| 字段 | 含义 |
| --- | --- |
| `kind` | `document` 或 `youtube` |
| `source_id` | 资料包或视频 ID |
| `title` | 标题 |
| `origin` | 本地 PDF 原路径或视频 URL |
| `status` | `ready` / `blocked_no_transcript` / `incomplete` |
| `files` | Markdown、pages、segments、manifest 等相对路径 |

`catalog.json` 只在本机，不提交。

## 6. 课程里怎么用

- 教材/论文：读 `output/<source_id>/pages/` 的指定页，claim 绑定页码；再用 `span-check` 做结构校验。
- 视频：读 `transcript.clean.md` 的段落或 `transcript.segments.json` 的时间点；引用时写 URL + 时间戳 + 视频 ID。
- 视频只作研究、事实核验与讲法参考；成片讲稿、动画与图表自制，不整段照搬转录或画面。
- 同一观点至少用教材/论文或第二个来源交叉校核；单条视频不构成规律证据。
- 视频画面若需引用，按该领域方案的图像规则单独标注出处与许可。

---

## 7. 版权与隐私

- 教材、论文、视频与转录均可能受版权保护；本机保存只用于研究、核验与课程研发。
- 不把整段转录、字幕文件或视频画面直接放进公开仓库、文章或成片。
- 视频里出现的个人信息、内部链接、凭据不进入资料包；必要时先脱敏。
- 需要公开引用时，逐条核对来源许可与合理使用范围。
