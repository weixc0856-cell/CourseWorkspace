# 锁定与失效（Picture / Dialogue Lock）

- **日期**：2026-11-12
- **状态**：可用。P4 完成（[工业化生产流程 V2.0](v2/工业化生产流程V2.0-建议稿.md) WP-4）。
- **命令**：`course-control lock`、`course-control lock-status`

---

## 1. 锁是快照，不是禁令

锁记录的是"某次人工认可时，东西长什么样"：谁批的、批的是哪一版画面、哪一版旁白、哪些资产。之后改不改由人决定，锁不阻止任何修改。

它要解决的问题只有一个：**改了上游，别让下游继续消费旧版本而没人发现。**

## 2. 两个锁

### Picture Lock

```text
build/<slug>/locks/picture.lock.json
```

| 记录内容 | 来源 |
| --- | --- |
| 画面单元与每个文件的 SHA-256 | 与 animatic 同一套时间线解析 |
| 镜头表版本（路径 + SHA-256 + schema 版本） | `storyboard.yaml` |
| 每个镜头的设计指纹 | `shot-sheet` 编译结果 |
| 镜头依赖的场景文件哈希 | 按引擎根解析 |
| 资产引用与哈希 | `asset_refs` |
| 审核记录 | `--approved-by` / `--note` |

检查项：`pictures`（每个单元都有画面）、`sheet_version`（v1 镜头表没有设计指纹，记 warn）、`assets`（引用的资产都存在）、`review_recorded`（没写签核人时 warn）。

### Dialogue Lock

```text
build/<slug>/locks/dialogue.lock.json
```

| 记录内容 | 来源 |
| --- | --- |
| 脚本哈希 | `authoring.narration.script.json` |
| 旁白音频哈希与时长 | `build/narration/narration.wav`、`narration.meta.json` |
| Voice Bible / Lexicon 的 id 与哈希 | meta 的 `assets` 块 |
| 逐段测量：起止、时长、原文哈希、送 TTS 的文本哈希、命中的词典条目 | meta 的 `segments` |
| 字幕对应关系 | SRT cue 起点落在哪个旁白段落 |

检查项：

| 检查 | 判据 | 失败含义 |
| --- | --- | --- |
| `script_matches_narration` | meta 记录的脚本哈希 == 当前脚本哈希 | 脚本改过、旁白没重录，字幕和混音会用旧声音 |
| `narration_file` | wav 存在 | 元数据还在，音频没了 |
| `assets_recorded` | meta schema ≥ 3 | 旁白早于声音资产体系，声线无法追溯 |
| `subtitles_mapped` | 每条字幕都落在某个旁白段落的区间内 | 字幕与旁白时间线错位 |

## 3. 失效规则

`lock-status` 把当前哈希与锁里的哈希逐项比对，每处差异都带出需要重新检查的下游：

| 变更 | 下游 |
| --- | --- |
| 脚本 | 旁白、字幕、时间线、混音 |
| Voice Bible | 旁白、字幕、混音 |
| Lexicon | 旁白、字幕、混音 |
| 旁白音频 | 字幕、时间线、混音 |
| 镜头表 | 镜头表编译、导演计划、animatic、受影响镜头 |
| 单个镜头设计 | animatic、受影响镜头 |
| 场景文件 | 受影响镜头 |
| 资产 | 受影响镜头 |
| 画面单元 | 时间线、最终合成 |
| BGM | 混音、音频 QC |
| 合成配置 | 合成结果、全片 QC |

规则表在 `CourseControl/src/course_control/locks/dependencies.py: RULES`，与本文同源，改一处即可。

## 4. 用法

```powershell
# 打锁（默认两个都打）
course-control lock --lesson <slug> --approved-by wayne --note "看完第二遍"
course-control lock --lesson <slug> --picture
course-control lock --lesson <slug> --dialogue

# 看漂移
course-control lock-status --lesson <slug>
course-control lock-status --lesson <slug> --json
```

`lock-status` 输出示例：

```text
picture: locked at 2026-11-12T10:32:34+00:00
  changed: picture:page-005  → re-check timeline, final_compose
  affected: timeline, final_compose
dialogue: locked at 2026-11-12T10:32:34+00:00
  no drift
```

有漂移或无法核对时退出码 1。

## 5. 一处强制执行

`subtitles-build` 在读旁白元数据后会核对脚本哈希：如果旁白是从另一版脚本合成的，直接 `blocked`（退出码 3），提示先重跑 `narration-build`。

这是"修改旁白后字幕不会继续消费旧版本"的唯一自动拦截点。其余下游靠 `lock-status` 报告，由人决定是否重做。

## 6. 实测（2026-11-12）

真实课程 `a01-why-cars-need-aerodynamics`：

| 项 | 结果 |
| --- | --- |
| 打锁 | picture + dialogue 两个锁文件写出；画面 24 个单元全部有文件 |
| 警告 | 镜头表是 v1（无设计指纹）；旁白 meta 是 schema 2（早于声音资产）——都是真实状态，不掩盖 |
| 字幕对应 | 全部 cue 落在旁白段落内，`subtitles_mapped` pass |
| 立即复查 | `lock-status` 两个锁都 `no drift` |
| 单元测试 | `test_locks.py` 12 例；CourseControl 全量 559 例通过 / 7 跳过 |

## 7. 还没做的

- **不自动重建**。锁只报告失效范围，`producer-rebuild` 仍是显式命令。
- **没有把 producer 指纹并进来**。`producer/rebuild.py` 按镜头做增量 diff，锁按画面单元和资产做快照，两者暂时各算各的；P4 之后可以把 producer 的 `ShotFingerprint` 直接写进 picture lock。
- **交接物不止这些**：合同、授权、版权账本仍由制片层负责，锁不覆盖。
