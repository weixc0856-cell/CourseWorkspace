## 1. 使命

建设 Wayne Wei 的个人媒体与知识内容生产系统：持续发现值得研究的问题，取得可靠来源，建立事实、证据与论点之间的关系，把复杂问题转成清晰叙事，按内容选择视觉表达，生成自然旁白，完成制作、质量检查与多平台交付，并沉淀可复用的知识、视觉资产与品牌资产。

不是“AI 视频生成器”，也不是“PPT 自动生成器”。系统最终只保护三件事：

1. **把问题讲明白。**
2. **把画面做好。**
3. **把交付做硬。**

自动化服务于这三件事，而不是让这三件事服务于自动化。

## 2. 定位与内容边界

品牌：**WAYNE WEI**。

定位：一个拥有工程背景、正在用软件和 AI 理解技术、商业与社会变化，并持续公开创造的人。

不把频道做成纯技术频道。内容可以在工程、AI、经济、商业、社会之间移动，但保持同一套判断方式：先看事实与证据，再拆机制，最后才给观点。

长期主题（不是每期都覆盖）：

1. AI 与技术变革。
2. 软件工程、编程与 AI 工具。
3. 工程技术、汽车工业与科学原理。
4. 经济、商业与社会运行机制。
5. 普通人如何理解技术变化，以及如何参与创造新的机会。

内容原则：不夸大 AI、不制造焦虑、不为流量牺牲事实、不过度简化、不写空洞励志、不把 AI 输出包装成专业结论、不假装在所有领域都是专家。

表达风格：Human, Clear, Rational, Practical, Curious.

品牌理念：**Build Public. Explain Clearly. Create Value.**
中文：不要只做时代变化的旁观者，要努力成为更好未来的创造者。

口号不逐条重复；出处只进画面 source 行与片尾。

## 3. 内容产品分层

同一套基础设施，五种产品形态。**分层由“要解决什么问题、需要多深的证据链”决定，不由时长单独决定。**

| 层级 | 时长 | 用途 | 叙事要求 | 视觉要求 |
| --- | --- | --- | --- | --- |
| A. Micro Explainer | 30–90 s | 一个概念、一个反常识事实、一个技术问题、一个观点 | 开头立刻建立问题；只解决一个点 | 一个主画面；允许静态；不堆背景 |
| B. Short Explainer | 90–180 s | 科学原理、AI 技术、软件工程、经济现象、工程知识 | 完整解释链：问题 → 机制 → 证据 → 结论 | 有真正的机制演示；结论可复述 |
| C. Research Brief | 3–6 min | 单篇论文、AI 技术新闻、产品技术分析、行业变化 | 研究问题 → 证据 → 机制 → 适用条件与局限 → 影响 | 证据大图 + 数据图；来源可追溯 |
| D. Deep Lecture | 10–30 min | 系统专题、技术课程、经济与商业知识、完整问题拆解 | 完整知识结构；连贯叙事；不靠扩写短视频凑时长 | 结构化板书为主，关键机制动画为辅 |
| E. Course Series | 按课程规模 | 系统教学、专业知识体系、长期知识产品 | 课程级架构；章节连续；每集有教学目标 | 统一页面系统；跨集资产复用 |

**产品层不是标签。** 每层对应不同的时长窗口、叙事模块、视觉密度和验收问句；`product_tier` 一旦声明，`preflight` 与 `validate` 按时长窗口检查，超出即报错，不靠人工记忆。

### 3.1 叙事模块

短视频与中长视频使用可组合模块，不强制五段式：

- `hook` / `context` / `mechanism` / `evidence` / `implication` / `conclusion`
- 每个模块可带：文本、旁白、证据引用、视觉事件、时间信息、转场。
- 模块可以重复、省略或重排；缺少 `hook`、`mechanism` 或 `conclusion` 时，检查器给出 review 项，不静默通过。

### 3.2 多平台

- 16:9 横屏是知识内容母版；B 层短视频同时支持 9:16 竖屏独立脚本。
- 竖屏不是横屏裁边：重新构图、重排文字安全区、重定位重点对象、重定字幕字号。
- `aspect` 与 `safe_area` 是产品层字段，不是渲染时的临时补丁。

## 4. 视觉品牌：共同气质，不同表达

统一的只有设计语言，不是所有视频的布局和动画形式。

| 内容方向 | 视觉家族 | 主要表达 |
| --- | --- | --- |
| 知识解释 | `editorial_science` | 清晰、简洁、逻辑优先；纸白底、结构化板书 |
| 工程演示 | `engineering_studio` | 空间、物理、真实感；三维与工程剖面 |
| 商业财经 | `editorial_science` + 数据图层 | 数据、案例、因果关系；图表与来源并置 |
| 观点叙事 | `deep_space` 或高对比编辑版 | 故事、情绪、思考；允许更长静止与更强字幕 |

- 令牌唯一来源：`shared/design-tokens/tokens.json`、`themes.json`、`brand.json`。
- Remotion、Manim、Blender、CodeVideo 读同一套令牌或由它导出的副本；副本必须有检查，不能手抄第二份。
- 品牌组件（标识、章节名、标题、片尾、进度）必须可显示、可隐藏、可换位置与尺寸；禁止所有画面强制 HUD。

## 5. 统一内容与证据链

```text
Observation → Research → Evidence → Claim → Narrative → Script
→ Visual Plan → Audio → Rendering → Quality Assurance → Delivery → Feedback
```

证据必须可追溯到来源：Source ID、原始链接、文档名、页码/段落、图表引用、原文结论、脚本引用位置、证据与论点的关系。

四类陈述严格区分，不得混写：

1. **DOCUMENTED**：原始资料明确说明的事实。
2. **REPORTED**：可靠报道陈述、但未见原始文件的内容。
3. **INFERENCE**：根据资料进行的合理推断。
4. **CLAIM**：创作者自己的观点或尚未验证的假设。

LLM 只能产出候选，不得把推断写成原文事实，不得生成没有来源的实验数据、性能数据或研究结论。

## 6. 视觉事件层

`Visual Event` 是内容与渲染之间的调度单元，不是动画合同。

必填字段：`event_id / start_s / duration_s / purpose / visual_type / renderer / asset_refs / evidence_refs / narration_ref / transition / layout / metadata`。

`visual_type` 至少覆盖：Text、Static Image、Chart、Diagram、Motion Graphic、Paper Figure、Video Footage、2D Animation、3D Animation、Manim Scene、Blender Scene。

允许一张图独立出现、长时间保持同一画面、多素材组合、全屏三维、以及完全不使用动画。**禁止强制每隔固定时间插入动画。**

渲染器通过统一适配器接收任务、校验输入、加载资产、执行渲染、输出标准产物并返回状态；渲染器之间不得直接依赖内部实现。

## 7. 完成标准（系统的验收口径）

不以代码行数、组件数量、自动化率或接入工具数量衡量。以下每一项都必须有可复现产物，不能只交接口。

| 核心能力 | 完成标准 | 证据 |
| --- | --- | --- |
| 品牌视觉 | 多引擎实际渲染一致 | 同一令牌在 Remotion / Manim / Blender 的实际帧或渲染件；令牌漂移检查通过 |
| 短视频 | 完整样片可播放 | 90–180 s 成片，含旁白、字幕、音画同步；媒体探测通过 |
| 长视频 | 完整样片可播放 | 10–30 min 成片；分段渲染与拼接记录 |
| 证据追踪 | 可追溯到原始来源 | 每条 claim 有 source/页码/图表；脚本引用位置可回查 |
| 视觉匹配 | 图示与旁白一致 | 每个视觉事件声明 purpose 与 claim；图文一致性检查 + 人工抽检 |
| 音频系统 | 分段生成和时间同步 | 分段音频、实测时长、字幕时间、音画同步报告；单段可重生成 |
| 局部重渲染 | 改一个片段不必全部重做 | 按 shot/segment 渲染并命中缓存的报告；未受影响单元不重跑 |
| 交付系统 | 自动检查并输出完整产物 | `release-check` 三态 + `package` + `package-verify`；缺项记 INCOMPLETE |

**skip ≠ pass。** 未执行的检查记 `not_run` / `INCOMPLETE`，不计入通过。

## 8. 工程约束

1. **先审查再施工。** 以实际代码与命令结果为依据，不把设计文档里的能力当作已实现。
2. **不重造上游。** 已有的研究、证据、知识库、字幕、质检、交付能力直接复用。
3. **不做投机抽象。** 每个阶段必须留下真实产物和可验证的验收结果；后续模块未开发时，不为它提前铺空接口。
4. **分阶段提交。** 每阶段：跑相关测试 → 更新文档 → 记录决策 → 独立提交。
5. **不静默降级。** 缺能力输出 `blocked` / `INCOMPLETE`，不用 mock 或空实现冒充完成。
6. **不伪造验收。** 不为通过修改测试预期、跳过检查或拿旧产物顶替。
