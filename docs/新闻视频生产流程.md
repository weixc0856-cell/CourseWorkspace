## 0. 立项与时长估算

```powershell
# slug：小写连字符，不含年份与裸数字
lessons/<slug>/
```

★ **先测语速再定稿**。本机 VoxCPM2 实测：英文 ≈ 133 词/分钟，中文 ≈ 4.4 字/秒，综合 RTF ≈ 9–10×（12 秒音频约 3 分钟合成）。
即 `预计秒数 = 英文词数 × 0.45`。一份 800 词的英文稿 ≈ 6 分钟；不要相信稿子自带的“预计 5 分钟”。

```powershell
# 单段试音，确认音色与语速（服务会自动拉起，用完见 §11 停止）
uv run --project CourseControl course-control narrate --lesson <slug> `
  --segment-id probe --text "<一段 60–80 词的原稿>" --out build/<slug>/probe/rate.wav
```

无旁白的系列（`BEYOND THE HEADLINES`）跳过试音，按系列 bible 的 beat 数估时长。

## 1. 研究与证据（先做，做不完不开工）

```powershell
uv run --project CourseControl course-control ingest --lesson <slug> --source <URL> --id S1
uv run --project CourseControl course-control digest --lesson <slug>
```

开工前必须写完 `authoring/fact-check.md`，结构固定为证据矩阵 / 时间线 / 反方证据 / 数字与口径 / 本片明确不主张 / 未入库来源（模板见 [新闻与调查报道标准.md](新闻与调查报道标准.md) §1.3）。

- 优先级：官方声明 / 监管与司法文件 / 财报 > 通讯社时间线 > 单篇快讯。
- **原始来源优先**：找到文件本体；拿不到原件时写明“未取得原件，转引自 <媒体>”。
- **时间线交叉验证**：每个因果句至少两个独立时间戳；不同时间的事不拼成因果。
- **反方证据检索**：主动找能推翻本片叙事的材料，结果写进「反方证据」；没找到也写检索范围与结论。
- ★ 抓取失败的源（如 403）**不写进 sources.yaml**，在 `authoring/fact-check.md` 记录“未入库及原因”。
- ★ PDF 用 `pdftotext` 落地成文本再 `ingest --source <本地txt>`，然后手工把 `sources.yaml` 的 `origin` 改回原始 URL、`extractor: pdftotext`。
- 同时写清：哪些是已核实事实、哪些只是报道、哪些是本片推论、本片明确不主张什么。

## 2. 叙事：六幕与页面切分

单一事实源：`build/<slug>/build_authoring.py`（生成 `narration.script.json` 与 `lecture_notes.md`），`authoring/narrative-plan.json` 声明 beat。

- 六幕：Cold Open → Context → Discovery → Mechanism → Counterargument → Implications；按 `cold_open` / `question` / `intuition` / `mechanism` / `test` / `connect` 落到 beat（映射表见 [新闻与调查报道标准.md](新闻与调查报道标准.md) §2）。
- 逐幕自查：这一幕结束后，观众能说出上一幕还说不出的什么？答不出就删或合并（信息 ≠ 认知）。
- 每页 30–55 秒；每段 30–55 词（中文 55–120 字）。
- ★ `lecture_notes.md` 的 **逐字口播** 必须等于该页 segments 用单个空格连接（`check_script_against_notes` 逐字比对）。
- ★ `narration.script.json` 的 `page.target_seconds` 必须 > 0（模型校验 `gt=0`）。
- `style` 只给 TTS，形如 `(calm, broadcast news delivery)`，每页只在首段给。

## 3. 幻灯片与讲师手册

- `slides.md`：英文正文 + `<div class="zh-sub">` 中文副标题；每页 ≤4 条要点，卡片式页面控制在 3 张以内（首期第 4 页 3 张卡就溢出过）。
- `lecture_notes.md` 每页四要素：`时长预算` / `动画切入` / `技术核查` / `逐字口播`。**技术核查要写“不许说什么”**（例如“不得写成已确认泄密”）。

## 4. 视觉导演：按信息类型选语法

六种语法与各自禁区见 [新闻与调查报道标准.md](新闻与调查报道标准.md) §3。落地要求：

- 画面变化由信息触发（人物出现 / 关系建立 / 资金流动 / 争议出现 / 结论变化），不是按秒数换镜。
- 一集混用两三种语法是正常的；不为多样性凑语法，不为“高级感”上 3D。
- 数据镜头只用真实数据点；系数、插值、推算必须在画面或字幕里标口径。

```powershell
# 镜头工程目录：仓库契约示例 CodeVideoStudio/shots/<shot>/；本机内容根的实际工程在 engines/code_video/shots/<slug>/
<镜头工程>/{SPEC.md,VERIFY.md,index.html,main.js,package.json}
```

- 1920×1080、30 fps、H.264、无音轨；`window.DUR` / `window.seek(t)` / `window.READY`，每帧是 `t` 的纯函数。
- ★ 合成时 cutaway 是**整屏替换**幻灯片（`presentation=cutaway`），所以动画要留出自己的标题区。
- ★ 画面底部预留 **~150 px** 给烧录字幕，所有文字内容结束在 y≈900 以内。
- ↑ 该尺寸可被多期复用，做完就提交进镜头工程目录（只提 5 个文件，`package-lock.json` 与 `node_modules` 不入库）。

## 5. 声音设计：四层，先写再混

```powershell
uv run --project CourseControl course-control sound-design --lesson <slug> --workspace .
```

- 四层：旁白 / 音乐 / 音效 / 环境声（字段仍是五轨，见 [声音导演层.md](声音导演层.md)）；规则与例子见 [新闻与调查报道标准.md](新闻与调查报道标准.md) §4。
- 音乐分段设计，关键证据处 `duck` 或 `silence`；音效只在画面真的变化时出现。
- 音乐不再被内容类型拦截（2026-11-14，D-097）；许可与电平照常检查，成片的交付质量是唯一门禁。
- 无旁白系列没有 Voice 层，用排版节奏承担；在系列 bible 声明。

## 6. 旁白

```powershell
uv run --project CourseControl course-control narration-build --lesson <slug>
```

- 按 `text_sha256` 缓存：改几句只会重合成那几段，但仍要几分钟——尽量一次改完。
- ★ 合成完再改 `script`/`notes` 会让 `narration.meta.json` 的源哈希过期（V-30），必须**再跑一次**（全缓存命中，很快）。

## 7. 审批与导演计划

```powershell
uv run --project CourseControl course-control validate --lesson <slug>
uv run --project CourseControl course-control narrative-validate --lesson <slug>
uv run --project CourseControl course-control director-plan --lesson <slug>
```

★ 每次改动 `script` / `lecture_notes` / `outline` 之后都要刷新 `authoring/approval.json` 的 sha256，否则 `narration-build` 直接拒绝（“script is not approved”）、`validate` 报 V-33。

★ `director-plan` 的两条硬规则：
1. `outline.page.visual_kind` 必须路由到已启用的引擎（`title/slide/recap → remotion`，`canvas/infographic → code_video`，`diagram → manim`）。只启用 `code_video` 时，静态页要写成 `slide` / `recap`。
2. 每页必须有 `source_refs`；`no_source` 字段导演层不识别。

## 8. 双语字幕

```powershell
uv run --project CourseControl course-control subtitles-build --lesson <slug> --no-strict
uv run --project CourseControl course-control subtitles-accept --lesson <slug>
```

- 只支持 **英文 → 中文**；中文口播要另做（本期未做）。
- ★ `subtitles-build` 的 `--no-strict` 只降级为 warning，`verify` 的 V-31 仍按严格政策判。所以超阈值的 cue 要**把边界后移**（≤0.2 s，文本不动），改 `bilingual.draft.json` 后重新 accept。
- ★ 中文断行按 15 字硬切会切断词。构建后对 `zh_lines` 做一次按标点/词边界的重排，残留的几处手工指定。
- 字幕强调重点，不逐字复刻旁白；色彩处理服从 [新闻与调查报道标准.md](新闻与调查报道标准.md) §5。

## 9. 构建与验收

```powershell
uv run --project CourseControl course-control build --lesson <slug>
```

阶段：validate → capture_slides → render:code_video → collect → compose → burn_subtitles → verify。
合格线：`final/build-report.json` 的 `verdict=pass`，无 skipped / not_run / fail。

程序通过不等于专业通过。发布前按 [新闻与调查报道标准.md](新闻与调查报道标准.md) §6 逐项打分：100 分制 ≥ 75 才发布，研究与事实准确性 < 16/20 直接不发布；并回答双验收问题（关掉旁白画面是否成立，打开旁白逻辑是否完整）。

## 10. 响度与 QC

```powershell
uv run --project CourseControl course-control audio-mix --lesson <slug>
uv run --project CourseControl course-control media-qc --lesson <slug>
uv run --project CourseControl course-control quality-report --lesson <slug>
```

- 新闻片现在允许音乐层（2026-11-14 起）。`audio-mix` 对无 BGM 的课程做单遍 `loudnorm=I=-16`，产出 `final/course-video-mixed.mp4`——**这才是交付母版**。
- 有音乐时混音仍用手工 `ffmpeg` 试混到 cue sheet，直到 `audio_mix` 消费 `sound_design.json`。sidechain 6–8 dB 是起点。
- `media-qc` 的 `freeze` 对信息图类 cutaway 会误报（局部运动低于 0.2% 阈值）；判假阳性并记录，不放宽检测器。
- ASR 未配置时 `speech_match` 恒为 INCOMPLETE：字幕与语音一致性**没有机器证据**，如实写进交付记录。

## 11. 内容复核与收尾

```powershell
uv run --project ContentQA content-qa review --lesson <slug>
uv run --project CourseControl course-control producer-run --lesson <slug>
```

- ★ ContentQA 只读 `lessons/<slug>/sources.yaml`（根目录），且每条只取 `excerpt` 前 800 字。摘录要覆盖被核查的句子，否则会大面积 `needs_human_review`。
- 无来源的技术常识（GPU 序列号、遥测字段）与作者判断，统一写进 `lessons/<slug>/quality-waivers.md` 做人工裁定，不改自动报告。
- 交付物：`final/course-video-mixed.mp4`（母版）、`course-video-captioned.mp4`（未归一）、`course-video.mp4`（无字幕）、`final/build-report.json`、`quality/`、`producer/`；最终交付包在 `deliver/<slug>/`。
- 发布前必读 `fact-check.md` 的「反方证据」与「本片明确不主张」，逐条确认画面没有违背。
- `producer-run` 的 `delivery_status=awaiting_approval` 是正常终态：发布由人签。

★ **谁启动谁停止**：`narration-build` / `narrate` 会拉起 50000 的 VoxCPM2 服务；收尾用 `course-control tts-status` 确认，空闲时停掉。
