# 课程质量模型（Course Quality Model）

日期：2026-11-13
性质：**验收标准**，不是新的 CI 门禁，也不是新的自动化模块。

## 1. 为什么需要它

现有质量能力分散在 `ContentQA`、`course-control quality-certificate`、`docs/课程生产交付物规范.md`、`docs/知识视频质量基准.md` 与各生产层文档里。它们回答的是“这一步有没有按契约完成”，不回答“这集课值不值得看”。

这个模型把“值不值得看”拆成八个维度，每个维度给出**验收问题**、**现有程序能查什么**、**必须由人判断什么**。目的是拿一集真实课程逐项过，而不是继续增加自动化。

## 2. 八个维度

### 01 知识质量 Knowledge Quality

- 验收问题：重要结论有来源吗？公式、数据、定义准确吗？有没有把相关说成因果、把推测说成事实？结论的适用条件和边界交代了吗？
- 程序可查：`authoring/source-digest.json`、`approval.json` 的 hash 链；outline 每页必须有 `source_refs` 或显式 `no_source`；`course-control content-root` / `separation` 保证证据路径可解析；`ContentQA` 的引用复核。
- 人工判断：结论是否真的被来源支持；推理是否成立；边界条件是否被写出。
- 缺口：从“来源”到“画面上的那句话”的逐句映射仍然靠人。TRACEABILITY 只到模块级。

### 02 教学设计 Learning Design

- 验收问题：学完会什么？前置知识是什么？概念按什么顺序递进？有没有案例、反例、练习？
- 程序可查：brief 的 objectives 与章节映射；导演层 `teaching_qa` 与章节目标；叙事规范里 A/B 证据类型标注。
- 人工判断：递进是否成立；练习是否真的检验理解而不是复述定义。
- 缺口：没有“练习与迁移”的产物。讲义与练习属于维度 06。

### 03 叙事与编辑 Story & Editorial

- 验收问题：开头提出的问题在结尾被回答了吗？每次切换有表达目的吗？有没有不必要的重复？某段是否讲得过久？
- 程序可查：`narrative-validate`（六段骨架、Shorts 时长与竖屏）；导演层章节/镜头时长窗口；`plan-audit`。
- 人工判断：节奏、重复、问题是否闭环。
- 缺口：镜头切换的**动机**没有结构化记录；视觉设计层的 `keyframes.change` 是目前最接近的字段。

### 04 视觉导演 Visual Direction

- 验收问题：每个镜头有明确的视觉主体吗？有前后层吗？运动是变换还是入场？关掉旁白还值得看吗？
- 程序可查：`course-control visual-design`（焦点贯穿、层次、运动类型、文本密度、安全区、连续性）；`layout` 校验；`palette_gate` 对比度。
- 人工判断：构图是否舒服、视觉重心是否正确、三帧之间是否真的在演进。
- 缺口：跨引擎主题（Manim / Blender / Motion Canvas 仍读各自常量）；设计有效性尚未用 A/B/C 样片验证。

### 05 声音导演 Audio Direction

- 验收问题：旁白清楚吗？音乐为什么在这里进、在这里退？音效是否对应真实画面动作？有没有该静音的地方？
- 程序可查：`course-control sound-design`（许可、内容类型的 BGM 策略、音效是否由画面触发、密度、最长连续音乐、响度/峰值目标）；`audio_plan` 的许可与电平；`audio_mix` 的 sidechain 与 loudnorm。
- 人工判断：听感、语气是否合适、混音是否让旁白始终优先。
- 缺口：`music[]` / `sfx[]` 还没落成 `audio_plan` 可消费的 cue；环境声没有素材库。

### 06 学习配套 Learning Materials

- 验收问题：讲义、术语表、参考资料、练习、知识地图是否齐备并且与视频一致？
- 程序可查：`docs/课程交付清单模板.md` 的清单覆盖；交付包清单。
- 人工判断：讲义是否帮助复习而不是逐字稿；练习是否可判分。
- 缺口：**这一维度目前基本没有产物**。这是最明确的空白。

### 07 观众体验 Audience Experience

- 验收问题：标题说清观众能得到什么吗？封面能在 3 秒内建立主题吗？简介交代了内容与适用人群吗？章节标记、字幕、双语质量如何？
- 程序可查：字幕 QC、`narrative-validate` 的 Shorts 规则、系列 `project.yaml` 的分集组织。
- 人工判断：标题/封面的吸引力；字幕可读性。
- 缺口：没有观看留存数据回流，也没有“观众在哪里退出”的反馈闭环。

### 08 工程交付 Production & Delivery

- 验收问题：同样输入能重新生成吗？改一段内容是否不必重做整集？素材来源与许可清楚吗？坏帧、静音、字幕错位能自动发现吗？
- 程序可查：`scripts/check.ps1` 全量回归；`locks/` 的 Picture / Dialogue Lock 与失效映射；`producer-affected` 的增量重建；`quality-certificate`；`deliver/` 清单；`separation` 的仓库边界。
- 人工判断：最终签收。
- 已有：`quality/media_qc.py` 覆盖解码、黑帧/冻帧、静音、字幕结构；有 ASR 对齐报告时还能核旁白与画面。
- 缺口：逐句同步只在对齐报告存在时可核；人工签收仍是唯一的发布判据。

## 3. 工程质量不等于课程质量

- **工程质量**：可复现、可追溯、可自动检查。CI 全绿说明这批文件没有坏，不说明这集课讲明白了。
- **课程质量**：必须靠理解、审阅、试听、实际观看判断。

**CI 通过不是发布标准。** 任何一集在 `check.ps1` 全绿之后仍然需要逐项走完下面这张表。

## 4. 单集验收表

复制到 `<内容根>/projects/<系列>/reviews/<slug>-acceptance.md`，逐条写结论与证据（时间点、截图、文件路径）：

```markdown
# <slug> 验收

| 维度 | 结论 | 证据 | 未解决 |
| --- | --- | --- | --- |
| 01 知识质量 | pass / fail / blocked | 来源清单、引用抽查 | |
| 02 教学设计 | | 目标、递进、练习 | |
| 03 叙事与编辑 | | 开头问题与结尾回答的时间点 | |
| 04 视觉导演 | | design_review.md、无声观看记录 | |
| 05 声音导演 | | sound_review.md、试听记录 | |
| 06 学习配套 | | 交付清单 | |
| 07 观众体验 | | 标题/封面/字幕 | |
| 08 工程交付 | | check.ps1 输出、锁与增量 | |

未解决项合计：__ ；是否可发布：__
```

规则：

- 任何一维 `fail` 都不能发布；`blocked` 必须写明缺少什么（凭据、模型、素材、人工）。
- 证据必须是可定位的：文件路径、命令输出、时间点。**skip ≠ pass**。
- 允许某一维不适用于本集（例如 Shorts 没有讲义），但要在表里写“不适用 + 原因”，不能留空。

## 5. 优先级

| 优先级 | 建设内容 | 原因 |
| --- | --- | --- |
| P0 | 知识准确性与证据追溯 | 讲错了，其余都白做 |
| P0 | 教学设计与知识递进 | 讲完不等于学会 |
| P0 | 叙事与编辑 | 决定观众看不看完 |
| P1 | 视觉与声音导演 | 决定质感；本层已落地，待 A/B/C 验证 |
| P1 | 学习配套 | 从“一个 MP4”变成“一套可复习的知识产品” |
| P1 | 成片与发布质量 | 决定能不能交付 |
| P2 | 观众反馈分析 | 形成下一版的输入 |

## 6. 如何用

1. 拿一集已经做完的真实课程，按第 4 节过一遍。不要先改系统。
2. 把每一条 `fail` 记录成问题，而不是直接补自动化。
3. 只有当同一个问题在两集以上重复出现，才考虑把它变成程序检查。
4. 新增检查时回到本模型：它属于哪个维度？程序能查，还是只能人看？

这条路线和 [知识视频质量基准](知识视频质量基准.md) 一致：先定义什么叫好，再决定用代码支持哪一部分。
