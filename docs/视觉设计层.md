# 视觉设计层（Visual Design Layer）

日期：2026-11-13
代码：`CourseControl/src/course_control/design/`
命令：`course-control visual-design`

## 1. 定位

导演层决定一个镜头**为什么存在**（章节、时长、引擎、旁白落点）；视觉设计层决定观众**看到什么**：艺术方向、blocking、三个关键帧、运动、连续性。它夹在导演计划和渲染引擎之间，输出一份引擎无关的设计。

它不新增动画引擎，不新增质量门禁，也不改 CourseControl 的主调度。设计是渲染之前的一步，和 [动画视觉导演规范](动画视觉导演规范.md) 的 `AnimationDirection` 是同一件事的细化：方向文件说“这个镜头要表达什么”，设计文件说“画面怎么组织”。

## 2. 为什么版式和配色不够

版式模板（`title_intro` / `two_column` / `process_flow` / `principle_diagram` / `formula_derivation` / `data_chart` / `code_demo` / `summary`）解决的是**东西放在哪**：区域、安全区、容量。

它不解决：

- 谁是这一个镜头的视觉主体；
- 主体怎么变，变化本身说明了什么；
- 有没有前后层，观众先看哪里；
- 三个关键帧之间对象是否还在同一个位置；
- 运动是“元素出现”还是“关系改变”。

同样一套配色和模板，可以做出编辑设计，也可以做出会动的 PPT。**颜色统一不等于画面有设计感。**

## 3. 一个镜头记什么

```json
{
  "art_direction": { "theme": "editorial_science", "family": "geometric",
                     "atmosphere": "exact, diagrammatic, slightly cold", "contrast": "balanced" },
  "composition": {
    "focal_object": "query_key_value",
    "focal_point": [0.35, 0.47],
    "negative_space": "right",
    "hierarchy": ["query_key_value", "support", "label"],
    "depth_layers": [
      { "id": "bg", "role": "background", "contrast": "quiet", "content": "the page tone" },
      { "id": "subject", "role": "subject", "contrast": "balanced", "content": "the one object" },
      { "id": "fg", "role": "foreground", "contrast": "quiet", "content": "labels and evidence" }
    ]
  },
  "keyframes": [
    { "id": "start", "at_s": 0.0, "objects": [ ... ] },
    { "id": "turn",  "at_s": 66.0, "objects": [ ... ] },
    { "id": "end",   "at_s": 118.5, "objects": [ ... ] }
  ],
  "motion": { "primary": "values change along one row, then propagate into the aggregate",
              "secondary": "labels follow the object they name", "camera": "slow push in",
              "end_hold_s": 1.5 },
  "continuity": { "persistent_objects": ["query_key_value"], "carries_from": "shot_002" },
  "beats": [
    { "at_s": 0.0,  "kind": "reveal",    "action": "the query enters" },
    { "at_s": 22.4, "kind": "transform", "action": "each key is scored against it" },
    { "at_s": 47.1, "kind": "highlight", "action": "the weighted sum settles" }
  ]
}
```

**页面不是镜头。** 导演层的 `shot_XXX` 在 deck 模式下是一整页（90–135 秒），而仓库的 beat 契约（`direction/beats.py`）把**一个镜头定义为 5–16 秒、间隔不超过 4 秒**。三个关键帧只能锚定页面的首、中、尾，中间必须由 `beats[]` 排满：每个旁白段落至少一次画面变化。派生时按旁白分段时刻生成；没有旁白稿时按 6–12 秒节拍生成。这一条不满足，设计层会直接报 `design.no_beats`（error）。

四类视觉能力（几何 / 工程 / 编辑 / 电影化）不是新的语法，而是 `art_direction.family`：它决定要不要中景层、要不要环境声、运镜靠不靠得住。同一集可以切换：

- 边界层 → 工程；
- 速度剖面 → 几何；
- 不同车型风阻 → 编辑；
- 尾流涡结构 → 电影化。

## 4. 派生草稿与授权设计

`authorship` 只有两个值：

- `derived`：由镜头、outline、版式区域确定性推导出来的草稿。它保证每个镜头都有 blocking、运动和三个关键帧，但措辞和对象是从标题与 claim 里取的，不是设计决策。
- `authored`：来自 `<内容根>/lessons/<slug>/authoring/visual-design.yaml`，顶层字段整体替换派生结果（`shot_id`、`duration_s` 不可改）。

```yaml
schema_version: 1
shots:
  shot_003:
    concept: attention weights become visible as area before any number is named
    art_direction:
      theme: editorial_science
      family: geometric
      atmosphere: quiet, exact, one accent at a time
      contrast: balanced
    composition:
      focal_object: attention_matrix
      ...
```

派生结果可以直接跑起来看，但不要把它当成交付设计。评审报告会把“全部是派生”写成一条 info。

```text
├── boards/shot_XXX.svg         # 每镜头 start / turn / end 三帧 + 层次 + 焦点
├── index.html                  # 按镜头顺序的看板（直接浏览器打开）

```

看完板的方式：按镜头顺序打开 `index.html`，先看构图，再看下面的检查。**设计评审的目的是在写动画代码之前发现“这一帧很空”或“三帧其实是同一帧”。**

## 6. 检查项（不是门禁）

| 规则 | 级别 | 拦什么 |
| --- | --- | --- |
| `design.focal_drifts` | error | 焦点对象没有贯穿三个关键帧，观众会丢失身份 |
| `design.reads_as_slide` | error | 单层 + 只入场运动 + 无辅助对象，结果就是会动的 PPT |
| `design.entry_only` | warning | 主运动是淡入/出现，而不是变换 |
| `design.depth_flat` | warning | 长镜头只有背景和主体，没有前中后 |
| `design.no_camera_motive` | warning | ≥6 s 的镜头，相机静止且内部无变化 |
| `design.text_heavy` | warning | 单帧标签超过 14 个词 |
| `design.out_of_safe` | warning | 对象越出安全区 |
| `design.overlap` | warning | 辅助对象被主体遮住超过三分之一 |
| `design.no_hold` | warning | 结果没有停留，观众读不完 |
| `design.no_beats` | error | 超过 20 秒的页面没有至少两次画面变化 |
| `design.page_not_shot` | warning | 页面超过 beat 契约的 16 秒；提醒按 beats 渲染而不是一个长镜头（文档级一条，不逐镜头刷屏） |
| `design.beat_gap` | info | 两次变化之间超过 4 秒，画面会“钉住” |
| `design.derived` | info | 这个镜头还是草稿 |
| `design.continuity_break` | warning | 相邻镜头没有共享对象 |

这些规则拦的是**已知的坏模式**，不是好设计。通过全部检查的镜头仍然可能很平。最终的判断是渲染出来、关掉旁白看一遍。

## 7. 与引擎的交接

设计是引擎无关的，引擎保留自己的表现力：

- Manim：用 `Transform` / `Create` 实现 turn 帧，不用淡入替换变换；
- Blender：相机动机与景别从 `motion.camera` 与 `shot_size` 取，材质和灯光不因统一主题而降级；
- Motion Canvas / Remotion：按 `keyframes.at_s` 排时间线，标签在对象之后到达。

主题（`shared/design-tokens/themes.json`）是事实源。目前已接通的只有 code_video（镜头声明主题时写出 `theme.json`）；Manim / Blender / Motion Canvas 仍读各自的常量，这是下一步的跨引擎适配，不在本层解决。

## 8. 边界

- 本层不做抽帧验收关卡（D-047）。看板是设计评审材料，不是验收门禁。
- 派生设计不做语义理解：它不知道“Query 先进入画面”比“左边放 Query”更好。需要这种判断时，写 `authoring/visual-design.yaml`。
- 设计的有效性必须用成片验证：同一段 30–60 秒内容，做 A（现有流程）/ B（加设计与关键帧）/ C（再加连续调度）三版，看关掉旁白后哪一版值得看。在通过这个对比之前，本层只是候选流程。
