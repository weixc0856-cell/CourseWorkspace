## Top 5（按浪费大小排序）

1. **改一处必跑生成器全链 + 残留扫描。** T1-01 三次返工同一根因：Re 10⁶→10⁷ 改计划漏改稿、R5 改写只同步口播链漏屏幕/分镜、第 3 页改写超支 3.9s 四处预算未跟。改任何上游（计划/稿/配置）后：重生成全部下游 → 跑 `display_chain_alignment` 等检查 → 残留扫描归零，才算改完。
2. **配置合同三查**（voice bible 三连坑，6 轮 + 3 次重合成）：①字段位置对不对（speed 在 lesson.yaml 的 narration 段，不是 spec）；②传资产 id 不传路径（传路径会拼成 `voice-bibles/voice-bibles/….yaml.yaml`）；③配置一次改齐再走重签——每改一次就重截图/重建分镜页/重签/重测，03:31–04:04 走了 3 轮。
3. **Windows 中文三件套**（编码簇 5 轮）：Python 加 `-X utf8`；含中文的脚本落盘执行，不塞 heredoc/`-c`（引号不配对 ×2、乱码入代码 ×1）；注意 `python -I` 会忽略 PYTHONIOENCODING，`-I` 与 `-X utf8` 同用。
4. **语速/时长一律实测，估算只作初值。** 规划基准 133 wpm 是估值，实测 148.5；先出样片测 wpm，再定分页预算与全量配音（见 [[duration-follows-clarity]] 口径：时长服从讲清楚）。
5. **大产物生成器落盘，不整份 Write 重写。** 实测 15 次 >8K 字符的 Write/Edit（213K 字符）是上下文主源之一；gen_scenes.py 曾 1 分钟内整份重写 2 次。生成器进仓库或内容根 `_authoring/`，增量 Edit，产物由脚本落盘（协作协议 §12 纪律 2）。

## B. 流程类

- **合同不熟成本**：shots/deck 死锁排查花 ~10 次 grep/sed。开工前先读 `docs/生产合同.md` 与 `course-control --help`，占位审批疑与 CLI 不会用有关（先查 --help 才手写）。审批一律走 `author-accept`，不手写 approval.json（E2 证据门会抓）。
- **重签循环**：配置批量改齐 → 一次重签。签核门行为正确，成本来自零碎改动。
- **模式切换**：切 compose.mode 后 storyboard 头注/时长 profile 需要跟改（V-49 会抓残留）；头注由会话本地脚本生成时，切换后必须重生成。

教训：**外部评审三次抓出同一类错，说明缺的是程序门不是细心**——E1 三链对齐门已上线（rubric vl4），同类错今后在 checks 阶段就红。

**素页根治（2026-11-21，D-119）**：反复丢失设计不是操作失误，是富渲染路径不存在——每次重生成必落 plain。根治两层：①可复用 deck 编译器进仓库（production.yaml→EVDS HTML，单一源，禁一次性本地脚本）；②E6 设计绑定门接进签核（deck HTML 缺失/素页/缺图/缺左下引用 → 拒绝签核）。**"有 CSS 有样板"不等于"有渲染路径"——设计资产必须被编译器消费，否则等于没有。**

## D. 监测机制（每集例行，不靠人盯）

1. 交付时跑账单脚本：token 构成 + 坑位信号（tool_errors 聚类、≥3 次重复命令、>8K Write payload 清单）一次产出，存 `build/_logs/token-bill-<lesson>.json`；
2. release-check 读账单：超 40M 成本当量无说明 → WARN，缺账单 → NOT_RUN（首轮非阻塞，硬阈值待三集实测）；
3. 新坑入本清单：审计发现新类型坑 → 补对应行 + 证据路径，清单随集数增长。
