# 多视觉语法生产系统 · 现有架构审计（P0）

日期：2026-11-09
范围：`CourseControl` / `RemotionStudio` / `CodeVideoStudio` / `ManimSandbox` / 现有 Producer·Director·QA 流程
性质：**只读审计**，本轮不改生产代码。
证据口径：`已验证事实`（代码/实跑可证）、`架构推断`（由代码结构推导）、`待验证假设`（尚无实测）。

---

## 1. 结论先行

系统不是“动画效果不够好”，而是把**一种运动语法**（长镜头连续变形）写成了**通用质量定义**：

- 生成层（`beats.py`）用 5–16 秒镜头、长寿命对象 ≥50%、每 4 秒必须有动作，把“短切/换构图”判成不合规；
- 评分层（`animation_score.py`）把 8–12 秒镜头、2.5 动作/10 秒、冻结 ≤9 次/分钟当作目标函数；
- 发布层（`docs/工业化动画工作流.md`）要求 **≥85 分**；
- 因此目标视频那种“3–6 秒一切、每拍新构图、对象不跨镜”的语法，**在现有门禁下最高只能拿 ~55 分**，属于结构性不可发布。

这不是模型能力问题，也不是语言/音色问题。是**契约把艺术语法和质量标准焊在了一起**。

## 3. 三层耦合图（现状）

```
slides.md / lecture_notes.md / outline.md
        │  V-03 页数对齐
        ▼
     Page（30–55s）
        │  collect: 每页一条 base shot
        ▼
  shots.json（base = 页；overlay = cutaway/PiP）
        │
        ├── render:manim / code_video / motion_canvas / blender
        │        （每个 cutaway 一条独立 MP4）
        ▼
   Remotion CourseTimeline（淡入淡出 + 字幕 cue）
        │
        ├── verify（V-10..V-36）
        ├── media-qc（黑帧/冻结/响度）
        └── animation-score（beats.yaml → 85 分）
```

- **Page 同时承担知识组织与视频镜头组织**（已验证事实：`collect()` 以页为单位生成 base shot）。
- **Shot 不是第一等公民**：`ShotSpec` 必须挂在 `slide` 上，`cue_seconds` 是页内偏移。
- **评分器同时承担技术正确性、艺术语法与发布合规**（已验证事实：`animation_score` 的 `gates` 分量直接读 `validate_sheet` 的 issues）。
- **同一套 `media-qc` 同时服务幻灯片、矢量图形、3D 模拟**，没有按视觉类型区分（已验证事实：`media_qc.py` 统一调用 `detect_black_freeze`）。

## 4. 各现有引擎被什么契约限制

| 引擎 | 现在能做什么 | 被什么卡住 |
|---|---|---|
| Manim | 长镜头、公式、连续变换 | `beats` 的 5–16 秒 + 长寿命对象；`collect` 的页级切分 |
| CodeVideo（HTML/Canvas/SVG） | 任意密度、任意构图、逐帧纯函数 | 被当作“插入镜头”，不能作为整片底片；每镜独立渲染；`overlay` 类型不含图形 |
| Motion Canvas | 时间线动画 | 页级切分 + 适配器要求整片导出 |
| Remotion | 合成、字幕、品牌、HUD 叠加 | 只做合成，不做镜头；转场只有 fade；字幕只有 cue |
| Blender | 三维镜头 | 页级切分 + 渲染开销 |

**架构推断**：引擎能力不是瓶颈。瓶颈是“所有镜头都必须先变成一个页的附属物”。

## 5. 质量体系现状

- `verify.py`：V-10..V-36，技术正确性为主（文件、分辨率、时间线、音频、字幕、meta）。这些属于**通用硬约束**，应保留。
- `media_qc.py`：解码/格式/响度/静音/黑帧/冻结/字幕。**响度、解码、格式是硬约束；冻结不是**（静态设计可以是合法表达）。
- `animation_score.py`：把运动密度、连续性、节奏、相机、门禁、冻结合成一个 0–100。**它把艺术偏好伪装成通用质量标准**（与任务文档的判断一致）。
- `content-qa` / `teaching-qa`：内容与教学层，独立，保留。

**已验证事实**：`animation-score` 的 `gates` 分量为 0 时直接 `verdict=fail`，且 CLI 以退出码 1 结束（`cli.py:1739-1749`）。

## 6. 已验证事实 / 架构推断 / 待验证假设

### 已验证事实
1. `beats.py` 的 5/16/4/0.5 为模块常量，`validate_sheet` 无 profile 参数。
2. `animation_score.py` 的 `TARGETS` 为模块常量，8–12 秒、2.5 动作/10 秒、9 冻结/分钟。
3. 用目标视频的节奏（4 秒一镜、无长寿命对象）代入现有评分，门禁分量归零、连续性归零，总分上限约 55。
4. `collect()` 在 deck/scene 模式下按页生成 base shot。
5. `ShotSpec.slide` 为必填 `ge=1`，`cue_seconds` 为页内偏移。
6. `Annotation` 仅 `text` / `legend`。
7. `CourseTimeline` 的转场只有 fade。
8. `capture.mjs` 已有 `--start/--frames`，长片可分块；180 秒整段捕获曾失败（差距清单 #20）。
9. `asr-align` 已产出词级时间戳（`word_timestamps=True`），但只被 QC 消费。
10. 四门真实课程全部为英文；中文链路未端到端跑过（不影响本轮架构判断）。

### 架构推断
1. 高密度短切片的真实瓶颈是“页为底片 + 每镜独立渲染”的生产组织，不是渲染器。
2. 现有 85 分线一旦保留为唯一发布线，任何非长镜头语法都会被系统性压低。
3. 把 `animation-score` 拆成 metrics 不会降低质量，因为这些指标本来就不是硬约束。

### 待验证假设
1. Qwen3-ASR / Whisper 多语种模型在本机 CPU 上对中文词级对齐的精度与耗时（需实测）。
2. 目标视频的画面中角色插画是否全部为代码绘制（只看到故事板缩略图，未逐帧验证）。
3. 长片（>180 秒）分块捕获 + 拼接后，Remotion 时间线的帧对齐是否逐帧一致（需实测）。
4. 现有 `media-qc` 在 3–6 秒切镜下的冻结误报率（需用样片实测）。
