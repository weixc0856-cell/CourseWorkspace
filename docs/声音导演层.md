# 声音导演层（Sound Direction Layer）

日期：2026-11-13
代码：`CourseControl/src/course_control/sound/`
命令：`course-control sound-design`

## 1. 五条独立轨道

声音不是一个 BGM 音轨，而是五条各自设计的轨道：

| 轨道 | 管什么 | 本层的落点 |
| --- | --- | --- |
| 旁白 Voice | 信息主体：语速、重音、停顿、语气 | `voice[]`：每段旁白的 delivery、emphasis、pause |
| 音乐 Music | 情绪与节奏：何时进、何时退、何时不响 | `music[]`：enter / hold / duck / lift / leave / silence |
| 音效 SFX | 动作与因果：只在画面真的发生变化时出现 | `sfx[]`：事件、触发点、强度、对应的画面事件 |
| 环境声 Ambience | 空间感：这个镜头在什么地方 | `ambience[]`：场景、电平、区间 |
| 混音 Mix | 统一它们：响度、峰值、闪避 | `mix`：-16 LUFS / -1 dBTP / duck 6–8 dB |

五条轨道分开写、一起听。合在一起的原因是它们服务同一个表达，不是因为它们是一种声音。

## 2. 与现有系统的关系

| 现有资产 | 本层的用法 |
| --- | --- |
| `LessonConfig.audio`（`content_kind` / `bgm`） | 内容类型决定音乐策略；声明过的 BGM 原样带进来并接受检查 |
| `voice/audio_plan.py` | 仍是 BGM 许可与电平的校验入口；本层不替代它 |
| `voice/audio_mix.py` | 消费 BGM cue 做 sidechain 与 loudnorm；本层只写设计，不混音 |
| `docs/内容类型与音频策略.md` | content_kind → 是否有音乐、基准电平 |
| `docs/音乐资产盘点.md` | 曲目、许可、推荐用途 |
| `docs/声音资产-VoiceBible与Lexicon.md` | 声线身份与读法词典；本层只写 delivery 意图 |
| 导演层 `plan.narration` | 旁白分段、`style`、`emphasis`、`pause_after_ms` |
| 视觉设计层 `visual_design.json` | 音效与环境声的触发依据：**没有画面事件就不写音效** |

先看 cue sheet，再看检查。静音在 cue sheet 里是一条 cue（`action: silence`），不是缺失。

## 4. 派生规则

**旁白 delivery**：先看脚本自己的标记（`style`），再按措辞判断——问句、结论（so / therefore / that means）、对比（but / however / unlike）、举例（for example / imagine）、过渡（next / now let）。都判断不出时保持 `calm_explanatory`。这是导演意图，不是 TTS 情绪标签。

**音乐**：

- `formal_course`：没有声明音乐时整集一条 `silence`（默认，不是禁令）；需要音乐时按 cue 设计，代码不拦截（D-097）。
- `news`：允许分段音乐（2026-11-14 起，见 [新闻与调查报道标准.md](新闻与调查报道标准.md) §4）。enter / hold / duck / lift / leave / silence 按信息设计，关键证据处必须 `duck` 或 `silence`。门禁不按内容类型拦截；许可与电平照常检查。
- `popular_science`：按章节。开场 `enter`，结论/回顾 `lift`，最长的机制章节 `duck`（把音乐几乎撤掉），其余 `hold`。

**音效**：只从视觉设计的 `turn` 关键帧生成，触发类型固定为 `visual_event`，`visual_ref` 写 `<shot>:turn`。工程与电影化画面各有一个通用材质音；几何与编辑画面**不配音效**——每一次数据变化都“叮”一声，很快会变成游戏 UI。

**环境声**：只给显示了物理空间的镜头（工程 / 电影化），电平 `very_low`。形式课程里的环境声会被标出来要求确认。

## 5. 检查项（不是门禁）

| 规则 | 级别 | 拦什么 |
| --- | --- | --- |
| `sound.voice_missing` | error | 有旁白却没有 voice cue |
| `sound.licence_unknown` | error | 来路不明的曲目进入混音 |
| `sound.sfx_unmotivated` | error | 音效声称由画面触发，却没有画面事件 |
| `sound.music_never_rests` | warning | 科普内容没有任何一段把音乐撤掉 |
| `sound.music_continuous` | warning | 连续音乐超过 4 分钟 |
| `sound.sfx_unverified` | warning | 有音效但没有视觉设计可核 |
| `sound.sfx_density` | warning | 任意 20 秒内超过 4 个音效 |
| `sound.ambience_in_lecture` | warning | 形式课程里出现环境声，需要确认 |
| `sound.loudness_target` | warning | 计划响度偏离 -16 LUFS ±1 |
| `sound.true_peak` | warning | 计划峰值高于 -1 dBTP |
| `sound.voice_monotone` | warning | 5 分钟以上所有段落同一 delivery |

## 6. 混音基准

起始参考，不是平台标准：

- 成片综合响度 ≈ **-16 LUFS**（立体声），True Peak ≤ **-1 dBTP**；
- 旁白永远优先；BGM 在旁白下 sidechain 闪避 6–8 dB；
- 音效不遮旁白、不突然刺耳；
- 不允许无意的爆音、底噪、突兀断点；
- 交付前用耳机、笔记本扬声器、手机扬声器各听一遍。

响度数字不能替代试听。`-16 LUFS` 通过而旁白听不清，仍然是不合格。

## 7. 边界与下一步

- 本层只做设计，不做 TTS、不做混音、不改 `audio_mix.py` 的处理链。
- 派生 `delivery` 不读语义，只读脚本标记与措辞。需要真正的语气导演时，在导演计划里给 narration segment 写 `style`。
- 音效与环境声依赖视觉设计层；两者一起跑才有触发依据。
- 下一步（按 [课程质量模型](课程质量模型.md) 的 P1）：把 `music[]` / `sfx[]` 落成 `audio_plan.json` 可消费的 cue，再让 `audio_mix` 按 cue 区间混，而不是一条 BGM 铺到底。
