> **结论先行**
>
> 1. CourseWorkspace 已经具备**跨学科课程的生产骨架**，但只有软件/计算机、AI/机器学习、工程技术三个方向有真实课程内容；其中只有汽车空气动力学有“完整成片”的历史记录。
> 2. 其余七个学科目前是**适应性判断**，不是已验证能力；不能对外表述为“已支持”。
> 3. 系统的强项是媒体生产与工程验收，不是专业判断。内容正确性、教学有效性，以及临床、法律、工程安全判断仍由人负责。
> 4. 学科不是最小判定单位；**学科 × 内容类型**才是。
> 5. 任何能力升级都必须有真实生产证据。设计、模板、POC、单测都不等于学科验证。

## 1. 文档目的与效力

### 1.1 回答三个问题

1. CourseWorkspace 可以生产哪些学科领域的内容？
2. 不同学科和内容类型分别能够达到什么生产水准？
3. 哪些工作可以自动完成，哪些需要专业人员参与，哪些不能由视频生产系统替代？

### 1.2 本规范不是什么

- **不是功能需求文档。** 不要求为每个学科建立独立 Agent、渲染引擎或专用工作流。

- **不是质量合格证明。** 质量状态以真实产物和 [PROJECT_STATUS.md](../PROJECT_STATUS.md) 为准。
- **不是对外宣传材料。** 对外表述受第 11 节约束。

## 2. 核心定位与四种能力

### 2.1 定位

CourseWorkspace 是面向多学科知识内容的**课程生产系统**：把来源、知识组织、教学设计、视觉表达、媒体生产与质量审查串成可复核的流水线。

它不是知识权威，不是学科专家，不是自动学术研究者，也不是“输入主题就输出正确课程”的黑箱。

### 2.2 四种能力必须分开

| 能力 | 含义 | CourseWorkspace 当前有什么 | 当前不能证明什么 |
| --- | --- | --- | --- |
| **内容生产能力** | 组织、解释、表达知识 | `authoring` 的来源摄取、摘要、brief/outline/script/content 候选稿，以及人工 sha256 批准门；`director` 的章节、镜头、旁白计划；`producer` 的订单与交付清单 | 不能证明知识正确、完整、符合学科共识 |
| **媒体生产能力** | 转化为视频、动画、图表、音频 | Reveal 截图、Motion Canvas 无头导出、Manim、Blender IR v2、CodeVideo、Remotion 合成、VoxCPM2 旁白、双语字幕、KaTeX 公式、ScientificFigures | 不能证明讲得对、教得好、学习者看得懂 |
| **质量验证能力** | 检查事实、逻辑、教学和媒体质量 | Q4 工程完整性较强（V-10..V-33、`probe_media`、构建报告）；Q1 只有单模型候选；Q2 基本没有；Q3 部分；Q5 以文件存在性为主 | 不能证明课程质量合格；`TESTED` ≠ `VERIFIED` |
| **专业判断能力** | 对复杂争议、专业实践和现实决策作可靠判断 | **没有人。** 系统只提供材料、结构、媒体和候选意见 | 不能替代医生、律师、工程师、史学家、艺术家 |

### 2.3 五条不等式

1. **渲染成功 ≠ 知识正确。** 动画可以解释模型，不能验证模型。
2. **自动测试通过 ≠ 教学有效。** 构建 `verdict=pass` 只说明工程产物符合契约。
3. **能生成某学科课程 ≠ 具备该学科生产能力。** 生成能力是媒体能力；学科能力需要来源、专家、真实案例和审核。
4. **设计完成 ≠ 实现；实现 ≠ 测试；测试 ≠ 真实生产验证；真实验证 ≠ 专家审核。**
5. **模型之间意见一致 ≠ 事实正确；人工批准内容 ≠ 教学质量合格。**

**结论：**

- 有真实课程内容的领域只有 3 个：**软件/计算机、AI/机器学习、工程技术（汽车空气动力学）**。
- 只有工程技术有“完整成片”的历史记录；软件与 AI 仍停在部分链路。
- 数学、自然科学、生命/医学、经济管理、社会科学、人文历史、法律政策、艺术设计**没有任何真实课程**。它们在本规范中只能是 `DESIGNED` 或评估性判断。

### 3.3 状态词表

| 状态 | 含义 | 判定依据 |
| --- | --- | --- |
| `DESIGNED` | 已完成设计，无实现或无真实生产 | 文档 / Schema / 模板 |
| `IMPLEMENTED` | 有代码或生产能力 | 代码路径 |
| `TESTED` | 有自动化测试 | 测试通过 |
| `VERIFIED` | 有真实生产任务验证 | 真实产物、构建报告、可复现命令 |
| `EXPERT_REVIEWED` | 已由领域专业人员审核 | 姓名、日期、审核范围、意见记录 |
| `PARTIAL` | 只覆盖部分场景 | 明确列出缺失环节 |
| `BLOCKED` | 存在明确外部阻塞条件 | 阻塞原因可核对 |
| `NOT_SUPPORTED` | 当前不支持 | 无实现或无合适生产手段 |

**规则：**

- 这些状态不能互相替代。`TESTED` 不等于 `VERIFIED`，`VERIFIED` 不等于 `EXPERT_REVIEWED`。
- 学科级状态按**最弱环节**取。例如媒体生产 `VERIFIED`、内容 QA `INCOMPLETE`，学科不能写 `VERIFIED`。
- `EXPERT_REVIEWED` 是独立轴：一门课可以工程上 `VERIFIED`，但没有专家审核。

### 3.4 学科级状态判定

| 状态 | 判定条件 |
| --- | --- |
| `VERIFIED` | 至少一门真实课程完成“来源 → 人工批准 → 媒体生产 → 合成 → 验收”，且产物可核对 |
| `PARTIAL` | 有真实课程或真实内容，但闭环缺环节 |
| `DESIGNED` | 只有内容模板、结构判断或理论评估，没有真实课程 |
| `NOT_SUPPORTED` | 没有合适生产手段，或明确不适合由视频系统承担 |
| `BLOCKED` | 外部条件限制（材料、专家、授权、设备） |
| `EXPERT_REVIEWED` | 在 `VERIFIED` 之上，领域专家审核了关键主张与适用范围 |

### 4.1 软件与计算机科学

**初步适配度：高；当前证据：`PARTIAL`。**

- **适合的内容：** 编程语言、数据结构与算法、操作系统、网络、数据库、软件架构、分布式系统、AI/机器学习、Git/Shell/Docker/CI-CD 等工具。
- **系统承载：** 代码/终端会话录制、CodeVideo 代码镜头、Manim 机制动画、Blender 架构示意、Reveal 幻灯片。
- **优势：** 代码可以运行，步骤可以复现，结果和日志可以形成证据链。
- **边界：** 不能仅凭生成代码证明工程实现正确；源码分析必须核对实际版本；大型系统的长期演进经验不能靠动画替代；安全课程需要隔离环境和专业审核。
- **当前可承诺：** L1 的概念、机制、流程和代码演示。**不能**承诺“完整软件工程课程已交付”，因为现有软件课程尚未闭环。

### 4.2 数学与统计学

**初步适配度：高；当前证据：`DESIGNED`。**

- **适合的内容：** 微积分、线性代数、概率论、数值计算、优化、统计推断、傅里叶分析、微分方程。
- **系统承载：** Formula Pipeline（KaTeX/Manim）、Manim 几何动画、ScientificFigures 数据图、Blender 空间关系。
- **优势：** 公式、几何、空间变换和函数关系容易转化为可视化；部分结果可由 SymPy 辅助校验。
- **边界：** 动画直觉不能代替严格证明；高阶数学需要准确的符号体系和证明逻辑；交互式探索不是当前视频生产能力的自然组成部分。
- **当前可承诺：** L1 概念与机制可视化；L2 推导（必须有数学家审核）。**不能**承诺严格证明课程，也**不能**把 E6.5 的技术切片当作数学学科验证。

### 4.3 自然科学

**初步适配度：高 / 中高；当前证据：`DESIGNED`。**

- **适合的内容：** 物理现象与原理、化学反应机理、分子结构、天体运动、地质过程、材料结构。
- **系统承载：** Manim、Blender IR v2、ScientificFigures、CodeVideo 模拟。
- **优势：** 抽象机制可以转成图形和动画，适合从宏观现象过渡到微观机制。
- **边界：** 科学可视化不等于科学验证；示意动画不能当作真实实验结果；前沿科学必须区分已验证结论、理论假设和研究争议；实验操作、安全规范和误差分析不能只靠动画。
- **当前可承诺：** L1 概念/机制；L2 实验展示（需要真实数据与领域专家）。**当前没有任何物理、化学、天文、地学课程证据。**

### 4.4 工程与应用技术

**初步适配度：高；当前证据：`PARTIAL` / 历史完整记录。**

- **适合的内容：** 机械、汽车、能源动力、流体、热能、航空航天、船舶、电子电气、自动化、机器人、智能制造。
- **系统承载：** Blender 三维结构、Manim 控制方程、CodeVideo 软件操作、ScientificFigures 仿真图、Remotion 合成。
- **优势：** 三维结构、工程流程、参数变化和仿真结果适合表达；可以结合真实软件和数据演示。
- **边界：** 仿真结果必须由专业人员验证；工程示意不能替代真实设备操作；设计规范、标准和安全要求必须核对适用版本；工程决策必须考虑真实边界条件。
- **当前可承诺：** L1 原理/流程/软件操作；L2 仿真/案例（专家验证）；L4 设备操作只能做知识准备。`02-car-aerodynamics` 是唯一有完整成片历史记录的课程，但当前工作区未保留产物，复验需重跑；且没有专家审核记录。

### 4.5 生命科学与医学

**初步适配度：中高 / 中；当前证据：`DESIGNED`。**

- **适合的内容：** 细胞与分子机制、基因表达、器官系统、神经机制、药物作用原理、基础医学知识。
- **系统承载：** Manim/Blender 机制动画、ScientificFigures 数据图、Reveal 结构讲解。
- **优势：** 生物结构和生理过程适合动画；可以连接宏观现象与微观机制。
- **边界：** 医学内容需要更高等级的专业审核；研究结果必须考虑样本、研究设计和证据等级；相关不能直接讲成因果；临床诊断、治疗决策和用药建议不能由自动化流程独立承担；视频不能替代临床实践。
- **当前可承诺：** L1 基础生物概念；L2 机制（必须专家）；L3 临床决策（专家主导，系统只辅助）；L4 医学实操只做知识准备。**当前没有任何生命科学或医学课程证据。**

### 4.6 经济与管理

**初步适配度：中高；当前证据：`DESIGNED`。**

- **适合的内容：** 微观/宏观经济学、国际贸易、产业经济、金融基础、公司财务、会计、管理学、组织行为、战略、市场营销。
- **系统承载：** 数据图表、时间线、机制动画、案例结构图、幻灯片。
- **优势：** 供需、资金流、产业链、商业流程适合可视化和案例拆解。
- **边界：** 模型结论依赖假设，不能把模型讲成现实必然；金融数据有时效性；商业案例容易产生幸存者偏差和事后归因；管理学理论有不同研究传统和适用情境。
- **当前可承诺：** L1 基础理论/机制；L2 案例与数据（必须核对时间与来源，并由领域专家审核）；L3 投资建议、市场预测、企业战略判断（系统不承诺）。**当前没有经济/管理课程证据。**

### 4.7 社会科学

**初步适配度：中高 / 中；当前证据：`DESIGNED`。**

- **适合的内容：** 心理学、社会学、人类学、政治学、国际关系、教育学、传播学、认知科学。
- **系统承载：** 时间线、关系网络、经典实验示意、理论对比表、幻灯片。
- **优势：** 理论概念可结构化；经典实验可示意还原；社会关系与因果假设可可视化。
- **边界：** 不同理论传统可能有根本分歧；实验结果必须交代样本、方法和复现；社会现象不能归结为单一原因；价值判断和政策后果不能由模型自动决定；不能把理论解释包装成无争议的事实。
- **当前可承诺：** L1 概念；L2 经典实验/理论比较（必须研究方法审查与多视角）；L3 学术争议与政策判断（专家主导）。**当前没有社会科学课程证据。**

### 4.8 人文与历史

**初步适配度：中高 / 中；当前证据：`DESIGNED`。**

- **适合的内容：** 历史事件与时间线、人物与制度变迁、哲学概念与思想流派、文学背景与主题、语言演变、艺术史、宗教学。
- **系统承载：** 时间线、人物关系图、文本对照、幻灯片、地图/图像资产。
- **优势：** 时间线、人物关系和制度结构适合可视化；可以组织成系统课程。
- **边界：** 原始史料与后世解释必须分开；历史叙事不能简化为单一因果链；哲学论证不能只做名词解释；文学和思想史细读必须保留原文、语境和版本；学术争议要充分呈现不同解释。
- **当前可承诺：** L1 时间线/概念；L2 文本与解释（必须专家）；L3 原创史学研究或哲学论证（系统不承诺）。**当前没有历史/哲学/文学课程证据。**

### 4.9 法律与公共政策

**初步适配度：中；当前证据：`DESIGNED`。**

- **适合的内容：** 法学基础、宪法、民法、刑法、国际法、比较法、公共管理、公共政策、政策评估。
- **系统承载：** 制度流程图、法条对照、案例时间线、幻灯片。
- **优势：** 法律关系、司法程序和政策流程适合结构化展示；适合制度讲解和案例教学。
- **边界：** 法律有明确的地域和时间效力；法条、判例、司法解释必须核对原始来源和版本；同一案件可能有不同解释；政策效果涉及复杂因果和价值选择；自动生成内容不能作为法律意见。
- **当前可承诺：** L1 概念/制度；L2 案例讲解（必须核对原文、版本并注明时效）；L3 法律意见/执业培训（系统不承诺）。**当前没有法律/政策课程证据。**

### 4.10 艺术与设计

**初步适配度：中高 / 中；当前证据：`DESIGNED`。**

- **适合的内容：** 设计原理、色彩、构图、视觉语言、建筑结构与空间、电影镜头语言、分镜、音乐理论、作品赏析。
- **系统承载：** 三维场景、图像/视频资产、镜头分析、动画、幻灯片。
- **优势：** 视觉表达和动画本身就是教学媒介；可以结合图片、视频、三维模型和案例分析。
- **边界：** 审美价值不能完全由自动化指标衡量；原创艺术质量依赖创作能力和审美判断；作品展示涉及版权和授权；设计能力需要实践、修改和反馈。
- **当前可承诺：** L1 理论/作品分析；L2 技术演示；L5 原创艺术创作（系统只辅助，不承诺专业水准）。**当前没有艺术/设计课程证据。**

## 5. 内容类型矩阵：比学科分类更重要

同一学科内部，不同内容类型的生产难度可能完全不同。**学科决定“用什么词汇和证据”，内容类型决定“用什么生产策略和审查规则”。**

### 5.1 内容类型总表

| 内容类型 | 典型任务 | 初步适配度 | 主要系统承载 | 自动验收可做到 | 必须人工 / 专家 | 当前最高可承诺 |
| --- | --- | --- | --- | --- | --- | --- |
| 概念解释 | 熵、认知失调、边际效用 | 高 | 幻灯片 + Manim/Motion + 旁白 | 版式、公式语法、媒体规格、字幕结构 | 来源抽查；高风险概念需专家 | L1 |
| 机制解释 | Attention 计算、细胞信号传导 | 高 | Manim/Blender/CodeVideo | 媒体规格、时间线、公式编译 | 领域专家确认机制与尺度 | L1（工程/AI）/ L2（生命科学等） |
| 流程演示 | 软件操作、CFD 后处理 | 高 | 会话录制、CodeVideo、幻灯片 | 会话证据、视频可解码、QC | 操作者复核真实环境 | L1 |
| 数学推导 | 方程推导、算法推演 | 中高 | Formula Pipeline + Manim | KaTeX 编译、括号/命令检查、SymPy 辅助 | 数学家逐步核对证明 | L2 |
| 实验展示 | 物理/化学实验 | 中 | ScientificFigures + 视频资产 | 仅媒体规格 | 实验者 + 领域专家；真实数据 | L2；真实操作属 L4 |
| 案例分析 | 工程案例、商业案例 | 中高 | 幻灯片 + 图表 + 时间线 | 结构、时间线、媒体规格 | 领域专家核对事实、数据与归因 | L2 |
| 理论争议 | 不同经济学派、社会学理论 | 中 | 对比结构 + 时间线 + 文献 | 无自动裁决 | 专家裁决；多视角审核 | L3 |
| 原始材料细读 | 历史档案、哲学原著、法律判决 | 中低 | 文本 + 注释 + 对照 | 无 OCR/PDF 摄取；仅结构检查 | 专家核对原件、版本、语境 | L3 |
| 实践技能训练 | 医疗操作、设备操作、实验室实操 | 低 | 视频 + 三维演示 | 不能自动验收技能 | 合格教练 + 真实设备/现场 | L4 |
| 原创艺术创作 | 电影、音乐、文学、艺术创作 | 不宜仅依赖自动化 | 媒体工具 + 人工创作 | 无审美自动验收 | 创作者 + 评审 | L5 |

### 5.3 同一学科、不同策略

| 学科 + 内容类型 | 必须回答的问题 | 主要审查规则 |
| --- | --- | --- |
| 心理学 + 经典实验 | 样本、方法、结果、复现争议是什么？ | 研究方法审查；相关不等于因果；多视角 |
| 历史学 + 历史事件 | 原始史料、时间线、不同解释、证据强度是什么？ | 史料与解释分离；版本与语境 |
| 数学 + 定理证明 | 定义、前提、推导步骤、逻辑校验是什么？ | 符号一致；证明缺口；数学家审核 |
| CFD + 工程案例 | 物理模型、边界条件、网格、求解、验证是什么？ | 仿真验证；规范版本；工程师审核 |
| 法学 + 案例分析 | 法律事实、适用法条、争议焦点、裁判理由、时效是什么？ | 原文/版本核对；地域时效；法律专家审核 |

> 这套分类用于指导现有 Director 的内容判断和 QA 的审查规则，**不意味着现在需要增加对应软件模块**。

## 6. 生产能力等级（L1–L5）

### 6.1 五级定义

| 等级 | 名称 | 典型内容 | 要求 | 对外承诺 |
| --- | --- | --- | --- | --- |
| **L1** | 高度自动化生产 | 基础概念、标准知识、软件操作、工程流程、数学/科学机制可视化 | 有可靠来源；可结构化；结论可验证；媒体链路自动；质量问题可自动检查或明确标记 | 可以自动化生产，但仍需来源、人工批准和抽查 |
| **L2** | 专业辅助生产 | 进阶工程、自然科学专业内容、经济管理、基础医学、理论比较 | AI 承担研究整理和内容生产；关键知识由领域专家审核；不确定结论明确标注 | 可以辅助生产，不能绕过专家 |
| **L3** | 专家主导生产 | 学术争议、深度历史、哲学文本细读、临床决策、法律案例、前沿科学 | 专家负责核心问题、材料解释和最终判断；AI 只做整理、表达和媒体制作 | 专家主导，AI 辅助；不能宣称自动完成 |
| **L4** | 强依赖真实实践 | 医疗操作、实验室操作、设备操作、现场工程训练 | 视频只做知识准备和过程解释；必须结合真实设备、实验环境或合格指导 | 不能宣称视频可替代实践 |
| **L5** | 无法保证结果的创作与判断 | 学术原创贡献、原创艺术审美、重大社会价值判断、复杂现实决策 | 系统可辅助构思、整理、表达和制作 | 不承诺自动完成，最终责任由人承担 |

### 6.2 判定规则

1. **等级按“学科 × 内容类型”判定，不按学科整体判定。** 同一门医学课，基础生理机制可以是 L2，临床诊断是 L3，手术操作是 L4。
2. **取最弱环节。** 媒体生产 L1、内容证据 L3，整体只能按 L3 表述。
3. **L1 不等于无人。** L1 仍需要来源、人工批准、抽样看片；只是不需要每页专家签字。
4. **L2/L3 必须有领域专家。** 没有专家时状态是 `BLOCKED`，不是“先发布再补审核”。
5. **L4 不能只靠视频。** 可以生产知识准备和演示，不能承诺技能掌握。
6. **L5 不承诺结果。** 可以参与，但不能用“已完成/已达标”描述。
7. **等级不能继承。** 不在“高适配学科”里就自动获得 L1；每个内容类型单独判定。

### 6.3 当前系统的实际最高等级

| 范围 | 当前实际最高 | 依据 |
| --- | --- | --- |
| 软件/AI 的概念、机制、流程、代码演示 | L1（生产链路部分验证） | 模板、引擎、POC、真实镜头；但完整课程未闭环 |
| 工程原理/流程/软件操作 | L1；仿真/案例 L2（需专家） | 汽车空气动力学历史成片；无专家审核 |
| 数学概念/可视化 | L1（潜力，未验证） | 公式与 Manim 能力存在；无独立数学课程 |
| 实验展示、案例分析、理论争议 | L2/L3（未验证） | 需要真实数据和专家，当前无课程 |
| 原始材料细读、临床/法律判断 | L3（未验证） | 需要专家主导 |
| 实践技能训练 | L4 | 视频不能替代真实操作 |
| 原创艺术创作 | L5 | 无客观自动验收标准 |

## 7. 能力边界登记表

### 7.1 八个必答维度

| 维度 | 必须回答的问题 | 对应现有落点 |
| --- | --- | --- |
| 知识生产 | AI 能否可靠地组织和解释知识？ | `authoring` + 人工批准 |
| 证据要求 | 是否有可靠、可追溯的来源？ | `sources.yaml`、`source_refs`、ContentQA |
| 专业审查 | 是否必须由领域专家签字？ | 人工审批；当前无 `EXPERT_REVIEWED` |
| 可视化 | 是否有适合的图形、动画和演示方式？ | 版式、配色、Manim/Blender/CodeVideo |
| 实践依赖 | 是否必须接触真实设备、实验或人群？ | 会话录制、真实数据、现场教学 |
| 自动验收 | 哪些质量指标能客观检查？ | V-10..V-33、`probe_media`、QC |
| 人工验收 | 哪些判断必须由人完成？ | 看片、来源核对、专家审核、发布批准 |
| 失败边界 | 哪些情况下必须停止生产或拒绝发布？ | 第 7.6 节停止规则 |

### 7.2 内容类型级登记表（生产责任）

| 内容类型 | 知识生产 | 证据要求 | 专业审查 | 可视化 | 实践依赖 |
| --- | --- | --- | --- | --- | --- |
| 概念解释 | AI 可组织，需来源 | 教材、论文、权威资料 | 高风险概念抽查；争议概念需专家 | 幻灯片、动画、图表 | 低 |
| 机制解释 | AI 可组织，机制图需专家确认 | 原始论文、教材、数据 | 专家确认机制、尺度、因果 | Manim/Blender/CodeVideo | 低–中 |
| 流程演示 | AI 可整理步骤 | 软件版本、操作记录、日志 | 操作者复核真实环境 | 录屏、代码镜头、终端 | 中（需真实软件） |
| 数学推导 | AI 可整理，不能保证证明 | 定义、定理、原始推导 | 数学家逐步审核 | 公式 + Manim | 低 |
| 实验展示 | AI 不能替代实验 | 原始数据、实验记录、视频 | 实验者 + 领域专家 | 科学图形、视频 | 高（真实实验） |
| 案例分析 | AI 可整理公开资料 | 一手案例、数据、访谈 | 领域专家核对事实与归因 | 图表、时间线、三维 | 中 |
| 理论争议 | AI 可并列观点，不能裁决 | 原始文献、不同流派 | 专家裁决与多视角审核 | 对比图、时间线 | 低 |
| 原始材料细读 | AI 可辅助，不能替代 | 原件、版本、档案 | 专家核对原文与语境 | 文本 + 注释 + 对照 | 低（但材料必须可得） |
| 实践技能训练 | AI 只能讲解 | 操作规范、设备、现场记录 | 合格教练 | 视频、三维演示 | 高（必须真实操作） |
| 原创艺术创作 | AI 可辅助 | 无客观证据标准 | 创作者/评审 | 媒体工具 | 低（但质量不可保证） |

### 7.3 内容类型级登记表（验收与失败边界）

| 内容类型 | 自动验收 | 人工验收 | 失败边界（停止规则） |
| --- | --- | --- | --- |
| 概念解释 | 版式、公式语法、媒体规格、字幕结构 | 看片 + 来源抽查 | 无来源、错误定义、适用条件缺失 → 停止 |
| 机制解释 | 媒体规格、时间线、公式编译 | 专家看机制 + 看片 | 机制无来源、尺度/因果错误 → 停止 |
| 流程演示 | 会话证据、视频可解码、QC | 操作者复现 | 版本不符、无法复现、环境不可用 → 停止 |
| 数学推导 | KaTeX/SymPy 辅助 | 数学家逐步核对 | 证明缺口、符号不一致、适用条件缺失 → 停止 |
| 实验展示 | 仅媒体规格 | 实验者 + 专家 | 无原始数据、无安全规范、动画冒充实验 → 停止 |
| 案例分析 | 结构、时间线、图表 | 专家核对事实与归因 | 数据过期、幸存者偏差、事后归因 → 停止 |
| 理论争议 | 无自动裁决 | 专家多视角审核 | 单一观点冒充共识、省略反方证据 → 停止 |
| 原始材料细读 | 无 OCR/PDF；仅结构检查 | 专家核对原件、版本、语境 | 无法获得原件、版本不明、断章取义 → 停止 |
| 实践技能训练 | 不能自动验收技能 | 教练现场评估 | 宣称可替代实践、无合格指导 → 停止 |
| 原创艺术创作 | 无审美自动验收 | 创作者/评审 | 承诺专业水准、版权不明 → 停止 |

### 7.5 状态升级检查清单

- [ ] 真实课程存在，slug 与目录可核对。
- [ ] 来源可追溯：`sources.yaml` + 摘要 + sha256。
- [ ] 人工批准：`authoring/approval.json` 哈希有效。
- [ ] 媒体产物真实：`probe_media` 通过，无截图拼帧、无伪造导出。
- [ ] 完整构建：`final/course-video.mp4` + `final/build-report.json` 可核对。
- [ ] Q4 工程完整性通过；失败项有记录，不是 `skip` 冒充 `pass`。
- [ ] Q1/Q2/Q3 不处于未声明的 `INCOMPLETE`；缺失项明确标注。
- [ ] L2 及以上有领域专家审核记录（姓名、日期、范围）。
- [ ] 人工发布批准已记录。
- [ ] 证据路径写入本规范或 `PROJECT_STATUS`。

### 7.6 停止规则

出现以下任一情况，**停止生产或拒绝发布**：

1. 重要事实、公式、数字没有可追溯来源。
2. 高风险医疗、法律、工程安全内容没有合格专家审核。
3. 内容依赖真实设备、实验、患者或现场技能，但只能提供视频。
4. 时效性内容无法确认版本、日期或适用地域。
5. 原始材料无法获得，或版本、语境无法核对。
6. 版权、肖像、音乐、数据集授权不明。
7. 需要原创审美、学术原创贡献或重大价值判断。
8. AI 输出未经程序校验或人工批准，却被当作事实或完成品。

> 这些规则与项目硬约束一致：`skip ≠ pass`，AI 输出不等于已完成，不能伪造验收。

## 8. 跨学科质量要求

不同学科的具体审查方式可以不同，但以下基本要求一致。

### 8.1 内容真实性

- 重要事实必须有来源。
- 重要结论必须有证据支持。
- 不能把推断说成事实。
- 不能把示意图说成真实数据。
- 不能忽略结论的适用条件。
- 时效性内容必须标注资料时间。

**项目现状：** `ContentQA` 能按页生成候选意见，但不是 Claim Registry，也没有独立的来源支持核验；模型返回 `supported` 不能写成事实通过。

### 8.2 证据层次

至少区分：

1. **原始资料**：原始论文、实验数据、档案、法条、标准、原始记录。
2. **二手资料**：综述、教材、研究报告、权威解释。
3. **作者解释**：对资料的归纳、分析和推断。
4. **教学表达**：类比、示意、简化模型。

**规则：** 教学类比不能冒充原始事实；作者解释不能伪装成学界共识。

**项目现状：** 来源摄取支持 URL / Markdown / TXT，不支持 PDF/DOCX；`sources.yaml` 记录来源，但没有自动的“证据等级”分类。课程级登记表必须由人填写证据等级。

### 8.3 教学有效性

课程应检查：

- 学习目标是否明确。
- 前置知识是否充分。
- 概念是否按合理顺序展开。
- 关键机制是否解释清楚。
- 是否提供案例和反例。
- 是否说明结论边界。
- 是否存在不必要的信息堆积。
- 是否形成完整的学习闭环。

**项目现状：** 只有导演计划里的 `learning_objective` 字段，没有独立的教学有效性校验、知识依赖图或学习者测试。**不能声称教学有效。**

### 8.4 视觉表达

- 动画应服务于理解。
- 图表应准确表达数据关系。
- 示意图应明确标注。
- 不能用视觉效果掩盖证据不足。
- 不同学科应选择适合自身知识结构的表达方式。

**项目现状：** 版式、配色、运镜、动画方向、公式和科学图形有规则与部分自动检查；最终视觉验收仍以人看完成片为准（D-047），不能用抽帧/关键帧评审替代。

### 8.5 专业责任

以下情况必须明确人工审核要求：

- 高风险医疗和法律内容。
- 工程安全和设备操作。
- 有重大争议的学术结论。
- 重要历史解释和原始材料争议。
- 具有明显公共影响的政策判断。
- 缺少可靠证据的前沿研究。

**项目现状：** 当前没有任何课程达到 `EXPERT_REVIEWED`。这不是流程缺陷的借口，而是能力边界：**没有专家审核，就不能对外宣称专业可靠性。**

## 9. 当前适用范围与优先顺序

以下排序只代表当前系统的预期投入产出比和风险控制，**不代表学科重要性，也不构成开发路线**。

| 优先级 | 学科领域 | 当前建议 | 当前可做 | 当前不可做 / 前置条件 |
| --- | --- | --- | --- | --- |
| P0 | 软件工程、计算机科学、AI | 继续作为主要生产方向 | 概念、机制、流程、代码演示；现有课程闭环 | 不能宣称“完整课程已交付”；大型系统经验、安全实验需专家 |
| P0 | 数学、物理、工程技术 | 充分利用机制可视化能力 | 概念/机制/公式可视化；工程原理与流程 | 严格证明需数学家；物理实验需真实数据；工程仿真需验证 |
| P1 | 能源、汽车、CFD、智能制造 | 建立专业差异化内容 | 工程案例、仿真解释、软件操作 | 仿真结果、规范版本、现场实践必须有专家与真实条件 |
| P1 | 经济学、管理学 | 拓展理论和案例课程 | 模型、图表、案例结构 | 数据时效、假设边界、幸存者偏差需专家审核 |
| P1 | 心理学、社会学 | 开展有来源的系统化讲解 | 概念、经典实验、理论比较 | 研究方法、复现、多视角审查 |
| P2 | 历史、哲学、文学 | 以专业资料和多视角分析为基础 | 时间线、概念、作品背景 | 原始材料细读、版本、解释争议需专家 |
| P2 | 生物学、医学 | 优先基础知识和机制课程 | 基础生物概念、机制动画 | 临床决策、用药建议、医学实操需专家与真实训练 |
| P2 | 法律、公共政策 | 强化时效、来源和专业审核 | 概念、制度、程序 | 法条/判例版本、地域时效、法律意见 |
| P2 | 艺术、音乐、建筑 | 以理论讲解、作品分析和技术演示为主 | 设计原理、构图、镜头分析、音乐理论 | 原创创作质量、审美判断、版权 |

**P0 的真实含义：** 先把现有软件/AI/工程课程的生产闭环、质量验收和交付完成，不是立刻扩到更多学科。

## 10. 当前阶段的执行原则

1. 继续完成现有课程生产链路，不因跨学科设想扩大开发范围。
2. 不为每个学科创建独立 Agent、渲染引擎或工作流。
3. 学科差异优先落在：导演层的内容策略、QA 的审查规则、版式/模板/资产、人工与专家门槛；不落在代码分支。
4. 新内容类型先做 POC 和真实课程，再判断是否抽象为通用能力。
5. 优先复用现有 `authoring`、`director`、`producer`、媒体适配器和 QA 能力。
6. 遇到问题时先判断属于哪一类，不能都归因于“缺少新功能”：
   - 内容资料不足；
   - 专业知识不足；
   - 教学设计不合适；
   - 视觉表达方式不合适；
   - 质量审查不充分；
   - 媒体生产能力不足。
7. 只有当多个真实课程反复遇到同类问题时，才考虑抽象为通用能力。
8. 任何新增能力必须回到 [PRD.md](../PRD.md)、[ARCHITECTURE.md](../ARCHITECTURE.md)、[DECISIONS.md](../DECISIONS.md) 立项，**不在本文直接派生开发任务**。

## 12. 复审与变更

### 12.1 触发条件

- 完成一门新的真实课程。
- 获得一次领域专家审核。
- 新增或验证一项质量检查能力。
- 新增引擎、内容类型或真实 POC。
- 发现现有判断与真实生产结果冲突。

### 12.2 更新内容

每次更新至少修改：

- 该学科 / 内容类型的证据状态；
- 当前最高可承诺等级；
- 可对外表述；
- 失败边界；
- 证据路径与日期。

### 12.3 复审节奏

- 每门课程交付后复审一次。
- 至少每季度复审一次。
- 产品负责人负责维护；领域专家负责审核专业判断；系统只提供证据。

| 生产闭环 | 来源 → 人工批准 → 媒体生产 → 合成 → 验收 → 交付批准 |
| 证据等级 | 原始资料 / 二手资料 / 作者解释 / 教学表达 |
| L1–L5 | 从高度自动化到不承诺结果的五级能力边界 |
| `skip ≠ pass` | 未执行的阶段不得写成通过；缺失、阻塞必须如实记录 |
