# 动画渲染适配器

日期：2026-11-08
状态：Motion Canvas 自动化已落地（D-054）；Manim / Blender / CodeVideo 已有适配器。

## 1. 目标

Director / Producer 只描述“镜头需要什么”，不关心引擎如何渲染。所有引擎共用一个适配器契约，统一输入、超时、重试、产物校验和失败语义。

```text
Director / Producer
        │  ShotPlan
        ▼
CourseControl/adapters
  ├─ motion_canvas.py   Renderer + Vite + Playwright + 帧接收器
  ├─ manim.py           uv run manim
  ├─ blender.py         scripts/blender-render.ps1 / IR v2
  └─ code_video.py      CodeVideoStudio capture + QC
        │
        ▼
StageOutcome(status, outputs, warnings, errors, reason, duration_ms)
        │
        ▼
collect → compose → verify
```

## 2. 统一契约

每个 adapter 的入口是 `run(paths) -> StageOutcome`，并遵循：

| 项 | 约定 |
| --- | --- |
| 输入 | `LessonPaths` 中的 storyboard、lesson 输出分辨率/帧率、shot id |
| 输出 | `outputs` 只列真实存在的 MP4/PNG 等产物；路径在 `build/<slug>/` 下 |
| 状态 | `pass` / `fail` / `skipped` / `not_run` / `not_applicable` |
| 重试 | 引擎自己声明上限；Motion Canvas 2 次，Manim/Blender/CodeVideo 目前 1 次 |
| 校验 | 引擎自有检查：Motion 新渲染校验分辨率/帧率/帧数，缓存校验分辨率/帧率/时长；Manim/Blender/CodeVideo 沿用各自 probe/QC。不是所有引擎都校验帧数 |
| 失败 | 写 errors 与日志；下游 `not_run`；不得用截图拼帧或旧文件冒充 |
| 部分成功 | 有产物但其他镜头失败 → 整个阶段 `fail`，产物保留供排查 |
| 证据 | 阶段日志 `build/<slug>/logs/`，引擎元数据（如 Motion `build/motion-canvas/<run>/meta.json`） |

## 3. 各引擎

| 引擎 | 入口 | 自动程度 | 产物校验 |
| --- | --- | --- | --- |
| Motion Canvas | `scripts/render-headless.mjs` + `src/headless.js` | 全自动（Vite 4173 + 帧接收器 4174 + Chrome） | 新渲染：ffprobe 分辨率/帧率/帧数；缓存：分辨率/帧率/时长 |
| Manim | `uv run manim render --media_dir ...` | 全自动 | ffprobe + 文件存在 |
| Blender | `scripts/blender-render.ps1`（adapter）；`scene-run` 是独立场景任务 | 全自动 | adapter 检查输出；`scene-run` 另有场景验收 manifest |
| CodeVideo | `CodeVideoStudio` capture + QC | 全自动 | `VERIFY.md` + QC + contact sheet；adapter 不额外计数 |

Motion Canvas 仍依赖本机 Chrome/Playwright 和 Vite，属于浏览器渲染，不是纯 Node；但它不需要人工点击编辑器。

## 4. 失败恢复

- Motion Canvas：最多 2 次尝试；每次先删除半成品；失败写 `attemptN.log`；两次失败后 `fail`，不产 MP4。
- 注入失败：`--fail-at <frame>` 让 exporter 在第 N 帧抛错；控制器断言无 MP4、meta 为 `failed_as_injected`。
- 其他引擎：沿用各自现有错误处理；没有验证过的自动重试不写成已有能力。

## 5. 人工节点重新定义

| 类型 | 处理 | 例子 |
| --- | --- | --- |
| 生产执行 | 自动 | 动画导出、TTS、字幕生成、渲染、合成、文件检查 |
| 风险/决策 | 保留人工 | 预算超限、商业授权、发布批准、最终验收 |

Motion Canvas 手动导出属于生产执行节点，已改为自动。编辑器保留给作者制作/预览；旧人工导出只作为合法缓存复用。

## 6. POC 证据（2026-11-08）

- 场景：`attention-flow`，1920×1080 / 30 fps / 142 帧 / 4.733 s。
- 连续 3 次输出 SHA256：`f9501d5967037121559701cc45cefdfac042d219d3bb3f221f7cdb19b99c5b8f`。
- 注入第 30 帧失败：无 MP4 产出，meta `status=failed_as_injected`，adapter 连续 2 次失败后 `fail`。
- `lesson-manual` fixture：adapter 自动导出 `gui_vs_cli_paths` 12.23 s，ffprobe 通过。
- 产物与日志：`build/motion-canvas/`（构建产物，不入库）。
- **分辨率限制**：1280×720 POC 出现左侧裁切，场景按 1920×1080 布局；adapter 固定使用 `outputs.animation_canvas`。任意分辨率/4K 需要先补场景自适应，不能直接切尺寸。

## scene 模式 base_file（2026-11-09）

- `compose.mode: scene` + `build/<slug>/scenes/manifest.json` 的 `base_file` 可以让一条
  连续动画承担整门课的底画面；`collect` 不再把 storyboard 镜头叠加到该底画面上。
- 适合机制解释类课程：一条 Manim 场景按旁白段落编排 beat，避免静态幻灯片占满时长。
- Manim 适配器缓存：`build/<slug>/animation/<scene>.mp4` 比 `.py` 场景新时直接复用，
  重建不会重复渲染长动画。
- 决策见 D-057；示例见 `ManimSandbox/05-transformer-5min/attention_5min.py`。

## 运行时版式门禁（2026-11-09）

- 场景必须在**每个 beat 结束、对象淡出之前**调用 `common.scene_checks.check_now(self, "beatN")`；
  只在 `construct` 末尾调用 `enforce` 是无效的，因为连续动画末尾已经清空画面。
- 检查包含：文字安全区、文字-文字重叠、文字被无关图形穿过；标签在自己容器内或高亮框
  完全包住文字不算重叠。
- `lesson.yaml.build.strict_layout: true` 时，Manim 适配器向渲染进程传
  `STRICT_LAYOUT=1`；任何版式问题都会让渲染失败，而不是只打印警告。
