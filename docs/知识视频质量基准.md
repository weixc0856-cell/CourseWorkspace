## 0. 结论先行

1. 对标的是三件事：知识经不经得起追问、解释是否沿着因果推进、画面能不能自己承担解释。片头、转场、团队规模不在对标范围。
2. 最终保证的是成片质量。**镜头必须多长、必须用哪种动画、必须用哪种语法，都不能写成契约或门禁。** 它们只是制作时的选择，验收时只看这个选择是否让内容讲得更清楚。
3. 质量分三级：**L1 必须达到**、**L2 分块努力**、**L3 长期探索**。发布只认 L1，加上“把问题讲明白、把画面做好、把交付做硬”三条。
4. 视觉语法按知识对象选，不按频道选。一集可以混用，一季不套模板。
5. 品牌视觉与场景视觉分两层：纸白、墨色、克制橙用于知识、图表与文字；深色空间、自然材质、光照用于机制与场景。统一的是艺术指导，不是背景色。
6. 验收只加三层：内容、视觉、交付。每层落到已有命令与人工签核，不新增门禁代码。
7. 先用一集真实成片验证，再谈批量。首个试验集是本机 AI 经济系列 E01（`runtime/course-content/ai-economics/episodes/E01/`），验收标准见该目录下的 `acceptance-standard.md`。
8. 所有视频以英文制作：画面文字与旁白用英文；字幕英文在上、中文在下。中文是字幕与文章版本，默认不做中文配音。

## 1. 定位：个人知识产品工作室

目标不是成为 AI 视频生产者。AI 视频生产者的竞争点是工具、成本与产量；这里要建立的是知识深度、视觉解释和工程化交付的组合。

| 能力 | 含义 | 怎么证明 |
| --- | --- | --- |
| Knowledge | 真正理解并能讲清一个领域，知道结论的边界 | claim 有来源，数字有口径，反例被主动处理 |
| Visual | 把只能用语言描述的过程变成观众看得见的因果 | 静音能看出过程，画面每镜都在增加信息 |
| Delivery | 稳定、可复现地交付成片与材料 | 构建、QC、字幕、交付包、签核有完整证据 |

由此得到两条排期约束：

- 不追求集数与频率超过质量。两周一集优于周更，质量不可压缩。
- 产能靠可复用资产与标准提升，不靠加引擎、加语法、加模板。

## 2. 参考群体：学什么，不学什么

参考对象只用于校准方法，不构成风格目标，也不构成验收结论。不能因为“像某个频道”判通过，也不能因为“不像”判失败。

| 参考 | 值得学的 | 在本项目的落点 | 不学 |
| --- | --- | --- | --- |
| 3Blue1Brown / Welch Labs | 抽象概念转成可观察、可推演的视觉过程；动画本身就是论证 | `long_take` / `geometric`；对象跨镜头存活，变换优先于替换 | 手绘风格、音效规模、以个人嗓音为卖点 |
| The Efficient Engineer / Branch Education | 结构清楚、空间关系准确、机制可解释 | `geometric` / 3D 剖面、爆炸图、运动过程；SPEC + VERIFY | 定制三维资产的数量与精度 |
| Real Engineering / Veritasium | 问题驱动、故事推进、现实案例与工程约束 | 冷开场用真实数据或矛盾；`test` beat 给边界与反例 | 外景拍摄、主持人出镜、现场采访 |
| Kurzgesagt | 视觉语言统一、构图完整、节奏与细节打磨 | 主题 token、统一构图、克制的运动；一场戏内风格稳定 | 插画团队、角色动画、逐帧美术 |
| MIT OCW / Stanford Online | 知识体系、推导严谨、课程连续、完整交付 | 季的依赖关系、术语表、每集前置、完整交付包 | 课堂录像形态、板书替代动画 |

使用规则：

1. 一集最多选两组主参考，由知识类型决定（见 §3）。混五家的优点是拼贴，不是综合。
2. 观察必须来自实际看片，记录“哪一期、哪个时间点、看到什么”。凭印象写“节奏好”没有用。
3. 参考语言与主产品语言不同时，只借结构，不借句式；英文稿另找英文母语样本校准。
4. 参考只用于制定本集标准，不进入发布签核的评分项。

## 3. 知识类型决定视觉语法

视觉技术服从知识表达。先问“观众要看见什么关系”，再选语法；不能先选动画模板，再往里塞知识。

| 知识类型 | 主要参照 | 应采用的视觉表达 | 注册表语法 |
| --- | --- | --- | --- |
| 数学、经济学理论 | 3Blue1Brown、Welch Labs | 动态图形、关系推演、概念变形；同一对象连续变化 | `long_take`、`geometric`、`data_viz` |
| 工程、物理机制 | Branch Education、Efficient Engineer | 三维结构、剖面、运动过程、参数实验 | `geometric`、`simulation`、`data_viz` |
| 商业、产业、历史 | Real Engineering、Veritasium | 纪录片式叙事、真实数据、场景与时间线 | `montage`、`kinetic_edit`、`data_viz` |
| 科学通识、宏观知识 | Kurzgesagt | 完整场景、统一艺术指导、视觉隐喻 | `geometric`、`simulation`、`montage` |
| 系统课程 | MIT OCW、Stanford Online | 概念递进、推导顺序、章节衔接、知识结构 | `kinetic_type`、`data_viz`、`geometric` |

规则：

1. 语法注册表 `shared/grammars/visual-grammars.yaml` 是唯一事实源；不新增语法名。现有七种覆盖不了时，先写待决问题。
2. 一集混用两种以上语法是正常的；一种讲得最好，就不为多样性凑第二种。
3. 不为“看起来高级”上 3D、粒子、发光或角色。没有内容理由的特效，按装饰处理，删掉。
4. 语法阈值（镜头时长、动作密度、长寿命比例、冻结段数）是诊断指标，不是放行条件（D-071）。一个 3 秒讲完的镜头不因低于下限被拉长；一个 30 秒连续演化的镜头不因平均时长被拆开。

## 4. 三级水平：必须、努力、探索

| 级别 | 定义 | 判据 | 当前目标 |
| --- | --- | --- | --- |
| **L1 专业知识视频** | 不是会动的 PPT；画面承担解释；排版、色彩、声音统一 | 静音仍能看出在表达什么；每镜有明确目的；无占位块、死帧、模板转场；交付完整 | **每集必须达到** |
| **L2 成熟 EduTube** | 完整视觉叙事；连续场景与空间关系；复杂机制可动态展示；镜头调度与细节设计 | 至少一个完整段落达到：对象跨镜头连续、机制随旁白推进、构图与节奏成立 | **每集挑 1–2 个关键段落努力达到**，不要求全片 |
| **L3 顶级团队制作** | 高度定制资产、复杂物理模拟、精细角色动画、纪录片级实拍与声音设计 | 团队级资产与工艺 | **长期探索**，不作为当前排期与验收条件 |

L2 按段落判定，不按全片判定。AI 目前能稳定产出漂亮的单帧与参数化图表，也能在受控段落里做出成熟频道水准；但整条片的空间一致性、结构准确性、物理一致性和艺术指导仍会掉。要求整片 L2，等于用不可能的标准逼出占位和补丁。

L2 需要跨过的五个环节，以及现有系统的应对：

| 环节 | 失败表现 | 现在靠什么兜住 |
| --- | --- | --- |
| 连续镜头之间的空间一致性 | 同一物体每镜换个样子 | 节拍表的长寿命对象、`production.yaml` 的镜头权威 |
| 复杂物体的结构准确性 | 部件比例、连接关系错误 | 资产的 `SPEC.md` + `VERIFY.md`、人工截帧 |
| 动画动作与物理规律的一致性 | 运动方向、速度、因果不符 | 模型驱动（`cost_model.py` 这类可执行模型）、`simulation` 证据标注 |
| 多个场景之间的艺术风格统一 | 一场白底、一场黑底蓝光 | `shared/design-tokens/themes.json`、一场戏内主题稳定 |
| 动画节奏与讲解逻辑的配合 | 画面做完了，旁白还没讲到 | 节拍表按旁白分段、实测旁白定时间 |

结论是一句：AI 能生成漂亮的单帧，不等于能自动导演一条好片。导演、视觉设计、场景制作和验收体系的存在，就是为了补这五个环节。

## 5. 品牌视觉与场景视觉

分两层，不混用。权威数据在 [shared/design-tokens/themes.json](../shared/design-tokens/themes.json)。

| 层 | 用途 | 色彩与材质 | 主题 |
| --- | --- | --- | --- |
| **品牌基础视觉** | 标题、图表、正文、知识结构、片头片尾 | 纸白 `#FBFAF7`、暖白、深炭墨色、克制的橙 `#E8733B` | `editorial_science` |
| **场景表达视觉** | 微观世界、宇宙、粒子、能源、机械结构、复杂物理模拟 | 深色空间、自然色彩、材质与光照，由内容决定 | `deep_space`、`engineering_studio` |

规则（与 `themes.json` 一致，不在这里另立一套）：

1. 默认 `editorial_science`。切到 `deep_space` 必须有内容理由：粒子、空间、发光、能量传播，或三维机构。不能只因为“深色好看”。
2. 一帧只有一个强调色；其余语义色只用于它们对应的对象。
3. 主题在一场戏内稳定；深浅切换发生在镜头边界，由内容触发。
4. 颜色在场景设计阶段确定：Blender 材质、Motion Canvas 图形、Manim 对象、Remotion 字幕共用同一套 token，不叠加全局滤镜。

两个要避免的极端：

- 所有场景都白底，视觉单调，机制类内容没有空间感。
- 所有场景都黑底蓝光，变成廉价的 AI 科技风，知识内容失去可信度。

需要的是统一的艺术指导，不是统一的背景色。

## 5.5 生产单位（2026-11-13，D-093 / D-094）

- **Episode** 是最小交付单位：8–12 分钟，目标 10 分钟，只回答一个核心问题。
- **Course（专题）** 是产品单位：9 集，约 90 分钟。
- **全书**是系列：10 个专题 / 90 集（汽车空气动力学，D-094）。
- 单集独立讲稿、视觉、配音、QC 与交付；一集不合格只返工该集。
- 不为凑时长注水；7 分钟能讲清楚就按 7 分钟交付。

## 6. 三层验收

三层独立报告，不允许综合分掩盖缺陷。任何一层失败都不能用另一层的高分抵消。

### 6.1 内容质量

| 检查 | 通过条件 | 现有落点 |
| --- | --- | --- |
| 来源分层 | 框架层、事实层、叙事层各就各位；叙事案例用事实层交叉校核 | 季方案、`authoring/fact-check.md` |
| 知识递进 | 每集只引用前面已建立的概念；术语全季统一；跨集回指不超过一句 | 季方案、`glossary.en-zh.md` |
| 独立价值 | 不是教材章节的视频化；每集回答一个观众能感知的问题，有现实案例和自己的分析 | 选题五问、季方案 |
| Claim | 每条关键主张有 `claim_id`、来源位置、人工签核；`span-check` 只证明文本在页上 | `knowledge-studio evidence`、`review-decide` |
| 数字 | 来源、口径、时间点、单位四件套齐全；推算数字给公式并标“模型推算” | 数据资产、`sources.yaml` |
| 边界 | 结论写明适用条件；常见误解被主动拆掉；反例进正片 | 脚本、`test` / `connect` beat |
| 版权 | 不复制他人图表、表格、案例原文；图表重绘 | 季方案的许可结论 |

硬规则：

- 旁白里出现的数字必须有来源；没有来源的数字不上屏、不上口播。
- 厂商自报数字标“厂商口径”；单例不能证明规律；平均值不说成每个人都如此。
- 数据与主张冲突时改主张，不改口径、不换样本、不延长区间。
- `span-check` 通过不等于结论成立；成立性由人签核。

### 6.2 视觉质量

| 检查 | 通过条件 |
| --- | --- |
| 每镜有目的 | 能用一句话说出这一镜在解释、比较、揭示或强调什么 |
| 画面承担解释 | 关掉旁白，画面仍有发展过程；不是文字、箭头、公式的逐页切换 |
| 运动有逻辑 | 变化对应旁白里的一个理解点；不用入场、缩放、平移冒充高质量动画 |
| 证据可区分 | `real_data` 有来源条；`simulation` 标“模型推算”；`schematic` 不伪装成结果 |
| 艺术指导统一 | 构图、层次、色彩、字体、安全区一致；无占位块、死帧、模板式转场 |
| 语法合适 | 按 §3 选择；不拿一种模板套所有内容 |

判定方式：

- 先做静音播放审查（[ACCEPTANCE.md](ACCEPTANCE.md) §0.2），逐镜记录。
- 再看截帧：每镜取首、中、尾帧，判断构图与变化，不凭描述。
- 最后完整看片，记录字幕遮挡、语义错误、节奏问题。自动化替代不了这三步。

### 6.3 交付质量

| 检查 | 通过条件 |
| --- | --- |
| 成片 | 文件可解码；分辨率、帧率、时长符合 lesson 声明；无黑帧、冻结、音画漂移 |
| 声音 | 旁白自然、无爆音；响度符合规范；音乐不压人声 |
| 语言 | 画面文字与旁白英文；中文只做字幕与文章版本；默认不做中文配音 |
| 字幕 | 英文在上、中文在下；语言声明、行宽、CPS、cue 数、术语一致；V-31 / V-44 无结构错误 |
| 证据与资产 | `sources.yaml`、数据快照、claim 绑定随产物归档 |
| 交付包 | `package` 完整；`package-verify` 通过；每项有 SHA-256 |
| 状态 | `skip` / `not_run` / `incomplete` 不写成 `pass`；发布需要人工签核 |

## 7. 每集怎么落地

一集的标准由三份东西组成：

1. 季方案里的选题、证据责任与时长预算（已有，见总纲 §13）。
2. 本集的制作验收标准（每集一份，模板见 §7.2）。
3. 真实成片的验收记录（时间戳、截帧、签字）。文档不是通过，成片才是。

### 7.1 执行顺序

```text
选题五问 → 框架/事实/叙事三层来源 → claim 与证据 → 脚本
→ 导演计划与节拍表 → 低清预览 → 全量构建 → media-qc / quality-gate
→ 静音看片 → 只听声音 → 完整看片 → 人工签核 → 交付包
```

规则：

- 证据没到位，对应段落的旁白不写；不能先用占位稿录完再补证据。
- 一集没通过人工看片与内容签核，不进入下一集批量。
- 资产可以复用，验收不能复用；每集重新判定。

### 7.2 单集验收标准的必填结构

每集 `acceptance-standard.md` 至少包含：

1. 当前状态：哪些证据、脚本、镜头、成片已经存在，哪些没有。
2. 目标水平：L1 必须；哪 1–2 个段落尝试 L2；L3 不做。
3. 内容验收：本集用到的 claim、需要的证据、数字四件套、禁止的越界表述。
4. 教学逻辑验收：每个 beat 结束时观众应该能说什么、不应该以为什么。
5. 视觉验收：逐镜计划表（语法、目的、画面必须出现什么、证据标注、不通过的样子）。表是计划，不是契约；合并、拆分、换语法都可以，只要解释链和证据不变。
6. 交付验收：成片、声音、字幕、交付包、状态与签核。
7. 审查流程：三种看片、谁签、记录在哪。
8. 判定与返工：什么是硬失败，什么只是记录。
9. 本集明确不要求：避免把诊断指标写成新门禁。

### 7.3 状态写法

- `design`：标准已写，尚未生产。
- `pending_evidence`：缺证据，不能进入脚本或不能进入成片。
- `in_production`：已在做，未验收。
- `accepted`：通过本集标准并有人工签核。
- `rejected`：未通过，记录原因与返工项。

没有真实成片与签字，任何集不得写 `accepted`。

这些是文档与单集验收状态，不替代 `BUILD_PASS` / `VERIFY_PASS` / `QUALITY_VERIFIED` / `RELEASE_APPROVED`；交付层仍按 [QUALITY_STANDARD](stabilization/QUALITY_STANDARD.md) 判定。

## 8. 反模式

1. 把五家参考的风格拼成一条片：Kurzgesagt 的配色 + 3B1B 的运动 + Veritasium 的开场 + MIT 的板书。结果是四不像。
2. 用“像不像某频道”打分。参考只校准方法，不进入评分。
3. 把“必须做满多少秒”“必须用某种动画”“必须用某种语法”写成验收条件。这是把制作手段当质量。
4. 为了 L2 硬上 3D、粒子、角色，结果结构错误、空间跳变。
5. 为了让规定满足，新增评分器、门禁或语法。D-071 已经规定：新增门禁必须对应可证明的缺陷。
6. 所有场景白底，或所有场景黑底蓝光。两种都是把背景当风格。
7. 用文字入场、缩放、平移填充镜头，把 PPT 动效叫动画。
8. 用播放指标（留存、完播）宣布课程合格。指标只用于发现问题。
9. 把 AI 生成的结构化计划、脚本、审查意见当完成品。它们都是候选，必须过程序校验与人工判断。
