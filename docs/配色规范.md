# 配色规范（Light Technical Editorial）

日期：2026-11-08
代码：`CourseControl/src/course_control/layout/schema.py`、`ManimSandbox/common/design_system.py`
预览：`build/01-transformer-demo/review/palette-system.mp4`

## 1. 结论

默认主题是**明亮的科技编辑风格**：暖白纸面、石墨正文、橙色品牌重点；蓝 / 青 / 紫只用来表达“输入 / 处理 / 输出”这类语义，不用来装饰。

整体比例：**70% 中性（纸面、留白、灰线）+ 20% 墨色（标题、结构）+ 10% 重点色**。一帧只允许一个橙色重点。

## 2. 检索依据

- 麦肯锡没有公开的品牌手册；流通的色值是第三方近似：Deep Blue `#051C2C`、Electric Blue `#2251FF`、白底、冷浅灰 `#F2F4F6`、边框 `#D9DEE3`、次要文字 `#5A6872`。来源：[McKinsey brand spec（approx）](https://github.com/hugohe3/ppt-master/blob/5e8856be0da8e6bc85c4aa28acc614478f7b7137/skills/ppt-master/templates/brands/mckinsey/templates/design_spec.md)。
- Claude / Anthropic：Clay `#D97757`、Page `#FAF9F5`、Card `#F0EEE6`、Hairline `#E8E6DC`、Ink `#141413`、Blue `#6A9BCC`、Green `#788C5D`。来源：[claudeplot colors](https://github.com/viniciusoike/claudeplot/blob/main/R/colors.R)、[Claude design tokens](https://github.com/beefiker/superloopy/blob/378169a2646b2f8b84dcff0c4fd9f0da9b7d8a32/skills/superloopy-frontend/references/design/claude.md)、[Anthropic palette](https://colorarchive.org/brands/anthropic/)。
- 本方案取两者的“报告感”：麦肯锡的克制结构 + Claude 的暖纸与陶土橙；不复制任何一家的品牌标识或版式。

| `ink` | `#252A31` | 标题、结构线 |
| `body` | `#2E3338` | 正文 |
| `muted` | `#6B7280` | 注释、轴标签 |

| `orange` | `#E8733B` | 品牌重点、当前焦点、attention 权重 |
| `blue` | `#4A82B8` | 输入、query、数据流 |
| `teal` | `#42A69A` | 处理、key、target、通过 |

| `red` | `#C75B55` | 误差、loss、错误 |

| `flow` | `#A8C6DE` | 浅色数据流箭头 |

## 4. 语义色

| 语义 | Token | 例子 |
| --- | --- | --- |
| 核心结论 / 当前焦点 | orange | attention 权重、正在讲解的公式项、结论下划线 |
| 输入 / 查询 | blue | 源句、query 向量、输入箭头 |
| 处理 / 运算 | teal | key、层归一化、target、通过状态 |
| 输出 / 预测 | purple | value、预测分布、输出 token |
| 误差 / 风险 | red | loss、gap、回传、错误 |

Transformer 课程的具体映射：

- Query 蓝，Key 青，Value 紫；
- Attention 权重橙；
- 数据流浅蓝；
- 输出 token 紫；
- Loss / 回传红。

结构框、标题、正文保持墨色；不要给每个模块换一种颜色。

## 5. 对比度

在 `#FBFAF7` 纸面上的 WCAG 对比度：

| 颜色 | 对比度 | 可用位置 |
| --- | ---: | --- |
| Ink `#252A31` | 13.84 | 正文、标题 |
| Body `#2E3338` | 12.22 | 正文 |
| Muted `#6B7280` | 4.63 | 注释（AA 正文） |
| Purple `#7A6FB0` | 4.26 | 图形、≥24 px 粗体标签 |
| Red `#C75B55` | 3.98 | 图形、错误强调 |
| Blue `#4A82B8` | 3.89 | 图形、输入标签 |
| Orange `#E8733B` | 2.90 | 图形、重点，不用于小字 |
| Teal `#42A69A` | 2.81 | 图形、处理标签 |

规则：语义色承担图形与大字，正文只用 ink / body / muted；橙色上不要放小白字。

## 6. 禁止项

- 大面积纯黑、深灰背景作为默认主题；
- 荧光绿、荧光紫、赛博渐变；
- 无意义的发光、粒子、扫描线、网格底纹；
- 卡片套卡片；
- 一页超过两个语义色（橙色重点不算语义色）；
- 为了“科技感”牺牲文字对比度。

暗色主题不作为默认主题；作为镜头显式声明的场景主题时，按第 9 节执行。

## 8. 边界

- 4 个早期 Manim 镜头已统一到纸白底与语义色；`style.background_mismatch` 不再出现。
- 语义色目前由人工在场景中选择；导演层记录角色，但还没有逐图元的颜色校验。
- 图表色序、代码高亮只定义了语义，还没有组件级色板。

## 9. 视觉主题（建议，非门槛）

单一白底或单一黑底都不对。浅色适合长时间阅读、公式推导和图表；深色适合粒子、空间层次和发光对象。
处理方式是**主题化**：镜头声明用哪套主题，而不是给成片统一换肤。

三套主题的色值在 `shared/design-tokens/themes.json`：

| 主题 | 用途 | 底色 |
| --- | --- | --- |
| `editorial_science`（默认） | 日常讲解、公式、数据图表、算法结构、动态文字 | `#FBFAF7` 暖白 |
| `deep_space` | 粒子与流场、三维结构、能量与信号传播、复杂系统的空间关系 | `#0A0908` 近黑 |
| `engineering_studio` | 机械结构、设备、汽车内外饰、产品拆解、工程场景重建 | `#E8E6E1` 中性灰 |

语义色保持不变（第 4 节），主题只更换底色与色阶。学科可以覆盖，例如流场里的红蓝代表压力与速度，
不必强行解释成"风险"和"输入"。

建议遵守的四条：

1. 默认 `editorial_science`。切到 `deep_space` 要有内容理由（确实在讲粒子、空间或发光），不是为了好看。
2. 深浅切换发生在镜头边界，并承担叙事。Transformer 的例子：token 与矩阵在浅色场景，
   attention 权重传播切进深色空间，计算结果回到浅色信息图——深浅本身成为段落划分。
3. 一帧只允许一个强调色，其余语义色只用在它们对应的对象上。
4. 颜色在场景设计阶段确定：Blender 材质、Motion Canvas 图形、Manim 对象、Remotion 字幕共用同一套 token，
   **不对成片叠加统一滤镜**。

字体与主题一起定了，不再逐片调整：

- 数字与公式：`Jost` 200（大字号）/ 300（正文尺寸），OFL-1.1，随仓库分发；
- 中文：`Noto Sans SC`，OFL-1.1；
- 段落正文仍是 Noto Sans SC 400，中文不使用合成加粗。

这一节不是门禁：没有校验器会因为用了深色主题而失败。它固定的是默认值，
目的是让后续课程不必每次重新决定"白底还是黑底、用什么字体"。

### 9.1 当前接入状态（不要假设它已经自动生效）

| 项 | 状态 |
| --- | --- |
| 字体：Jost 200/300 随仓库分发、Remotion 首帧前加载 | **已接入**（`RemotionStudio/src/fonts/loadFonts.ts`） |
| 字体 token：`fonts.display` / `fonts.numeral` | **已接入**（`shared/design-tokens/tokens.json`） |
| 三套主题色值 | **已定义**（`shared/design-tokens/themes.json`） |
| 镜头声明主题 `Shot.theme` / `ShotSpec.theme` | **已接入**：取值 `editorial_science` / `deep_space` / `engineering_studio`，缺省为 `editorial_science` |
| 场景按主题取色 | **code_video 已接入**：镜头声明主题时，`adapters/code_video.py` 会在场景目录写出 `theme.json`；Manim / Blender / Motion Canvas 仍各自硬编码 |

用法：在 `storyboard.yaml` 的镜头条目上写 `theme: deep_space`，该镜头的场景目录会得到 `theme.json`
（含 `colors`、`semantics`、`rules`）。场景读它，不读环境变量、也不叠加滤镜。

```python
from course_control.theme import load_theme, write_theme_json
colors = load_theme(workspace, "deep_space")["colors"]
```

仍然缺的一环：Manim / Blender / Motion Canvas 的场景还没有读 `theme.json`，它们继续用各自的常量。
主题字段对它们是"声明了但不生效"，不会报错。
