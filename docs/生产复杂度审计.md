## 2. 实际生产链：一个主入口，89 个侧门

`scripts/build-lesson.ps1` 只调用一件事：`course-control build`。它进入 `pipeline.py`，而 `pipeline.py` 的 imports 只有 12 个模块：

```text
pipeline.py
├── rendering.adapters (+ base)
├── platform.atomic / build_lock / checkpoint / config_resolve / workspace_layout
├── content.collect / contracts / paths / validators
├── delivery.report
└── quality.verify
```

**其余 89 条命令都不在一次课程构建的主链上。** 它们不是死代码——都能从某个入口到达——但它们的产物没有被 `build` 读取。这是“复杂度超过交付需要”的真实形态：不是文件没人用，而是**入口太多、彼此不汇合**。

## 3. 五个审计重点的结论

### 3.1 引擎：数量多，但使用分布很清楚

| 引擎 | 实际使用课程数（共 15） | 定位 |
| --- | ---: | --- |
| code_video | 9 | 事实上的主力（vibe 系列、新闻类） |
| manim | 7 | 数学/原理动画 |
| blender | 2 | 三维与工程场景 |
| motion_canvas | 2 | 结构动画（含 1 门 deck 课） |
| remotion | 全部 | 合成层，不在 `engines:` 列表 |

没有发现重复适配器。真正的问题是 `recording` 模式：契约与 `collect.py` 支持，`printwindow` / `vscode_runner` / `container_runner` / `session_runner` / `session_evidence_v1` 共约 1,630 行为它服务，但**当前 15 门课没有一门是 `mode: recording`**。

判断：保留，但归类为“产品线能力待验证”，不再追加投入，直到有一门真实录制课。

### 3.2 CourseControl：重复不在文件，在“结论”

- `quality/` 不是 6 处重复计算，而是一条阶梯：`verify` / `media_qc` / `code_video_qc` 产出分阶段证据 → `quality` 汇总五维报告 → `quality_gates` 出 gate → `defect` 出缺陷 → `certificate` 合并三者给发布结论。模块之间是组合，不是重复。
- 真正的成本在**编排**：一份发布结论需要 `quality-diagnose → quality-gate → quality-certificate` 三步、四个中间文件，缺一步证书就只报 `incomplete`。2026-11-14 已用 `quality-certificate --refresh` 收成一条命令。
- `content/` 的契约版本：`contracts`（在用）、`contracts_v1`、`v1_timeline`（被 `collect.py` 用于桥接）、`e65`、`legacy_e6`、`legacy_registry`，合计约 2,745 行。其中只有 `contracts` 与 `v1_timeline` 在生产链上。
- `animatic` 与 `pipeline` 不重复：animatic 只做预览，不进构建。

### 3.3 V2 增量：已落地，但只有一项进了主链

| 能力 | 当前消费方 | 是否进 `build` |
| --- | --- | --- |
| `platform.checkpoint`（阶段 DAG） | `pipeline.py` | **是** |
| `platform.run_record` | 仅 `cli/project.py` | 否 |
| `platform.artifacts` | `quality/certificate.py` + CLI | 否 |
| `quality.defect` / `repair` / `regression` | 互相 + `cli/quality.py` | 否 |
| `quality.certificate` | 仅 `cli/quality.py` | 否 |
| `delivery.project` | `cli/lesson.py`、`cli/project.py` | 否 |
| `knowledge_studio.knowledge_ir` | 仅 KnowledgeStudio CLI | 否 |
| `delivery.orchestrator`（producer） | 仅 `cli/producer.py` | 否 |

### 3.4 文档

74 个文件、14,963 行，接近代码量的一半。主题重叠最明显的是“视觉/声音”：`动画视觉导演规范`、`视觉设计层`、`版式系统`、`课程视觉风格指南`、`知识视频质量基准` 五份都在说画面；`内容类型与音频策略`、`音乐资产盘点`、`声音资产-VoiceBible`、`声音导演层` 四份都在说声音。目前分工是清楚的（意图 / 规范 / 资产 / 流程），但没有一份索引说明“先读哪份”。

### 3.5 测试

85 文件 / 9,999 行，637 例通过。没有发现“没有断言”的测试文件；主要成本在**实验模块的测试**（录制、legacy 适配、V2 闭环），它们保护的代码不在主链上。

## 4. 四象限分类

### A. 核心生产（不进任何瘦身清单）

`pipeline.py` 主链 + `rendering/adapters/*` + `content/{contracts,collect,paths,validators,timecode}` + `voice/*` + `quality/{verify,media_qc}` + `platform/{atomic,build_lock,checkpoint,config_resolve,utils,media,vendor,workspace_layout,timeouts}` + `rendering/{blender_*,theme,layout,formula*,branding}`。

### B. 有价值的辅助能力（保留，隔离，不并入 build）

| 能力 | 行数 | 当前入口 | 隔离方式 |
| --- | ---: | --- | --- |
| 导演层 + 制片层 | 2,532 + 1,862 | `director-*` / `producer-*` | 保持独立命令；不自动进 build |
| 视觉设计层 / 声音导演层 | 1,423 + 683 | `visual-design` / `sound-design` | 同上；**尚未被引擎消费** |
| Animatic 预览 | 837 | `animatic` | 预览专用 |
| KnowledgeStudio / ContentQA / ModelingStudio / ScientificFigures | 约 6,700 | 各自 CLI | 独立工程，不并入主链 |
| 录制课工具链 | 约 1,630 | `session-*` | 等一门真实录制课再投入 |

### C. 待证明价值（保留代码，冻结扩展）

`platform.run_record`、`platform.artifacts`、`quality.{defect,repair,regression,certificate}`、`delivery.project`、`knowledge_ir`、`content.{e65,legacy_e6}`。

判定规则（满足任一即降级为 D，可删）：
1. 连续两个版本周期没有任何课程构建读取它的产物；
2. 它的能力可以由主链已有模块以不超过 50 行实现；
3. 删除后 `check.ps1` 与历史交付物不受影响。

### D. 清理候选（当前很少）

- 无外部引用的命令：`formula-video-qc`、`simulation-validate`（其余未引用命令是 `brief`/`outline`/`script`/`content-draft` 作者别名，保留）。
- 文档中的重复主题（见 3.4），先合索引，不删文档。

**重要发现：没有“零引用”的 Python 模块。** 每个模块都能从某个 CLI 入口到达。所以这次瘦身的第一杠杆不是删文件，而是**收敛入口与结论**。

## 8. 停止条件

- 任何一批改动导致 `check.ps1` 失败或历史交付物无法重建 → 回滚该批，停在上一批。
- 同一问题修复超过 3 次 → 停止，记录证据，等人工决定。
- AI 不自行判定“模块无价值”；C 类降级为 D 必须满足第 4 节的三个条件之一，并留下证据。
