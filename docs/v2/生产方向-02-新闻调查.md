# 生产方向 02：新闻与调查

- **日期**：2026-11-14
- **定位**：在现有新闻标准之上的一条生产线，不新建第二套代码。编辑标准以 [新闻与调查报道标准](../新闻与调查报道标准.md) 为准，执行步骤见 [新闻视频生产流程](../新闻视频生产流程.md)。
- **适用**：新闻事件 + 证据梳理 + 机制解释 + 独立评论；单集 4–12 分钟，默认 10 分钟。
- **当前实例**：`nvidia-huang-file`（262 s，82 分主观粗评，标杆）；`data-center-power-bill`（在产）；`projects/beyond-headlines/` 是系列材料。

---

## 1. 产品单位与边界

| 层级 | 单位 | 当前落点 |
| --- | --- | --- |
| 系列 | 一个新闻/调查栏目 | `projects/<系列>/project.yaml`（`mode: topic_video`） |
| 集 | 4–12 分钟，一个事件或一个追问 | `lessons/<slug>` 或 topic composition |
| 幕 | 六幕：Cold Open → Context → Discovery → Mechanism → Counterargument → Implications | `authoring/narrative-plan.json` |
| 段 | 1–3 分钟，一个证据动作 | `authoring/production.yaml` 的 `sequences[]` |

这条线可以是 4 分钟的短调查，也可以是 12 分钟的完整调查；时长由事件和证据决定，不设全局秒数门禁。`duration.profile: news` 只是默认窗口，课可以自己声明。

## 2. 三种内容必须分开标注

| 类型 | 回答 | 证据要求 | 画面责任 |
| --- | --- | --- | --- |
| 新闻事实 | 发生了什么、谁说了什么、时间线 | 原始报道、官方文件、当事人原话；交叉验证 | 原始画面 + 来源条 |
| 调查与解释 | 为什么发生、利益关系、各方说法是否成立 | 时间线、文件、数据、多方观点；反方证据检索 | 图表、关系图、地图、动画 |
| 评论与判断 | 可能改变什么、对产业/政策/普通人意味着什么 | 明确标为分析/推论；未证实部分写“不主张” | 主持人口播/字幕 + 简洁图示 |

旁白不能把推论说成事实。每一幕结束时，观众应该能分清：哪些是已知，哪些是解释，哪些是判断。

## 3. 四份核心材料，落在现有产物上

评审建议单独建 `source-register`、`claim-ledger`、`analysis-brief`、`video-script`。本项目不新建平行模块，映射到已有产物：

| 评审材料 | 本项目产物 | 说明 |
| --- | --- | --- |
| source-register | `authoring/sources.yaml` + `authoring/fact-check.md` 的来源表 | 每条来源记类型、机构、时间、链接/页码、取用位置 |
| claim-ledger | `ContentQA` 的 `review/claim_registry.json` + `sources.yaml` 的 claim 引用 | 每条关键论断对应证据、反方证据、状态 |
| analysis-brief | `authoring/fact-check.md` 的证据矩阵、时间线、各方说法、反方检索、数字口径、本片明确不主张 | 做不完不开工 |
| video-script | `authoring/narrative-plan.json` + 口播稿 + `authoring/production.yaml`/`storyboard.yaml` + `visual-design.yaml` + `sound_design.json` | 脚本、镜头、声音分开设计 |

如果一条新闻需要独立于课程生产，仍然放在 `projects/<系列>/` 下，用 `ProjectSpec` 的 `topic_video`；**不要另建一个代码仓库或第二套渲染器**。渲染、预览、缓存、发布检查复用 CourseControl。

## 4. 六幕与 10 分钟骨架

标准要求六幕，评审给的 10 分钟表可以直接映射：

| 评审表 | 六幕 | 任务 |
| --- | --- | --- |
| 0:00–0:45 一个值得追问的问题 | Cold Open | 用原始画面/原话提出矛盾 |
| 0:45–2:30 发生了什么 | Context | 时间线、多方表述、已知事实 |
| 2:30–4:30 背景和关键事实 | Discovery | 文件、数据、历史资料，找到关键证据 |
| 4:30–7:00 利益与机制 | Mechanism | 谁受益、谁承担、机制如何运转 |
| 7:00–9:00 不同解释及其证据 | Counterargument | 反方解释、竞争叙事、证据强弱 |
| 9:00–10:00 判断与未知 | Implications | 影响、边界、仍不能确认的部分 |

这是默认骨架，不是秒数门禁。4 分钟的片子可以把 Context/Discovery 合并；12 分钟的片子可以给 Mechanism 两个段落。

## 5. 素材体系

| 素材 | 作用 | 处理 |
| --- | --- | --- |
| 新闻机构原始报道 | 建立事实和时间线 | 切片、网页滚动、截图；画面标来源 |
| 官方公告、文件、财报 | 核实关键事实和数字 | 引用原文；数字给口径 |
| 当事人采访、演讲 | 呈现当事方真实表述 | 保留原声语义，不改原声改变意思 |
| 现场视频、新闻画面 | 现场感和视觉证据 | 核验来源、时间、地点、是否剪辑 |
| 自制图表、地图、动画 | 解释新闻画面说不清的机制 | 流程图、关系图、时间线、数据图 |
| 旁白/评论 | 串联逻辑、提出判断 | 事实/分析/判断分层标注 |

**新闻切片不是主体。** 它的任务是“发生了什么”；“为什么”和“意味着什么”必须由自制图表、动画与旁白完成。

## 6. 事实核验

每条关键事实至少过四关：

1. **来源**：原始机构、作者、时间、链接；转载不算原始来源。
2. **交叉**：至少两个独立来源，或一个原始文件 + 一个独立报道。
3. **时间线**：事件顺序能对上；数字口径一致。
4. **反方检索**：主动找相反证据；找不到也写检索范围。

视频素材额外核验：拍摄时间、地点、原始发布者、是否剪辑/加速/拼接、是否 AI 生成。无法核验的画面，要么不用，要么明确标“未核实”。

## 7. 版权与授权：与 D-099 的关系

所有者 2026-11-14 的 D-099 与 D-101 明确：**硬性门禁只有最终交付质量；没有什么东西是不能引用的。** 不设素材类型准入，不设授权审批。评审提出的版权提醒不改这条规则，只把三件事分开记录：

| 层次 | 规则 | 是否门禁 |
| --- | --- | --- |
| 1 来源使用 | 任何来源都可以作为研究、核查、登记材料；不预先禁止任何来源类型 | 否 |
| 2 内容引用 | 可以在片中使用新闻切片、官方发布、网页滚动、截图、书图、论文图；画面或片尾标来源 | 否 |
| 3 素材再利用 | 实际复制、剪辑、再发布的法律风险单独记录（`rights_note` / `usage`）；标注来源不等于获得授权 | 否；作为风险记录，由所有者决定是否接受 |

只保留三条红线：**不伪造、不错配来源、不改原声以改变语义。** 音乐作为背景使用是另一件事，许可与署名仍按 D-097 记录，属于交付/法律检查，不属于“能不能引用”的内容准入。

## 8. 声音

四层，不按内容类型拦截：

1. **旁白**：解释证据与判断；语速随论证变化。
2. **音乐**：分段进退；关键证据处 `duck` 或 `silence`。
3. **音效**：对应画面动作；不制造无意义刺激。
4. **环境声**：现场感；与原始素材的空间一致。

`sound_design.json` 已经能记录 music/sfx/ambience；预览会把有资产的 cue 混进 480p 预览。正式混音目前仍只消费 BGM，这是已知缺口，不在预览里冒充完成。

## 9. 生产线步骤

```powershell
# 1. 选题与问题定义
#    产物：projects/<系列>/episodes/<slug>/brief.md（一个问题 + 为什么值得解释）

# 2. 来源与证据
course-control ingest --lesson <slug> --source <url|pdf|md>
course-control digest --lesson <slug>
course-control author-accept --lesson <slug> --kind digest

# 3. 事实核查（做不完不开工）
#    产物：lessons/<slug>/authoring/fact-check.md
#    证据矩阵 / 时间线 / 各方说法 / 反方检索 / 数字口径 / 本片明确不主张

# 4. 叙事与脚本（课程形态用 --lesson；主题视频形态用 --project）
course-control narrative-validate --lesson <slug>
course-control script --lesson <slug>
course-control author-accept --lesson <slug> --kind script

# 5. 视觉与声音设计
course-control director-plan --lesson <slug>
course-control visual-design --lesson <slug>
course-control sound-design --lesson <slug>

# 6. 旁白、字幕
course-control narration-build --lesson <slug> --mode reference_only --timing measured
course-control subtitles-build --lesson <slug>
course-control subtitles-qc --lesson <slug>

# 7. 预览：先镜头、再段落、再全片
course-control render shot    --lesson <slug> --shot <id>      --mode preview
course-control render segment --lesson <slug> --segment <id>   --mode preview
course-control render project --lesson <slug>                  --mode preview
course-control preview-pilot  --lesson <slug>

# 8. 正式渲染与发布检查
course-control render project --lesson <slug> --mode release
course-control release-check --lesson <slug>
```

主题视频形态（`project.yaml`）：

```powershell
course-control project-validate --project <内容根>/projects/<系列>/project.yaml
course-control narrative-validate --project <内容根>/projects/<系列>/project.yaml
course-control render project --project <内容根>/projects/<系列>/project.yaml --mode preview
course-control release-check --project <内容根>/projects/<系列>/project.yaml
```

## 10. 验收

按 [新闻与调查报道标准](../新闻与调查报道标准.md) §6 的 100 分制打分，≥75 发布、≥85 专业线；研究与事实准确性 <16/20 不发布。再回答两个问题：

1. 关掉旁白，画面是否仍能成立？
2. 打开旁白，逻辑是否完整？

**注意**：100 分制是人工编辑评分，不是程序比例门禁。如果所有者要取消数字阈值，改 D-096，不在本文暗改。

## 11. 这条线与课程线的区别

| 维度 | 课程线 | 新闻线 |
| --- | --- | --- |
| 内容权威 | 书/教材/论文，先修关系 | 原始报道、文件、当事人表述 |
| 结构 | 五段式，知识递进 | 六幕，矛盾升级 |
| 画面 | 概念、机制、图表、案例 | 原始画面 + 自制图表/地图/动画 |
| 声音 | 旁白为主，音乐克制 | 四层声音，证据处让路 |
| 验收 | 八维 + 交付质量 | 100 分制 + 双验收问题 |
| 复用 | 系列知识地图、视觉词典 | 来源库、claim 库、时间线模板 |

两条线共用渲染、预览、缓存、字幕、混音与 `release-check`；不共用编辑标准和内容结构。
