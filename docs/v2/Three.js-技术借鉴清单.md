# Three.js 技术借鉴清单

- **日期**：2026-11-14
- **状态**：评估记录；不纳入 v0.2，不新增门禁
- **结论**：v0.2 继续做 Blender 管线；v0.2 验收后，再做一个独立的 Three.js 视觉引擎实验。

## 0. 现有技术栈（先校正事实）

`RemotionStudio/package.json` 当前是：

- React **18.3.1**，不是 React 19；
- `@react-three/fiber` **8.18.0**（对应 React 18）；
- `@react-three/postprocessing` **2.16.3**；
- `three` **0.160.0**；
- `remotion` **4.0.539**。

未安装：`@react-three/drei`、Theatre.js、GSAP、VTK.js。

因此“已有 React 19，所以直接上 R3F v9”这个前提不成立；升级 React 19 / R3F 9 是单独的技术升级，不是顺手接入。

## 1. 值得借鉴的技术点

| 技术 | 借鉴价值 | 现在怎么做 |
| --- | --- | --- |
| **GLB / glTF 作为资产交换格式** | 高。Blender 资产可被 Three.js 加载，资产库不绑定单一渲染器 | 下一阶段给资产库增加可选 `glb` 变体与导出记录；先拿 1–2 个资产验证材质/尺度是否无损，不批量转换 |
| **Three.js + R3F** | 中高。已有 R3F 8，可做可参数化、实时三维镜头 | 不新装；v0.2 后用现有栈做一条 10–20 s 实验镜头 |
| **Drei** | 中。相机控制、GLTF 加载、环境辅助能省代码 | 等实验需要时再加；不因为“生态全”而预装 |
| **Theatre.js** | 中。可视化时间线/曲线，适合人工精调相机和灯光 | 暂不引入；Core Apache 2.0，Studio 编辑器 AGPL 3.0，商业化前要单独审许可 |
| **Three.js Postprocessing** | 中。景深、Bloom、AO、色调 | 已有 `@react-three/postprocessing`；优先用现有，不另起一套 |
| **VTK.js** | 高（仅工程/CFD）。体数据、标量/矢量场、网格 | 现在不引入；等汽车空气动力学项目真正需要 CFD 数据展示时再验证 |
| **Remotion** | 高。已有，负责时间轴、字幕、音频、输出 | 继续用；Three.js 只输出按帧画面，不另建视频系统 |
| **GSAP** | 低（当前）。时间线能力强，但会和 Remotion 的帧时间轴形成两套系统 | 不引入；先用 Remotion + R3F 的确定性帧驱动 |

## 2. 工具分工（只作为选型参考，不是门禁）

| 内容 | 优先工具 | 原因 |
| --- | --- | --- |
| 山川、环境、历史场景、电影化镜头 | Blender | 复杂光照、离线渲染、镜头控制 |
| 机械拆解、产品结构、工程镜头 | Blender | 几何、材质、灯光 |
| GPU/芯片/服务器等可参数化结构 | Three.js / Blender | 结构清晰时可实时、可交互；需要电影感时用 Blender |
| CFD 流场、体数据、网格 | Blender + VTK.js | 电影化外壳 + 科学数据表达 |
| 公式、几何推导 | Manim | 数学表达直接 |
| 图表、数据动画、排版 | SVG / Remotion | 文字与数据清晰 |
| 完整课程时间轴 | Remotion + 现有流程 | 统一输出与交付 |

## 3. 建议的实验（v0.2 之后）

同一个 10–20 s 镜头，分别用 Blender 和 Three.js 做一遍，只比较：

1. 制作时间；
2. 画面表现力；
3. 相机/动画控制难度；
4. 1080p 连续输出稳定性；
5. 后续修改成本。

不做自动审美评分，不新增发布门禁。实验结论只回答“这类镜头更适合哪个引擎”。

额外验证 A750 8 GB：

- 浏览器 WebGL 连续渲染 1000+ 帧是否稳定；
- 显存占用与崩溃点；
- headless Chromium 输出是否与预览一致。

## 4. 不借鉴的部分

以下内容不进入 CourseWorkspace，也不新增门禁：

- 六个维度的课程质量评分体系；
- 每条课程一套 Content/Visual/Audio/Technical/Final 五层档案；
- 额外的故事板/关键帧/声音审批关口；
- 自动审美评分、自动导演、自动选引擎。

现有 `release-check`、`media-qc`、`subtitles-qc` 与人工看片已经覆盖交付质量；视觉判断仍由所有者做。

## 5. 结论

- **v0.2 不扩展**：继续 P0–P3。
- **Three.js 不是备用工具**：它是实时/可参数化三维的独立引擎，但先不接入正式流水线。
- **先借 GLB/glTF**：这是最低成本、最高复用价值的接口。
- **先做一条对照实验**：通过后再决定哪些镜头交给 Three.js。
