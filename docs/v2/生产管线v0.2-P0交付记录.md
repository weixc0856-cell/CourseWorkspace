## 1. 已实现

### 1.1 Build manifest

每次 Blender 构建在输出目录的 `manifests/` 下写：

```text
<shot>-<build-id>.json
<shot>-<build-id>.log
```

manifest 记录：

- `build_id`、`project`、`shot`、`environment`
- `builder_version`、`blender_version`、`python_version`、`addons`
- `inputs`：shot spec、environment spec、library、builder、每个资产的路径/版本/许可/`sha256`
- `visual_grammar` 与 `visual_grammar_file` 哈希
- `render_profile`、`render`（engine、samples、resolution、frames、frame_range、fps、passes、output）
- `seed`
- `status`（`running` / `pass` / `fail`）、`error`
- `started_at` / `finished_at` / `elapsed_s`
- `output`、`temp_output`、`log`

资产哈希规则：

- 文件资产（HDRI、heightmap）：哈希文件。
- 贴图目录：递归哈希目录内所有文件。
- 模型（glTF）：递归哈希模型所在目录，覆盖 `.bin` 与同目录贴图，避免“模型文件没变、贴图变了”仍命中缓存。

### 1.2 缓存

缓存键包含：

- shot spec / environment spec / library / builder 的 sha256；
- 每个资产的 id、版本与 sha256；
- Blender、Python、addons、builder 版本；
- render profile 与 render 参数；
- visual grammar id 与 grammar 文件哈希；
- seed。

命中条件：

- 已有 manifest `status=pass`；
- `cache_key` 相同；
- `shot` 相同；
- `output` 文件存在且大小 > 0。

命中时 Builder 不重建场景，直接打印：

```text
ASSET_SCENE_CACHED <manifest> <output>
```

### 1.3 输出原子化

渲染先写临时文件：

```text
.<output-stem>.<build-id>.tmp.<ext>
```

渲染成功后再 `os.replace` 到正式路径。失败保留临时文件与 `status=fail` manifest。

### 1.4 入口

```powershell
# 直接构建（默认启用缓存）
blender --background --factory-startup --python scripts/build_asset_scene.py -- `
  --spec <shot>.json --profile blockout --manifest-dir <dir>

# 强制重建
... --no-cache

# PowerShell 包装（先校验 spec，再构建）
scripts/render-asset-shot.ps1 -Spec <shot>.json -Profile preview `
  -ManifestDir <dir> [-NoCache] [-Frames 1]
```

## 4. 已知限制

- 渲染前的 Python 异常会写 fail manifest；Blender 进程被强制杀死时，manifest 可能停在 `running`，需要人工标记。
- 还没有批量构建器与 `--resume`；单镜重试目前通过逐个调用 shot 实现，已通过的 shot 会命中缓存。
- `review` / `final` profile 尚未加入；当前仍是 `blockout / preview / hero`。
- Visual Grammar 文件已进入哈希，但 Builder 还没有消费它的默认值（P3）。
- 没有记录显存占用；P0 只记录耗时。
- `manifest` 默认写到输出目录的 `manifests/`；如果输出分散，需要显式 `--manifest-dir`。
