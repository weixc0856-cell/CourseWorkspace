# 预览与发布双模式（Preview / Release）实施计划

- **日期**：2026-11-14
- **状态**：生效；按本文实施
- **来源**：所有者 2026-11-14 转发的生产线建议，所有者要求“结合实际梳理计划，全量落实”
- **原则**：只把可核验的客观事实当作门槛。交付质量与法律风险之外，不设比例、秒数、素材禁用一类的门禁。预览层级是工作方式，不是审批关卡。

---

## 1. 差异核验

先把建议里的事实与仓库对一遍。结论：方向成立，但有三处需要按现状改写，否则会重复造已有的东西。

| 建议中的主张 | 仓库现状 | 处置 |
| --- | --- | --- |
| 目前没有 480p 快速预览 | **已有**：`course-control animatic`（FR-40）输出 480p 全片、旁白、contact sheet、逐单元缓存；三门口径实测 | 保留，作为 P2 的现有实现；新增 P0/P1 与统一入口，不重建 P2 |
| `build` 从脚本直接进正式渲染 | 主链确实到 `verify` 就结束；但 `producer-run` 已有“订单 → 导演 → build → 清单”，`checkpoint` 已有阶段 DAG 与 resume | 统一入口优先复用这两层，不另写调度器 |
| Visual Direction 没有被引擎消费 | 属实。`build` 只消费主题映射（`pipeline.py:183`），构图/关键帧/运动/连续性未进入成片 | 把完整设计写入 `shots.json`，由 Remotion 消费；引擎侧导出 `design.json` 并给出读取约定 |
| Sound Design 没有被消费 | 属实。`pipeline.py` 不读 `sound_design.json`，`audio_mix` 只消费 BGM | 预览混音读取 cue；正式混音只消费有资产、许可与电平可核的 cue，缺资产记 warning |
| 课程与主题视频是两套生产 | 属实。16 个交付物里 5 个是线外 Remotion/FFmpeg 作品，不在 `lessons/` | 统一 `ProjectSpec` 入口与构建记录；不强行统一底层引擎 |
| 修改一个镜头应只重渲染受影响部分 | `checkpoint` 是阶段级，`producer-rebuild` 是镜头指纹，`animatic` 是单元级缓存；**缺**引擎单镜头预览缓存 | 新增预览缓存，键含镜头源、设计、配置、分辨率 |
| 需要 `release-check` | 不存在；`build` 不跑 `media-qc`/`quality-report` | 新增一条命令串起现有检查，`PASS/FAIL/INCOMPLETE` 三态 |
| 风水第一期有 20 个镜头 | 实际是一条 152 s 的 Remotion 单片（`RemotionStudio/src/fengshui/`），没有镜头文件；`data.ts` 有 21 个时间区段 | P0/P1 以时间窗为单位，先不改内容结构 |
| 480p 是低质量成片 | 预览不是交付物 | 所有预览产物写 `preview` 身份，禁止进 `deliver/` |

## 2. 两个模式，三个层级

### 2.1 模式

| 模式 | 用途 | 分辨率 | 产物位置 | 能否交付 |
| --- | --- | --- | --- | --- |
| `preview` | 尽早发现问题、缩短反馈循环 | 短边 480（横 854×480，竖 480×854） | `build/<slug>/preview/` | 否 |
| `release` | 正式渲染与发布 | 课程/项目声明值（默认 1080p+） | `build/<slug>/final/` | 是，且仍需 `release-check` |

预览改变的是成本，不改变设计：摄影机、灯光、场景、运动、字体、构图、配色、时间线全部沿用正式配置，只降低分辨率、采样、编码与部分后处理成本。

### 2.2 层级

| 层级 | 命令 | 回答的问题 | 默认成本 |
| --- | --- | --- | --- |
| P0 镜头 | `render shot` | 这个镜头本身成立吗 | 最低 |
| P1 段落 | `render segment` | 这些镜头连起来成立吗 | 中 |
| P2 全片 | `render project --mode preview` | 整条片子像完整作品吗 | 接近完整 |

三个层级都可以单独跑。**没有“必须每集都做 P0/P1”的规定**；成熟模板可以只做 P2 或抽样。触发预览的条件是变更：新增风格、组件、场景类型、引擎版本、字体/材质/灯光、镜头衔接，或此前出过错的模块。

## 3. 统一入口

```text
course-control render shot    --lesson <slug> --shot <id> [--mode preview|release]
course-control render segment --lesson <slug> --segment <id> [--mode preview|release]
course-control render project --lesson <slug> [--mode preview|release]
course-control render project --project <path>/project.yaml [--mode preview|release]
course-control preview-pilot  --lesson <slug>                # P0/P1/P2 成本记录
course-control release-check  --lesson <slug> [--json]
course-control release-check  --project <path>/project.yaml [--json]
```

- 课程与主题视频共用同一套命令、预览产物结构和构建记录。
- 主题视频在 `project.yaml` 的 `production.topic_video` 下声明 `entry` / `composition` / `segments`，不要求改写成课程。
- 课程项目在 `project.yaml` 的 `production.course.lesson` 指向已有课程；缺省用 project id。
- `--mode release` 对课程走现有 `run_build`；对主题视频走同一套 release 记录与检查。

## 4. 增量与缓存

每个预览单元有指纹，至少包含：

- 单元设计数据（`visual_design.json` 中该单元的条目）
- 镜头/场景源文件与依赖资源的 SHA-256
- 渲染入口、composition、帧范围
- 预览配置（短边、fps、编码）
- 字体、主题、材质等全局资源的版本

指纹一致即复用；不一致只重编该单元。P1/P2 只重新拼接受影响的单元。

预览缓存与正式缓存物理分开：`preview/cache/` 只能服务预览，禁止升级为交付文件。

## 5. 发布检查

`release-check` 只回答“这一版能不能发”，按顺序执行并记录每一步：

1. `media-qc`（全片解码、响度、黑帧、冻结、字幕结构）
2. `subtitles-qc`（启用字幕时）
3. `quality-report`（五维汇总）
4. `quality-gate`（硬失败、未完成、阻断警告）
5. `quality-certificate`（发布结论）

结果只有三种：

- `PASS`：所有要求的检查执行且通过。
- `FAIL`：有明确不合格项。
- `INCOMPLETE`：缺检查、缺证据或检查无法执行；**不得当作通过**。

不新增风格、比例、秒数、素材类型门禁。事实与证据按现有 ContentQA/claim 规则核验；法律风险按现有许可规则核验。

## 6. 落地顺序

| 阶段 | 工作 | 完成标志 |
| --- | --- | --- |
| A | 预览核心：模式、层级、单元、缓存、Remotion 时间窗渲染、引擎单镜头渲染 | P0/P1/P2 可跑，产物带 `preview` 身份 |
| B | 统一入口：`render` 命令组；课程/主题视频共用 | 一门课与一条主题视频用同一命令出预览 |
| C | 设计消费：`visual_design.json` → `shots.json` → Remotion；引擎导出 `design.json` | 改设计会改画面，且会触发对应单元重渲 |
| D | 发布检查：`release-check` 串起现有五步 | 输出三态，缺项不通过 |
| E | 声音预览：旁白 + BGM + 有资产的 cue | P2 预览可听出音乐进退 |
| F | 试点：风水第一期 P0/P1/P2 + 1080p 对照，记录时间、差异、返工 | 一份实测记录 |
| G | 文档与状态：README、阅读顺序、PROJECT_STATUS、CLAUDE 编号 | 文档不再互相打架 |
