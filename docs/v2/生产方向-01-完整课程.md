# 生产方向 01：10–20 分钟完整课程

- **日期**：2026-11-14
- **定位**：指导性生产方向，不是新的门禁。契约仍以 PRD、ARCHITECTURE、ACCEPTANCE 为准。
- **适用**：一本书、一个学科或一套理论拆成的系列课程；单集 10–20 分钟，集与集之间有知识递进。
- **当前实例**：汽车空气动力学 90 集（10 分钟/集，D-094）；`02-car-aerodynamics` 已是 20 分钟 `standard` 配置。Information Rules 是同一方向的候选书。

---

## 1. 这是什么，不是什么

**是**：一门课的一集。观众看完一集，能回答一个明确问题；看完一季，能建立一套前后依赖的知识结构。

**不是**：书的章节摘要；不是把目录换成视频列表；不是单条爆款科普；不是把 20 分钟压成 5 分钟的视觉集锦。

这个方向的中心不是“画面多漂亮”，而是**知识递进 + 视觉解释 + 可持续生产**三件事同时成立。

## 2. 产品单位与时长

| 层级 | 单位 | 当前落点 |
| --- | --- | --- |
| 系列 | 一本书 / 一个学科 / 一套理论 | `projects/<系列>/project.yaml`（`mode: course`）+ 系列大纲 |
| 季 | 8–12 集，约 80–180 分钟 | `project.yaml` 的 `production.course` |
| 集 | 10–20 分钟，只回答一个核心问题 | `lessons/<slug>/lesson.yaml` |
| 段 | 2–5 分钟，承担一个论证步骤 | `authoring/production.yaml` 的 `sequences[]` |
| 镜 | 5–15 秒，一次视觉变化 | `storyboard.yaml` / `production.yaml` 的 shots |

时长用课程自己的 `duration` 声明，不用全局秒数门禁：

```yaml
duration:
  profile: standard        # target 1200 s / max 1320 s
  target_seconds: 1200
  min_seconds: 1080
  max_seconds: 1320
  page_tolerance_seconds: 1.5
```

`standard` 的默认窗口是 target 1200 s、max 1320 s，已经覆盖 20 分钟。此前 `ai-economics-e01` 的 950 s 是**该课自己写的 max**，不是全局上限；要改的是那一课的声明，不是校验器。

已知风险：a01 在 21.5 分钟、307 条字幕处失败并整集归档（D-093）。10–20 分钟单元必须用 P1/P2 提前看字幕密度、旁白同步和段落节奏，不等到成片再发现。

## 3. 一集的结构

默认五段，不按书的目录切，按观众的认知顺序切：

| 段 | 时长预算（非门禁） | 任务 | 画面 |
| --- | --- | --- | --- |
| 1 问题 | 0:00–1:30 | 用一个具体问题、反常识或现实案例进入；告诉观众这一集要回答什么 | 一个强视觉锚点 + 一句问题 |
| 2 建立 | 1:30–5:00 | 给出理解问题所需的最少概念；每个概念配一个可复用的视觉对象 | 图表、关系图、机制动画 |
| 3 推进 | 5:00–12:00 | 用案例/数据/推导把概念推到结论；这是主体 | 2–4 个段落，每段一个论证动作 |
| 4 反证 | 12:00–16:00 | 给出一个反例、边界条件或竞争解释；说明结论在哪儿不成立 | 对照、分支、失败案例 |
| 5 收束 | 16:00–20:00 | 回答开头的问题；给出一句可带走的结论；为下一集留一个具体问题 | 回到开头画面 + 下一集钩子 |

短集（10–12 分钟）把 3/4 段压紧，不删掉“反证”；长集（18–20 分钟）可以多一个案例段，但不把同一结论讲两遍。

**结构不是门禁。** 分集方案里写明为什么偏离，就可以偏离；发布检查不检查段数或秒数。

## 4. 参考对象怎么用

参考对象只校准方法，不复制内容与风格。每个参考对象按五个问题拆：

1. **开场**：问题、故事、反常识还是现实案例？
2. **知识组织**：一集讲几个概念，它们是什么关系？
3. **解释方式**：案例、图表、数学模型还是动画？
4. **知识递进**：前面建立的视觉/概念，后面怎么再次出现？
5. **收束**：形成什么新理解，留下什么问题？

落到本项目的参照。第一轮先看六个：CrashCourse、MRU、Yale Financial Markets、Wendover、3Blue1Brown、The Swedish Investor；其余作为补充。

| 参照 | 学什么 | 不学什么 | 本项目落点 |
| --- | --- | --- | --- |
| CrashCourse | 一集一个独立问题；前后集铺垫；理论/案例/总结的配比 | 快节奏、高密度剪辑 | 分集大纲、`narrative-plan`、每集问题句 |
| Marginal Revolution University | 一个理论拆成多个知识点；图表解释关系；单集知识负担 | 纯板书式画面 | `outline` 的知识点拆分、`visual-design` 的图表镜头 |
| The Great Courses | 一门课如何分章；几十集如何保持整体一致 | 传统讲座形式 | 系列 `project.yaml`、集号与先修关系 |
| Wendover Productions | 从具体问题切入；地图/数据/动态示意图；多场景推进 | 纯纪录片式的素材堆叠 | `production.yaml` 的段落与镜头、地图/流程镜头 |
| Economics Explained | 理论与现实案例的连接；数据图表支持观点 | 宏观概述替代严谨教材 | `fact-check.md`、证据矩阵、案例镜头 |
| 3Blue1Brown | 连续视觉概念；前面建立的画面在后面复用 | 每集重新起一套视觉 | `continuity` 对象、`visual-design.yaml`、主题映射 |
| YaleCourses | 学科深度；从基本问题建立完整框架 | 课堂录制形式 | 分集大纲的论证链、参考书目 |
| StatQuest | 概念拆得细；前后依赖明确；直观 → 数学 | 低视觉投入 | 概念先修图、`outline` 的知识点粒度 |
| The Swedish Investor | 一本书的核心思想提炼；章节组织成一条论证主线 | 书籍摘要式复述 | 系列总纲、每集“一个论点” |

拆解记录放在 `<内容根>/references/<id>/`，用 `course-control reference-compare` 对比。**不要在仓库里存参考视频或截图。**

## 5. 生产线步骤

以一门课的一集为例。每一步都可以单独跑，失败就停在原地，不跳到下一步。

### 5.1 系列级（一本书一次）

```powershell
# 1. 系列契约：集数、单集时长、来源
course-control project-validate --project <内容根>/projects/<系列>/project.yaml

# 2. 总纲：集号、标题、核心问题、先修关系
#    产物：projects/<系列>/COURSE_MAP.md、第一季方案.md

# 3. 参考拆解：六个参照各一份五问记录
#    产物：<内容根>/references/<id>/record.md
```

### 5.2 单集级

```powershell
# 1. 证据与来源
course-control ingest --lesson <slug> --source <book|paper|url>
course-control digest --lesson <slug>
course-control author-accept --lesson <slug> --kind digest

# 2. 分集方案 / 大纲 / 脚本
course-control brief --lesson <slug>
course-control outline --lesson <slug>
course-control script --lesson <slug>
course-control author-accept --lesson <slug> --kind outline
course-control author-accept --lesson <slug> --kind script

# 3. 叙事契约（长视频必须）
course-control narrative-validate --lesson <slug>

# 4. 导演与设计
course-control director-plan --lesson <slug>
course-control visual-design --lesson <slug>
course-control sound-design --lesson <slug>

# 5. 旁白与字幕
course-control narration-build --lesson <slug> --mode reference_only --timing measured
course-control subtitles-build --lesson <slug>
course-control subtitles-qc --lesson <slug>

# 6. 预览：先镜头，再段落，再全片
course-control render shot    --lesson <slug> --shot <id>      --mode preview
course-control render segment --lesson <slug> --segment <id>   --mode preview
course-control render project --lesson <slug>                  --mode preview
course-control preview-pilot  --lesson <slug>                  # 记录 P0/P1/P2 成本

# 7. 正式渲染
course-control render project --lesson <slug> --mode release

# 8. 发布检查
course-control release-check --lesson <slug>
```

### 5.3 每集必须留下的证据

- `authoring/sources.yaml`：来源、作者、版本、页码/URL、取用位置。
- `authoring/fact-check.md`：事实、推论、争议、未知；关键数字的口径。
- `authoring/narrative-plan.json`：六段叙事骨架与时长。
- `authoring/production.yaml` 或 `storyboard.yaml`：镜头、段落、引擎、转场。
- `build/<slug>/design/visual_design.json`：构图、关键帧、运动、连续性。
- `build/<slug>/sound/sound_design.json`：旁白、音乐、音效、环境声、混音目标。
- `build/<slug>/quality/`：字幕 QC、媒体 QC、质量报告、发布证书。

## 6. 预览策略

| 层级 | 什么时候做 | 看什么 | 不通过时 |
| --- | --- | --- | --- |
| P0 镜头 | 新镜头、改构图/运动/引擎版本 | 主体、层次、文字安全区、运动动机 | 只重做该镜头 |
| P1 段落 | 镜头衔接、旁白与画面同步、风格切换 | 段落是否讲完一个论证动作 | 只重做该段落 |
| P2 全片 | 每集正式渲染前 | 节奏、信息密度、前后风格、声音关系 | 回 P1 或改脚本 |

**默认每集做 P2；P0/P1 按变更触发，不做硬性次数要求。** 成熟模板可以只做 P2 或抽样；新增风格、组件、引擎版本、字体/灯光/衔接逻辑时，重新做 P0/P1。

预览不是交付物：`build/<slug>/preview/`，不进 `deliver/`。

## 7. 质量与验收

按 [课程质量模型](../课程质量模型.md) 八维逐项过，程序能查的用命令，剩下的人看：

| 维度 | 程序证据 | 人工判断 |
| --- | --- | --- |
| 01 知识质量 | `sources.yaml`、`fact-check.md`、claim 证据 | 结论是否被来源支持 |
| 02 教学设计 | 大纲目标、先修关系、`teaching-qa` | 递进是否成立 |
| 03 叙事与编辑 | `narrative-validate`、段落时长、`plan-audit` | 问题是否闭环、节奏 |
| 04 视觉导演 | `visual-design`、`layout-validate`、P0/P1 | 构图、重心、三帧是否演进 |
| 05 声音导演 | `sound-design`、`audio-plan`、媒体 QC | 听感、旁白优先 |
| 06 学习配套 | 交付清单 | 讲义、术语表、练习 |
| 07 观众体验 | 标题、封面、字幕 QC | 3 秒是否建立主题 |
| 08 工程交付 | `release-check`、锁、增量、清单 | 最终签收 |

发布只回答三件事：内容是否讲明白、画面关掉旁白是否成立、交付是否达到发布标准。**不设“必须有 N 个镜头”“动画必须占多少比例”“每集必须多少秒”的门禁。**

## 8. 系列连续性

系列不是把单集拼起来。每季至少维护三份东西：

1. **知识地图**：集号、核心问题、先修集、复用概念。
2. **视觉词典**：反复出现的对象（如汽车、气流、边界层）在每一集的外观、颜色、视角。
3. **声音词典**：旁白音色、术语读法、音乐主题、标志性音效。

视觉词典落到 `visual-design.yaml` 的 `continuity` 对象与 `theme`；声音词典落到 Voice Bible / Lexicon 与 `sound_design.json`。同一对象在下一集出现时，先查词典，不重新设计。

## 9. 试点与指标

第一集 10–20 分钟样片用 `preview-pilot` 记录：

- P0 / P1 / P2 各花多少时间；
- 正式渲染时间；
- 需要人工修改的镜头数；
- 每轮返工次数；
- 缓存命中率；
- 字幕 QC / 媒体 QC / 发布检查结果。

这些数字决定这一季能不能按 10–20 分钟排产，不靠感觉。

## 10. 不做什么

- 不把书的目录直接变成集号；先做知识地图，再分集。
- 不为了“像课程”而拉长；7 分钟能讲清楚就按 7 分钟交付。
- 不为了“像视频”而加无解释作用的运镜、粒子和转场。
- 不把参考频道的风格当模板；只借结构、证据组织与视觉语法。
- 不在没有来源的情况下生产；无法验证的内容不交付。
