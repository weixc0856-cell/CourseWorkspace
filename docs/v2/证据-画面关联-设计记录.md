# 证据—画面关联：P4 设计记录

- **日期**：2026-11-14
- **状态**：设计记录，未生效；v0.2 不实现
- **位置**：v0.2 验收之后的 P4
- **目的**：让重要画面能追溯它解释的观点、依据和确定性等级，而不是只靠旁白或画面暗示。

## 1. 为什么放到 P4

v0.2 先解决可复现、Environment Linking、Shot Review、Visual Grammar + QC。证据—画面关联需要改动 shot spec、review 模板与 release-check，属于内容语义层；在镜头级生产还不稳定时加入，会把 Builder 和数据契约一起放大。

## 2. 拟议字段

Shot spec 可选增加：

```json
{
  "claim": {
    "id": "ridge-blocks-wind",
    "text": "A ridge reduces wind speed behind it.",
    "type": "fact",
    "evidence_ref": "authoring/fact-check.md#ridge-wind",
    "source_note": "Measured / reported / inferred; state which."
  }
}
```

`type` 只允许四类，与新闻标准一致：

- `fact`：已证实；
- `report`：来源报道；
- `inference`：本片推论；
- `unverified`：未证实，不得包装成结论。

## 3. 消费方式

- `review.md` 显示 `claim.id / type / evidence_ref`，让人先看依据再看画面。
- `release-check` 只在 shot 声明了 `claim` 时检查 `evidence_ref` 是否存在；没声明不扣分，避免把每个氛围镜头都变成证据题。
- 如果画面与 claim 类型不符（例如 `unverified` 被写成肯定句），记录为缺陷，不自动判定审美。
- 不在 Blender 里做语义判断；证据关联只进入 spec、review 和 release 报告。

## 4. 不做什么

- 不新增风格/比例/秒数门禁。
- 不要求每个镜头都有 claim。
- 不让 AI 自动给事实置信度；置信度来自证据文件。
- 不在 v0.2 改数据库、schema 或验收项。

## 5. P4 验收（未来）

1. 一个 shot 能声明 claim 与 evidence_ref。
2. Review Package 显示 claim 类型与依据路径。
3. release-check 对声明了 claim 但缺 evidence_ref 的 shot 报 `INCOMPLETE`。
4. 未声明 claim 的镜头不被惩罚。
