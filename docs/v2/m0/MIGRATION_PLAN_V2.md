# CourseWorkspace V2 迁移计划（草案）

- **日期**：2026-11-13
- **状态**：**草案，未生效**
- **用途**：回答一个问题——现有 217 个 CourseControl 源文件、28 个 Schema、六个渲染工程，V2 落地时各自怎么办。
- **底线**：不推倒重来；不新增平行实现；每个阶段都能独立验收，失败可停在原地。

---

## 1. 结论

现有生产引擎（渲染、合成、声音、知识抽取、交付）保留。V2 新增的是**前端 Intelligence、统一项目契约、编排拓扑、质量闭环**四块。旧模块通过适配器接入，不做目录搬迁。

分阶段顺序有一条硬依赖：**P5 的真实运行必须先于任何抽象设计**。没有一次真实的全链路数据，ProjectSpec 与自动化等级的字段就是猜的。M0 文档可以先行（本轮已完成），代码改造按 M1 之后推进。

## 3. 阶段划分

### M0 · 文档基线（本轮，已完成草稿）

- 产出：本目录六份文件。
- 验收：六份文件能被逐条追溯到代码或缺口编号（F-1～F-10）；不声称任何未实现的能力。
- 风险：与 PRD/ARCHITECTURE 并行。控制方式：M1 起逐条并入权威文档，本目录不新增第 7 份。

### M1 · 闭环修补（成本最低，收益最直接）

范围（全部来自 `V2-工业化完成度评估.md` §7）：

1. F-1 字幕 QC 接入交付门。
2. F-2 质量门校验报告新鲜度。
3. F-3 预览与验收容差一致，超阈值告警。
4. F-9a/b/c 文档漂移、状态矛盾、`PROJECT_STATUS.md` 更新。
5. F-8 五态映射表。

验收：三条失败路径各有自动化测试；文档中引用的路径全部可解析。

### M2 · P5 真实基线

选一门新课，用现有命令手工走完八阶段，全程记录：每阶段耗时、人工动作、失败点、重跑范围。

验收（沿用 V2 评估 §6 前三条）：

1. 20 分钟课从研究走到 `package-verify` 通过，`quality-gate` 五维无 `incomplete`。
2. 至少一次真实返工，返工后只有受影响片段重编。
3. 改一次旁白，只有旁白/字幕/混音重做，画面指纹不变。

这一步不写新代码（M1 除外），产出是数据。ProjectSpec 的字段从这些数据里来。

### M3 · 契约落地

新增 ProjectSpec、ArtifactRegistry、RunRecord。要求：

- 只读接入，不改变现有命令行为。
- 没有 `project.yaml` 的项目由现有契约合成，标记 `synthesized: true`。
- 索引可从目录重建。

验收：13 门存量课用合成路径全部通过 validate；新项目用真实 ProjectSpec 通过。

### M4 · 编排拓扑

- `STAGE_ORDER` 换成阶段 DAG，默认路径与现在一致。
- 恢复粒度细化到下游子图。
- 新增 `RECOVERY_EXHAUSTED` 的落点。

验收：注入一个阶段失败，恢复只重跑受影响节点；与 M2 的返工范围数据一致。

### M5 · 质量闭环

- defect 统一 schema，五维检查改为产出 defect。
- 诊断：归因映射表 + 影响面反查。
- 修复：四类策略，attempt 上限 3。
- 回归：defect 集合差分，报告新鲜度强制校验。
- 交付证书。

验收：用 M2 的真实缺陷样本重放，系统能诊断、修复、复验并在无法修复时停机。

### M6 · 前端 Intelligence 与 Mode B

- UNDERSTAND：概念层、claim 层、冲突处理。
- PLAN：课程大纲与叙事结构自动生成，覆盖与先修检查。
- Mode B：`profile: news` 先行，再扩通用主题视频。

验收：给一本书产出前 3 集课程规划；给一个主题产出一条视频规划；规划通过覆盖/先修/一致性检查。

## 4. 依赖与风险

| 风险 | 影响 | 应对 |
| --- | --- | --- |
| M0 文档与 PRD 并行，逐渐分叉 | 第二套真相 | M1 起逐条并入；M6 结束前本目录标记为历史 |
| 没有 P5 数据就设计 ProjectSpec | 字段猜错，返工 | M2 先于 M3 |
| A3 对事实验证的要求被低估 | 系统停不下来，或胡乱通过 | 证据状态机先于自动化创作落地 |
| 单机资源成为瓶颈 | 30–50 集无法调度 | 先测单集墙钟，再谈系列排产 |
| 修复闭环引入不确定性 | 越修越乱 | attempt 上限与熔断规则先行 |

---

## 5. 不做什么

- 不迁移目录、不重命名现有包、不改 80 个现有命令。
- 不替换渲染引擎、不引入外部工作流引擎、不引入数据库服务。
- 不在 M2 之前写自动创作代码。
- 不为通过检查而修改阈值或预期。
