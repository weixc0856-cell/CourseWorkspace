# CourseWorkspace V2 产品规格（草案）

- **日期**：2026-11-13
- **状态**：**草案，未生效**。本文件描述产品责任边界的目标形态；生效前必须先改 `docs/PRD.md` 并在 `docs/DECISIONS.md` 记一条决策。
- **取代关系**：不取代 `docs/PRD.md` v1.0。两版并存期间，代码与验收以 PRD v1.0 为准。

---

## 1. 产品定义

CourseWorkspace 是一套**内容生产系统**：

> 输入原始材料，产出达到精品标准的课程或主题视频，全程无人值守，质量验收是唯一交付门槛。

与 PRD v1.0 的"把人工撰写的课程内容转换成成片视频"相比，系统承担的责任从**生产**前移到**研究、规划、创作**，从"工具链"变成"生产线"。

### 1.1 一句话边界

系统负责：理解材料 → 建立知识结构 → 设计教学内容 → 写脚本 → 视觉导演 → 生产媒体 → 质量验收 → 打包交付。

系统不负责：替所有者决定"要做成什么"（选题与系列战略仍由人定），不替所有者承担事实责任的最终归属。

---

## 2. 两种原生生产模式

两种模式共用同一个生产内核，差别只在输入组织方式与内容组织策略。

| 维度 | Mode A 课程生产 | Mode B 主题视频 |
| --- | --- | --- |
| 输入 | 一本书、多份 PDF/论文/网页、已有课程材料、明确主题 | 一个主题、一个问题、一篇文章、一组参考资料、一个研究方向 |
| 中间结构 | 知识图谱 → 课程大纲 → 分集规划 | 研究结论 → 叙事结构 → 单集或系列规划 |
| 组织单位 | 集（lesson），一集 10–30 分钟 | 视频（video），单条 3–20 分钟或系列 |
| 质量重心 | 知识覆盖、先修关系、学习效果 | 事实准确、叙事完整、信息表达效率 |
| 交付模板 | 视频 + 音频 + 字幕 + 讲义 + 课件 + 练习 + 来源 + 质量证书 | 视频 + 音频 + 字幕 + 文稿 + 来源 + 质量证书 |
| 现有对应 | `lessons/<slug>/` + `course-control build` | `docs/新闻视频生产流程.md` 的人工流程，尚无独立模式 |

课程集数 30–50 是**规划目标区间**，不是硬门禁。实际集数由知识体量决定，允许落在区间外并记录理由。

## 3. 与 PRD v1.0 的冲突点

这些冲突必须显式解决，不能靠写架构文档绕过。

| # | PRD v1.0 位置 | 原文要点 | V2 目标 | 处理方式 |
| --- | --- | --- | --- | --- |
| C-1 | §1 产品目标 | 把**人工撰写的课程内容**转换成成片 | 从原始材料自动产出 | 改写目标段落 |
| C-2 | §1.2 非目标 | 无人工确认的整课内容直接落盘 | 无人工审批节点 | 删除或改写该条 |
| C-3 | §1.2 非目标 | 让 LLM 直接判定课程事实正确性 | 程序化证据验证 + 独立来源；LLM 只产候选判断 | 改写为"LLM 不单独裁决事实，裁决依据是可定位证据与确定性检查" |
| C-4 | 硬约束 1（CLAUDE.md） | 课程正文只允许格式级调整，改语义必须先问 | 自动生成内容需要新的所有权与审校规则 | 新增"生成内容的归属与责任"条款 |
| C-5 | 硬约束 4（CLAUDE.md） | AI 输出不等于已完成，最终事实判断由人工与来源证据负责 | 证据验证自动化，人只在拒收复核时出现 | 改写为"AI 输出必须经程序校验；无法验证即不交付" |
| C-6 | §1.2 非目标 | 多用户并发、多机器调度不在范围 | 仍是单机，V2 不改变 | 保持 |
| C-7 | D-071 / 质量基准 | 发布需要人工签核 | 自动验收，人只在成品复核时介入 | 另立决策，不与 V2 绑定 |

C-1 至 C-5 属于同一次决策，应一次性记录，避免出现半套边界。

## 4. 质量定位

**Premium。** 五个必要条件，缺一不交付：

1. 知识准确：每条事实主张有可定位来源；冲突来源已处理；数据口径一致。
2. 结构完整：课程有先修关系与覆盖检查；主题视频有完整叙事弧。
3. 视觉达标：按 `docs/知识视频质量基准.md` 的三层验收，L1 全过，L2 按分块达标。
4. 音频达标：响度、语速、停顿、字幕对齐按现有 `subtitles-qc` / `media-qc` 规则。
5. 交付完整：manifest 全项 present，`package-verify` 通过，质量证书附在交付包内。

质量不是"检查跑完了"，是"检查的结论支持交付"。`incomplete` 一律视为未通过。

## 5. 自动化等级

统一定义四级，避免"全自动"被不同模块各自解释。

| 等级 | 含义 | 人的位置 |
| --- | --- | --- |
| A0 | 人工驱动，工具辅助 | 每一步 |
| A1 | 自动执行，人工逐步确认 | 每个阶段末 |
| A2 | 自动执行，只在异常时请求确认 | 异常 |
| A3 | 无人值守，自动诊断、修复、重试；不合格不交付 | 只在最终拒收复核 |

V2 目标是 A3。当前系统在 A0–A1 之间：构建、渲染、校验自动，研究、创作、审批是人工。

A3 的硬性停机条件（不满足就停在原地，产出缺口报告，不降级交付）：

- 事实无法用可定位证据验证，且补充研究后仍无法验证。
- 自动修复达到策略上限（同一缺陷 3 次），按项目熔断规则停手。
- 资源限制触发（`ProductionOrder.limits`：墙钟、API 成本、本地模型调用次数、磁盘）。
- 任何阶段出现 `blocked` 且没有允许的回退路径。

## 6. 用户角色

| 角色 | V1 做什么 | V2 做什么 |
| --- | --- | --- |
| 所有者 / 制片人 | 写内容、审内容、签核发布 | 给材料、定选题与标准、看成品、拒收 |
| 系统 | 渲染与合成 | 研究、规划、创作、生产、验收、修复 |
| 审稿人 | 逐条核对事实 | 只在系统停机时处理缺口 |

人的工作从"逐页写"变成"定标准与验收"，这是产品边界变化带来的直接后果，也需要新的操作规范。

---

## 7. 成功标准

产品级验收（不是单集验收）：

1. 给一本书，系统在无人介入下产出至少 3 集可交付课程，每集通过 `package-verify` 与质量证书。
2. 给一个主题，系统在无人介入下产出一条可交付主题视频。
3. 两种模式共用同一套 ProjectSpec、同一套质量引擎、同一套交付包结构。
4. 任何一集失败时，系统能定位到阶段与受影响资产，重跑范围小于全量。
5. 无法验证的内容被拦下，并留下缺口清单，而不是悄悄发布。

单集验收标准沿用 `docs/知识视频质量基准.md` §7.2 的必填结构。

---

## 8. 明确不做

在线编辑器、逐帧人工修改工具、多人协作审稿平台、实时交互教学、自研基础模型、自研 3D 渲染引擎、多 Agent 自由讨论系统。

这些能力与"无人值守做稳定"没有直接关系，V2 期间不投入。
