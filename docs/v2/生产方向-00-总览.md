## 2. 共用的生产线

三条线共用同一套控制层，不共用内容标准和视觉语法：

```text
ProjectSpec / lesson.yaml
  → validate / narrative-validate
  → director-plan / visual-design / sound-design
  → narration-build / subtitles-build
  → render shot | segment | project --mode preview
  → preview-pilot（成本记录）
  → render project --mode release
  → release-check（PASS / FAIL / INCOMPLETE）
```

- 课程项目：`project.yaml` 的 `production.course.lesson` 指向已有课程。
- 主题视频/新闻/3 分钟片：`project.yaml` 的 `production.topic_video` 声明 `entry` / `composition` / `output` / `delivery_dir` / `shots` / `segments` / `licences`。
- 所有线共用预览缓存、增量指纹、字幕、混音与发布检查；引擎可以不同。

## 3. 什么不是门禁

以下都不是发布条件：

- 镜头数量、动画比例、每集秒数、每段时长；
- 必须做 P0/P1/P2 几次；
- 必须使用某种视觉语法、某种引擎、某种转场；
- 素材类型、素材来源、是否“授权”；
- 画面风格、配色、字体、构图偏好。

预览层级是工作方式；成熟模板可以只做 P2 或抽样。触发预览的是变更，不是日历。

## 4. 什么仍然是门禁

- **客观事实**：来源、引述、数字、时间线、画面上下文；无法验证的内容不交付。
- **交付质量**：解码、分辨率/帧率、响度/峰值、黑帧/冻结、字幕结构、音画同步、许可与署名（音乐作为背景使用时）。
- **法律红线**：不伪造、不错配来源、不改原声语义。

`release-check` 只输出 `PASS` / `FAIL` / `INCOMPLETE`；缺检查、缺证据、无法执行记 `INCOMPLETE`，不得当作通过。

## 5. 需要所有者决定的三件事

1. **新闻 100 分制**：现有标准 ≥75 发布、≥85 专业线。如果只保留“交付质量”门禁，需要决定这个数字阈值是否继续作为发布条件（改 D-096）。
2. **风水无旁白**：现有频道规则是“无旁白，英文大字 + 中文字幕”；评审建议的旁白驱动结构与它冲突。保持无旁白，或改系列规则。
3. **10–20 分钟课程**：现有 `duration.profile: standard` 默认 target 1200 s / max 1320 s，已覆盖 20 分钟；此前 `ai-economics-e01` 的 950 s 是课程自己的声明，不是全局上限。若要统一 10–20 分钟，按课程声明窗口，不新增全局秒数门禁。
4. **素材引用与再利用**：来源使用、内容引用不设准入；实际复制/再发布的法律风险只做记录（`rights_note` / `usage`），不作为门禁。音乐作为背景音乐使用时，许可与署名仍按 D-097 记录；如果所有者要连这条也取消，需要明确改 D-097，本文不暗改。
