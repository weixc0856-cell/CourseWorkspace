## 0. 结论

v0.1 已经打通：

```text
Spec → Validate → Build → Render → Assemble
```

但这只证明“能生成画面”，还没有证明“能稳定生产”。v0.2 不追求更多功能，先把五件事做实：

1. 同一个 Environment 能被多个 Shot 独立引用；
2. 修改一个 Shot 不会污染共享 Environment；
3. 每次构建都能追溯输入资产、版本与参数；
4. 每个 Shot 都能自动生成可审查的 Review Package；
5. Visual Grammar 与技术 QC 真正进入 Builder 和 release 流程。

**AI Planner 暂缓。** 在 Builder 接口稳定之前，不让 AI 自动生成完整场景。

| 项 | 决策 |

### 新增模块

```text
CourseControl/src/course_control/scene_spec/
  manifest_core.py     # stdlib：哈希、版本采集、manifest、缓存键与原子写入
```

`manifest_core.py` 不依赖 pydantic，Blender 5.2 自带 Python 3.13 可直接按文件路径加载；CourseControl 的测试从包内导入同一份逻辑。

### Build Manifest

每次 shot 构建生成：

```json
{
  "schema_version": 1,
  "build_id": "20261114T221500Z-a1-3f2c",
  "project": "fengshui-a",
  "shot": "a1",
  "builder_version": "0.2.0",
  "blender_version": "5.2.3",
  "python_version": "3.12.x",
  "addons": [{"name": "io_scene_gltf2", "version": "..."}],
  "inputs": {
    "shot_spec": {"path": "...", "sha256": "..."},
    "environment_spec": {"path": "...", "sha256": "..."},
    "library": {"path": "...", "sha256": "..."},
    "assets": [{"id": "heightmap.srtm_n29e101", "version": 1, "sha256": "..."}]
  },
  "visual_grammar": "cinematic_realism@1.0",
  "render_profile": "preview",
  "frame_range": [1, 360],
  "fps": 30,
  "resolution": [540, 960],
  "engine": "BLENDER_EEVEE",
  "samples": 16,
  "seed": 0,
  "output": "...",
  "started_at": "...",
  "finished_at": "...",
  "status": "pass",
  "elapsed_s": 71.4,
  "log": "..."
}
```

### 关键规则

- `build_id` 由构建系统生成，AI 不填写。
- 资产 id 必须能在 `library.json` 找到；找不到就失败，不猜路径。
- 记录实际 Blender 版本与加载的 addons；不写“应为 5.2”。
- 记录输入文件 sha256；spec 改一个字符，缓存必须失效。
- 随机种子显式写入；没有随机时写 `0`。
- 构建日志写入 manifest 同目录 `build.log`；失败也写。
- 输出先写临时目录，验证通过后原子替换正式文件。

### 缓存与增量

```text
Asset → Environment → Shot → Render → Review → Final Movie
```

- 修改 shot spec：只重建该 shot 的 render/review，不重建 environment。
- 修改 environment spec 或资产：重建引用它的 shot。
- 修改字幕/BGM：不重建 Blender。
- 修改 Visual Grammar：重建所有声明该 preset 的 shot。
- 缓存键至少包含：spec 哈希、asset 版本与哈希、builder 版本、Blender 版本、render profile、grammar 版本。

### 渲染 profile

在现有 `blockout / preview / hero` 基础上补齐：

| Profile | 用途 | 关键参数 |
| --- | --- | --- |
| Blockout | 构图与空间验证 | EEVEE 16，540×960 |
| Preview | 运动与节奏 | EEVEE 32，540×960 |
| Review | 正式画面审查 | 1080×1920，中等采样 |
| Hero | 重点镜头 | 1080×1920，高采样 |
| Final | 最终输出 | 项目声明分辨率，正式采样 |

每个 profile 控制分辨率、采样、纹理、体积、模拟精度；记录实际显存与耗时。

### 失败恢复

- 每个 shot 独立执行、独立状态。
- 状态：`pending / running / pass / fail / skipped`。
- 失败保留日志与临时输出，不覆盖上一次通过版本。
- `--resume` 从失败 shot 继续。
- 单镜失败不阻塞其他镜头；最终报告逐镜列出。

### 测试

- manifest 必填字段齐全。
- 同一输入二次构建命中缓存。
- spec 哈希变化使缓存失效。
- 资产缺失时构建失败且 manifest 写 `status=fail`。
- 模拟第 2 个 shot 失败，`--resume` 只重跑第 2 个。

### 交付物

- `build-manifest.json` + `build.log`（每镜每次）
- 缓存键与失效规则文档
- 单镜重试演示记录

## P1｜Environment `.blend` + Library Linking

- **状态**：Linking / 隔离已实现（2026-11-14）；Library Overrides 未实现
- **交付记录**：[生产管线v0.2-P1交付记录.md](生产管线v0.2-P1交付记录.md)

### 目标

把 JSON 三层结构补成 Blender 文件三层结构：Environment 可复用，Shot 独立。

### 目录选择

不新建 `production/` 平行树，沿用现有 kit：

```text
<内容根>/assets/3d/kits/fengshui/
├── environments/
│   ├── ridge.json
│   ├── valley.json
│   └── water.json
├── shots/
│   ├── a1.json
│   └── a4.json
└── blends/
    ├── environments/
    │   ├── ridge.blend
    │   ├── valley.blend
    │   └── water.blend
    └── shots/
        ├── a1.blend
        └── a4.blend
```

`.blend` 是构建产物，spec 是版本化输入。`blends/` 与 JSON 分开，避免规格文件与工程文件混在一起。第一阶段重点是验证 Environment Linking；`a1.blend` / `a4.blend` 是否各自保存，由镜头复杂度决定，不强制每个 shot 都有独立文件。

### Environment Builder

新增构建模式：

```powershell
scripts/render-asset-shot.ps1 -Spec environments/ridge.json -Profile environment
```

或等价命令：

```powershell
blender --background --factory-startup --python scripts/build_asset_scene.py -- `
  --spec <...>/ridge.json --build environment
```

Environment `.blend` 内容：

- Collection `ENV`：地形、天空、大气、水面、布景。
- Collection `ENV_LIGHTS`：环境固定灯光。
- Collection `ENV_ASSETS`：链接或导入的资产。
- 不包含 shot 相机、shot 专属灯光、shot 动画。
- 保存时使用相对路径重映射，换机器可重定位。

### Shot Builder

Shot `.blend` 内容：

- 链接 `ridge.blend` 的 `ENV` collection。
- 自有 `SHOT_CAMERA`、`SHOT_LIGHTS`、`SHOT_FX`。
- 需要局部修改链接对象时使用 Library Overrides；不需要修改的对象保持链接。
- 保存 shot `.blend` 后再渲染。

### 验收测试

1. 构建 `blends/environments/ridge.blend`，记录 sha256。
2. 构建 `a1` 与 `a4` 两个 shot（可共享或各自保存 `.blend`，但都必须引用同一 `ridge.blend`）。
3. 在 a4 改相机与一盏 shot 灯光，保存并渲染。
4. 重新计算 `ridge.blend` sha256，必须与步骤 1 相同。
5. 打开 a1，确认相机仍是 a1，不受 a4 影响。
6. 删除 a4 的 shot 覆盖，确认链接对象仍在。

### 风险

- Blender 5.2 的 Library Overrides API 与旧版不同；先做最小链接测试，再扩展。
- Windows 路径与相对路径重映射容易断；构建后用 `bpy.data.libraries` 检查链接路径。
- 若 Linked Collection 在 headless 渲染中不稳定，回退到“environment 合并 + shot 覆盖”，但必须在任务书里记录原因，并把验收项 1/2 标为未通过，不得写成通过。

### 交付物

- `ridge.blend`、`valley.blend`、`water.blend`
- `a1.blend`、`a4.blend`（同 environment 的两个 shot）
- 链接与覆盖测试记录
- `docs/3D动画生产流程.md` 的 Blender 落地章节更新

## P2｜Shot Review

- **状态**：已实现（2026-11-14）
- **交付记录**：[生产管线v0.2-P2交付记录.md](生产管线v0.2-P2交付记录.md)

### 目标

每次构建后自动生成可审查的镜头包，让人快速判断“这条镜头能不能用”，而不是只看一张渲染图。

### 目录

```text
<内容根>/build/<project>/review/<shot>/
├── first.png
├── middle.png
├── last.png
├── contact-sheet.jpg
├── preview.mp4
├── metadata.json
├── qc.json
├── review.md
└── logs.txt
```

### 自动生成

1. 首帧、中间帧、尾帧：ffmpeg 从渲染视频抽取。
2. Contact Sheet：Pillow 拼图，至少 9 帧，覆盖全镜头。
3. 低清预览：已有 preview/blockout 直接复制；没有则从正式视频降采样。
4. `metadata.json`：分辨率、帧率、时长、帧数、engine、samples、profile、manifest 路径、耗时。
5. `qc.json`：黑帧、冻结、时长偏差、音频缺失、解码错误；复用 `quality/media_qc.py` 与 `code_video_qc.detect_black_freeze`。
6. `review.md`：镜头 id、版本、变更点、已知问题、需要人决定的问题；不写自动审美分。
7. `logs.txt`：Blender 与 ffmpeg 日志尾部。

### Shot A/B Comparison

```text
build/<project>/review/compare/a1-v001-v002-v003.jpg
```

- 从同一 shot 的多个 build manifest 取首/中/尾帧。
- 并排显示，标版本号与关键参数。
- 不做 AI 打分；只提供并排画面，由人选择。

### CLI

```powershell
course-control shot-review --project <project.yaml> --shot a1
```

或挂到构建流程末尾自动执行。它是交付证据，不是审美门禁。

### 测试

- 用一个 3 秒测试视频生成完整 Review Package。
- 黑帧视频必须被 `qc.json` 标记。
- contact sheet 尺寸与帧数正确。
- manifest 缺失时 `metadata.json` 写 `INCOMPLETE`，不伪造参数。

### 交付物

- `CourseControl/src/course_control/review/`（shot_review.py、compare.py）
- `course-control shot-review` 命令
- a1/a3 的真实 Review Package
- 一份 A/B 对比样张

## P3｜Visual Grammar + QC 集成

### 目标

让四套 Visual Grammar 从“文档”变成 Builder 的默认值与约束，并把技术 QC 接进现有 release-check。

### Visual Grammar 结构

在 `shared/grammars/style-presets.yaml` 上增加版本与三层结构：

```yaml
id: cinematic_realism
version: "1.0"
global:
  color_management: agx
  look: "AgX - Medium High Contrast"
  grain: subtle
  typography: editorial
environment:
  lighting: natural_cinematic
  atmosphere: volumetric
  world_strength: 0.35
camera:
  lens_default: 45
  depth_of_field: selective
  motion_blur_shutter: 0.5
shot_overrides:
  allow_custom_lighting: true
  allow_custom_color: true
```

### Spec 引用

Environment 或 shot 增加：

```json
"visual_grammar": "cinematic_realism@1.0"
```

Validator 检查：

- preset 存在；
- 版本存在；
- 未知字段报错；
- shot override 只能覆盖允许的字段。

### Builder 消费

Builder 只消费它能执行的字段：

- 色彩管理：view transform、look、exposure。
- 环境：world strength、atmosphere density、light color/energy 默认值。
- 相机：默认焦段、DOF、motion blur shutter。
- 渲染：默认 engine/samples/resolution，但 shot spec 显式值优先。

不消费的字段（字体、颗粒、字幕层级）导出到 `look.json`，交给 Remotion/后期。**不在 Blender 里假装做排版。**

### QC 集成

`release-check` 增加一个 `shot_review` 步骤：

- 输入：项目 shot list、每个 shot 的 Review Package。
- 缺 Review Package → `INCOMPLETE`，不是 PASS。
- 人工豁免必须写 `exemptions/<shot>-<delivery-version>.json`：对象、原因、操作人、时间、缺失检查项、交付版本；状态为 `EXEMPT`（或整体 `PASS_WITH_EXEMPTION`），不得写成 PASS。
- 黑帧/冻结/解码失败 → `FAIL`。
- 人未确认审美 → 记录 `review.md` 的 `decision: pending`，不冒充通过。
- 已有 `media-qc`、`subtitles-qc`、`loudness` 继续复用。

topic 视频当前没有字幕 QC；如果项目声明了字幕，v0.2 补上 `check_srt`，没有字幕则写 `not applicable`，不写成通过。

### 测试

- `cinematic_realism@1.0` 能解析并应用 look。
- 不存在的版本被 validator 拒绝。
- Builder 输出 manifest 记录 grammar id@version。
- `release-check` 在缺 shot review 时为 `INCOMPLETE`，有完整包时为 `PASS`。
- 黑帧 Review Package 使 release-check `FAIL`。

### 交付物

- 更新后的 `style-presets.yaml`
- `scene_spec` 模型与 schema 的 `visual_grammar` 字段
- Builder 的 grammar 消费逻辑
- `release-check` 的 `shot_review` 步骤
- grammar 消费与 QC 测试

## 5. 执行顺序

1. **P0**：先做 manifest 与缓存键；没有可追溯构建，后面的复用与审查都没有证据。
2. **P1**：用 `ridge` 做最小链接测试；只建 `a1` / `a4` 两个 shot，不一次性迁移全部场景。
3. **P2**：把 a1/a4 的 Review Package 跑通；再接 a3。
4. **P3**：先让 Builder 消费 grammar，再把 shot review 接进 release-check。
5. **P4**：P0–P3 验收通过后，再补到 6–9 镜和完整 1080p。

P1 与 P2 可以并行，但 P2 的 metadata 依赖 P0 的 manifest；P3 的 QC 依赖 P2 的 Review Package。

## 7. 风险与停止条件

- **Blender Linking 不稳定**：先最小测试；若 Linked Collection 在 headless 下不可靠，回退到合并模式，并在验收表把项 1/2 标为未通过，不得写成通过。
- **8 GB A750 显存**：Review/Hero 分辨率与采样分开；记录显存与耗时；不靠无差别降分辨率掩盖问题。
- **缓存误命中**：缓存键必须包含 spec、资产哈希、builder/Blender 版本、grammar 版本；任何一项缺失都视为不可复现。
- **同一问题最多尝试 3 次**：第 3 次仍失败，停止，记录问题、已尝试修复、证据、下一步建议，等待人工决定。
- **不伪造验收**：缺 Review Package、缺 manifest、缺镜头，一律 `INCOMPLETE`；skip 不是 pass。
- **不新增风格门禁**：Visual Grammar 是默认值与约束，不是发布条件；发布仍按最终交付质量与法律风险。
