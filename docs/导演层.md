# 导演层（Director Layer）

日期：2026-11-08
代码：`CourseControl/src/course_control/director/`
命令：`course-control director-plan` / `director-validate`

## 1. 定位

导演层把**已批准**的 brief / outline / narration script / storyboard 收敛成一份可执行的制作计划：章节、镜头、引擎、时长、旁白落点、连续性检查。

它不写 Manim/Blender 场景代码，不调用渲染引擎，不生成旁白。它只做决定和校验，执行交给现有引擎与 CourseControl 主链。

## 2. 复用了什么（没有重复造轮子）

| 现有资产 | 导演层的用法 |
| --- | --- |
| `authoring/models.py` 的 `Brief` / `Outline` / `NarrationScript` | 唯一内容输入；不重新生成课程内容 |
| `contracts.py` 的 `Storyboard` / `ShotSpec` | storyboard 覆盖与 handoff 格式 |
| `engine_router.route_engine` | visual_kind / needs_3d → 引擎与 profile |
| `animation_direction.ShotDirection` | 每个镜头的方向文件直接通过 `direction-validate` |
| `paths.LessonPaths` / `engine_root` | 解析场景路径、构建目录 |
| `authoring/approval.json` | 输入是否经人工批准（sha256 校验） |
| `utils.probe_media` | 测量已渲染插入镜头的实际长度 |
| `layout/` 版式库 | 每镜头选模板、区域、安全区与容量校验 |

没有新增依赖。

## 3. 结构

```text
approved brief / outline / script / storyboard
        │
        ├─ teaching   → chapters + learning objectives（brief 目标按关键词与标题权重映射）
        ├─ visual     → engine / profile / scene / readiness / camera / motion
        ├─ layout     → 模板、区域、安全区、字幕保留带
        ├─ storyboard → shots、连续时间轴、转场、旁白引用
        ├─ audio      → narration segments（词数估算时长，保留 style / pause / emphasis）
        └─ continuity → 时长、覆盖、引擎、素材、旁白的跨镜头检查
        │
   validator（硬闸门）
        │
director_plan.json / storyboard.director.yaml / directions/*.json / director_review.md
```

## 4. 质量闸门

结构性（`director-validate` 可单独跑）：

- 总时长落在 lesson 的 min/max 窗口，且与 target 的偏差不超过容差；
- 章节时长之和等于总时长；
- 镜头覆盖 slide 1..N 且各一次；`cue_seconds` 是页面内偏移，不是全局开始时间；
- 每个镜头必须有已知版式模板，区域在安全区内、互不重叠，主视觉面积达到模板下限；
- `cue_seconds` 必须落在页面内；插入长度越过页面边界时告警；
- 时间轴首尾相接，镜头跨度等于 target；
- 章节起止与所辖镜头一致；
- 旁白 id 存在、每个镜头都有旁白、无孤儿片段。

上下文（`director-plan` 时跑）：

- 引擎必须在 lesson.engines 中（remotion 作为合成层例外）；
- 3D 页面必须走 Blender，除非 storyboard 显式覆盖；
- scene 路径必须存在；
- 每个镜头必须有来源；
- 至少有一个可渲染镜头；
- 估算旁白超出页面预算或不足 60% 时告警；
- 单个镜头 >180s、章节 >420s、引擎频繁切换、场景复用告警；
- 已渲染镜头与页面预算差距过大时给出 `insert.short` 提示；
- 风格角色缺失（query/key/value/result/mask）告警；章节目标只能回退到占位句时告警；
- 输入未批准或 hash 变化 → `source.approval` 告警，计划状态降为 draft。

错误会阻断计划；警告进入 `director_review.md`，由人看片决定。

## 5. 命令

```powershell
# 生成并校验
uv run --project CourseControl course-control director-plan --lesson 01-transformer-demo --workspace .

# 只重跑结构校验
uv run --project CourseControl course-control director-validate `
  --plan build/01-transformer-demo/director/director_plan.json

# 导出的镜头方向可直接用现有契约校验
uv run --project CourseControl course-control direction-validate `
  --spec build/01-transformer-demo/director/directions/shot_003.json

# 用导演 handoff 驱动 build（显式指定，不自动替换课程 storyboard）
uv run --project CourseControl course-control build --lesson 01-transformer-demo `
  --storyboard build/01-transformer-demo/director/storyboard.director.yaml --skip-compose

# 在已有构建上只重渲染选定镜头
uv run --project CourseControl course-control build --lesson 01-transformer-demo `
  --storyboard build/01-transformer-demo/director/storyboard.director.yaml `
  --shots shot_007 --skip-compose
```

输出：

```text
build/<slug>/director/
├── director_plan.json          # 完整计划 + 检查结果
├── storyboard.director.yaml    # 非 remotion 镜头，可直接对照 ShotSpec
├── directions/shot_XXX.json    # 每镜头 AnimationDirection
├── shot_specs/shot_XXX.json    # 非 remotion 镜头的 ShotSpec handoff
└── director_review.md          # 章节/镜头表 + 错误/警告 + handoff
```

## 6. POC 结果（01-transformer-demo）

- 5 章 / 12 镜头 / 1200 s / 54 段旁白；
- 12 个 ready（Manim 7 + Blender 1 + Remotion 4），0 个 planned；
- 实际渲染验证 5 个 Manim 镜头：`QkvFanoutScene` 10.1 s、`RowTraceScene` 8.0 s、`ResidualBypassScene` 9.1 s、`CrossAttentionFlowScene` 8.5 s、`LossBackpropScene` 8.6 s；
- 0 error，9 warning：5 个页面的旁白估算超出预算、4 个早期 Manim 插入镜头的背景是黑色而课程风格是暖白纸面；
- 12 个镜头全部获得版式模板：1 个 title_intro、3 个 process_flow、5 个 principle_diagram、1 个 data_chart、2 个 summary；
- 章节目标来自 brief 的 6 条 objective，映射结果与章节内容一致（c4 得到训练/损失目标，c5 得到 recap 目标）。

POC 暴露的第一个问题：**已有插入镜头与课程风格不一致**。4 个 Manim 镜头没设 `config.background_color`，按 Manim 默认是纯黑；课程风格指南要求白底。deck 模式下会从白底幻灯片硬切到黑底片段。导演层用 `style.background_mismatch` 把它标出来，处理方式只有两个：重做这些镜头的背景，或在 lesson 中显式声明“黑底插入”的例外。

POC 暴露的第二个问题：**页面预算 ≠ 镜头长度**。5 个 Manim 插入是 8–10 s，页面预算是 105–135 s；deck 模式下这是合理的（幻灯片负责其余时间），scene 模式则必须把这些镜头扩成整页动画。导演层用 `asset_seconds` 与 `insert.short` 把这件事显式记录；handoff 的 `expected_duration_s` 写实测插入长度（10.1 / 8.0 / 9.1 / 9.6 / 9.2 s），不写页面预算，避免下游按 120 s 去找一个不存在的片段。

## 7. 边界

- 导演层不替代人工批准：输入 hash 不匹配时只生成 draft 并告警，不自动放行。
- `build --storyboard` 可显式加载 handoff，但不自动替换课程 storyboard；`--shots` 只过滤渲染，collect/compose 仍使用完整 storyboard，因此适用于已有构建产物上的局部重渲染。
- 时长来自 outline 预算与旁白词数估算；实测时长在 `narration-build` 后才会进入时间轴。
- 连续性检查是规则级的（时长、覆盖、引擎、素材），还不是分镜级语义检查。
