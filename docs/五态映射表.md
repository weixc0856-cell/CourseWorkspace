# 五态映射表

- **日期**：2026-11-13
- **用途**：把建议稿里的五个 `*_VERIFIED` 名字，映射到代码实际使用的状态名。**只做阅读映射，不改名**（D-089 第 2 条、P0 审计 §5.6）。
- **权威**：状态由 `CourseControl/src/course_control/quality/quality.py` 计算并写入 `build/<slug>/quality/quality-report.json` 的 `states` 块。本文件不产生新状态。

---

## 1. 映射

| 建议稿名称 | 代码状态 | 判定条件 | 写入位置 |
| --- | --- | --- | --- |
| `ENGINEERING_VERIFIED` | `BUILD_PASS` 且 `VERIFY_PASS` | 构建报告 verdict 为 pass；`verify` 无失败项 | `quality-report.json.states` |
| `CONTENT_VERIFIED` | Q1 `内容可信度 = PASS` | Content QA 无未决意见，claim 证据充分 | `quality-report.json.dimensions[0]` |
| `VISUAL_VERIFIED` | Q3 `视听体验 = PASS` | `media-qc` 全项 pass，无未决 WARN | `quality-report.json.dimensions[2]` |
| `PACKAGE_VERIFIED` | `package-verify` 返回空问题列表 | 交付包 manifest 全项 present，哈希一致 | `deliver/<slug>/manifest.json` + 命令输出 |
| `RELEASE_APPROVED` | `REVIEW_APPROVED` 且 `RELEASE_APPROVED` | review 与 release 两次人工签核都已完成 | `quality/review-approval.json`、`quality/release-approval.json` |

补充状态（建议稿没有，但代码在用）：

| 状态 | 含义 |
| --- | --- |
| `VERIFY_WARN` | 通过，但有需要展示的警告 |
| `VERIFY_INCOMPLETE` | 有检查未能执行；不得当作通过 |
| `VERIFY_FAIL` | 有硬性失败项 |
| `NEEDS_HUMAN_REVIEW` | 存在 `human_review` 类警告 |
| `BLOCKED_WARNINGS` | `blocking` 类警告的 id 列表，阻断发布 |
| `QUALITY_PASS` | 旧名，等价于 `VERIFY_PASS`，仅为兼容读取 |

---

## 2. 读法

1. `QUALITY_VERIFIED` 只表示五维全部 `PASS`，不表示发布已批准。
2. `RELEASE_APPROVED` 需要前四步都成立，再加两次签核；任何一步 incomplete 都会让它为 false。
3. 报告的新鲜度由 `quality-gate` 校验：报告与产物哈希或时间不一致时记为 `incomplete`，不采信旧结论。

---

## 3. 不做什么

- 不改代码里的状态名。改名要动 `quality.py`、`stats.py`、`cli/render.py`、`tests/test_quality.py` 与全部既存报告，对出片质量没有收益。
- 不把 `BUILD_PASS` 与 `VERIFY_PASS` 合并成单一 `ENGINEERING_VERIFIED`。构建成功与验收通过是两件事，合并会丢掉失败的位置。
- 不让本表成为第二套状态机。新增状态必须先改 `quality.py` 与 Schema，再更新本表。
