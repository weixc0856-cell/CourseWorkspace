# 制片层（Producer Layer）

日期：2026-11-08
代码：`CourseControl/src/course_control/producer/`
命令：`producer-order` / `producer-run` / `producer-status` / `producer-affected`

## 1. 定位

- **出品人（人）**：定方向、给资源授权、最终验收。
- **制片层（本模块）**：管订单、预算、用量、阶段状态、交付包和增量重建；不创作。
- **导演层（`director/`）**：决定章节、镜头、引擎、旁白落点并做硬校验。
- **引擎与 CourseControl 主链**：真正渲染、合成。

制片层不读密钥、不调用模型、不渲染、不发布。它只声明“允许什么”，记录“用了多少”，并按证据判断“交付了没有”。

## 2. 输入：ProductionOrder

`build/<slug>/production/order.json`

| 字段 | 来源 / 说明 |
| --- | --- |
| `audience` / `language` / `target_seconds` / `must_cover` | 默认取 brief 与 lesson，可用 CLI 覆盖 |
| `style` | 背景、墨色、accent、warm、字体（与视觉风格指南一致） |
| `authorizations` | `allow_network`、`allow_new_dependencies`、`allow_publish`、`allow_render`、可用的模型后端与 API 提供方 |
| `limits` | 最大墙钟时间、API 费用、本地模型调用次数、磁盘 |
| `approved_by` / `approved_at` | 人工批准；未批准只能到 `awaiting_approval` |
| `must_not` | 明确禁止讲的内容 |

```powershell
uv run --project CourseControl course-control producer-order `
  --lesson 01-transformer-demo --workspace . `
  --audience "零基础" --language zh --target-seconds 1200 `
  --must-cover "背景" --must-cover "Attention" `
  --max-wall-seconds 14400 --max-api-cost-usd 0
```

## 3. 输出：七件交付物

`producer-run` 生成 `build/<slug>/delivery/manifest.json` 与 `README.md`：

| 项 | 内容 | 判定 |
| --- | --- | --- |
| `01_final_video` | 成片与字幕版 | 缺一即 blocked |
| `02_script` | brief / outline / script / sources | 必备文件全在才 present |
| `03_storyboard` | director plan、storyboard、全部 direction | 任一缺即 partial/blocked |
| `04_assets` | 每个非 remotion 镜头的场景源 | planned 镜头计入 missing |
| `05_audio` | narration.wav、subtitles.srt | 缺一即 blocked |
| `06_config` | lesson.yaml、order、toolchain、state | state 先生成，避免自相矛盾 |
| `07_acceptance` | build-report.json、director_review.md | 缺 build-report 即 partial |

规则：

- `skip` 不写成 `pass`；缺文件就是 blocked/partial。
- 只有**所有项 present 且订单已人工批准**，整体才是 `delivered`。
- 媒体按路径 + sha256 引用，不复制大文件；文本资产同样记录 hash。

## 4. 状态与用量

`build/<slug>/production/state.json`

- `stages`：validate / director / render / audio / delivery；
- `usage`：墙钟、API 费用、本地模型调用、磁盘；
- `shots`：每个镜头的指纹（内容、旁白、场景源、direction）；
- `director_plan_sha256`；
- `status`：`new / planning / blocked / awaiting_approval / delivered`。

超过 `limits` 直接 blocked，并在报告里列出超限项。

## 5. 增量重建

每个镜头保存四类 hash：

- `content_sha256`：claim、视觉隐喻、页面预算、引擎、场景名；
- `narration_sha256`：该镜头所有旁白文本；
- `scene_sha256`：场景源文件；
- `direction_sha256`：导出的镜头方向。

`producer-affected` 对比当前计划与上次状态：

| 变化 | 结论 | 需要的动作 |
| --- | --- | --- |
| 内容变化 | redesign | 重写 direction、重渲染、必要时重配音、重合成 |
| 场景源变化 | re-render | 只重渲染该镜头 |
| 旁白文本变化 | re-narrate | 只重生成该段旁白并重合成 |
| direction 变化 | recompose | 重合成 |

POC 实测：手动修改 `shot_003` 的 claim 后，`producer-affected` 报 `shot_003: redesign`；重新 `producer-run` 后恢复 `no affected shots`。

`producer-rebuild` 把这一步接起来：

- 默认只打印受影响镜头与将要执行的命令；
- `--execute` 时检查 `order.authorizations.allow_render`，然后调用 `build --storyboard ... --shots ... --skip-compose`；
- 渲染成功后只刷新这些镜头的指纹，其他镜头状态不动；
- `--compose` 才会在重渲染后继续 collect/compose。

实测输出：

```text
shot_003: redesign (claim, visual, engine or page budget changed)
authorized: yes
command: uv run --project CourseControl course-control build --lesson 01-transformer-demo   --storyboard build/01-transformer-demo/director/storyboard.director.yaml   --shots shot_003 --skip-compose
```

## 6. 命令

```powershell
# 1. 立项（写 order；可 --approve "Wayne" 记录人工批准）
uv run --project CourseControl course-control producer-order --lesson 01-transformer-demo --workspace .

# 2. 自动执行当前可自动的部分：validate → director plan → delivery → state
uv run --project CourseControl course-control producer-run --lesson 01-transformer-demo --workspace .

# 3. 查看订单、阶段、用量、缺失
uv run --project CourseControl course-control producer-status --lesson 01-transformer-demo --workspace .

# 4. 受影响镜头 → 局部重渲染（默认只打印命令；--execute 才执行）
uv run --project CourseControl course-control producer-rebuild --lesson 01-transformer-demo --workspace .
uv run --project CourseControl course-control producer-rebuild --lesson 01-transformer-demo --workspace . --execute

# 4. 修改内容后，看哪些镜头需要重做
uv run --project CourseControl course-control producer-affected --lesson 01-transformer-demo --workspace .
```

`producer-run` 在 blocked 时返回 1，`producer-status` 同样返回 1，可直接作为 CI/交付闸门。`producer-order --force` 会重建订单并清空人工批准，需要重新 `--approve`。

## 7. POC 结果（01-transformer-demo）

- 订单：`01-transformer-demo-v1`，1200 s，英文，6 条 must-cover，未批准；
- 状态：`blocked`；导演计划 `ready`（12 镜头，12 ready，0 planned）；
- 交付：`01` blocked、`02` present、`03` present、`04` present（8/8）、`05` blocked、`06` present、`07` partial（2/3）；
- 缺失 4 项：成片、旁白、字幕、build-report；
- 用量：墙钟约数秒（只做规划与打包），API 0，模型调用 0；
- 没有读取任何密钥，没有触发渲染、TTS 或发布。

这不是失败。它准确说明“设计层已完成，制作层还缺什么”，而不是把 10 秒插入镜头冒充 20 分钟成片。

## 8. 边界

- 制片层不执行渲染/TTS；这些仍需显式命令或后续接入。
- `producer-run` 的“自动”范围目前是 validate → director → package → state；不是整条制作链。
- 订单批准是人的动作；代码只记录，不代替。
- 增量重建已能生成并执行局部重渲染命令；默认只重渲染资产，collect/compose 需要显式 `--compose`，且要求其他镜头已有产物。
- 凭据只在调用端的系统环境变量里；制片层只记录授权布尔值。
