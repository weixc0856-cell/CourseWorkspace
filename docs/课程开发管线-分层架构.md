# 课程开发管线：分层与命名

- **状态**：现行。平台层与课程项目层的边界以本文件为准。
- **适用**：汽车空气动力学以及后续所有学科课程。任何"把某一门课的计划、Claim、卡片、资产写进程序仓库"的做法都违反本文件。

## 1. 五层

```text
上游资料层    Docling Bridge                 output/<source_id>/ + catalog.json
              KnowledgeStudio               knowledge/<source_id>/（页级检索）
                 │  标准交接：to-lesson --register --digest
                 │            to-knowledge → retrieve --pages N-M --full-pages --register
                 ▼
平台管线层    CourseWorkspace 仓库           CourseControl / KnowledgeStudio / 渲染器 / 共享 schema
              （只放代码、schema、测试、通用规范；不放任何一门课的计划与素材）
                 ▼
课程项目层    <内容根>/projects/<course_id>/  project.yaml（ProjectSpec）
              （课程规模、计划、卡片目录、Claim 索引、声线、禁用词、交付策略）
                 ▼
单集层        <内容根>/runtime/course-content/<course_id>/episodes/<ID>/card.yaml
              <内容根>/lessons/<slug>/       lesson.yaml / sources / digest / spec / brief / outline / narrative / deck / notes / script
                 ▼
产物层        <内容根>/build/<slug>/        过程产物（可删、可重建）
              <内容根>/deliver/<slug>/      最终交付包
```

### 1.1 每层只有一个权威

| 层 | 权威文件 | 谁写 | 不放在这里的东西 |
| --- | --- | --- | --- |
| 上游资料层 | Docling `manifest.json` + `document.json` + `assets/` | Docling Bridge | 课程计划、Claim、页面 |
| 平台管线 | `CourseControl/`、`KnowledgeStudio/`、`shared/schemas/`、`docs/` | 工程 | 某门课的 180 集计划、教材图、成片 |
| 课程项目 | `projects/<course_id>/project.yaml`（`production.course`） | 课程 owner | 单集讲稿、页面 HTML |
| 单集 | `episodes/<ID>/card.yaml` + `lessons/<slug>/lesson.yaml` + `authoring/episode.spec.yaml` | 作者 + 校验 | 课程级计划（引用项目层） |
| 产物 | `build/<slug>/`、`deliver/<slug>/` | 流水线 | 任何需要长期维护的源文件 |

## 2. 课程项目合同（ProjectSpec）

路径：`<内容根>/projects/<course_id>/project.yaml`。模式 `project.mode: course`，`production.course` 至少包含：

```yaml
project:
  id: automotive-aerodynamics
  mode: course
  title: Automotive Aerodynamics
input:
  sources:
    - {type: book, uri: "docling:hucho-en-5e", authority: primary}
production:
  course:
    lesson_count: {target: 180, min: 180, max: 180}
    lesson_seconds: {min: 480, max: 900}
    lesson: t1-01-why-aerodynamics
    plan: runtime/course-content/automotive-aerodynamics/COURSE_MAP.md
    expected_episode_count: 180
    cards_dir: runtime/course-content/automotive-aerodynamics/episodes
    claim_index: runtime/course-content/automotive-aerodynamics/book/index.json
    voice_profile: audio/courses/automotive-aerodynamics/voice.yaml
    forbidden_lesson_slugs: {aero-t1-01: T1-01}
    forbidden_slide_terms: ["of 90", "of 80"]
```

- `plan` / `cards_dir` / `claim_index` / `voice_profile` 都是**相对内容根**的路径。
- 课程链（`course_chain.py`）先读这份 `project.yaml`，找不到才回退到仓库的 `config/course-chain.yaml`（仅 legacy/测试用）。
- `config/course-chain.yaml` 不再保存任何真实课程的规模、计划、禁用词；它只是一个空壳回退。

## 3. 加一门新学科的标准步骤

1. **资料**：Docling Bridge `convert` → `validate`；产出 `output/<source_id>/`。
2. **检索**：`to-knowledge output/<source_id>`；需要单集时按页范围 `retrieve --pages N-M --full-pages --register`。
3. **项目**：建 `projects/<course_id>/project.yaml`；写计划、集数、卡片目录、Claim 索引、声线。
4. **单集**：建 `episodes/<ID>/card.yaml` 与 `lessons/<slug>/`；`lesson.yaml` 写 `course_id` / `episode_id`。
5. **证据**：`course-control digest`；Claim 进 `book/curation.yaml` → `book/index.json`。
6. **合同**：`brief → outline → narrative-plan → script`，逐项人工签。
7. **开发**：`storyboard-page` → 人工逐页签 → `build/collect` → `animatic` → `render` → QC → `package`。

## 4. 测试边界

- `scripts/check.ps1`：**平台回归**。只使用 `%TEMP%/CourseWorkspace/run-*` 的隔离内容根、合成夹具和单测；不读取生产内容根，也不要求任何一门课已生产。
- `scripts/check_course_chain.py --all`：**生产内容检查**。遍历内容根里所有声明了 `course_id` 的 lesson，按各自的 `project.yaml` 校验计划/card/lesson/spec。
- `course-control release-check --lesson`：**单集交付检查**；需要真实内容、签字与成片。
- 三者不能互相替代：平台回归绿不等于某门课已生产；生产链绿也不等于平台回归绿。
