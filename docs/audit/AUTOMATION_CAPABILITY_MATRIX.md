# 自动化能力矩阵

- **审计日期**：2026-11-10
- **问题**：如果出品人只给目标、确认方向、审核结果，其他交给 AI 和自动化，今天究竟能做到什么程度？
- **答案先行**：单门课的**渲染与合成**可以做到 A3；**内容、分镜、美术**仍在 A1–A2；**从来源到成片的无人值守**是 A1，不是 A4。

> **2026-11-10 落实状态**：`package`/`release-approve`/`verify_media` 已实现；01 的 20 分钟构建已进入 compose（超时改为按课程时长推导）。自动化等级本身未变：渲染/TTS/合成仍是 A3，视觉创作仍是 A1。

---

## 0. 等级定义

| 等级 | 含义 | 判定标准 |
| --- | --- | --- |
| A0 | 完全人工 | 没有程序或模型参与 |
| A1 | AI 辅助，人工主导 | 模型给候选，人做大部分判断与执行 |
| A2 | AI 执行，人工确认 | 程序/模型完成主体工作，人逐项确认后进入下一步 |
| A3 | 自动执行，异常人工 | 正常路径无人值守；失败、超时、质量异常需要人 |
| A4 | 稳定自动化，可无人值守 | 有调度、重试、恢复、监控、稳定生产记录；人只做最终验收 |

A4 不是"跑通过一次"，而是"多门课、多次运行、异常可恢复、质量稳定"。

## 2. 汇总等级

| 维度 | 等级 | 说明 |
| --- | --- | --- |
| 单个渲染任务（给定场景） | **A3** | 命令可无人值守跑完；失败需人修 |
| 单门课从已批准内容到成片 | **A2–A3** | TTS、渲染、合成、QC 可自动；字幕批准与失败修复需人 |
| 单门课从来源到成片 | **A1–A2** | 研究、分镜、美术、事实裁决仍需人 |
| 多门课并行 | **A0** | 设计上单实例、串行；无队列 |
| 夜间无人值守 | **A1** | 可以挂一个长任务（TTS/渲染）；没有调度、监控、失败后继续 |
| 长时间运行稳定性 | **A2** | 3.2 h TTS 有真实记录；没有连续多课/多日记录 |
| 失败自动恢复 | **A1** | 缓存能避免重做；没有顶层重试/断点 |
| 人工介入频率 | 高 | 每镜 1–5 次返工；每课至少 3 次人工批准（内容、字幕、发布） |
| 62 秒样片的生产时间 | 约 1 小时机器 + 数小时人 | 06 production log：TTS 10 min、Manim 8 min、CodeVideo 25 min、ASR 8 min、构建 98 s |
| 5 分钟课的生产时间 | 约 1 小时 TTS + 数小时渲染 + 数天人工 | 05 首次 TTS 按 10× 推算约 49 min（meta 只记录了缓存命中）；Manim 多轮预览；compose 6 min |
| 20 分钟课的生产时间 | 3.2 h TTS + 约 25 min compose + 数天人工 | 01 旁白已完成；成片 1195.605 s 已产出（C-30 已修复） |

> 这些数字来自本机真实日志与 meta，不是估算表。TTS 的 RTF 在 06 的单段是 10.2×，01 整课是 9.6×；用 `音频秒数 × 10` 做容量规划是合理的保守值。

## 3. 成本

| 项 | 实测/可读 | 说明 |
| --- | --- | --- |
| 本地 LLM | 0 API 费用 | 8080 CPU-only，约占 19 GB 内存；时间成本为主 |
| 远程 DeepSeek | 未完整记账 | 任务记录没有 token/cost 字段；`total_cost_usd` 在 Claude Code 结果里存在但未落盘到 `runtime/tasks` |
| TTS | 0 API 费用 | VoxCPM2 本地；3.2 h CPU 换 20 min 音频 |
| 渲染 | 0 API 费用 | 05 compose 371.5 s；aging 278.5 s；nvda 355.9 s |
| 磁盘 | 每课 0.1–0.4 GB | 01 的 build 约 368 MB；narration 337 MB；05 216 MB |
| 人工 | 最大成本 | 镜头代码、返工、字幕校对、看片 |

**结论**：算力不是瓶颈，人工与美术是。项目自己的 Blender 评估也得出同一结论。

## 4. 失败与恢复：现在能做到什么

| 场景 | 现在 | 是否可自动恢复 | 证据 |
| --- | --- | --- | --- |
| TTS 某段失败 | 抛错；已完成的段有缓存 | 重跑即可，跳过缓存 | `narration_course.py` 的 cache_key；06 s005 异常后 `--force` |
| Motion 渲染失败 | 重试 2 次，仍失败 `fail` | 是（有限） | `adapters/motion_canvas.py` |
| Manim 渲染失败 | 退出码非 0 → `fail`；无重试 | 否 | `adapters/manim.py` |
| CodeVideo 捕获失败 | 错误写入 build-report；缓存可复用 | 重跑 | `adapters/code_video.py` |
| Remotion 合成失败 | 保留 staging；verdict fail | 重跑整段 | `test_staging.py` |
| 构建中某一阶段失败 | 下游 `not_run`；无断点 | 否，需从头 `build`（缓存可省渲染） | `pipeline.py` |
| 本地模型 8080 被占 | 等待到超时，或 `blocked`；不杀他人 | 半 | `ai_runtime.service` |
| 远程 API 不可达 | `blocked`/`failed`，不冒充本地 | 半 | `remote.py`；真实冒烟 |
| ContentQA 两次运行 | 第二次覆盖第一次任务记录 | 否 | C-05 |
| 人工批准被撤销/内容改动 | sha256 失配，命令拒绝 | 是 | `authoring/approval.json` |

**关键判断**：缓存让"重跑"比"恢复"更常用。项目没有状态机式的 resume；对单机单用户，这可以接受，但不能称为 A4。

## 5. 无人值守能做到什么程度

| 场景 | 能否今晚挂着跑 | 条件 |
| --- | --- | --- |
| 20 分钟整课 TTS | 能 | VoxCPM2 50000 端口可用；约 3.2 h；失败段需次日重跑 |
| 5 分钟 Manim 渲染 | 能 | 场景已写完；Manim 1800 s 超时；失败需人看日志 |
| 5 分钟整课构建 | 能 | 旁白/字幕已批准；compose 约 6 min；失败需人 |
| 20 分钟整课构建 | **A3** | 单一 build 下 compose/burn/verify 全 pass；并发 build 会覆盖 staging，已用 BuildLock 禁止 |
| 从来源到成片 | 不能 | 需要研究、批准、分镜、美术 |
| 多门课排队 | 不能 | 无队列/调度 |
| 失败后自动继续下一课 | 不能 | 无编排 |

## 6. 各环节的升级条件

| 环节 | 从当前到下一级需要什么 | 是否值得 |
| --- | --- | --- |
| 来源摄取 | 支持 PDF/DOCX、失败重试、来源去重 | 中 |
| 知识结构 | 把 KnowledgeStudio 接进至少一门课；目录校准自动化 | 低（当前无需求） |
| 事实核查 | 外部证据库、来源引用校验、人工裁决界面 | 中（成本高） |
| 口播稿 | 把批准门接进一条命令；风格样例库 | 中 |
| 导演计划 | 让 build 默认消费导演计划；统一镜头粒度 | **高** |
| 视觉资产 | 模板化 3 类镜头（标题/矩阵/流程）；Agent 对照实验 | **高** |
| 动画渲染 | 共享 QC；按课程时长推导超时 | **高** |
| 旁白 | 声线盲听、段落级情绪控制 | 中 |
| 字幕 | 标点/词边界分段；中文字符级校验；人工校对工具 | **高** |
| 合成 | 断点续渲；按课程时长超时 | 中 |
| 媒体 QC | 冻结阈值按语法重标定；ASR 默认跑 | 中 |
| 教学 QA | 真人学习者证据 | 低（当前做不到） |
| 交付 | `package` 命令 + `release-approve` + 哈希 | **高** |

## 7. 结论

- **A3 已经属于渲染、TTS、合成、QC 这些"给定输入就能跑"的环节。**
- **A4 不属于任何环节**，因为缺少调度、恢复、监控与多课记录。
- **整条链路是 A1–A2**，因为研究、分镜、美术、事实裁决和最终签核仍由人主导。
- 如果把"自动化率"定义为"不需要人碰的分钟数 / 总分钟数"，当前大约是 40–60%；如果定义为"不需要人判断的环节数 / 总环节数"，大约是 4/15。

下一阶段提高自动化率的最短路径不是加 Agent，而是：

1. 把 01 的剩余人工步骤跑完，得到第一门 20 分钟课的完整生产记录；
2. 把字幕分段与交付打包自动化；
3. 把导演计划变成 build 的默认输入；
4. 只在一个镜头上试 Agent 生成，拿到返工与质量数据再决定。
