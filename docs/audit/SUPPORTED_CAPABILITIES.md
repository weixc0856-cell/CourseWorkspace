# 当前支持的能力边界

- **审计日期**：2026-11-10
- **判定规则**：只有"真实课程 + 真实产物 + 自动检查 + 人工看过"才算**已生产**；只有设计稿、模板、POC、单测的写**可配置/需开发**。
- **读法**：这张表回答"现在接一个项目，能不能做、要做到什么程度、要投多少人"。

---

## 0. 一句话

系统能稳定生产**5 分钟以内的技术/工程/新闻类讲解视频**，质量在"合格的小频道"区间；能生产 20 分钟课程，但还没有交付过；经济学、商业分析、纪录片、Shorts 目前是设计能力，不是生产记录。

### 1.1 质量说明

- "能生产"不等于"能发布"。05/06/nvda 的 `RELEASE_APPROVED` 都是 `false`；没有一门课有人工发布签核。
- 新闻片的事实底账是项目里最强的内容资产：一手来源、事实/报道/判断三分、明确"不主张什么"。这套方法可以复制到其他类型。
- 技术课的内容准确性只做了 spot-check；05 的 43 条 claim 只有 3 条被双模型同时支持，38 条需要人工裁决。

### 2.1 开发支持的分级

1. **直接支持**：新视觉语法、内容 QA 规则、新课程（用现有引擎）。
2. **配置/适配即可**：新学科内容、新片型（在现有三种 compose 模式内）、新配色/版式。
3. **局部开发**：新渲染器、新 TTS/ASR、新 Agent 任务、数据可视化、前端只读面板。
4. **重大改造**：多课并行、多人协作、云端渲染、实时交互、完整前端。
5. **不适合**：把系统当通用低代码视频平台、当知识权威、当自动事实核查器、当自动发布器。

## 4. 接一个新项目的现实路径

### 4.1 5–8 分钟技术讲解（最成熟）

1. 选一个能用一个机制讲清的问题。
2. 写 800–1,200 词英文/中文口播（按 133 wpm / 4.4 字每秒估算）。
3. 用 3–5 个镜头：1 个 hook（CodeVideo/kinetic）、2–3 个机制（Manim/CodeVideo）、1 个 recap。
4. 跑 `narration-build` → `subtitles-build` → 人工校对 → `authoring/approval.json`。
5. `build` → `media-qc` → `quality-report` → 人工看片。
6. 预计：机器 1–2 小时，人工 1–3 天（含镜头代码与返工）。

### 4.2 20 分钟课程（已验证）

1. 01 已完整构建：1195.605 s / 1080p30，verdict=pass；保留这次工时与失败点（并发 build 覆盖 staging）。
2. 再决定是否需要更多视觉资产；不要在未交付前扩课。
3. 预计：TTS 3.2 小时；compose 25 分钟；人工数周。

### 4.3 新闻/行业分析（内容强，画面弱）

1. 一手来源至少 2 条；写 `fact-check.md`，区分事实/报道/判断。
2. 8 页以内；每页英文要点 + 一个 cutaway；中文交给字幕，不放在幻灯片底部。
3. 预计：机器 10 分钟；人工 1–2 天（来源、文案、审校）。

### 4.4 经济学/商业（设计能力）

1. 先做 1 集 8 分钟样片，不排整季。
2. 需要新的数据图语法（折线/柱状/分布）和案例素材；现有 ScientificFigures 只是静态图。
3. 在样片通过人工看片前，不要承诺季播。

## 5. 结论

- **能做的**：5 分钟内的技术/工程/新闻讲解；双语字幕；TTS；多引擎镜头；确定性构建与证据。
- **能做但未证明的**：20 分钟课程；Shorts；经济学/商业；数据驱动分析；纪录片式。
- **不能做的**：无人值守的整课生产；自动事实裁决；专业频道级视觉；多用户/云端。
- **最该先做的**：把 01 交付出来，让"20 分钟课程"从"有能力"变成"有记录"。
