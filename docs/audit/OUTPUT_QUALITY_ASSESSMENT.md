# 输出质量评估

- **审计日期**：2026-11-10
- **评估对象**：05、06、nvda、aging 四支完整成片；01 的动画素材；品牌 2D/3D 片段
- **方法**：在成片的关键时间点抽帧并逐张查看；读取 `build-report.json`、`media-qc.json`、`quality-report.json`、`gate.json`、`asr-alignment.json` 与生产日志；不依赖评分器结论
- **限制**：本环境不能听音。声音质量只评估可测指标（响度、音轨存在、ASR 可懂度），**不评估音色自然度、情绪、停顿**；这些标 `待验证`
- **评分尺度**：1 原始/不可用；2 录屏或幻灯片；3 合格的小频道；4 成熟的独立教育频道；5 专业频道（3B1B/Kurzgesagt 级）

> **2026-11-10 落实后更新**：06 已执行 `audio-mix`（loudness-only），母版 -15.8 LUFS；SRT 已按标点/词边界重排，V-31 对 Remotion 字幕 pass。05 的 `animation-score` 在去掉免费分后为 84.7（原 100）。视觉判断基于重排前的抽帧，结论不变。

## 1. 内容质量

### 1.1 05 Transformer 5 min

**优点**

- 叙事骨架完整：冷开场 → 问题 → 直觉 → 机制 → 测试 → 收尾（`narrative.json` 六段 pass）。
- 机制顺序正确：句子 → Q/K/V → 点积 → softmax → 加权 → 多头；没有明显的事实错误。
- 每页有"技术核查"字段，写明不能说什么（例如"不要把 Q 与 V 打分"）。

**问题**

- 事实核查覆盖不足：43 条 claim 中只有 3 条被双模型同时支持，38 条需要人工裁决，2 条有冲突；26 条有来源缺口。
- 画面里的矩阵/权重是示意值，没有真实模型输出；观众无法从片中判断这些数字是否可信。
- 5 分钟讲完 attention、多头、位置编码、残差、训练，信息密度高，但每个机制只停留 20–40 秒；对零基础观众偏快。
- 没有学习者证据；Teaching QA 只有结构检查。

**评分 3.5/5**：讲清楚了主干，但没有达到"看完能自己复述并应用"的教学深度。

### 1.2 06 Attention 62 s

**优点**

- 62 秒只讲一件事，钩子、几何、矩阵、流动、遮罩、总结、收尾，结构干净。
- 中文口播自然，句子短，适合短视频。
- 画面文字克制，没有堆砌。

**问题**

- **因果遮罩被说成普遍规律**：cue 11"还有一件事：注意力只能看它前面"。这只适用于 decoder 的自注意力；encoder 的自注意力是双向的。01 的技术核查明确要求"Decoder self-attention must be masked/causal... do not describe it as ordinary self-attention"。这是一个会被懂行观众抓住的概念错误。
- 标题《Attention in Ninety Seconds / 九十秒看懂注意力》，实际 62.17 秒；标题里的时长是计划值。
- 矩阵数值标注"示意，不是模型输出"；这很诚实，但也意味着"矩阵"这一段的视觉只是装饰，不能支撑"看懂"。
- 没有讲 softmax、value 向量本体、多头；作为 60 秒 teaser 可以，作为"看懂注意力"不够。

**评分 3.0/5**：合格的短视频，概念有一处过度简化。

### 1.3 nvda GPU 新闻 5:54

**优点**

- 项目里最强的内容底账：4 条一手来源（NVIDIA 员工信、董事会声明、新加坡 MHA 澄清、BIS 2025-05-13 指南），事实/报道/判断三分，明确写出"不主张什么"。
- 不把"GPU 无法追踪"绝对化，区分身份、位置、使用者三层；这是专业新闻的写法。
- 中文副题与英文正文的对应关系清楚。

**问题**

- 画面是 8 页英文要点 + 每页底部一段 80–120 字中文段落；抽帧 80 s 可见中文段落字号小、行距紧，视频里几乎不可读。
- 这是"PPT 录屏"的形态，与项目自己在 D-057 里说的"deck 模式不再用于机制解释"有张力。
- 字幕-语音一致性未验证（ASR 未跑，media QC `INCOMPLETE`）。

**评分 4.0/5（内容）/ 2.0/5（视觉）**：内容可信，画面没有承担叙事。

### 1.4 aging 3D 145 s

**优点**

- 用 3D 世界 + HUD 讲"衰老为什么演化"，视觉隐喻清楚。
- 所有数字（population、mean age、late-acting mutations）来自模拟，不是随口说的。
- HUD 在 Remotion 层绘制，世界片不烧字，后期可改。

**问题**

- 这是 Primer 的复刻 POC，不是原创内容；生物学解释的深度有限。
- 一个固定广角镜头持续 145 秒，没有镜头语言；观众看到的是"一个有 HUD 的鱼缸"。
- 生物是胶囊 + 头 + 腿，暗色场景，细节在 1080p 下不清楚。

**评分 2.5/5（内容）**：POC 级，不能当正式课程。

### 1.5 01 Transformer 20 min

- 12 页、54 段、1195.6 秒旁白；脚本结构完整，技术核查细。
- 但**没有成片**，也没有被批准的字幕；不能评价最终内容。
- 从已渲染的 `qkv_fanout` 抽帧看，画面是"盒子 + 箭头 + 无坐标柱状图"，比 05 的稀疏向量图更清楚，但仍不是连续图解。

**评分：未评**。内容素材 3.5，交付 1.0。

## 2. 视觉质量

### 2.1 逐片观察

**05 Transformer（抽帧 5/30/70/110/150/200/250/285 s）**

- 30 s：标题卡淡入，几乎空白；这是开场，可以接受，但持续偏长。
- 110 s：五个词片在顶部，公式在右上，两个向量在画面中央偏左；向量只占画面高度约 1/3，右侧和下方大面积空白。
- 150 s：词片与扇形箭头挤在左上，右下全空；构图的视觉重心在左上角，16:9 画幅没有被使用。
- 250 s：head 1/2/3 → 拼接 → W_O → output 的流程图，元素完整、对齐干净，但仍是通用方框箭头，没有"information flow"的质感。
- 285 s：收尾卡，干净。
- **总评 2.5/5**：排版正确、颜色克制、没有遮挡；但构图稀疏、主体偏小、画面缺少视觉焦点，像"讲义插图"而不是"视频画面"。

**06 Attention（抽帧 3/13/25/38/48/59 s）**

- 3 s：大字"让每个词"+ 例句 + 底部字幕；层级清楚，留白合理。
- 13 s：q/k 向量与点积公式；干净，但向量偏小，公式与字幕在底部同一带，略挤。
- 25 s：注意力矩阵；5×5 网格居中，标题左上，说明文字小；这是全片最好的一帧。
- 38 s：加权流动；边线极淡，几乎看不见，"重要的连接变粗"没有在画面上成立；整帧大部分是空白。
- 48 s：遮罩矩阵；斜线填充清楚，是全片第二好的一帧。
- 59 s：收尾；大字 + 例句，干净。
- **总评 3.0/5**：一致的编辑风格、克制的配色、清楚的层级；但关键机制帧（38 s）没有把话说清，整体信息密度偏低。

**nvda（抽帧 80/150 s）**

- 80 s：英文标题 + 4 条粗体要点 + 底部中文段落；典型的 PPT 页。
- 150 s：三层证据的动画中段，左上标题、左侧 H100 卡、右侧半透明层；大量空白，元素在淡入过程中。
- **总评 2.0/5**：信息在，但视觉没有设计；中文段落不可读。

**aging（抽帧 45/130 s）**

- 45 s / 130 s：同一个广角世界，右侧 HUD；生物在暗色地面上，湖水是一块灰色椭圆，植被是暗绿点。
- 构图稳定，但缺乏层次、光线和镜头运动；暗部细节丢失。
- **总评 3.0/5**：作为 3D POC 合格，作为成片偏"游戏截屏"。

**品牌 2D（抽帧 2.5 s）**

- 顶部 WAYNE lockup，中央英文标题，纸白背景；干净、克制、可读。
- **总评 4.0/5**：接近专业频道片头。

**品牌 3D（opener 抽帧 2/14/19 s）**

- 2 s：灰白方块角色站在暖灰地面，纸片散落；像早期灰盒。
- 14 s：角色与纸片、$ render lesson 文字；仍是灰盒。
- 19 s：巨幅黑 W + WAYNE；W 没有橙色电流，背景是暖灰，不是品牌纸白。
- **总评 2.0/5**：技术链路成立，美术不成立；项目自己的 README 也这么说。

### 2.2 视觉质量的共性问题

1. **主体太小、留白太大**：05/06 的向量、矩阵、图表只占画幅的 1/3–1/2，16:9 的下半部分经常空着。CodeVideo 的 skill 自己要求"主体至少占画面高度 1/3"，但没有成为门禁。
2. **构图不均衡**：05 的 150 s 把内容堆在左上；nvda 的 150 s 也是左上。缺少"视觉重心"的设计。
3. **关键机制帧不够强**：06 的 38 s 边线太淡，观众看不到"权重变大"；这是"把问题讲明白"的直接失败，不是审美问题。
4. **通用方框箭头**：05 的 250 s、01 的 qkv 都是盒子 + 箭头；没有 3B1B 那种"同一对象持续变形"的连续感。
5. **缺少镜头语言**：aging 145 秒一个固定广角；05 的相机基本固定；06 只有 1 次推近。项目自己在 3B1B 差距文档里承认"多数镜头只是静态等待旁白"。

## 5. 技术通过 ≠ 质量通过

| 技术指标 | 状态 | 画面实际 | 差距 |
| --- | --- | --- | --- |
| `build-report.verdict=pass` | 05/06/nvda/aging 全 pass | 画面稀疏、PPT、灰盒 | 工程契约不检查构图 |
| `animation-score=84.7/98.8` | 05/06 | 58/9 段冻结；免费分已移除 | 剩余分数仍来自 `beats.yaml` 自报，不是像素 |
| `quality-gate.releasable=true` | 05/06 | Q1/Q2/Q3/Q5 WARN | grammar 与 hard 不覆盖内容/画面 |
| `media-qc` PASS/WARN | 05 WARN、06 WARN、nvda INCOMPLETE | 06 响度低 6.8 dB | 响度只是 WARN，不阻断 |
| V-31 pass | 05 | 中文断词 | 行宽/CPS 检查不覆盖断词 |
| ASR 覆盖 0.992/0.935 | 05/06 | 字幕可懂 | 不检查语义与断句 |

**结论**：项目当前的自动检查能证明"文件是完整的、时间轴是连续的、音轨是存在的"，不能证明"讲得对、看得下去、听起来自然"。

## 6. 稳定 / 偶发 / 达不到

### 稳定能达到

- 1080p30 H.264、音轨存在、时长窗口、构建报告、失败可见。
- TTS 可懂（ASR 覆盖 0.93–0.99）。
- 5 分钟以内的结构完整讲解。
- 品牌 2D 片头片尾。
- 新闻的事实底账（如果人愿意做）。

### 偶发能达到

- 干净的构图（06 的 25/48 s，05 的 250 s）。
- 一致的双语字幕（05 burn-in）。
- 3D 场景（aging 的 HUD + 世界，但美术不稳定）。
- 1–2 个真正"动画在论证"的镜头（06 的 48 s 遮罩）。

### 达不到

- 3B1B 式的连续图解：对象跨镜头存活、同一场景持续变形。
- 专业声音设计：音效、音乐、词级同步、情绪。
- 专业构图与美术：主体占满画幅、光线、材质、镜头语言。
- 20 分钟课程的稳定交付（未验证）。
- 事实自动核查、教学有效性证明。

## 8. 最该修的三件"看得见"的事

1. **06 的 38 s**：把加权流动的边线加粗、加对比，让"重要的连接变粗"真的发生；这是内容问题，不是审美问题。
2. **05/06 的构图**：把主体放大到画幅的 50–70%，减少下半部空白；至少让每个关键帧有一个明确焦点。
3. **字幕断行**：按标点/词边界切，不允许"表/示，。"这种断法；01 和 05 都要重切。

这三件不需要新架构，只需要编辑与少量代码。
