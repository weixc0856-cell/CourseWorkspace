## 2. 实施顺序与验收

原则：每一步都必须产生可运行代码 + 可复现产物 + 一个“能红”的负例；不提前为后续模块铺空接口。

### P1 产品层合同（本轮）

- **产物**：`production/product.py`（五层定义、时长窗口、叙事模块、纵横比）；`lesson.yaml.product_tier` 可选字段；`course-control product-check`；`preflight` 输出产品层与窗口判定；JSON Schema 由模型导出。
- **验收**：单元测试覆盖每层的合法/越界时长、缺失声明、竖屏字段；对 `<内容根>` 的两条真实 lesson 跑出 PASS 与一条人为越界 FAIL。
- **不做**：不新建第二套产品 schema 文件手写维护。

### P2 视觉事件合同（本轮）

- **产物**：`production/visual_events.py`；从 `build/<slug>/shots.json` + `timeline.spec.json`（或 storyboard）编译 `build/<slug>/contracts/visual-events.json`；`course-control visual-events` 与 `visual-events-check`；校验渲染器注册、资产存在、claim 可解析、旁白区间合法。
- **验收**：对真实 lesson 生成事件表并通过检查；负例覆盖未知 renderer、缺 purpose、悬空 claim、越界时间、缺资产。
- **不做**：不替换现有 shots/timeline；它是同一条数据的规范化视图，供检查与后续渲染调度使用。

### P3 短视频组件与 JSON 分镜（本轮）

- **产物**：`RemotionStudio/src/short/` 四个组件 + `ShortStoryboard` composition；`shared/schemas/short-storyboard.schema.json`；由数据驱动，支持主题令牌与横竖屏。
- **验收**：渲染一段 90–180 s 样片（实际 mp4），媒体探测通过；组件负例（缺数据、超长文本、图片缺失）能红。
- **不做**：不做通用视频编辑器，不引入新依赖。

### P4 样片（本轮）

- **短视频**：90–180 s，实际渲染，含旁白、字幕、音画同步。
- **长视频**：10–30 min，实际渲染或由现有分段渲染拼装；记录分段、缓存与拼接。
- **验收**：`ffprobe` + `media-qc` + `subtitles-qc`；成片可播放；报告写入 `build/_shared/ip-samples/`。

### P5 质量与交付接入（本轮或下一轮）

- **产物**：`visual-events-check` 与 `product-check` 接入 `release-check`（缺失记 INCOMPLETE，不静默 PASS）；图文一致性的结构性检查（旁白段落 → claim → 视觉事件 → 资产）。
- **验收**：正例 PASS、缺视觉事件 INCOMPLETE、缺 claim 绑定 FAIL 三个状态都能复现。

### P6 跨引擎令牌一致性检查（已完成；导出未做）

- **产物**：`theme-check` 比对 tokens / themes / Manim / 版式；`token-frames-check` 对 Remotion 与 Manim 的同一布局色板帧做逐点比对，并校验 token 期望色、几何边界与输入哈希。
- **验收**：改一个 token 后 `theme-check` 变红；空白帧、两帧同错、缺格、越界/零尺寸布局都必须 FAIL；stub 或非对象报告记 INCOMPLETE；品牌证据必须是 schema 2、13 行、帧文件存在且三组哈希匹配，并且每行能从实际帧重算出来；伪造行或放宽 tolerance 必须 FAIL；帧损坏/尺寸错误或 tokens 缺 key 记 INCOMPLETE，不抛 traceback。
- **明确未做**：没有 `theme-export`，也没有生成第三份令牌文件；Blender 场景色不纳入品牌令牌。
