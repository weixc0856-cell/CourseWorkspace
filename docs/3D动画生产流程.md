# 3D 动画/电影生产流程

- **日期**：2026-11-14
- **定位**：以 AI 为构建指导、以现成资产库为基准、按 Blender 电影/动画标准流程组织生产。
- **适用**：需要 3D 场景的主题视频、课程 hero 镜头、系列片头与机制演示。
- **原则**：**发布门禁只有最终交付质量。** 本文的“检查点”是制作流程节点，不是发布门禁；不设镜头数量、动画比例、时长比例一类的硬性门槛。
- **资产原则**：**能用现成的绝对不重复造轮子。** 先查资产库；没有合适资产再下载登记；确实没有才自建，并写明理由。

---

## 1. AI、人、程序的分工

| 角色 | 负责 | 不负责 |
| --- | --- | --- |
| **AI** | 资料检索、参考拆解、镜头表初稿、场景配方、Blender Python/几何节点代码、资产检索、渲染、缓存、QC、差异报告 | 不单独裁决事实；不单独判定“好看”；不跳过程序检查写通过 |
| **人** | 选题、叙事、镜头取舍、hero frame 审美、animatic 锁定、最终拒收 | 不替代程序逐条查渲染/字幕/响度 |
| **程序** | Schema 校验、场景校验、媒体 QC、字幕 QC、发布三态、缓存与报告 | 不判断叙事与审美 |

AI 的产出都是**候选**：必须落到可渲染的文件、可校验的 Schema、可定位的帧。

## 2. 端到端流程

```text
0 立项与视觉路线
  → 1 剧本与六拍
  → 2 镜头表 / 场景分解 / 资产盘点
  → 3 Blockout（所有场景的粗模）
  → 4 Layout + Animatic（480p 粗剪）
  → 5 资产与细节（只做锁定镜头）
  → 6 动画与特效
  → 7 灯光与最终渲染
  → 8 剪辑 / 合成 / 调色 / 字幕
  → 9 声音与混音
  → 10 QC / 交付 / 归档
```

核心顺序：**所有场景先 blockout，不是所有场景先做完细节。** 细节按镜头分配，animatic 锁定后再投入。

## 2.1 三层结构：资产库 → 环境 → 镜头

场景不是一个巨大的 master `.blend`，而是三层文件，层与层之间只通过 id 和 spec 连接：

```text
Level 1  Asset Library
         <content_root>/assets/3d/library.json
              ↓ 只引用资产 id
Level 2  Environment / Set
         assets/3d/kits/<series>/environments/<place>.json
              ↓ 只引用一个 environment
Level 3  Shot
         assets/3d/kits/<series>/shots/<shot>.json
              ↓
         Scene Spec → Blender Builder → Validator → Renderer
```

| 层 | 拥有什么 | 不拥有什么 |
| --- | --- | --- |
| **Asset Library** | 模型、贴图、HDRI、heightmap 的路径、许可、版本、质量档、依赖 | 摆放、相机、灯光 |
| **Environment** | 地形、天空、环境光、布景、固定灯光；可被多个镜头复用 | 镜头时长、相机运动、输出路径 |
| **Shot** | 相机模板/关键帧、帧数、时长、渲染 profile、输出、可选的局部覆盖 | 不复制地形和整套资产 |

**为什么拆：** 一个地点会被多个镜头复用；如果把镜头塞进环境文件，每个镜头都会复制一套场景，改地形就要改很多份。拆开以后，环境只维护一次，镜头只关心“怎么拍”。

**Blender 落地方式：**

- 环境 spec 可单独构建为 `blends/environments/<place>.blend` 作为可复用 set；shot 构建为 `blends/shots/<shot>.blend`，通过 Library Linking 引用环境 collection 与 `AssetWorld`，只保留自己的相机和灯光。
- 构建模式：`--build environment` / `--build shot` / `--build inline`（旧兼容）/ `--build auto`（默认，有 env blend 就走 shot，否则 inline）。
- 当前只用了 Linking，没有用 Library Overrides；改链接对象本身仍不支持，shot 局部调整用新增自己的灯光/相机解决。
- 规模变大后，再切到 Blender Library Linking + Overrides：环境是 linked collection，镜头只存相机、灯光 override 和动画。切换不改变 spec 格式。
- 不在环境里写死某一镜头的相机；相机永远属于 shot。

**AI 的输入输出：** AI 只写 JSON spec（scene specification），不逐镜头生成任意 Python。Builder 是固定程序，只认 spec 和资产库；Validator 先检查，再交给 Blender。这样同一份 spec 可复现，出错能定位到字段。

**契约与能力注册表：**

- JSON Schema：`shared/scene-specs/environment.schema.json`、`shot.schema.json`、`camera.schema.json`、`terrain.schema.json`、`render.schema.json`、`lighting.schema.json`、`animation.schema.json`、`asset_catalog.schema.json`。
- 能力注册表：`shared/scene-specs/capabilities.json`（相机模板、引擎、profile、pass、资产类型、质量档、风格 preset）。
- 校验命令：`course-control asset-scene-validate --spec <spec>.json --json`。
- 生成 Schema：`course-control asset-scene-schema --output shared/scene-specs`。
- 构建命令：`scripts/build_asset_scene.py --spec <spec>.json --profile blockout|preview|hero`。

**这不是发布门禁。** Schema 只保证“能构建、资产存在、相机参数完整”；画面是否成立仍由 blockout/animatic/hero frame 的人工检查点决定。

**风格 preset（Visual Grammar）：** `shared/grammars/style-presets.yaml` 定义 `cinematic_realism`、`scientific_visualization`、`stylized_diorama`、`technical_cutaway` 四套构图/相机/灯光/色彩/声音默认值。环境或镜头用 `style` 引用；镜头可以覆盖，但要写明理由。

## 3. 各阶段

### 阶段 0：立项与视觉路线

**输入**：系列方案、分集主题、预算/时间、现有资产库。

**动作**：

- 写 `brief.md`：一句话核心点、目标观众、2–3 个支撑结论、边界。
- 决定画幅、时长预算、语言、字幕。
- 决定每条镜头的视觉路线：`A 3D` / `B 纸墨 2.5D` / `C 科学可视化`。
- 查资产库：`scripts/asset_library.py --tag ...`。

**产物**：`brief.md`、`project.yaml`、`lane-plan.md`（每条 beat 用哪条路线）。

**检查点**：人确认“这条片子主要用哪条视觉路线”。

### 阶段 1：剧本与六拍

**输入**：`brief.md`、来源材料。

**动作**：

- 写脚本；标事实/推论/边界。
- 写 `narrative-plan.json`（六拍）。
- 写口播/字幕草稿。

**产物**：`script.md`、`narrative-plan.json`、`captions.srt`。

**程序检查**：`narrative-validate`。

**检查点**：人确认叙事结构；AI 不替人做叙事取舍。

### 阶段 2：镜头表 / 场景分解 / 资产盘点

这是整条流程的**权威节点**。

**动作**：

- 写 `shot-list.yaml`：每镜的 id、beat、lane、scene、camera、duration、move、assets、captions、audio、status。
- 写 `scene-list.yaml`：每个 environment 的地点、资产、用途；相机归 shot，不归 environment。
- 写 `asset-gaps.md`：缺什么、候选来源、许可、体积、面数。
- AI 用 `asset_library.py` 检索；没有就列候选，不直接下载。

**产物**：`shot-list.yaml`、`scene-list.yaml`、`asset-gaps.md`、`storyboard.md`（缩略图/草图）。

**检查点**：人确认镜头表；确认哪些镜头是 A hero，哪些交给 B/C。

**停止条件**：资产缺口没有候选、许可不明、镜头表无法覆盖六拍 → 停，不进入 blockout。

### 阶段 3：Blockout（所有场景）

**动作**：

- 每个地点建一个 **environment spec**：地形、天空、布景、固定灯光；不追求材质，也不写某一镜头的相机。
- 每个镜头写一个 **shot spec**：引用 environment，定相机模板/关键帧、帧数、时长、输出。
- 用低分辨率（`--profile blockout`）渲染每个镜头的首/中/尾帧。
- 检查构图、景别、空间关系、镜头是否重复。

**产物**：

```text
assets/3d/kits/<series>/environments/<place>.json
assets/3d/kits/<series>/shots/<shot>.json
build/<ep>/blockout/<shot>-frame-*.png
```

**检查点**：人看 blockout 帧，确认“这个镜头成立”。

### 阶段 4：Layout + Animatic

**动作**：

- 在 shot spec 里选相机模板（hold-dolly-hold、横移、升降、环绕等）；不在环境里改相机。
- 用临时旁白/音乐/字幕，按六拍拼 480p animatic。
- 检查镜头时长、节奏、音画同步、镜头顺序。

**产物**：`build/<ep>/animatic/animatic.mp4`、`timeline.json`、`shot-lock.yaml`。

**检查点**：人锁定镜头顺序与时长；`shot-lock.yaml` 记录锁定版本。

**注意**：animatic 是决策工具，不是成片；不追求画质。

### 阶段 5：资产与细节（只做锁定镜头）

**动作**：

- 只对 `shot-lock.yaml` 里保留的镜头做细节。
- 查库/下载/登记资产；设置 PBR、HDRI、材质、比例。
- 先出 1080p 单帧 hero frame；通过后再做动画。

**产物**：更新后的 environment spec、`hero-frame.png`、`asset-manifest.md`。

**检查点**：hero frame 必须像“电影剧照”，不像场景测试；不通过就回到资产/构图，不进入动画。

### 阶段 6：动画与特效

**动作**：

- 相机动画：关键帧 + 逐关键帧 easing；推荐 hold → 匀速 → hold。
- 物体/角色/植被/水/粒子；运动模糊开启。
- 逐镜头渲染低分辨率预览，检查卡顿、跳帧、穿模、比例。

**产物**：`build/<ep>/animation/<shot>.mp4`、渲染日志、逐帧差异记录。

**检查点**：人看运动；AI 报告重复帧、速度突变、缓存命中。

### 阶段 7：灯光与最终渲染

**动作**：

- 最终 HDRI/三点光/体积雾/景深；AgX/调色。
- 输出 render passes（beauty / AO / depth / mist / cryptomatte 按需）。
- 1080p 或项目声明分辨率；正式帧率。

**产物**：`build/<ep>/final/<shot>/`、渲染报告、`media-qc` 预检。

**检查点**：曝光、噪声、黑帧/冻结；不通过就回灯光/采样。

### 阶段 8：剪辑 / 合成 / 调色 / 字幕

**动作**：

- 按 `shot-lock.yaml` 拼时间线；A/B/C 镜头共用一套 A Look：标题、字幕、颗粒、暖光、进度线。
- 字幕英文在上、中文在下；行宽/CPS/时间轴。
- 调色、颗粒、轻过渡；不做花哨转场。

**产物**：`build/<ep>/final/course-video.mp4`、字幕文件、`quality/subtitles-qc.json`。

**程序检查**：`media-qc`、`subtitles-qc`。

### 阶段 9：声音与混音

**动作**：

- 旁白 / 音乐 / 音效 / 环境声四层；关键证据处 duck/silence。
- 混音响度与峰值目标；输出 stems（按需）。

**产物**：`final/course-video-mixed.mp4`、`audio/mix.json`、cue sheet。

### 阶段 10：QC / 交付 / 归档

**动作**：

- `release-check`：media QC、字幕 QC、质量报告、质量门、缺陷、证书。
- 许可与署名核对。
- 打包 `deliver/<ep>/`；归档 shot list、scene 版本、asset manifest、decision.md。

**产物**：交付包、`quality/certificate.json`、`decision.md`、`LICENSES` 记录。

**发布**：`PASS` / `FAIL` / `INCOMPLETE`；缺项不得写成通过。

## 6. Blender 场景标准

- 单位：米；1 unit = 1 m。
- **环境与镜头分离**：`environments/<place>.json` 定义 set，`shots/<shot>.json` 定义相机/时长/输出；环境 `.blend` 可复用，镜头 `.blend` 按需生成。
- Collection：`ENVIRONMENT`、`ASSETS`、`CAMERAS`、`LIGHTS`、`FX`。
- 相机命名：`cam_<shot>`；一个镜头一台相机；相机不写进 environment spec。
- 资产引用优先用 collection/linked asset，不复制整套模型；当前 builder 用资产 id 导入，规模变大后切 Library Linking。
- 每个环境保存 `environments/<place>.json`；每个镜头保存 `shots/<shot>.json`；`.blend` 是构建产物，不是唯一真相。
- 版本：`<scene>_vNN.blend`；`shot-lock.yaml` 记录使用版本；spec 是版本化输入。
- 8 GB A750：2K 贴图优先；实例化；控制 bounces；blockout/preview 用 EEVEE，hero 再 Cycles/高采样。

### 6.1 相机模板

`camera.template` 是受控词汇，不让 AI 每镜头手写关键帧：

| 模板 | 用途 | 必要参数 |
| --- | --- | --- |
| `static_hold` | 固定机位，靠画面内部运动 | location / target |
| `dolly_in` / `dolly_out` | 推近/拉远；默认 hold → 匀速 → hold | location、end_location |
| `pan` | 横移 | location、end_location |
| `tilt` | 固定机位、抬/低头 | location、end_target |
| `crane` | 升降 | location、end_location |
| `orbit` | 环绕 | center、radius、角度 |
| `tracking` | 跟随目标 | location、end_location |
| `parallax` | 分层视差推镜 | location、end_location、target 偏移 |

默认把模板展开成 4 个关键帧：首 hold（BEZIER）、入 move（LINEAR）、出 move（BEZIER）、尾 hold（BEZIER）。需要更复杂运动时，才在 shot spec 写显式 `keyframes`。

### 6.2 渲染 profile 与 passes

- `blockout`：EEVEE 16 samples，540×960，用于构图/节奏。
- `preview`：EEVEE 32 samples，540×960，用于 animatic。
- `hero`：spec 里声明的分辨率/采样（通常 1080×1920，EEVEE 或 Cycles）。
- `render.passes` 可选：`beauty`、`ao`、`depth`、`mist`、`normal`、`emission`、`cryptomatte`；builder 输出 multilayer EXR 到 `render.pass_dir`，用于镜头复核/合成，不替代 H.264 预览。

### 6.3 Build manifest 与缓存

每次构建在输出目录的 `manifests/` 写：

```text
<shot>-<build-id>.json   # 输入哈希、版本、render 参数、status、耗时
<shot>-<build-id>.log    # spec、cache key、render、blend、output
```

缓存键包含 spec / environment / library / builder / 资产 / Blender / Python / addons / render profile / Visual Grammar / seed 的哈希。命中条件：已有 `status=pass`、`cache_key` 相同、`shot` 相同、输出文件存在。命中时打印 `ASSET_SCENE_CACHED` 并跳过重建。

```powershell
# 默认缓存；强制重建用 --no-cache
scripts/render-asset-shot.ps1 -Spec <shot>.json -Profile preview `
  -ManifestDir <dir> [-NoCache] [-Frames 1]
```

manifest 是构建证据，不是发布门禁；发布仍由交付质量决定。

### 6.4 风的可视化

风本身不可见，画面只表现“风的结果”。当前受控方式：

| 方式 | 说明 | 适用 |
| --- | --- | --- |
| `wind.style: motes` | 实例化细长尘/雪颗粒，沿风向线性移动，运动模糊拉成短 streaks | 山脊、谷地、水面；P5 使用 |
| `wind.style: ribbons` | 半透明流线带，沿路径移动；更图解化 | 机制示意 |
| `wind.style: mist` | 体积雾/噪声漂移；更像云雾 | 需要大气流动时 |

P5 选用 `motes`：它比白色线条自然，但仍不是 CFD 模拟。成片右下角固定标注 `WIND: SCHEMATIC · NOT A SITE MEASUREMENT`，不得把画面当成实测风场或古代理论的科学证明。

`wind` 字段属于 shot，不属于 environment；同一环境的不同镜头可以用不同风速/密度/高度。参数只控制视觉，不产生物理结论。

## 7. 资产库工作流

1. `asset_library.py --tag/--kind/--query` 检索。
2. 有合适资产 → 直接用；记录 `used_in`。
3. 没有 → 找 Poly Haven / ambientCG / NASA / USGS 等 CC0/公有领域候选；核对许可、体积、面数、尺度。
4. 下载到 `assets/3d/...`，更新 `library.json` 与 `LICENSES.md`。
5. 仍没有 → 写 `asset-gaps.md`，说明为什么必须自建；自建后同样登记，供后续复用。
6. 不在没有检索证据的情况下手搓模型或几何。

## 8. AI 的边界

- AI 可以提出镜头、相机、资产、代码、检查结果；**不能单独裁决事实，也不能单独判定作品合格**。
- AI 的每个结论必须落到文件、帧、报告；不能只说“已完成”。
- 遇到不确定：先做不依赖该答案的部分，把问题集中到检查点问人。
- 同一问题尝试 3 次仍失败：停止，记录问题、已尝试修复、证据、下一步建议。

## 9. 检查点与停止条件

| 检查点 | 位置 | 人确认什么 | 不通过时 |
| --- | --- | --- | --- |
| C0 | 阶段 0 | 视觉路线与画幅 | 回到 brief |
| C1 | 阶段 1 | 六拍叙事 | 改脚本/结构 |
| C2 | 阶段 2 | 镜头表与 lane 分配 | 改镜头表 |
| C3 | 阶段 3 | blockout 构图 | 改场景/相机 |
| C4 | 阶段 4 | animatic 节奏 | 改时长/顺序 |
