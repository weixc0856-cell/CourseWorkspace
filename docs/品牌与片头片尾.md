# 品牌与片头片尾（Brand Layer）

日期：2026-11-10
代码：`RemotionStudio/src/brand/`、`CourseControl/src/course_control/branding.py`、`adapters/brand.py`
配置：`shared/design-tokens/brand.json`（Remotion 与 Python 共同读取）
命令：`course-control brand-plan` / `brand-render`

## 1. 定位

`Wayne-CFD` 是频道名，`WAYNE` 是视觉主品牌，`ENGINEERING & COMPUTATION` 是内容边界。

品牌层只负责片头、片尾与签名，并且**只允许英文**。它不参与课程内容、导演计划或事实判断；正片是原子资产（Atomic Asset），品牌永远在成片（含字幕/BGM）完成之后按 `片头 → 正片 → 片尾` 纯线性拼接，正片视频轨与音频轨不裁剪、不淡入淡出、不提前播放。品牌默认关闭，只有 `lesson.yaml.branding` 显式开启才生效；开启后正片帧与音频包必须与母版逐字节一致（见 §7.2 抽样核验）。

## 2. 与既有视觉规范的合并

品牌没有新建第二套色板。角色直接映射 `shared/design-tokens/tokens.json`：

| 品牌角色 | Token | 值 |
| --- | --- | --- |
| 背景 | `paper` | `#FBFAF7` |
| 主文字 | `ink` | `#252A31` |
| 正文 | `text` | `#2E3338` |
| 辅助 | `muted` | `#6B7280` |
| 强调 / W 中的电流 | `orange` | `#E8733B` |
| 细线 | `border` | `#E3E0D7` |

外部方案给出的 `#F7F7F8` / `#18191C` / `#F25F22` 是另一套近似值；采用会与课件、Manim、Blender 形成两套 hex，破坏 FR-31 的单一色板，因此不采纳。

字体只用已打包的 `Noto Sans SC`：Latin 400/600/700 + 中文 400（字幕与正片沿用）。品牌画面全英文，**不再注入中文粗体**；片头片尾不出现任何中文字符。

## 3. 网格、字号与标识

所有品牌帧共用 `src/brand/layout.tsx`：1920×1080、96 px 安全边距、12 栏、24 px 栏距。字号六级（168 / 72 / 44 / 30 / 18 / 13），大字号负字距（−0.05 em / −0.025 em），小标签宽字距（0.16–0.2 em）。唯一的结构装饰是 1 px 细线。

标识是**一条折线构成的 W**（`BrandMark`）：单一 SVG path、`pathLength={1}` 的 dash 描边，任何 fps 下逐帧可复现；中间上升笔画内嵌一条更细的橙色“电流”，不填充色块。lockup 的 W 按**字冠中心**对齐字标，不按容器底对齐（后者会掉到副标题基线上）。

动态标题按“中文 1 em、英文 0.55 em”估算宽度，从给定字号里选能放下的一档，避免换行压住其他元素。

## 4. 字段权限

品牌帧只允许以下字段进入画面：

| 画面 | 允许 | 禁止 |
| --- | --- | --- |
| 课程片头 | 品牌 lockup、英文单集标题 | 分类编号（`05`）、中文副题、系列名、下一课、口号、频道名 |
| 课程片尾 | 品牌 lockup、`Thanks for watching.`、`Subscribe for more deep dives.` | 课程元数据、`NEXT`、中文、重复的订阅标签 |
| 新闻片尾 | 英文栏目、真实日期、lockup、致谢、CTA | 中文、来源占位符 |
| 竖屏签名 | lockup、英文栏目 | 中文、标题、长视频片尾 |

`Branding` 契约里已删除 `series` / `next_title` / `episode` / `subtitle`；写入这些字段会直接校验失败，而不是被默默渲染。

## 5. 画面规格

### 5.1 课程片头（默认 3.0 s，硬切）

| 时间 | 动作 |
| --- | --- |
| 0.00–0.50 | W 逐笔画出 |
| 0.35–0.90 | WAYNE 字距收拢 |
| 0.75–1.20 | 居中英文单集标题 |
| 1.20–3.00 | 定格保持 |

画面只有两件东西：顶部居中的品牌 lockup、画面中央的英文标题。**末帧保持标题卡，正片硬切进入**；不淡出、不做纸面遮罩。第一版在第 2.95 s 开始淡出，结果 3.0–3.5 s 几乎全空，接正片前有半秒“断气”。

### 5.2 课程片尾（默认 12 s）

居中的收尾卡：lockup → 96 px 细线 → `Thanks for watching.` → `Subscribe for more deep dives.`。约 1.1 s 内全部到位，其余时间保持静止，给 YouTube 互动元素留干净背景。右侧不画面板、不画虚线框。

几何约束（`CenteredLockup`）：

- 上层 `[W 图标] + [WAYNE]` 作为一个整体行居中，图标与字标按中心对齐；
- `ENGINEERING & COMPUTATION` 居中于**整组（图标 + 字标）**，不依附于 WAYNE 文本宽度；
- 细线、致谢、CTA 均独立居中；
- 字距会在最后一个字形后留下空隙，tagline 用 `marginRight: -0.22em` 抵消，否则墨迹中心会偏左约 2–3 px；
- 五个内容带的墨迹中心与 960 px 中轴误差必须 ≤ 1 px，用 `scripts/brand-centers.py` 验证。

### 5.3 新闻片尾（默认 6 s）

同一张收尾卡，左上英文栏目、右上真实日期（`branding.date`），不写占位来源。新闻不开片头，第一句口播即开场。

### 5.4 竖屏签名（默认 1 s，1080×1920）

lockup + 英文栏目，居中在 9:16 安全区。不复用长视频片尾。

## 6. 配置

`lesson.yaml`（全部可省略；缺省 `branding` 关闭，既有课程时长与验收不受影响）：

```yaml
branding:
  theme: wayne-light
  intro: {}                      # preset: auto → 按 content_kind
  outro:
    duration_s: 12               # 必须在 preset 的 min/max 内
  date: "2026-11-09"             # 仅新闻片尾使用
  preview_safe_area: false       # true 时画出 YouTube 预留区虚线（仅预览）
```

`intro.enabled: false` 可单边关闭；`preset` 也可写死（`course_intro` / `course_outro` / `news_outro` / `short_signature`），但必须符合形态规则：新闻配课程片头、竖屏配课程片头/片尾、长视频配签名都会报错。

## 7. 流水线与时间轴

```text
validate → capture → render:* → collect → compose
        → burn_subtitles (可选) → brand (可选) → verify
```

- 观看母版按 `course-video-mixed.mp4` → `course-video-captioned.mp4` → `course-video.mp4` 选择；品牌只加在母版两端。
- 输出 `final/course-video-delivery.mp4`，并写 `final/brand.json`（母版、模式、时长、fps、分辨率、音轨、哈希、**video_timing**、**audio_alignment**、问题列表）。
- 片段缓存按 `composition + duration_frames + props + 分辨率 + fps` 的哈希判定；`--force` 绕过。
- 拼接**不直接对 MP4 做 `-c copy`**：各段 timescale 不同，concat 不会重缩放映时间戳，正片帧会被压到同一 PTS（实测每帧只加 11 微秒），画面成了“快闪”，音频和字幕却按真实时间走。现在先把每段重封装成 MPEG-TS（`-c copy -bsf:v h264_mp4toannexb`），再按**视频流时长**写入 concat 的 `duration`，最后重封装为 MP4；编码帧与音频样本仍是复制，不重编码。
- 若时长、分辨率、fps、音轨、帧间距或音频对齐任一不符，自动回退重编码并记录 `mode`。

### 7.1 正片音频绝对对齐（程序核验）

拼接后自动执行：

1. 片头静音轨的音频时长必须与片头视频时长相差 ≤ 1 帧（AAC 帧量化允许 2–20 ms）；
2. 单独测量正片**第一段非静音音频**的时间 `body_first`；
3. 再测成片里同一事件的时间 `actual`，期望 `expected = intro_s + body_first`；
4. `|actual − expected| ≤ 0.2 s` 才写 `audio_alignment.status = "pass"`，否则 `brand` 阶段失败，不产出交付文件；
5. V-36 再读 `brand.json`，`status = fail` 直接判失败。

### 7.2 帧时间戳门禁

只看时长和 DTS 单调不够——时间戳塌缩的文件时长仍然正确。拼接后读取全部视频包 PTS，排序后统计帧间距：

- 正常：间距 ≈ 1/fps；
- 塌缩：大量间距 < 半帧（实测 0.000011 s）；
- 同时校验唯一帧数与 `时长 × fps` 的差 ≤ 2%。

结果写进 `brand.json.video_timing`；`clustered_intervals > 2` 或帧数不符即判 `fail`，触发重编码回退，V-36 同样拒绝。

实测（292.367 s 母版 + 3.0 s 片头 + 12 s 片尾）：`body_first=0.0`、`expected=3.0`、`actual=3.085`、`delta=0.085`、`status=pass`；成片 0–3.085 s 静音，第一句人声出现在 3.085 s，即片头结束后 85 ms（原片开头的自然停顿），不是抢跑。

## 8. 验收

`verify` 的 **V-36**：

- 品牌关闭 → `not_applicable`；
- 开启时要求 delivery、`brand/plan.json`、`final/brand.json` 同时存在；
- 从 plan 与母版实测重算 `body + brand`，与交付时长比对（容差 = 片段数 / fps + 0.15 s）；
- 分辨率、fps、音轨与母版一致；`sha256` 与 `brand.json` 一致；`audio_alignment.status` 不是 `fail`；
- 交付包在品牌开启时把交付文件列为必需项。

## 9. 已验证

- `tsc --noEmit` 通过；已加入 `scripts/check.ps1`。
- 品牌单测 29 个：预设/形态规则、时长边界、分辨率约束、字段权限（拒绝 series/next_title/episode/subtitle）、props 不含元数据、缓存键、母版优先级、首段声音检测（有前导静音 / 从 0 开始两种）、帧间距分析（正常 / 塌缩 / 缺帧）。
- 真机：3.0 s 片头（90 帧）、12 s 片尾（360 帧）、1 s 竖屏签名；与 292.367 s 母版拼接 → **307.367 s**，`mode=copy`（TS 重封装），`video_timing`：9221/9221 帧、最小间距 0.012 s、clustered 1、pass；`audio_alignment=pass`（delta 0.107 s）。正片帧与音频包逐字节比对一致（framemd5 / packet md5）。
- 视觉审查：`build/brand-review/final-intro.png`、`final-outro.png`、`final-handoff.png`（含硬切前后帧）、`final-outro-sheet.png`。

## 10. 边界

- 品牌组件固定 1920×1080 / 1080×1920，其它分辨率在 `brand-plan` 阶段报错（4K 未参数化）。
- 无音效资产，片头片尾保持静音。
- 新闻正片的来源条/日期卡未接入；竖屏生产链路只提供签名；缩略图与信息图模板未做。
- 品牌全英文是硬规则；中文课程标题不进入品牌画面（英文 `title_en` 必填）。
- 本轮只改了片尾组件与静帧，没有重新拼接成片；下一次 `brand-render --stitch` 才会把新几何带入交付文件。
