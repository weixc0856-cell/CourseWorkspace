## 4. 接口缺失

1. **统一 `ShotSpec`**：当前枚举只有 `motion_canvas|manim|blender`；session、simulation、graphics 无法进入 lesson/storyboard。
2. **`NarrationSpec`**：没有逐镜头旁白、文本哈希、音频哈希、时长、voice 的统一结构。
3. **`TimelineSpec`**：`shots.json` 是渲染产物，不是可审阅的时间线契约；没有统一的帧/毫秒规则。
4. **`RenderManifest`**：E6 有临时 manifest，课程构建有 `BuildReport`，但两者不互认。
5. **素材引用**：`LessonConfig.content.assets` 只是目录名，没有 `AssetRef`（路径 + 哈希 + 版本）。
6. **Track 适配接口**：Manim 走 adapter，Session 走独立 CLI，E6 走手工 manifest；没有统一“镜头 → 素材 → 时间线”的适配层。
7. **课程级 session ID**：`SessionSpec.session_id` 只在 session 内部；与 lesson/shot 的关联未写入课程报告。

## 8. 架构判断

- 现有分层是正确的，**不要为了统一契约重写稳定轨道**。
- 主要问题不是缺功能，而是**同一种事实（时间、证据、旁白、渲染）有多套表示**。
- 推荐路径：先加一层**规范化契约与适配器**，让 Manim / Session / Simulation / Graphics 各自产出同一套 `RenderManifest` 与 `EvidenceManifest`，再由 `TimelineSpec` 统一进入 Remotion/FFmpeg。
- E6 是第一个迁移对象：保留 Manim 代码，只把产出映射到 V1。
