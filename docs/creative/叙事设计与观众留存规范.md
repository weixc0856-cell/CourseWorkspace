# 叙事设计与观众留存规范

- **版本**：v1.0
- **状态**：现行创作规范（Director / Producer / 质量审查共用）
- **适用范围**：长视频课程、5 分钟以内的短课/校准片、30–90 秒竖屏 Shorts
- **依据**：Veritasium、3Blue1Brown、StatQuest、Primer、Fireship、Two Minute Papers 的公开作品分析；结合 CourseWorkspace 现有 Director、Producer、ContentQA、Media QA 能力整理
- **约束**：参考对象用于提取方法，不复制内容、视觉资产或表达风格；任何事实主张仍以来源证据为准。

---

## 0. 定位

CourseWorkspace 不是动画频道，也不是传统网课，而是**以科学、工程、计算机和 AI 机制解释为核心的可视化知识频道**。

因此吸收的是六种能力，而不是六套画风：

| 能力 | 主要参考 | 学什么 | 不学什么 |
| --- | --- | --- | --- |
| 选题与叙事 | Veritasium | 反直觉现象、问题意识、证据推翻错误直觉 | 为反转制造伪争议 |
| 视觉解释 | 3Blue1Brown | 变量关系、连续运动、画面承担解释 | 为复杂而复杂、动画与概念脱节 |
| 教学拆解 | StatQuest | 先直觉后术语、小步建立局部结论 | 过度简化导致失真 |
| 机制模拟 | Primer | 规则、初始条件、演化、参数对比 | 把示意动画说成真实求解 |
| 信息节奏 | Fireship | 开场不寒暄、短句、对比、视觉强调 | 高密度剪辑牺牲理解 |
| 研究转译 | Two Minute Papers | 问题、方法、结果、局限 | 把摘要包装成突破 |

**差异化**：真实工程与 CFD 背景 + 可运行、可验证的动画与模拟。别人可以复制风格，不能复制“能跑、能复现、有证据”的机制解释。

---

## 1. 两类产品，分开设计

### 1.1 长视频（主资产）

- 常见目标 10–22 分钟；时长由内容决定，不强行凑。
- 必须有完整的问题、机制、推导、验证和结论。
- 5 分钟以内的成片按**短课/校准片**处理：用于验证生产链和叙事骨架，不替代完整课程。
- 允许 5–10 分钟的专题短片，但必须遵守同一叙事骨架与质量门禁。

### 1.2 Shorts（流量入口）

- 30–90 秒，竖屏 9:16。
- 只讲**一个**反直觉问题或一个关键机制。
- 前 3 秒给出结果、冲突或现象；结尾形成完整小结论或自然引向长视频。
- **必须是独立脚本，不是从长视频机械裁切。**
- 每条 Shorts 有自己的 `video_form: short`、`narrative-plan.json` 和质量报告。

### 1.3 同一主题的产品族

以“幽灵堵车”为例：

| 产品 | 内容 | 作用 |
| --- | --- | --- |
| 长视频 | 规则、模型、拥堵波、参数实验、结论 | 建立信任与专业壁垒 |
| Shorts 1 | 前车刹车，为什么后面越来越堵 | 现象钩子 |
| Shorts 2 | 没有事故也会堵？ | 认知冲突 |
| Shorts 3 | 一个跟车模型如何产生拥堵波 | 机制展示 |

三条 Shorts 都能独立观看，同时自然引向长视频。

## 2. 长视频叙事骨架（默认模板）

每个长视频在 `lessons/<slug>/authoring/narrative-plan.json` 中声明六个 beat，并由
`course-control narrative-validate --lesson <slug>` 校验结构和时间。

| Beat | 作用 | 参考区间 | 画面/口播要求 |
| --- | --- | --- | --- |
| `cold_open` | 现象、矛盾、错误直觉或意外结果 | 0–20 s | 不寒暄；先给结果或冲突 |
| `question` | 明确本集问题、为什么值得看、最后能回答什么 | 20–60 s | 一句话说清问题 |
| `intuition` | 用简单例子建立变量与关系 | 约 1–4 min | 先直觉，后术语 |
| `mechanism` | 动画/公式/模拟展示因果关系 | 约 4–12 min | 画面承担解释，不是装饰 |
| `test` | 案例、边界、反例、参数变化 | 约 12–17 min | 明确解释在什么条件下成立/不成立 |
| `connect` | 重新组织成完整模型，连接真实工程/AI | 最后 1–3 min | 总结、迁移、下一步 |

规则：

1. 不要求每 90 秒机械切一个“闭环”；真正要求的是观众始终知道：现在解决什么问题、刚刚理解了什么、为什么继续看。
2. `cold_open` 不超过 30 秒；`question` 不超过 90 秒（超时给 warning，不硬失败）。
3. beat 不得重叠；`cold_open` 必须在最前，`connect` 通常在最后。
4. 叙事时长与 `lesson.yaml.duration.target_seconds` 偏差超过 15 秒或 10% 时给 warning。

## 3. 每个知识模块的教学闭环

一个**模块**（不是每一页）应尽量包含：

1. 问题或真实场景。
2. 直觉解释。
3. 正式概念/定义。
4. 原理或机制。
5. 具体例子。
6. 反例或常见误解。
7. 应用场景。
8. 理解检查（问题、预测、小练习）。

不要求每页重复八步；要求每个重要模块能回答“为什么需要它、它解决什么问题、什么时候会错”。

## 4. 视觉生产方式：A 档、B 档与混合

A/B 是**视觉生产方式**，不是内容质量等级。

### A 档：概念与关系可视化

- 参考：3Blue1Brown + StatQuest。
- 适用：Transformer、Attention、Embedding、数学、算法、CFD 控制方程。
- 画面：矩阵、向量、粒子、色块、连线、状态转换、分阶段结构图。
- 要求：视觉对象与概念一一对应；运动解释变量关系。

### B 档：系统与现象模拟

- 参考：Primer + Two Minute Papers。
- 适用：CFD 流动、交通流、多智能体、优化过程、论文实验。
- 画面：粒子、场分布、网格变化、参数对比、基线与改进。
- 要求：**明确标注证据类型**：
  - `real_data`：真实实验/测量数据；
  - `simulation`：数值模拟；
  - `schematic`：概念示意，不是求解结果。
- 禁止把示意粒子动画说成真实 CFD 求解；模拟必须能说明规则、初始条件与参数。

### 混合

允许同一期混用：A 档解释 Q/K/V → B 档展示注意力权重变化 → A 档解释输出向量为什么变化。混合的价值在教学，不在风格。

## 5. 口播、字幕与节奏

1. 先讲问题和意义，再给正式定义。
2. 关键术语首次出现给白话解释。
3. 复杂概念放慢；重要结论后留停顿。
4. 口播必须与画面同步；不允许为凑时长重复表达。
5. 语速/停顿/句长/字幕字符数只是**初始参考值**，必须用真实样片校准，不作为所有课程的硬门槛。
6. 字幕依据最终音频的实际时间信息生成；当前未接入 ASR/强制对齐时，状态必须是 `INCOMPLETE`，不能写 PASS。
7. 不允许每期强行制造悬念、幽默或“惊天反转”。

## 6. Shorts 脚本规范

- 时长 30–90 秒；竖屏 9:16；单主题。
- 结构：
  1. 0–3 s：结果、冲突或现象（不寒暄）。
  2. 3–15 s：明确问题。
  3. 15–70 s：一个机制或一个对比，一次讲透。
  4. 最后 5–15 s：完整小结论，或自然引向长视频。
- 必须独立撰写、独立录制/合成；不得直接裁切长视频中间 60 秒。
- 选题优先：反直觉现象、常见误解、单变量对比、一个可复现的小实验。
- 不在 Shorts 中塞入需要长推导才能成立的主张。

## 7. 选题与开场检查

| 类型 | 检查问题 | 示例 |
| --- | --- | --- |
| 反直觉型 | 观众的默认判断是什么？证据如何推翻它？ | 网格加密 10 倍，结果反而更不可信？ |
| 机制揭秘型 | 系统内部发生了什么？ | Transformer 怎么知道该关注哪个词？ |
| 阶梯教学型 | 能否拆成 3–5 个可独立理解的小问题？ | 梯度下降：损失、梯度、方向、学习率 |
| 模拟探索型 | 规则是什么？改变参数会看到什么？ | 无事故、无红绿灯，为什么还会堵车？ |
| 快节奏概括型 | 一句话能否建立核心认知？ | Git 记录的是状态变化，不是文件备份 |

每个选题在 `narrative-plan.json` 中写清 `audience`、`promise`、`payoff`；写不清就不进入制作。

## 8. 质量门禁与状态

五条质量防线继续独立报告，不允许综合分掩盖缺陷：

| 维度 | 与创作规范的关系 |
| --- | --- |
| Q1 内容可信度 | 主张、来源、证据；模型一致不等于事实正确 |
| Q2 教学有效性 | `narrative-validate` 通过只证明结构，不证明讲得懂；真实学习者证据缺失时不得 QUALITY_PASS |
| Q3 视听体验 | 口播/字幕/音频/画面/音画一致；未接入 ASR 时字幕一致性为 INCOMPLETE |
| Q4 工程完整性 | 构建、解码、帧数、时长、证据链 |
| Q5 最终交付 | 文件、双语、版权、人工批准 |

状态：

- 每个维度：`PASS / WARN / BLOCKED / INCOMPLETE`。
- 三层：`BUILD_PASS / QUALITY_PASS / RELEASE_APPROVED`。
- `INCOMPLETE` 是生产中的合法状态，不是正式交付的合格状态。
- `RELEASE_APPROVED` 必须有人工批准文件，系统不得代签。

## 9. 数据与迭代

同一平台、相近主题、相近时长下比较：

| 指标 | 目的 |
| --- | --- |
| 前 30 秒留存 | 开场是否有效 |
| 平均观看时长 | 整体吸引力 |
| 平均观看百分比 | 不同长度相对表现 |
| 章节流失点 | 哪个解释环节让人离开 |
| 评论中的理解问题 | 是否真正讲清楚 |
| Shorts → 长视频转化 | 短内容是否带来有效观众 |

不要只看播放量和完播率；不同平台与受众来源不可直接横比。

## 10. Director / Producer 执行契约

1. `lesson.yaml` 增加 `video_form: long | short`（默认 `long`）。
2. 长视频与 Shorts 都必须提供 `authoring/narrative-plan.json`，并在 `authoring.narrative` 中登记。
3. `course-control narrative-validate --lesson <slug>` 写入
   `build/<slug>/quality/narrative.json`；结构错误为 `fail`，时间偏差为 `warn`。
4. 质量报告 Q2 优先读取 `teaching-qa.json`；没有时读取 `narrative.json`：
   - `pass/warn` → Q2 记 `WARN`（结构通过，教学效果未被证明）；
   - `fail` → Q2 记 `BLOCKED`；
   - 缺失 → `INCOMPLETE`。
5. Producer 不得用“叙事结构通过”替代教学质量结论；不得自动批准发布。
6. Shorts 使用独立 lesson 目录与独立脚本，不复用长视频的旁白时间轴。

---

## 11. 反模式

- 六种风格平均混合，形成“拼接版”。
- 为反转制造伪争议，或每期强行惊天悬念。
- 为了动画好看牺牲解释，或动画只做装饰。
- 把示意模拟写成真实 CFD/实验数据。
- 把模型投票或叙事结构校验当成事实/教学通过。
- 机械每 90 秒切一个 HUD 闭环。
- 从长视频裁一段就发 Shorts。
- 用固定语速、固定字幕字数为所有课程设硬门槛。
- 工程构建通过就宣布课程质量合格。
