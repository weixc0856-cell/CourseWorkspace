# 课件生成调用指南（Prompting Guide）

本指南约定如何调用 `tech-course-deck-studio-v3`，生成本工程可直接渲染的中英双语技术课件（`slides.md`）与独立讲师手册（`lecture_notes.md`）。它不实现生成器本身，只定义输入、输出、版式和验收标准。

跨仓的总流程（四阶段、多引擎动画、自动构建、本地模型与配音）见 [课件制作总指导](../../docs/课件制作总指导.md)；本文件只负责幻灯片侧的单页规范。

**工程基准**

- `reveal.js 6.0.2`，画布 `1280 × 720`，16:9。
- 全工程只有一个渲染外壳：[template/index.html](../template/index.html)。
- 课件内容写入工作区根目录的 `lessons/<lesson-slug>/slides.md`，通过 URL 参数切换。
- 每套课件由两个文件组成：`slides.md`（纯展示）与 `lecture_notes.md`（逐字稿与导播）。`slides.md` 内不得出现 `Notes:`、口播、时长或动画标记。
- 视觉主题为 [css/mckinsey-orange.css](../css/mckinsey-orange.css)：纯白底、深炭灰正文、麦肯锡橙强调色。
- 本工程不嵌入视频：动态内容由 [MotionStudio](../../MotionStudio)、[ManimSandbox](../../ManimSandbox)、[BlenderStudio](../../BlenderStudio) 独立产出，最终由 [RemotionStudio](../../RemotionStudio) 合成；`slides.md` 中不出现 `<video>`、自动播放或视频尺寸适配。
- 可选参考成品：内容根下任意课程的 `lessons/<slug>/slides.md`。
- 课件预览默认监听 `8081`；`8080` 固定留给本地模型服务，两者可同时运行。
- 自动截图与最终合成由 [CourseControl](../../CourseControl) 调度；本文件的“无构建步骤”仅指幻灯片 Markdown 不需要构建。

调用生成器时，把本文件与上述模板、主题、样例一并作为上下文。生成器不得要求为每一套课件修改 `template/index.html`。

## 一、输出契约

| 项目 | 约定 |
| --- | --- |
| 课件目录 | 工作区根目录的 `lessons/<lesson-slug>/` |
| slug 规则 | 小写字母、数字、短横线，例如 `02-attention-patterns` |
| 展示文件 | `lessons/<lesson-slug>/slides.md`（纯净，无口播） |
| 讲师文件 | `lessons/<lesson-slug>/lecture_notes.md`（逐字稿与导播） |
| 资源目录 | `lessons/<lesson-slug>/assets/` |
| 预览地址 | `http://localhost:8081/?lesson=<lesson-slug>` |
| 页面规模 | 推荐 15~20 页；单页只承载一个核心命题 |
| 主语言 | 页面上方英文；下方中文对照，放在 `.zh-sub` |
| 交付方式 | 两个独立文本块：A 追加到 `slides.md`，B 追加到 `lecture_notes.md`，不得混在同一块里 |
| 构建步骤 | 无。`live-server` 直接加载外部 Markdown |

不允许多套课件各自复制一份 HTML 外壳。新增样式只能写入主题文件，并经确认后使用；不要在页面里写 `<style>` 或内联样式覆盖主题。

## 二、推荐工作流：大纲规划 → 分幕交付

一次性生成 15~20 页容易发生截断、事实漂移和版式失控。建议固定为三个阶段：

1. **阶段一：只定大纲**，确认叙事线、每页论点和视觉类型。
2. **阶段二：分幕写正文**，每批 4~6 页，同时交付 `slides.md` 片段与对应的 `lecture_notes.md` 块。
3. **阶段三：本地验收**，检查路径、排版、事实，以及两份文件的页序是否对得上。

### 阶段一：发起需求与大纲对齐

复制下面的模板，替换方括号内容后发给生成器。此阶段明确要求“不写正文”。

```text
请调用 tech-course-deck-studio-v3，为当前 reveal.js 课件工程规划一期课件大纲。
本阶段只输出页面规划，不写正文、逐字稿与口播。

【课件主题】
（例如：《Attention Is All You Need》论文精读 / 汽车外流场气动阻力分解 / 美联储加息周期与流动性传导）

【目标受众】
（例如：初中级算法工程师 / 流体仿真初学者 / 财经泛科普受众）

【预计时长】
（例如：6~8 分钟试制切片 / 20 分钟完整课）

【lesson slug】
（例如：02-attention-patterns；只能使用小写字母、数字和短横线）

【规划页数】
15~20 页

【核心重点】
1. （必须讲透的知识点或推导）
2. （必须完成的对比、实验或案例）
3. （必须落到工程实践的结论）

【参考资料 / 核心依据】
（论文、教材、标准、财报、数据集或可核查链接；请标注版本与年份）

【特殊页要求】
（例如：第 8 页用 .metric-grid；第 12 页用 .split 左右对比；第 14 页需要带行高亮的代码块）

【输出要求】
1. 只输出大纲，不输出页面正文、公式全文或演讲逐字稿。
2. 每页给出：页码、主标题、核心命题、视觉类型（公式/图表/代码/指标卡/双栏）、版式类、证据来源、一句中文直觉。
3. 标出需要新增的 SVG 或图片资源，以及建议文件名。
4. 标出建议用 -- 做垂直拆页的位置；没有必要时不要拆。
5. 对不确定或缺乏来源的数据明确标注“待核实”，不要编造。
6. 叙事必须形成“问题 → 机制 → 证据 → 取舍 → 结论”的闭环。
7. 先输出【技术假设与事实前置审查表】：模型宽度、分布假设、因果掩码、自回归解耦边界、数据或论文版本，后续推导依赖的前提必须在这里钉死。
8. 大纲表增加“预计时长”和“动画需求（引擎 + 场景名）”两列；动画只给名字，不写代码。
```

大纲确认前，不要进入正文生成。至少检查以下四点：

- 每页是否只有一个主张，标题是否能独立说明该主张。
- 公式、图表和代码是否服务于论点，而不是装饰。
- 关键数字、论文结论、实验条件是否有明确来源。
- 15~20 页是否能支撑约 25~40 分钟讲解；每页口播按 1.5~2 分钟估算。

### 阶段二：分幕正文生成指令

大纲确认后，每次只生成 4~6 页，且必须分成两个互不混杂的文本块。复制下面的模板，填写页码范围。

```text
大纲已确认。请输出第 [X] 页到第 [Y] 页，分两个独立文本块交付：
文本块 A 追加到 slides.md，文本块 B 追加到 lecture_notes.md。

【工程约束】
1. 文本块 A 输出可直接追加到 lessons/<lesson-slug>/slides.md 的 Markdown/HTML 片段，不要用代码围栏包住整批内容；文本块 B 同样是可直接追加的 Markdown。
2. A 块中，页面之间只用独占一行的 --- 分隔。只有大纲明确要求时才使用独占一行的 -- 垂直拆页。
3. A 块中，页面上方使用英文主内容；页面下方使用 <div class="zh-sub"><p>中文对照与白话解释</p></div>。
4. 文本块 A 禁止出现任何 Notes:、口播、时长、导播提示或动画标记；屏幕上出现什么，A 块就写什么。
5. 文本块 B 按 Slide N 编号，与 A 块页序一一对应；每页四要素：时长预算、动画切入（引擎 + 场景名 + 秒点）、技术核查、逐字口播（1.5~2 分钟，含现场设问与过渡句）。
6. 公式必须核验符号、维度和适用条件。当前工程没有数学排版插件，禁止使用 $...$ 或 $$...$$；请用 .equation 容器配合 <sub>/<sup> 和 Unicode 数学符号。
7. 代码块使用带语言标记的 Markdown 围栏；需要分步高亮时使用 python [1|3-4|6-7] 作为围栏语言标记，并确保每行代码完整、可解释。
8. 图片统一使用根路径：![alt](/lessons/<lesson-slug>/assets/xxx.svg)。不要使用 assets/xxx.svg。
9. 只使用主题中已有的 CSS 类。需要新组件时先停下并说明原因，不要自创类名或内联样式。
10. 数值、结论和引用必须有依据；无法核实时标注“待核实”，不要补写看似合理的数字。

【本批范围】
第 [X] 页至第 [Y] 页。

【衔接要求】
从第 [X] 页的标题开始输出，不要重复第 X 页之前的页面。
如果本批不是第一批，请在本批第一页内容前加一行 ---，与本批之前的内容衔接。
本批最后一页末尾不要留下结尾分隔符。

【额外要求】
（例如：第 8 页放三张指标卡；第 10 页代码块按 import / forward / loss 三步高亮）
```

### 批次拼接规则

每个批次的两个块应能分别独立粘贴到 `slides.md` 与 `lecture_notes.md` 末尾。建议按以下顺序操作：

1. 建立 `lessons/<lesson-slug>/assets/`。
2. 将第一批的 A 块写入 `slides.md`，B 块写入 `lecture_notes.md`。
3. 后续批次开头用 `---` 接上，不要在文件里出现连续两个 `---` 空页；B 块的 Slide 编号接着排。
4. 全部批次落盘后，运行 `npm run dev`，逐页检查。
5. 如果生成器改写了前一批页面，不要直接覆盖本地已验收内容；只接收新增范围。

## 三、单页写作规范

### 3.1 页面结构

每页按以下顺序组织：

1. `##` 主标题，短、具体、可独立成立。
2. 英文主内容：1~4 条论点、一个关键公式/图表/代码，或一组指标。
3. 中文对照：`.zh-sub`，解释英文主内容，不逐字翻译；补足直觉、边界条件和工程含义。
4. 到此结束。不写备注、时长或导播提示——这些属于 `lecture_notes.md`。

### 3.2 信息密度

- 单页核心论点最多 3~4 条。
- 每条论点控制在 1~2 行；避免整段论文摘要。
- 一页只放一个主图或一个主公式。图和公式同时出现时，删掉非必要文字。
- 某页超过 4 条论点或预计超出画布时，用 `--` 拆成同主题的垂直子页，并在 `lecture_notes.md` 对应块说明切换。
- 中文对照通常控制在 2~4 句；术语第一次出现时保留英文原词。

### 3.3 分页符号

- `---`：下一页，水平移动。
- `--`：当前主题下的下一页，垂直深入。
- 两者都必须独立成行，前后保留空行。
- 不要在标题、公式或正文中把 `--` 当作装饰线，避免被解析成分页。

```markdown
## First slide

English thesis.

<div class="zh-sub"><p>中文对照。</p></div>

---

## Second slide

--

### Detail within the same theme

只有在确实需要分层讲解时才使用垂直子页。
```

### 3.4 讲师手册 `lecture_notes.md`

口播不写在幻灯片里。每套课件在同目录维护一份 `lecture_notes.md`，按 `Slide N` 与 `slides.md` 页序一一对应（封面算第 1 页，`--` 子页记为 `3b`）。每页固定四要素：

```markdown
### Slide 2: Scaled Dot-Product Attention（方差推导与缩放）

- **时长预算**：90 秒
- **动画切入**：第 45 秒切入 Motion Studio 场景 `variance_drift`；无动画写“无”
- **技术核查**：先声明 q_i、k_i 独立同分布且单位方差，再讲方差随维度线性增长

#### 逐字口播

各位工程师朋友，看屏幕上的公式……
```

逐字稿按 150~180 字/分钟估算，与时长预算对得上；动画切入里的场景名必须能在动画仓找到同名文件。

## 四、组件手册（以当前主题为准）

以下组件的 HTML/CSS 已在工程中实现。生成器应优先复用，不要另造相似组件。

### 4.0 原始 HTML 块的边界

外部 Markdown 会先被解析成 HTML 再插入页面。块级 `<div>` 内的内容请全部使用显式 HTML 标签：

```html
<div class="split">
  <div>
    <h4>左侧标题</h4>
    <p>左侧内容。</p>
  </div>
  <div>
    <h4>右侧标题</h4>
    <p>右侧内容。</p>
  </div>
</div>
```

不要在 `<div>` 里直接写 `## 标题` 或 Markdown 列表；为保证解析稳定，HTML 块内部不要留空行。

### 4.1 封面（`.title-slide`）

```html
<div class="title-slide">
  <p class="eyebrow">Technical Courseware / 02</p>
  <h1>Title<br>Goes Here</h1>
  <p class="title-cn">中文主标题：一句说明课程范围。</p>
  <p class="title-en">One English sentence that frames the lecture.</p>
  <div class="title-rule"></div>
  <div class="title-meta"><span>Foundation Models</span><span class="dot"></span><span>Lecture 02</span><span class="dot"></span><span>2026</span></div>
  <div class="deck-index">02</div>
</div>
```

封面不写 `.zh-sub`；中文标题使用 `.title-cn`。`deck-index` 只做装饰，不承载信息。

### 4.2 双语对照（`.zh-sub`）

```markdown
English explanation stays in the main slide body.

<div class="zh-sub"><p>中文对照与直觉解释，放在每页下方。可以补充适用条件、工程含义和常见误解。</p></div>
```

`.zh-sub` 已经包含虚线分隔、灰色小字号和左对齐规则，不要再手动加 `<hr>` 或设置字体大小。

### 4.3 指标卡（`.metric-grid` + `.metric`）

用于性能、维度、超参数和对比数据。注意不要沿用旧版示例中的 `.card` 结构。

```html
<div class="metric-grid">
  <div class="metric metric--accent">
    <div class="metric__value">O(1)</div>
    <div class="metric__label">Sequential operations</div>
  </div>
  <div class="metric">
    <div class="metric__value">512</div>
    <div class="metric__label">Hidden dimension · d_model</div>
  </div>
</div>
```

`metric--accent` 会把顶部细线改成橙色。指标值必须带单位、条件或维度，不要只写一个漂亮数字。

### 4.4 内容卡（`.cards` + `.card`）

用于并列的三个概念、三种取舍或三条结论。

```html
<div class="cards">
  <div class="card">
    <span class="card__index">01 / RELATE</span>
    <h3>Relationships over recurrence</h3>
    <p>Attention learns which tokens should exchange information.</p>
  </div>
  <div class="card">
    <span class="card__index">02 / COMPUTE</span>
    <h3>Parallel over sequential</h3>
    <p>The sequence becomes one matrix operation.</p>
  </div>
  <div class="card card--accent">
    <span class="card__index">03 / COST</span>
    <h3>Quadratic attention</h3>
    <p>An n × n score matrix grows in time and memory.</p>
  </div>
</div>
```

每张卡只放一个短标题和 1~2 句解释。三张卡通常比四张更适合 16:9 画布。

### 4.5 双栏对比（`.split`）

```html
<div class="split split--top">
  <div>
    <h4>RNN / LSTM</h4>
    <p>Sequential dependency, memory bottleneck, harder to parallelize.</p>
  </div>
  <div>
    <h4>Transformer</h4>
    <p>Full parallelism, global receptive field, quadratic attention cost.</p>
  </div>
</div>
```

可选修饰类：

- `split--top`：两栏顶部对齐，适合文字量不同的对比。
- `split--wide-left`：左栏更宽，适合文字 + 右侧图表的组合。

### 4.6 公式块（`.equation`）

当前工程未加载 KaTeX / MathJax。不要写 `$...$` 或 `$$...$$`，否则会原样显示。使用 HTML 上下标、Unicode 数学符号和 `.equation`：

```html
<div class="equation">Attention(Q, K, V) = softmax( QK<sup>T</sup> / √d<sub>k</sub> ) V</div>
```

多行公式用 `<br>` 分隔：

```html
<div class="equation">head<sub>i</sub> = Attention(QW<sub>i</sub><sup>Q</sup>, KW<sub>i</sub><sup>K</sup>, VW<sub>i</sub><sup>V</sup>)<br>MultiHead = Concat(head<sub>1</sub>, …, head<sub>8</sub>) W<sup>O</sup></div>
```

需要复杂排版的分式、矩阵或推导时，优先制作 SVG 图，或先给 `template/index.html` 加数学插件并验证；不要在课件中塞入不能渲染的 TeX。

### 4.7 代码与分步高亮

代码块使用 Markdown 围栏。方括号中是从第一步到后续步骤的高亮行号，已验证可用：

````markdown
```python [1|3-4|6-7]
def scaled_dot_product_attention(q, k, v, mask=None):
    d_k = q.size(-1)
    scores = torch.matmul(q, k.transpose(-2, -1)) / math.sqrt(d_k)
    if mask is not None:
        scores = scores.masked_fill(mask == 0, -1e9)
    weights = torch.softmax(scores, dim=-1)
    return torch.matmul(weights, v)
```
````

要求：

- 每个代码块不超过 8~10 行，只保留当前论点需要的代码。
- 代码块必须有语言标记（`python`、`javascript`、`bash` 等）。
- 行号高亮只用于讲解顺序，不要给每页都加。
- 伪代码必须明确标注为 pseudocode，不能伪装成可运行代码。

### 4.8 引用块（`blockquote`）

用 Markdown 引用即可获得左侧 4px 橙线和浅橙底：

```markdown
> **Key idea.** The Transformer removes recurrence from the computation path, not by making recurrence faster.
```

引用块适合承载一句结论或一个反直觉判断，不要用它包裹整页正文。

### 4.9 图片与图表

图片放在 `assets/` 下，统一使用服务器根路径：

```markdown
![Attention flow](/lessons/02-attention-patterns/assets/attention-flow.svg)
```

需要控制图表高度或配图注时，使用 HTML：

```html
<figure>
  <img class="diagram" src="/lessons/02-attention-patterns/assets/attention-flow.svg" alt="Four-step scaled dot-product attention flow.">
  <figcaption>图 1：Q/K/V 投影、打分、softmax 与加权求和。</figcaption>
</figure>
```

- `.diagram` 的最大高度为 350px，适合双栏内的图。
- `.diagram--full` 的最大高度为 320px，适合单页横向大图。
- 每张图必须有 `alt` 文本；图中的文字要能被投影看清，避免把论文原图直接缩小到不可读。
- 建议使用原创 SVG，颜色沿用主题色板：`#1A1A1A`、`#595959`、`#EB6100`、`#FFF5F0`、`#E5E5E5`。

### 4.10 表格

原生 Markdown 表格已由主题接管，用于维度对照、算法优劣或参数表：

```markdown
| Model | Complexity | Sequential ops | Long-range path |
| --- | --- | --- | --- |
| RNN | O(n · d²) | O(n) | O(n) |
| Transformer | O(n² · d) | O(1) | O(1) |
```

单位、维度和测试条件必须写清。不要让表格成为堆数字的角落。

## 五、内容质量门槛

生成器在交付前必须通过以下检查：

1. **事实有锚点**：关键数字、论文结论、产品行为和实验结果标注来源；来源至少包含作者/机构、年份和章节、页码或链接之一。
2. **公式可核验**：符号定义、张量维度、单位、假设条件和适用边界齐全；不能只给结论形式。
3. **代码可信**：可运行代码给出完整依赖和上下文；片段代码明确说明省略部分；不得杜撰 API。
4. **事实与解释分离**：把“论文报告的结果”和“讲者的推论”分开写；不确定内容标注“待核实”，不要用语气伪装确定性。
5. **比较公平**：对比方法使用同一数据集、同一指标和同一条件；条件不同必须写明。
6. **中文不篡改技术含义**：中文可以更直白，但不得省略关键限定词，不得把“在某些设置下”改成“总是”。
7. **无营销腔**：删掉“颠覆性”“革命性”“完美解决”等无信息量措辞，改用机制、条件和边界。
8. **页页可演讲**：`lecture_notes.md` 每页口播 1.5~2 分钟，包含开场句、一个设问、必要的停顿和承上启下句。

## 六、本地调试与排障

### 启动

```bash
npm run dev
```

打开：

```text
http://localhost:8081/?lesson=<lesson-slug>
```

建议同时检查 `1280 × 720` 与 `1600 × 900` 两种窗口尺寸。前者接近设计画布，后者接近常见投影环境。

### 常见问题

| 现象 | 常见原因 | 修正 |
| --- | --- | --- |
| 页面显示 ERROR / HTTP 404 | `lesson` slug 写错，或 `slides.md` 不存在 | 检查目录名与 `?lesson=` 参数，确认文件在 `lessons/<slug>/slides.md` |
| 图片 404 | 写成了 `assets/x.svg` 相对路径 | 改成 `/lessons/<slug>/assets/x.svg` |
| 屏幕上出现口播稿 | 把 `Notes:` 写进了 `slides.md` | 删除，改写进 `lecture_notes.md` 的同编号块 |
| 演讲者视图没有台词 | v3 起口播不再进 `slides.md` | 副屏或平板打开 `lecture_notes.md` 提词；`S` 视图只看计时与下一页预览 |
| 公式原样显示 | 使用了 `$...$` / `$$...$$` | 改成 `.equation` + HTML 上下标，或先接入数学插件 |
| 分页失效 | `---` / `--` 与文字在同一行 | 让分页符独立成行，前后留空行 |
| 右侧内容被裁切 | 单页文字或图片过密 | 删减到 3~4 条论点，或把细节拆成 `--` 垂直子页 |
| HTML 内的 Markdown 不渲染 | 把 Markdown 标题或列表放进了块级 `<div>` | 在 HTML 块内全部使用 `<h3>`、`<p>`、`<ul>` 等显式标签 |
| 代码没有行高亮 | 围栏信息字符串缺少方括号语法 | 把围栏语言写成 `python [1|3-4|6-7]` |
| 组件没有样式 | 使用了旧版类名或自创类名 | 对照本文件与 `css/mckinsey-orange.css` 使用现有类 |

### 本地上线前检查单

- [ ] `slides.md` 位于正确目录，`?lesson=` 参数与目录名完全一致。
- [ ] 所有分页符独立成行，页与页之间没有多余空页。
- [ ] 除封面外，每页都有英文主内容和 `.zh-sub` 中文对照。
- [ ] `slides.md` 中没有任何 `Notes:`、口播或时长文字。
- [ ] `lecture_notes.md` 页数与 `slides.md` 一致，每页四要素齐全。
- [ ] 图片路径均为 `/lessons/<slug>/assets/...`，没有 404。
- [ ] 所有公式通过 `.equation` 或 SVG 显示，没有裸露的 `$`。
- [ ] 所有 CSS 类都存在于主题文件，没有自创或拼写错误的类名。
- [ ] 在 `1280 × 720` 和 `1600 × 900` 下逐页翻看，无文字裁切、无横向溢出。
- [ ] 关键数字、公式、引用均已核对，未核实项已经标出或删除。
- [ ] 全套课件能连续讲完，页面之间没有重复论点或断裂过渡。

## 七、最小可复用页骨架

将下面的结构作为每一页的起点，再按需替换组件：

```markdown
## A specific, self-contained claim

One English paragraph or up to four bullets that support the claim.

<div class="zh-sub"><p>两到四句中文解释：补充直觉、边界条件与工程含义。</p></div>
```

对应的讲师手册块：

```markdown
### Slide 3: A specific, self-contained claim

- **时长预算**：90 秒
- **动画切入**：无
- **技术核查**：（本页最容易讲错的前提）

#### 逐字口播

本页约 90 秒。先给结论，停 2 秒，指向图表或公式，问观众一个具体问题；最后用一句过渡带出下一页。
```

封面页使用 `.title-slide`，不需要 `.zh-sub`。其余页面统一保持“英文主内容 → 中文对照”的顺序；口播与导播信息全部写在 `lecture_notes.md`，便于批量验收。
